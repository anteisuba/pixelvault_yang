> **只取形态，不取颜色**（owner 2026-08-09：「css 这边我想对齐一下这个……除了颜色」）。
> **方法**：claude-in-chrome 打开 owner 自己的画布项目（登录态），**程序化读 computed style**，禁目测。只读不点花积分的控件；只做了一次「选中节点」以让动作条与提示词面板浮出。

## 4 · 可直接翻译的十条形态规则（不含颜色）

1. **圆角只有三档 + 圆**：控件 8 · 浮层与工具条 12 · 大输入面板 16 · 圆钮 50%。
2. **画布上的卡不参与圆角体系**：直角、无边、无影，卡就是媒体本身。
3. **字号只有三档**：13 UI · 14 输入 · 11 元信息。
4. **间距严格二倍**：2 / 4 / 8 / 16。图标与文字之间恒 2px。
5. **图标恒 14px**（次级 16）。
6. **控件高三档 24 / 28 / 32**，圆角一律 8。
7. **投影只给真正的浮层**（一层，`0 4px 10px`），面板与工具栏一律零投影。
8. **节点名字与尺寸标注在卡外上方同一行**，左名字（13）右元信息（11）。
9. **连线细（2px）+ 宽热区（20px）**：视觉轻、可点性高。
10. **缩放二分法**：媒体与连线随缩放；文字与 chrome 反缩放（屏幕固定尺寸）。

### ⭐ 真机验出来的两处空改（2026-08-10，owner 登录后逐项验）

6-A 第一版有两条「已采纳」**根本没落到画面上**。两条都是同一个病：**改了一个没人读的地方**。写在这里，因为下一个照着这张表实现的人会踩同一个坑。

**① 连线的粗细与热区不在 CSS 里。** 我改的是 `canvas.css` 的 `--canvas-edge-w` / `--canvas-edge-hit-w`，而这两个 token **零消费者** —— 边的 style 由 `StudioNodeWorkbench` 从 **`constants/node-studio.ts` 的 `NODE_STUDIO_EDGE_VISUALS`** 内联写死。真机实测渲染仍是 3px / 16px。
→ 已改常量（`strokeWidth` 四档 3→2 · `interactionWidth` 16→20），两个零消费者 token 已删。真机复验：9 条边热区全 20px、已建立边 2px。
⚠ `pendingStrokeWidth: 1.5` **不动** —— 未就绪虚线是有意的弱信息档，不在本条范围。

**② 圆角只归了 CSS 那一半。** `canvas.css` 里的字面量归档之后，真机一量画布上**还有 87 处野值**：6px×4 · 10px×42 · 14px×29 · 18px×11 · 22px×1。来源在**组件的 Tailwind 类**：每个 shadcn 原语（Popover / Button / Tabs …）一进画布就带进 `rounded-sm/md/lg/xl/2xl`，而它们从 `--radius: .625rem`（10px）**等差派生** = 6 / 8 / 10 / 14 / 18。
⛔ **改 `--radius-*` 没用，试过了**：`globals.css` 用的是 `@theme inline`，Tailwind 把定义内联进工具类，域内覆盖 `--radius-lg` 一点效果都没有；唯一还起作用的杠杆是 `--radius` 本身，但等差派生**没有任何一个 r 能同时给出 8 / 8 / 8 / 12 / 16**（r=12 时 md 变 10、2xl 变 20）。
→ 已在 `.domain-canvas` 内直接覆盖工具类。这不是绕过 token 体系，正是它说的那条路 —— **薄脊柱 + 域皮肤，原语零改换皮**；特异度 `(0,2,0)` 稳压 `(0,1,0)`，域外一点不动。真机复验：**87 → 4**（其中 7px×2 是媒体窗 `calc(--canvas-card-radius - 1px)` 的内缩，有意为之）。

**教训一句话**：`docs` 里写「已采纳」之前，判据是**真机量到的渲染值**，不是「我改了那个看起来对的 token」。这两条闸门三样全绿、也进了 commit，全都拦不住。
