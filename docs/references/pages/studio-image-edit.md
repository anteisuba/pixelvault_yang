## 0 · 作用域

`/studio/image` 右侧结果区（`StudioCanvas`）里「看一张图 / 编辑一张图」这条链。**不含**左参数栏
（`StudioPromptArea`，另有会话在飞）、不含多模型结果图墙的改动、不含 video / audio 模态。

## 1 · 舞台归属 ✅ owner 拍板

**一条规则**：舞台显示「当前这张图」，来源不限。

| 情形             | 舞台显示                                                        |
| ---------------- | --------------------------------------------------------------- |
| 有生成结果       | 结果优先（单张 `GenerationPreview` / 多张 `CompareGrid`）       |
| 无结果、有参考图 | **显示当前参考图**（大图 + 「参考图 N / M · W × H」+ 编辑入口） |
| 无结果、无参考图 | 保持今天的空态（eyebrow + 三个示例 chip + 继续创作 + 教程）     |

⚠ 参考图上舞台**不改变它的身份** —— 它仍是生成的输入，槽位仍在左栏。舞台只是把它显示在最大的地方。

## 2 · 编辑态结构

**方向 A（舞台接管）**：进编辑后，右侧结果区整片切成编辑态。左参数栏不动、不收窄。

三区，自上而下 / 自左而右：

1. **返回条**：`← 回到工作台` + 「正在编辑 · 参考图 N / M · W × H」。⚠ 必须一直显示当前编的是哪一张。
2. **图区**（占满剩余宽度减去工具栏）：大图 + 编号框浮层。
3. **工具栏 320px**：工具行（拉框 / 笔刷 / 橡皮 / 清空）· 注释清单 · 主动作 · 历史行。

⚠ **不引入 Tailwind arbitrary values**（Hard Rule 5）；320 与 288 走 `w-80` / 既有栏宽常量。

## 3 · 状态矩阵

| 态          | 舞台                                                       | 判据                 |
| ----------- | ---------------------------------------------------------- | -------------------- |
| 空          | 今天的空态，不动                                           | 无结果且无参考图     |
| 查看        | 大图 + 「参考图 N / M · W × H」+ 编辑入口                  | 无结果且有参考图     |
| 编辑 · 待改 | 返回条 + 大图 + 工具栏；清单为空时给一句「在图上拖一个框」 | 进入编辑态、尚未画框 |
| 编辑 · 有框 | 图上编号 ①②③；每框在清单里一行，可改文字、可删             | ≥1 个框              |
| 提交中      | 主动作转圈；**逐条报状态**，不是整轮一个进度               | 已提交               |
| 单条失败    | 该条变红 + 「重试这条」；**其余条不受影响、不回滚**        | 某条返回失败         |

⚠ 「单条失败可单独重试」是硬要求 —— 图墙已经做到（每格自报状态），编辑面不许退化成「一步失败重来整轮」。

## 4 · 入口（三个，都进同一个编辑态）

1. **舞台上的当前图** → 「编辑这张」按钮 / 点图。**E1 只做这一个。**
2. **生成结果** → `GenerationPreview` 工具行里已有的 ✎（`onEdit`）。
   ⚠ 今天它 `router.push` 去 `/studio/node?canvasTool=image-edit`（`StudioCanvas.tsx:237`）——**改成就地打开**，不再跳画布。
3. **左栏参考图缩略图** → 点开即编辑。⚠ **排最后**：它在 `StudioPromptArea` 内部，与在飞会话冲突，等那条线收了再补。

⛔ **不新增第二个放大态**。`ImageAttachmentPreviewStrip` 今天那个只有 ✕ 的预览 Dialog，要么长出编辑能力，要么并入本编辑态 —— 不许两个放大态并存。

## 5 · 注释清单 → 后端选路

图上**只画编号**，文字走清单进 prompt，**不落像素**（2026-07-11 拍板，理由未变：痕迹落像素 + 不结构化）。

| 用户做了什么      | 走哪条                                                  |
| ----------------- | ------------------------------------------------------- |
| 一个框 + 一句话   | `inpaint`（框即 mask）—— **已跑通**                     |
| 多个框 + 各自注释 | 编号 ①②③ 画图上、注释以清单进 prompt → `object-replace` |
| 不框 + 整体一句话 | `style-transfer`                                        |

✅ **`object-replace` 已于 2026-08-19（E3）从零建成并提回 ready**，默认模型 `gemini-3-pro-image`
（三选一实测选定，任务包 §7.11）。⚠ **`style-transfer` 至今零执行路径，仍是 hidden** —— 要用它得先建，
别只改 `availability` 那一行（E0 的教训）。

⚠ **E3 的能力边界（真机实证）**：模型按**名字**改，不按框 —— 改动会溢出框（「加靴子」会把画面里所有
光脚都加上）。框是「定位兜底 + 让用户看见圈了哪儿」，不是选区。要精确到一处，退回单框 `inpaint`。

## 6 · 编辑结果的去向 ✅ owner 拍板

**就地替换该参考图槽位**，并留一条历史链可回退。

- 历史链 = **注释清单的历次快照**，不是另一份数据（E3 与 E4 是同一个东西，别做成两份）。
- ⚠ 派生 generation 今天带的是机器写的 prompt（`[inpaint] from generation …`），它会灌进用户提示词框。
  **派生时保留源图的 prompt，编辑指令另存字段。**
- 派生节点 / 派生结果一律用 `generation.url`（R2 持久副本），不用 provider 返回的临时 URL。

## 7 · 共享与专属边界

**复用行为、不重造**：

- 笔刷涂抹 = `StudioInpaintEditor`（已实现，20 步撤销，导出蒙版**必须是源图真实像素**——见其内注释）。
- 能力契约 = `canvas-image-edit-capabilities` + `canvas-capability-runtime`，画布与工作台**同一套**。
- 源图尺寸 = 自己量位图（`new Image()` 探针），**量到的赢过 `data.mediaWidth`**。

**不碰**：`StudioPromptArea` / `BaseModelPickerPanel` / `StudioCostPreview`（在飞）· 图墙 `CompareGrid` 的选 winner 手势 · 左参数栏宽度。

## 8 · 响应式

- `lg`(1024) 以下：工作台已退回纵向（参数在上、结果在下）。编辑态在该档**图区占满宽度、工具栏移到图下方**，不做三栏。
- ⚠ 断点用 `lg` 与 `useIsMobile` 对齐 —— 平板 768–1023 用 `md` 会出现空沟（`StudioWorkbenchLayout` 已有此注释，别重蹈）。

## 10 · 验收

1. 四态逐态真机截图，与已确认原型比对（空 / 查看 / 编辑·有框 / 单条失败）。
2. 三个入口各进一次，**进的是同一个编辑态**（不是三份实现）。
3. 多框场景：画 3 个框 → 清单 3 行 → 一次提交 → 成品**无标注痕**、三视图一致（首发验收场景，任务包 §五）。
4. 单条失败：只重跑那一条，其余不动、不回滚。
5. 编辑完**参考图槽位就地更新**，且能回退到上一次。
6. 提示词框里**不出现** `[inpaint] from generation …` 这类机器串。
7. 全量 tsc + 全量 vitest + eslint。
