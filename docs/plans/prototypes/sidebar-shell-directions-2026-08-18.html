丝滑 · 根因4 条
01
宽度动画是 linear，而且动的是布局属性 你点名的
机械感的第一来源：匀速曲线没有起停。更重的问题是它动的是 width / left——主内容整棵树每帧跟着回流。 项目自己的 interaction.md §2 硬原则 2 写着「禁止用 top/left/width 做高频动画」，壳在违反自己的规矩。 sidebar.tsx:224 transition-[width] 200ms linear sidebar.tsx:235 transition-[left,right,width] 200ms linear
02
两条独立的 transition 在赛跑 你点名的
占位元素（推开主区的 sidebar-gap）和真身（fixed 的 sidebar-container）各跑一条过渡，属性集还不一样。 理论同步，实际容易半帧错位——观感就是「侧栏和内容没黏在一起」。
03
切工具时，颜色是瞬时换的——没有任何过渡 你点名的
这是「切换工具不丝滑」的第一现场。菜单项的过渡属性只列了三个，背景色和文字色都不在里面：点一下，旧格子的灰底啪地消失、新格子的灰底啪地出现。 顺带，它的曲线/时长也不是项目 canon 的那一套。 真机 getComputedStyle（激活项 · 图像） transition-property : width, height, padding transition-duration : 0.15s transition-timing : cubic-bezier(.4, 0, .2, 1) ← Tailwind 默认 canon 应为 : 120ms / cubic-bezier(.22, 1, .36, 1)
04
收起时标签是被硬裁的，不是淡出的 你点名的
只有 overflow:hidden + truncate，没有 opacity 过渡。192→48px 的过程里文字像被门夹住。
好看 · 层次4 条
05
激活块和分割线是同一个灰 你点名的
--sidebar-accent 与 --sidebar-border 解析出来是同一个值。所以「你在哪」这个最重要的信号， 用的是和分隔线一样的墨水，对轨面只有 1.21:1。 激活块 rgb(229,229,229) 轨面 rgb(250,250,250) → 1.21 : 1 右边框 rgb(229,229,229) ← 与激活块同值
06
hover 和 active 共用一个 token，悬停任一项都长得像「当前项」 我加的
hover:bg-sidebar-accent 和 data-[active=true]:bg-sidebar-accent 是同一个颜色。 鼠标扫过列表时，每一项都短暂地伪装成当前工具。这不是审美问题，是可用性 bug—— 所以三个方向里我都把 active 换成了「指示器 + 墨色加深」，hover 只留极轻的底色，两者不再同形。
07
轨面和主区面 1.04:1，分区全靠一条发丝线 我加的
rgb(250,250,250) 贴着 rgb(255,255,255)，肉眼近乎同一张纸。 现在唯一的分界是那条 1.21:1 的右边框。方向 C 就是冲这条来的：改用「底色 vs 卡片」的天然层次，边界不再需要线。
08
底部账户区占了 167.5px，四行各自带框 我加的
真机量到 header 61 / 导航 682.5 / footer 167.5——账户区吃掉竖向 18%，而且积分盒、额度条、头像行、语言行 四行各有边框或底色，视觉重量比上面真正的导航还大。理由很简单：它们是读数，不是去处， 不该和导航抢层级。三个方向里我都把它收成一行（积分 + 头像），额度和语言进头像菜单。
结构与响应式 · 你没点名4 条
09
「敬请期待」在收起态变成一个没有意义的箭头 我加的
你第一张截图里工具组下面那个孤零零的 > 就是它。展开器在 48px 轨里点开也无处显示标签， badge「3」本身也被 group-data-[collapsible=icon]:hidden 藏了。删得掉—— 收起态直接不渲染这一行，而不是把它缩成一个箭头。
10
桌面侧栏和移动轨是两套组件手工同步，已经漂了 我加的
AppSidebar 和 MobileCollapsedRail 各维护一份图标清单。桌面工具组有「敬请期待」（增强 / 解析 / 故事）， 移动轨完全没有——那三个入口在小屏不可达。真机数了一下：移动轨 16 个可点元素 vs 桌面 12 个，构成不同。 方向 A 顺手解决它：两个断点收敛成同一个形态、同一套组件。
11
断点是 1024，平板拿到的是手机形态 我加的
桌面侧栏是 lg:（1024）才出现。768–1023 的平板明明放得下 192px 侧栏，却只能拿到 「44px 死轨 + 44px 顶栏 + 抽屉」。 ⚠ 这条是代码事实，不是渲染实测——本机 resize_window 调用返回成功但 innerWidth 恒为 1920， 视口切不过去，平板与手机档我这次没验过，不能按已验处理。
12
品牌名挂着逐字乱码的 hover 动画 我加的
HyperText animateOnHover duration={600}。一个每天要看几百次的导航元素上放炫技动画， 和 interaction.md §5「动效只服务状态 / 连续性 / 反馈，禁止无信息的装饰」直接冲突。 建议撤掉——品牌感应该来自字形和留白，不是来自它会抖。

三个方向 结构不同，不是换色

门禁要求三个「结构明显不同」的方向。下面三个的区别在于展开这件事对主区做了什么—— A 不碰主区，B 推挤主区，C 让两者都变成浮在底色上的面。你的两个诉求（好看 / 丝滑）在三个里都能满足， 差别在代价落在哪里。

A 静轨 B 分段板 C 浮岛
结构 56px 图标轨永远在。展开=标签层覆盖在主区上滑出，主区宽度恒定。 保留推挤式 200px 面板，把 12 行重排成「去处 / 工具 / 账户」三段，段间用留白分不用线。 壳底变浅灰，侧栏和主区各成一张圆角卡浮在上面，中间留 10px 缝。
切工具时在动什么 transform + opacity（指示器滑动、图标变色） transform + opacity（单一指示器滑动） transform + opacity（白色浮片滑动）
收展时主区回流 没有——抽屉是覆盖层 有，但曲线换成 canon 的 320ms 有，10px 缝把半帧错位吸掉
顺手解决 01·02·03·04·06·09·10·11（两套导航合一） 01·03·04·05·06·08·09 03·04·05·06·07（两个白面的问题）·08
代价 常驻标签消失，靠图标认路。现在 3D / 画布 / LoRA 三个图标在 16px 下不好分，得先换。 宽度动画还在，只是曲线正确了。移动端仍是另一套。 主区可用宽度少 16px；画布是全屏工作面，被圆角卡框住可能不接受，需要逐域逃逸口。
改动量 大（要重写 ui/sidebar.tsx 的收展模型 + 合并移动轨） 小（改 token、加指示器、重排分组，primitive 基本不动） 中（shadcn 已有 variant="inset"，主要成本在逐域验证）

我推荐 A。理由是它同时命中你说的两件事而且没有折中：主区宽度恒定 = 收展和切换全程零回流， 这是「丝滑」的物理上限；同时它把桌面和移动收敛成一套组件，第 10 条那种「两边手工同步然后漂掉」的账以后不会再欠。 B 是最省的增量——如果你只想要立刻好起来、不想动 primitive，选它，一天能落完。 C 视觉收益最大（第 07 条只有它真正解决），但画布域要单独谈。
