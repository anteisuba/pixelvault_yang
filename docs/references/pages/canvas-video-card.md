## 0 · 域定义

视频节点是一个可继续参与连线的**视频产物**；右侧编排器是该节点的**唯一下单面**。

- 视频卡只回答“这段视频是什么、现在是什么状态”。
- 右侧编排器回答“本次要怎么生成、使用哪些素材、用什么模型与参数”。
- 已连接素材仍属于画布真节点，不复制、不搬家；编排器只是读取和指定。
- 卡匣/节点定位不在本轮范围；扩大入口复用现有
  `NodeDetailPanel`，不再在节点旁维护第二套详情页。

## 1 · 视频卡

| 部件   | 规格                                                        |
| ------ | ----------------------------------------------------------- |
| 名字   | 卡外左上，族图标 + 原地可编辑名称；复用 `NodeShell.Header`  |
| 卡内   | **只有视频媒体**，不显示场记条、模型、参数、成分 chip、页脚 |
| 空态   | 媒体窗内显示真实空态                                        |
| 生成中 | 媒体窗内显示真实生成中态，不伪造百分比                      |
| 就绪   | 原生 `<video controls>`，poster 复用 `videoThumbnailUrl`    |
| 端口   | 左右垂直居中，保持 React Flow 真锚点                        |

视频卡不因打开编排器改变尺寸；这样连线锚点与下游布局不跳。

## 2 · 右侧编排器

- 只在单选视频节点时出现；拖拽节点、多选时隐藏。
- 固定在视频卡**右侧**；以顶部锚点定位后，桌面上移 `40px`、窄屏上移
  `20px`，落在节点工具条与视频卡之间的视觉中带。
- 桌面间距 `24px`；窄屏间距 `20px`。
- 紧凑宽度使用 `--canvas-card-w-console: 320px`。
- 右上仅保留“展开编辑器”图标；进入中央 `NodeDetailPanel` 后，节点旁不再
  同时保留一套重复详情表单。
- 取消选择节点后整个编排器隐藏。

### 紧凑态

保持一个宽松的输入面，不堆叠重复标签：

1. 模型/模式摘要与“展开编辑器”入口。
2. 已连接参考素材缩略条；没有素材时显示下一步，不放假缩略图。
3. 一块占主面积的原生 `<textarea>`；已有 `@token` 由素材按钮按光标位置
   插入。紧凑态不再使用会在受控回写后丢失选区的 `contenteditable`。
4. 底部 dock：真实模型选择器、参数入口与生成按钮。参数弹层只显示当前
   模型声明支持的时长、画幅、分辨率和音频能力；紧凑时长使用单一滑杆，
   不再额外联动一个“自定义”开关。

### 详细态

- 从侧栏进入中央 `NodeDetailPanel`；视频节点尺寸、坐标和连线不变。
- 继续消费与紧凑态同一份 `useVideoComposer` 状态和节点数据，不复制
  prompt、模型或参数状态。
- 显示真实素材管理、模型选择、模型能力驱动参数、负面词、seed、
  发送预览和错误/缺失原因。
- 不在节点旁重复渲染详情表单；关闭详情页后回到紧凑侧栏。

## 3 · 真值与能力边界

- 不造假模型、素材、容量、生成进度或请求预览。
- 素材缩略与连接计数来自 `useVideoComposer.referenceTokens`；详细态的
  发送预览与溢出继续来自 `useVideoComposer.sendPreview` 和
  **`CanvasSlotRack`**。
  ⚠ **2026-08-10 校正死指针**：这里原本写 `ReferenceManagerPanel`，而那个组件
  已在 2026-08-09 阶段 1 整个删除。槽架契约见
  [`canvas-slot-rack.md`](canvas-slot-rack.md) —— 顺带一提，「紧凑态只显缩略、
  详细态才有完整账」那套**也已作废**：两档密度现在是同一个件的两个**默认折叠
  深度**，计数框出来必须是同一个数。
- 无角色标签的直连图片按镜头参考收割；`声音 → 非角色图片 → 视频` 保留
  画布边作为绑定关系，声音以“随图片发送”的路由引用显示，并进入同一份
  实际发送计划。它不是复制素材，也不需要新增数据库归属字段。
- 模型选择复用 Studio 的 `CanvasRoutePicker` / `MainModelPicker`；
  `getVideoModelCapabilities` 管具体选项，`video-model-resolver` 管
  Seedance reference sibling，`getVideoModelSendContract` 管素材槽、
  参数是否可编辑和当前执行链是否可用。
- `buildVideoSendPreview` 是预览与真实提交的唯一发送计划；画布提交不得
  另行重算引用顺序、容量或 prompt token。
- 不支持的能力不渲染；缺素材/缺模型/生成中使用真实 disabled reason。

### 模型专属发送契约

| 模型族             | 当前素材槽                                                  | 参数边界                                                              | 执行状态                                |
| ------------------ | ----------------------------------------------------------- | --------------------------------------------------------------------- | --------------------------------------- |
| Seedance Reference | 图片 ≤ 9、视频 ≤ 3、音频 ≤ 3、总数 ≤ 12；音频不能单独发送   | 时长、画幅、分辨率、原生音频、seed；支持 `@ImageN` 位置 token         | Fal 已接入；VolcEngine 未迁移           |
| Seedance base      | 文本或单张首帧                                              | 时长、画幅、分辨率、原生音频、seed                                    | Fal 已接入；VolcEngine 未迁移           |
| Kling V3 Pro       | 当前只发一张明确首帧；不把平铺素材伪装成 Element            | 时长、画幅、负面词、原生音频；不发 resolution/seed                    | Fal 已接入                              |
| HappyHorse v1.1    | 文本或单张首帧                                              | 时长、画幅、720/1080p、seed；模型有原生音频但公开 schema 没有音频开关 | Fal 已接入                              |
| Gemini Omni        | 图片 content array；官方未公布硬图片上限；不发音频/视频参考 | 16:9 / 9:16；时长与 720p 由模型决定                                   | Interactions execution 未迁移，禁用发送 |

未知/自定义视频模型不能只因使用 Fal adapter 就被判定为可执行；必须先有
明确的 worker serializer 和官方能力契约。

## 4 · 响应式与可访问性

- 侧栏用 React Flow `NodeToolbar` 锚定节点并随节点移动，但保持可读的
  屏幕尺寸，不成为 viewport 固定抽屉。
- 窄屏仍在节点右侧，保持 `20px` 间距；画布平移负责把它带进视野。
- 控件均可键盘到达，输入区阻止 React Flow 快捷键冒泡。
- 关闭、展开、生成、模型/参数控件有可读 label。
- 动效只使用 Canvas `150/250/420ms` 三档，并尊重 reduced motion。

## 5 · 验收

1. 点击视频节点出现右侧编排器；拖拽只移动节点，不误开或保留浮层。
2. 编排器左边缘与视频卡右边缘固定相距 24px；打开中央详情不移动视频卡。
3. 视频卡内不再出现成分栏、紧凑 composer 或页脚。
4. 左上名称可 Enter/blur 提交、Esc 取消。
5. 直连散图与经图片路由的声音出现在素材条和真实发送预览；提示词、
   模型、参数和生成按钮读写现有真实状态。
6. 多选与拖拽时编排器隐藏；取消选择后隐藏，重新选择可恢复。
7. 375px 与桌面路径均无布局跳变、遮挡或水平间距漂移。
8. 侧栏预览的接受/丢弃素材与真实请求 payload 完全一致。
9. 定向 Vitest、全量 typecheck、相关 lint 与真机点击/拖拽回归通过。
10. 编排器内部控制区的双击不冒泡为节点双击；只有显式扩大入口进入中央详情。
11. “从画布选择”只列出可合法连入当前视频的现有节点，选中后直接建边；
    “＋”先选图片、视频或声音，再从对应素材库创建节点并建边。两者都不得
    打开详情。
12. 节点双击、视频预览、片盒排序和 Studio 回跳都不得打开详情；所有节点族
    只能由明确标注的扩大图标写入 `expandedNodeId`。

## 6 · 视频模式与模型选择器（2026-08-08 owner 拍板，已落地）

### 6.1 两件事分开

|                                          | 归属         | 职责                                             |
| ---------------------------------------- | ------------ | ------------------------------------------------ |
| **模式**（关键帧 / 多图参考 / 全能参考） | **视频节点** | 决定节点长什么样、走哪个端点、模型选择器里出现谁 |
| **模型选择器**                           | 共享组件     | 在模式已定的前提下选 系列 → 型号 → 渠道          |

- **没有「全部」档**。模式不只是筛选器，它还决定端点，而「全部」在端点决策上是空的
  （不知道该走 text-to-video 还是 reference-to-video）。默认档 = **关键帧**。
- **纯文生视频不是单独一档**，它是关键帧档下「两个槽都空」的自然状态。
- 落点：`src/constants/video-node-modes.ts`（枚举 + 模式 ↔ `referenceMode` 双向映射 +
  `resolveVideoModelId` 端点解析）· 节点字段 `videoMode`（`src/types/node-workflow.ts`，
  **可选且不写 migration**，存量节点从当前模型反推）· `src/lib/video-node-model-resolver.ts`。
- 模式与 `getVideoModelSendContract().referenceMode` 一一对应 ⇒ **加新模型不用登记模式**，
  契约填对模式自动正确。解析不到时**返回 null 而非回退**——Kling 没有多模态端点，
  回退会让用户以为在用全能参考、实际发的是首帧请求，宁可让该型号从列表消失。

### 6.2 模式的 UI 形态 —— 靠界面表达，不靠文案

| 模式     | 图片区                        | 视频区   | 音频区   |
| -------- | ----------------------------- | -------- | -------- |
| 关键帧   | **两个具名位置**：首帧 / 尾帧 | 不存在   | 不存在   |
| 多图参考 | 多张平铺，无语义              | 不存在   | 不存在   |
| 全能参考 | 多张平铺                      | **存在** | **存在** |

**「不存在」是真的不渲染，不是禁用后置灰**——置灰仍然是在用文案解释「你不能用它」。

### 6.3 三层钻取的模型选择器

```
第 1 层 系列  MODEL_FAMILIES（Seedance · Kling · Veo · MiniMax H3 · HappyHorse · Gemini Omni …）
第 2 层 型号  MODEL_VARIANTS（2.5 · 2.0 · 2.0 fast · 2.0 mini）  ← 四个维度里唯一的新数据
第 3 层 渠道  adapterType（火山 / BytePlus / fal）              ← 唯一职责是比价
```

三条贯穿规则（`BaseModelPickerPanel`）：

1. **搜索绕过全部分层**——平铺过滤，不做三层的搜索。
2. **跳过要连锁**——每层各自判断「只有一个候选就跳过」，可能一路跳到底。
3. **返回要回到「最近一个没被跳过的层」**，不能是常量。

⭐ 这个结构顺手消掉了 reference 变体的概念负担：`SEEDANCE_20` 与 `SEEDANCE_20_REFERENCE`
是两个端点，**用户只需要看见「Seedance 2.0」，端点由模式挑，reference 这个词不必出现在 UI 里**。

地基不变量（`model-variants.test.ts` 钉住）：**(型号 × 渠道 × 模式) 唯一定位一个 `AI_MODELS` 条目。**
撞车就意味着有两个条目除 id 外完全同构，那时模式切换会随数组顺序随机挑一个端点。
⚠ `MODEL_VARIANTS` 的值**显式写死，不从 id 字符串推导**；枚举值一个都没改（存量项目与 ScriptDoc 依赖它们）。

### 6.4 渠道比价的口径（`constants/models/unit-prices.ts`）

`cost` 是 credit 数横向比不了，故另建单价表。**基准档钉死在 720p / 每秒 / 含音频 / 无视频输入**——
分辨率和有无视频输入都影响单价，不钉基准就没法横向比。同一型号跨渠道价差可以很大
（Seedance 2.5 在 fal 是 BytePlus 的 2.06 倍），不摆到用户眼前他就会在毫不知情的情况下多付一倍。

- **宁可留空，不填没核实过的数字**——缺失时隐藏价格而非显示占位；比价的价值全在可信度。
- ⚠ **不复用 `HOMEPAGE_MODEL_REFERENCE_PRICES`**：那张表自称 display-only、口径未标注，且数据对不上。
  `unit-prices.test.ts` 守住「同一个模型不得同时出现在两张表里」，避免一个模型两个价格来源。
- **立案未做**：homepage 那张表要逐个核实 20+ 模型官方定价才能合并；合并前两张表并存是已知的坏味道。

### 6.5 模式切换的冲突处理

| 对象                               | 处置                                           | 理由                                               |
| ---------------------------------- | ---------------------------------------------- | -------------------------------------------------- |
| 模型选择                           | **清空**                                       | 不符合新模式的模型直接从列表消失，当前选择一并清掉 |
| 模型相关参数（时长档 / 分辨率档）  | **清空回默认**                                 | 新模型未必支持旧档位（2.5 有 30s，Kling 没有）     |
| 用户已传的素材（图 / 视频 / 音频） | **保留在数据层，切回来还在，当前模式下不发送** | 素材是用户的劳动，模式是可来回切的视图状态         |

⚠ 第三行的两个实现后果：**发送时按模式过滤**（过滤点在 `buildVideoSendPreview` / 提交链路，不在 UI，
否则多图参考模式会把藏着的视频一起发出去触发 400）；**UI 要有「有东西没被发送」的提示**——
这是唯一需要文案的地方，§6.2 的「靠形态不靠文案」管的是模式差别，不管这个。

### 6.6 已知未竟

- ⬜ **三种模式各自的槽位形态还没做**：三档目前共用同一套素材区，多图参考档照样渲染视频/音频槽
  （即 §6.2 那张表还没在 UI 上完全兑现）。连带未做的是「N 段素材在当前模式下不会发送」提示的
  非关键帧部分（关键帧那部分已随首尾帧落地）。
- ⬜ fal / MiniMax / BytePlus 的单价补齐（各自接入时顺手做，别单独立项）；周检脚本扩到
  `verifiedAt` 超期告警。

## 7 · AI 增强 = Seedance 提示词规划器（2026-09-03 落地）

视频卡上的「AI 增强」按钮（`enhanceSeedancePrompt`，`StudioNodeWorkbench`）把节点
正文当粗想法，交给 `services/prompts/seedance-prompt-plan.service.ts` 规划成
`timeline / motion / camera / duration / audioIntent / finalPrompt` 写回节点。本轮把它
从 2.0 口径升到 2.5，并接上真实的 @引用槽位：

- **方法论两层，一个事实一个家**：模型中立的电影语法在
  `constants/cinematic-grammar.ts`（`CINEMATIC_SHOT_GRAMMAR`：景别/角度/运镜词汇、
  Z 轴空间描述、身体表演白描、光线连续性、按秒分节拍）；2.5 专属的稳定性杠杆在
  `constants/seedance-prompt-plan.ts` 的 `SEEDANCE_25_CONTROL_RULES`——全局锁定行
  先声明一次、一镜一动作且绑定事件而非计时、转场必须命名、每镜重述站位与结束态、
  易漂事实在易漂镜头重复、20–30s 用四段节奏（开场/发展/升级/收束）、单次直出不拼接。
- **参考素材走和发送路径同一份投影**：规划器收到的 `references` 由
  `summarizeVideoSendReferences(buildVideoSendPreview(...))` 产出——模式 → 端点 →
  容量 → 过审 → 槽位之后**真会发出去**的 `@ImageN`（带名字 / kind / category）、
  `@VideoN` 数量、`@AudioN` 的说话人。旧的 `summarizeUpstreamSeedanceReferences`
  （手数计数、写死 2.0 的 9/3/3）已删。schema 上限统一读
  `VIDEO_REFERENCE_LIMITS`（30 / 10 / 10，新增 `VIDEOS`）。
- **@引用的两层不变**：规划器被要求用 `@名字` 原样引用具名图（创作层 token，
  MentionInput 渲染成胶囊；发送时 `translatePromptTokensToPositional` 改写成
  `@ImageN（名字）`，参考顺序变了也不失联）；未命名的用槽位 token。每个参考必须领
  **一个**职责——控制什么、不影响什么（角色图只定脸/发/服装；场景图只定布局、材质、
  光向；镜头/关键帧图定构图或首帧；特写定面部细节；参考视频只给运镜或只给动作或只给
  风格）。
- **未实测**：规则措辞按 2.5 第三方指南与官方公式写，尚未用真实生成校准；先跑一两条
  看 finalPrompt 形态再调。
