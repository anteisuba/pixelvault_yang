## 1 · 域定义（设计口径）

`references/domains/canvas.md` 已经定义了"画布负责什么"（业务契约）。本节是**设计需要的那一层**：谁在用、造型哪些对象、优待哪些任务、想要什么使用感受、明确不做什么。

### 1.1 核心用户与场景

画布不是"第一次生成"的地方，是**第二次以上**的地方：

- Studio = "给我来一张 / 来一段"（轻量单次）。
- Canvas = "这条片子由 8–12 个镜头组成，主角必须是同一个人，声音必须是同一个音色，最后要拼成一条完整的片子"。

**判据**：如果一个任务用 Studio 一次就能完成，它就不该是画布的最高频任务。画布存在的理由是**复用、一致性、序列**这三件 Studio 做不到的事。

### 1.2 核心对象（设计必须给造型的实体，按权重排序）

| #   | 对象                                          | 是什么                                                                                  | 为什么重要                                                      |
| --- | --------------------------------------------- | --------------------------------------------------------------------------------------- | --------------------------------------------------------------- |
| 1   | **生成聚合体**（视频生成节点，现名 seedance） | 唯一真正"下单"的对象：1 prompt + image_urls(≤9) + audio_urls + video_urls               | provider 袋型合同的化身。画布的全部装配动作都是为了喂它         |
| 2   | **一致性身份**（角色/场景收集器卡）           | 名字 + 出场图组（主图恒第一 + 标"出场"的额外图）+ 绑定音色                              | 画布相对 Studio 的核心价值（硬约束 §6.3：不能退化成散图堆）     |
| 3   | **图片素材**                                  | 散图 / 镜头静帧 / 特写 / 关键帧                                                         | 既是产物又是原料 —— 双身份是造型难点                            |
| 4   | **声音身份**（音色）                          | Fish Audio 音色 / 上传参考音频 / 生成的参考样音；绑角色 → 成"听觉身份"，不绑 → 走"旁白" | 一致性的另一半                                                  |
| 5   | **序列容器**（片盒 videoMerge）→ 成片         | 保序装订视频段 → 合成长片                                                               | 今天最没有空间表达的对象（痛点 §9.2）                           |
| 6   | **剧本**（ScriptDoc）                         | title/logline/styleNote/background/roles/shots(含 dialogue)                             | **不是画布节点**，是投影源。今天住在助手侧 `ScriptDocWorkspace` |
| 7   | **关系**（边）                                | 供给/制片关系；合法性唯一事实源 `node-connection-rules.ts`                              | 数据层锁定，**呈现完全开放**                                    |
| 8   | **项目**                                      | 一张画布 = 一个 `NodeWorkflowProject`；viewport 不入存档                                | 顶栏已有切换                                                    |

### 1.3 最高频任务（排序 —— 设计必须优待前三，第 4–6 不能挤掉前三）

1. **一组素材 → 一个视频**（袋型合同装配 + 写 prompt + 生成）
2. **逐镜推进**：静帧先审 → 通过 → 再喂视频
3. **一致性复用**：同一角色卡进多个镜头，允许每镜覆写
4. **剧本起手** → 投影 N 镜（owner 本轮要测的入口）
5. **拼接长片**
6. **就地修图**（近场编辑，能力已跑通）

### 1.4 默认入口与起手

空画布 → **助手（剧本脑）为主路径**，"＋添加"为逃生舱（现状 `NodeCanvasEmptyGuide` 已是这个判断，owner 要求重整造型与信息量）。
起手的设计问题不是"放几个按钮"，而是：**第一屏要不要就让用户看见这条片子的产线全貌（哪几站、现在在第一站）**。

### 1.5 与相邻域的流转边界（造型上必须读得出来）

画布**不做**：通用白板 · 第二个 Studio 表单 · 资产管理器 · LoRA 编排 · 完整音频工作台。
画布**做**：把上述各域的产物组织成一条可控产线。

### 1.6 域性格锚点（建议，待 owner 拍板）

> **"看一眼就知道这条片子做到哪一步了，以及下一步该点哪。"**

三个词：**掌控 · 可预演 · 不怕乱**。

选这个锚点是因为它**同时压住 §9 的四个真痛点**（关系不可见 / 长片没位置 / 空态不清 / 功能分化不清），而不是又一个材质叙事。它不预设深浅、不预设材质 —— 深/浅、玻璃/实色由方向自证（`brand-dna.md`：全局不规定深浅）。

**刻意不选的锚点**（避免重蹈旧轮）：「导演的制片桌」「导演的工作台」—— 这两个都是**材质隐喻先行**，它们在两轮里都没有回答"下一步该点哪"。

### 1.7 三个标志性组件（每个方向都必须交出这三件的造型，缺一即打回）

1. **生成聚合体**（袋型合同怎么被看见：槽位、上限 ≤9、prompt、结果）
2. **身份卡**（名字 + 出场图组 + 音色三件套怎么一眼成立，且怎么"出现在多个镜头里"）
3. **序列/成片**（顺序怎么被看见、怎么改序、成片在哪）

半件加分项：**助手 ↔ 画布的接缝**（剧本投影出来的东西，和用户手搭的东西，看起来是不是一家人）。

### 1.8 禁区（三方向共同，硬）

| 禁区                                     | 理由                                                                                                                     |
| ---------------------------------------- | ------------------------------------------------------------------------------------------------------------------------ |
| **状态不能只靠颜色**                     | 全局品质底线                                                                                                             |
| **关系不能靠"对象消失"表达**             | 吞噬的根本病（owner 动摇的根因）。允许"吸入"动作，但成分**必须留下可见凭证**（缩略图/名字/票据），不能只剩一个 chip 文本 |
| **不许伪装 provider 能力**               | ≤9 上限、音频绑定名、@token 必须真实可见；不做假进度条、假批量                                                           |
| **不做万能面板**                         | 助手 / 图片编辑 / 视频生成 / 资源管理四件事必须有各自的位置与边界（owner 明确诉求）                                      |
| **不继承旧皮作为默认答案**               | 暖炭+纸卡+石绿、冷石墨+钨丝琥珀都不是起点；但也不禁止深色                                                                |
| **不提出没有分片路径的方案**             | `StudioNodeWorkbench.tsx` 3348 行是成本中心；任何方向必须能拆成可真机验证的小切片，不能"一次性重写"                      |
| **不把画布降成通用白板 / 不吞并 Studio** | 硬约束 §6.4                                                                                                              |

## 2 · 工作流重设计 —— 「第一条产线」

owner 本轮的测试链路：**一个想法 → 助手生成剧本 → GPT Image 2 出图片素材 → 接声音 → 生成一段视频**。
本文把它定为 **P1 产线**，并作为三方向的**共同验收靶子**：三个方向都必须让这条链在**一屏内可读、可推进、可看出进度**。

### 2.1 今天走这条链的真实步数（代码实读，2026-07-25）

| 站                   | 今天发生什么                                                                                                                                    | 事实来源                                                                                              |
| -------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------- |
| ① 想法 → 剧本        | 空态点「聊大纲」→ 助手 chat → `ScriptDocWorkspace` 出 outline（roles / shots / dialogue，可反问澄清）→ 两阶段：outline 确认 → shots 细化        | `ScriptDocWorkspace.tsx`(1429) · `types/script-doc.ts` · `use-script-breakdown.ts`                    |
| ② 剧本 → 节点        | `projectScriptDocToGraph` 投影**五列**：角色图节点(role=character) → shotText → voice → seedance → videoMerge，左→右锚定                        | `node-workflow-script-doc.ts:228/258/297/327/378/407` · `NODE_STUDIO_NODE_PLACEHOLDER.scriptDocSpawn` |
| ③ 出图素材           | **每个角色节点单独**点生成，模型选 GPT Image 2（`gpt-image-2`，flagship，`available:true`，画布图片节点吃全量 `getAvailableImageModels()`）     | `use-workflow-model-options.ts` · `constants/models/image.ts:18-30`                                   |
| ④ 静帧（"先审再喂"） | **投影不建镜头静帧节点** —— 需手动加 image(role=shot) → 手动连角色/场景 → 再单独生成。官方工作流 §5.5 在起手路径上是**断的**                    | `node-workflow-script-doc.ts` 全文只投影 role=character                                               |
| ⑤ 接声音             | voice 节点选 Fish Audio 音色 / 上传参考音频 / 生成样音；`voice → character → seedance` 传 audio_urls，绑角色=「角色「X」的音色」，不绑=「旁白」 | `node-workflow-graph.ts:790-795` · `NODE_STUDIO_VOICE_PROFILE_SOURCES`                                |

### 2.2 断点清单（设计要治的，全部是事实不是猜测）

1. **没有"整条链"的表达** —— 投影出五列节点，用户看不出"下一步该点哪"；进度只存在于**单个节点**上（`node-canvas-progress-track` 是节点级 indeterminate 条）。
2. **每一步都是单点手工** —— 未见任何批量入口（`generateAll` / `batchGenerate` / `queueAll` 在 `node/` + `hooks/node/` 零命中；生成走 `use-node-media-generation` 单节点路径）。4 个角色 = 4 次点击 + 4 次盲等。
3. **静帧站缺投影**（见 ②/④）—— "静帧先审再喂"是官方六工作流之一，但剧本起手路径不生成它。
4. **"审核"不存在** —— 没有"通过/重来"这个动作；用户自己看，看完自己记。
5. **声音语义窄** —— 画布只有"音色/参考音频"一个音频对象；成品音轨（BGM / 音效 / 独立配音轨）**不是一等对象**，长片合成也不接受音轨。
6. **成片没有常驻位置** —— videoMerge 是画布上又一个节点，长片顺序不可一眼见（痛点 §9.2）。
7. **画布级粘贴缺失** —— 粘贴只在局部输入区；`CanvasSurface` / `StudioNodeWorkbench` / `CanvasWorkspaceLayout` 无 paste 监听（owner 明确想要）。
8. **工具栏位置错位** —— 工具条在**底部**（`CanvasBottomDock`，`absolute bottom-*`），owner 想要**左侧竖栏 + 玻璃质感**。
9. **四功能入口散** —— 助手在右 dock、图编在 workspace、视频在节点内、资源在卡匣横匣，边界不清。

### 2.3 工作流设计原则（三方向共同承诺，形态各自不同）

| #   | 原则                                | 检验方式                                                                                                                      |
| --- | ----------------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| P-1 | **产线可见**                        | 任何时刻画布上存在"这条片子做到哪"的表达（分带 / 行状态列 / 产线卡，形态由方向定）                                            |
| P-2 | **下一步唯一**                      | 每个对象上**最多一个主动作**，随状态改写（缺素材→补 / 有素材→出静帧 / 有静帧→出视频 / 有视频→纳入成片）。并列 5 个按钮 = 打回 |
| P-3 | **批量是一等公民**                  | 同类推进可多选一次触发，且有真实队列视图与失败重试（不做假进度）                                                              |
| P-4 | **审核是显式一站**                  | 静帧/视频有"采用 / 重来"，采用后才向下游流动                                                                                  |
| P-5 | **助手是起手 + 改稿，不是全程司机** | 投影后用户接管；助手可被召回做**局部**改（`focus={kind:'shot',id}` 已支持）                                                   |
| P-6 | **成分不消失**                      | 任何绑定手势后，成分在聚合体上留可见凭证                                                                                      |

> ⚠ P-3 / P-4 / 静帧投影 / 画布级粘贴 = **新建能力**，不是换皮。是否纳入本轮范围需 owner 拍板（见 §7 Q3）。

## 3 · 状态矩阵（三方向共用，Claude Design 必须逐格覆盖）

| 状态                      | 必须证明                                 |
| ------------------------- | ---------------------------------------- |
| 空（新项目）              | 起手唯一路径清楚；不是一堆按钮           |
| 剧本已出 / 未投影         | 剧本与画布的关系可读                     |
| 已投影未生成              | 12 镜规模下不糊；"下一步"明确            |

## 4 · 三个结构方向

三者的差异**不在颜色**，在三件事：**空间是否被赋予语义**、**关系靠什么读**、**序列住在哪**。

### 方向 A · 工序带（Banded Pipeline）—— 几何即工序

**空间**：保留无限画布（缩放/平移/框选全留），但叠一层**语义分带**：自左向右 5 条竖带 = ① 剧本·班底 → ② 素材 → ③ 声音 → ④ 镜头·视频 → ⑤ 成片。带是**软约束**：新对象按类型自动落带；拖出带外回吸（或"带外 = 自由试验区"）。带头 = 站名 + 计数 + 「推进本站」。
**关系**：短连线，只跨相邻带。因为"位置 = 工序"，穿越全画布的长线自然消失 —— 关系靠**列的先后**读，连线退居辅助。
**序列**：第 ⑤ 带就是时间线（横向 = 顺序），拖动排序即改序，成片是这条带的产物。
**产线推进**：顶栏一条 5 站产线进度条（点站聚焦视口）；每带一个站级批量动作（"给这 4 个角色出图"）。
**助手**：**左侧起手栏**（它是产线第一站，不是右侧附属），剧本文档常驻其中，可收起为竖 rail。
**工具栏**：最左竖玻璃 rail（工具/添加/视图），底部彻底腾空。
**空态**：只有第一带亮着，其余 4 带是灰站台 + 站名 → 用户第一眼就看见全程；输入框直接长在第一带里。
**四功能分化**：助手=第①带；资源(卡匣)=第②带常驻侧架；图编=近场工具条 + 全屏 workspace；视频=第④带。
**优点**：owner 的 P1 链路 = 从左走到右，零解释；进度/批量/审核都天然有位置；一次治好"长片在哪"+"功能分化"+"空态"。`applyDagreLayout`（dagre `rankdir:'LR'`）已经是左→右分 rank，分带与现有"整理"语义同向。
**风险**：强几何削弱自由创作（散图实验、一图多用会跨带）；带内纵向拥挤（12 镜 × 3 素材）；需要落带吸附 + 带背景 + 视口分段导航（中等工程量，动 workbench 布局层）。
**适合**：以线性成片为主的用户 —— 正是 owner 本轮的测试意图。

### 方向 B · 分镜表（Shot Table）—— 行即镜头，放弃自由平面

**空间**：主区不是画布而是**纵向镜头行列表**，一行一镜：`[镜号+摘要] [成分槽：角色·场景·静帧·音] [结果：视频] [状态]`。行可展开成大卡（prompt + 参数 + 结果监视）。顶部/左侧常驻**班底架**（角色/场景/音色）。自由画布**降级为"实验台"视图**（散图、图片编辑、临时素材住那里）。
**关系**：**完全不画线**。归属 = "它在这一行的这个槽里"；身份 = 班底架里的引用（同一角色在多行以头像 chip 出现，hover 同源高亮）。
**序列**：行序 = 成片序；拖行即改时间线；底部「合成长片」= 片盒的重表达。
**产线推进**：**列操作** —— 整列"出静帧"、整列"出视频"；每行一个主动作随状态改写（P-2 的最纯形态）。
**助手**：剧本面板与行表是**同一份数据的两种视图**（改剧本 → 行表跟随）。剧本起手的表达力最强。
**工具栏**：左竖 rail = 视图切换（分镜表 / 实验台 / 成片）+ 添加。
**空态**：一个空剧本 + 一行"从想法开始"输入 → 生成 N 行。
**优点**：与"剧本→分镜→逐镜→拼接"1:1 对齐；一致性单位最强；无连线心智负担；批量/状态/审核天然有位置；与 Studio 及其它域**辨识度最高**（它看起来像制片管理工具，不像又一个节点编辑器）。
**风险**：**放弃自由画布是最大赌注** —— 硬约束只禁止"降成通用白板"，未禁止结构化，但 Figma 式手感（中键平移、框选、任意排布，`NODE_STUDIO_CANVAS` 里刻意做过的东西）价值下降；ReactFlow 退到实验台；等于**新建一个主视图**（成本最高，但可先作为"第二视图"并存，不必一次性替换）；非线性玩法被挤进抽屉。
**适合**：镜头多、要一致性、剧本先行的成片型工作。

### 方向 C · 组装台（Assembly on Free Canvas）—— 自由画布 + 容器 + 仪表盘

**空间**：完全保留自由无限画布。改的是**对象形态**：视频生成节点升级为**组装台大卡** —— 袋型合同直接可视化：三条槽轨（image ≤9 / audio / video）+ prompt 面 + 结果监视。
**关系**：**票据即关系** —— 成分被装入时**不消失**，在槽轨里留一枚可见票据（缩略图+名字），原卡留在画布上；选中时才亮起短"脐带线"。长连线不再是主要读法（正面推翻吞噬的"消失"）。
**序列**：底部**常驻成片托盘**（位置即顺序，可拖排），片盒 = 托盘的持久化形态。
**产线推进**：一张浮起的**产线卡**（剧本 ✓ / 素材 4/6 / 声音 2/2 / 镜头 0/6 / 成片 —），点某项聚焦对应对象，「推进」= 批量选中同类未完成项。
**助手**：右侧可收起 dock（现状形态，owner 已认可）+ 剧本在 dock 内切页。
**工具栏**：左竖玻璃 rail（工具/添加/视图）；底部只留成片托盘 → 直接治"工具在底部"的错位。
**空态**：画布中央一行"从想法开始"输入 + 3 个例子 chips（起手即对话）。
**优点**：**工程风险最低** —— 现有 78 组件、近场工具条、助手 dock、ReactFlow 全部可演进，切片路径最清楚；保留自由度与"画布"身份；同时治关系可见（票据）+ 长片（托盘）+ 工具错位（左 rail）+ 产线可见（产线卡）；owner 想学 haivis 的三件（大画布 / 右助手 / 近场工具条）原样成立。
**风险**：自由 = 无纪律，12 镜项目仍靠用户自己排布；产线卡是**仪表盘**而非空间，指导性弱于 A/B（"下一步该点哪"要多读一次）；组装台展开的遮挡策略需要设计（半屏/侧开/原地长大）。
**适合**：既要实验又要成片、习惯 Figma 式自由的用户。

### 4.2 主流方向调查（2026-07-25 联网实查，owner 要求）

**结论：2026 的主流分成两派，而且头部产品同时做两派。**

| 产品                                               | 主结构                                                                                             | 关系怎么读                                                                                      | 值得学的具体点                                                                                                                                                                                                       |
| -------------------------------------------------- | -------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **ComfyUI**                                        | 自由节点图                                                                                         | 连线                                                                                            | granular 控制的基线；乱是公认代价                                                                                                                                                                                    |
| **Krea Nodes**                                     | 无限画布 + 节点图                                                                                  | **类型色 handle + 连线**（单节点最多 10 条出线）；`section` 节点 + `Group` 按钮治乱；便签写逻辑 | ① 左侧栏切 pan/select 双模式 ② **运行前按节点显示 compute cost** ③ **Node Agent**：自然语言 → 先给"分几站"的 plan（可换模型/删站）→ 再实时把节点连出来，自动校验不兼容并补转换节点，**复用画布上已有节点与缓存输出** |
| **Freepik Spaces**（2025-10）                      | 节点图 + 协作                                                                                      | 连线；可对单节点评论                                                                            | **`List` 节点（2026-02）= 把批量做成画布上的一个对象**（喂一批 prompt 出上百变体）＋ **网格批量审核**（成批看、一键标记、批量改）                                                                                    |
| **Figma Weave**（原 Weavy，2025-10 被 Figma 收购） | 节点 + 设计面板                                                                                    | 连线                                                                                            | 工程优先、精确可复现                                                                                                                                                                                                 |
| **Runway Workflows**（2025-10）                    | 节点画布 + 可存模板                                                                                | 连线                                                                                            | **同一产品里"Chat mode 轻量 / Workflows 编排"深浅两档** —— 与 PixelVault「Studio 浅 / Canvas 深」同构，说明这条分工是主流共识                                                                                        |
| **Flora**                                          | 无限画布                                                                                           | 叙事/storyboard 取向                                                                            | 快速迭代优先                                                                                                                                                                                                         |
| **即梦 AI**                                        | **双模式**：智能画布（无限画布 · 全资产聚合 · 拖拽编辑）＋ **故事创作模式（分镜 + 时间轨道管理）** | 画布内节点式串联                                                                                | **序列不塞进画布，而是另一个模式**                                                                                                                                                                                   |
| **LTX Studio**                                     | 剧本 → 自动分场 + 分镜缩略图 + 机位建议                                                            | 分镜表（无连线）                                                                                | **`Elements` 面板 + `@` tag**：角色/道具/场景存成 Element，`@名字` 打进任意镜头 → 跨镜一致                                                                                                                           |
| **Leonardo**                                       | 图层面板（Photoshop 式）                                                                           | 图层                                                                                            | 反例：不走节点图也能活，但编排力弱                                                                                                                                                                                   |

**五条对本项目有直接后果的发现**：

1. **没有任何主流产品用"吞噬/对象消失"表达关系。** 关系一律是**连线**（+ 类型色 handle）或**成员归属**（group / section / 行）。→ 吞噬是 PixelVault 独有发明，且是逆主流的孤例。**建议正式退役。**
2. **连线不是问题，乱才是问题；主流治乱靠分组不靠隐藏。** Krea 的 `section` 节点 + `Group`、便签，是"保留连线 + 分区收纳"。→ 现状「关系线总开关默认可隐藏」是把症状盖住。
3. **批量是画布上的一个对象，不是全局按钮。** Freepik 的 `List` 节点 + 网格批量审核是当前最成熟形态。→ 你选的"批量推进 + 真实队列"应该长成**一个可连线的批量对象 + 一块网格审核区**，而不是顶栏一个"全部生成"。
4. **一致性单位 = 注册表面板 + @token，主流已收敛。** LTX 的 `Elements` 面板 + `@名字` ≈ PixelVault 的卡匣 + `@token`（本项目已经有，且做得更细：出场组 + 音色）。→ 这是本项目**已经领先**的地方，设计上应该把它**升成常驻主角（班底架）**，而不是塞在底部横匣。
5. **序列/时间线是第二模式，不是画布内挂件。** 即梦（故事创作 + 时间轨道）与 LTX（分镜表）都把序列独立出来。→ 「长片在哪」的答案更可能是**一个序列视图**，画布内只留入口/暂存。

**另一条结论**：Runway 的 "Chat mode / Workflows" 双档证明 **Studio 浅 + Canvas 深**这条产品分工站得住，不必怀疑。

### 7.1 C+ 已确认的结构条款（2026-07-25，owner 逐项确认，具备结构约束力）
