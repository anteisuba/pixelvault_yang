PixelVault · UI/UX 总结 · 2026-09-17

首页要不要加「视觉滚动」，怎么加最好

结论先说：要加，但不是加视差装饰，而是把现有六段自动播放的演示改成「滚动即操作」——用户滚多少，演示走多少。首页现在是 13 页整屏跳转（snap），中间没有进度可用，所以真正要改的是滚动模型，动效只是结果。

A · 保留整屏跳转，加页内视差
维持 13 页 snap deck；每页进入时用 IntersectionObserver 触发一次性动画（现状 + 背景层轻微视差）。
好在
· 改动最小，现有 GSAP 演示可复用
· 键盘 / 目录跳页逻辑不变
代价
· 滚动没有「中间态」，视差只能是装饰
· 用户仍然被动看演示，看完才知道要等
· 在矮视口下裁切问题不解
B · 连续滚动 + 钉住演示（scrub）
推荐
页面变成一条长卷；每个功能段 200–250vh，演示卡 position: sticky / GSAP pin，段内滚动进度驱动演示状态（写字 → 出图 → 结果）。段首保留 snap-start。
好在
· 滚多少看多少，节奏交给用户，这才是「视觉滚动」的价值
· 每段结束态自然停在「去用这个」按钮上，解决不可点的问题
· 矮视口自适应：钉住区按 vh 缩放
代价
· 需要把六段演示改成「按进度求值」的状态机，工作量中
· GSAP ScrollTrigger 只允许在 HomeV4 内动态导入（CLAUDE.md 边界）
· 手机上 pin 抖动，需要降级
C · 横向卷轴
把 deck 横过来，滚轮驱动横向平移，功能段像胶片一格格过。
好在
· 与「导演台 / 分镜」叙事贴合，识别度高
代价
· 触控板与手机手势冲突大，无障碍差
· 三语文案长度不同，横向排版难控
· 与应用内一律纵向滚动的心智不一致
推荐结构 · 连续滚动 + 钉住演示（桌面）
Hero · 100vh
标题 + 副标 + 两个 CTA；作品墙随滚动向两侧散开（scrub）。
01 图片 · 250vh 钉住
左文案固定，右演示卡钉住；滚动进度 0→1 = 写 prompt → 四家出图 → 结果态 + 「去用」。
02 LoRA · 250vh
滚动 = 挂载权重从 2.0 滑到 0.1，四张对照图跟着变。
03 音频 · 200vh
滚动推进三句台词逐句「说出」；音频不自动播放，按钮触发。
04 视频 · 250vh
滚动把四个参考拖进槽位 → 出片；视频帧用海报序列不播 mp4。
05 画布 → 06 库 → 终页
画布连线随滚动生长；库页平铺；终页两个 CTA + 页脚。模型站改成横滑列表放在终页之前。
右侧圆点目录保留，改为跟随 section 进度的细进度条；每个 section 顶部保留 snap-start 让键盘 / 触控板一格一段，但段内滚动自由。
落地要点
按 CLAUDE.md 与 ui-defaults 的边界
高
降级永远先做
现状 · prefers-reduced-motion 下现有演示照常播放。
建议 · reduced-motion → 直接渲染每段的「结果态」+ 按钮，不钉住不 scrub；手机（<768）同样走结果态 + 轻微淡入，不做 pin。
高
只动 transform / opacity，帧预算 16ms
现状 · 演示里有布局变化（chip 出现、列表增行）。
建议 · 把演示元素全部预渲染，再用 opacity / translate / clip-path 揭示；图片用 <img decoding=async> 预载，视频用海报帧序列。
中
scrub 状态机而不是时间线
现状 · 现在是 GSAP 时间线自动播放。
建议 · 每段定义 progress 0–1 的关键帧表（0.0 空态 · 0.3 输入完 · 0.7 出图 · 1.0 结果 + CTA），ScrollTrigger scrub: 0.6 平滑；键盘翻页跳到 1.0。
中
目录与可达性
现状 · 右侧圆点目录只表示页。
建议 · 圆点改进度条段；每段有 h2 与 aria-label，section 顶部 scroll-margin-top 让锚点可分享（/#lora）。
中
首屏性能
现状 · hero 拉公开画廊最新作品 10 张 + 品牌走马灯。
建议 · hero 图用固定 6 张 + LQIP；GSAP 与演示资源在 hero 之后按需加载，LCP 只算标题与首图。
低
模型站
现状 · 5 个模型站各是整屏轮播（7 张卡）。
建议 · 并成一段横滑卡片列表（每模态一行），不参与 scrub；点封面进工作台预选模型。
