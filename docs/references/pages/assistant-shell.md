## 1. 业务职责

统一助手负责跨图片 Studio、视频 Studio、LoRA 与节点画布提供同一套 AI 对话体验：

- 真正的多轮 Markdown 对话，而不是只返回提示词的转换器。
- 共享新对话、模型选择、历史、分享、联网研究和多附件输入。
- 图片、视频、LoRA、画布只注入各自领域上下文与可执行动作；不得复制四套会话引擎。
- 助手不会直接生成媒体，也不会未经用户确认修改编辑器内容。
- ⚠ **画布是例外，2026-08-08 owner 拍板改的**：结构 op（建节点 / 连线 / 改名）**不用确认，直接落画布** —— 它们免费、且整批只占一个撤销步。`set_review_state` 与 `generate` 仍然逐条确认。依据与实测记录在任务包 `assistant-ab-design-2026-08-08.md` §2、§B2（已随 plans 清理，git 历史可取）。

非目标：本轮不改图片/视频生成模型、计费、素材归档、画布写操作审批规则或 LoRA 训练流程。

## 2. 已确认关键切片

### 2.1 桌面几何

- 助手是覆盖主工作区的固定浮卡，不参与主工作区 flex/grid 尺寸计算。
- 默认距视口顶部 `64px`、右侧和底部各 `16px`；画布顶栏保持完整宽度，“画布外观”入口固定在最右侧且不被助手覆盖。
- 普通对话态默认宽 `360px`，允许拖拽到现有共享宽度上下限并记忆。
- 画布 Script 展开态仍是画布域专属状态；桌面宽度为 `min(64rem, 72vw)`，普通对话态与其他三处保持同宽。
- 画布内容不为助手让位；会被永久遮挡的常驻控件继续让位。
- 节点画布桌面助手的标题栏空白区域可直接拖动；标题栏内按钮、输入与菜单仍只响应自身操作，不触发拖动。移动只使用 `transform`，不改变面板尺寸；位置限制在画布工作区内，标题栏聚焦后方向键可逐步移动、`Home` 复位到默认右上角。面板移走后，原右侧 rail 不得留下拦截画布点击的透明热区。移动端维持底部抽屉，不提供自由移动。

### 2.2 移动端

- `<1024px` 使用接近全屏的底部抽屉，同一会话、模型与附件状态，不复制业务逻辑。
- 不提供拖拽改宽；关闭后焦点返回触发按钮；打开时不自动聚焦输入框。

### 2.3 共享头部

顺序固定为：新对话 → 联网研究 → 模型选择 → 历史 → 分享 → 展开（仅支持的域）→ 收起。

节点画布是导航位置例外：桌面历史记录入口与可搜索列表迁入画布左侧 activity rail，成为「节点 / 当前项目 / 历史对话」第三视图；桌面助手头部不再重复历史按钮。选择历史会话时打开普通对话态。移动端没有左侧 rail，继续保留头部历史入口；图片、视频与 LoRA 助手也仍保留头部历史入口。

- 头部控件在窄浮卡内必须可见；模型触发器允许截断。
- 模型/历史弹层在浮卡内侧对齐并使用碰撞检测，不得向视口外或不可见方向展开。
- 三处使用同一助手模型注册表：OpenAI GPT-6 Astra 与 GPT-5.6 三档、Gemini 3.7 Flash、DeepSeek V4 Pro、DeepSeek V4 Flash Vision Exp、Claude Fable 5.1、Grok 4.6；Qwen 不进入助手。
- 缺 key 时仍显示模型并打开 `QuickSetupDialog`，不得禁用整个入口。

## 3. 对话与领域上下文

正文使用正常 AI 对话：用户消息、流式/加载态、Markdown 回复、错误重试与历史恢复。
提示词操作作为回复下的显式动作出现，不再定义整个助手：

- 图片/视频：填入提示词、追加提示词。
- LoRA：填入正向、追加正向、填入负向、暂存搭配建议。
- 画布：结构写入**直接执行**（免费、一步可撤）；审核态与生成沿用“提案 → 用户确认 → 才执行”。

每次发送读取实时领域上下文：

| 域   | 注入上下文                                                    |
| ---- | ------------------------------------------------------------- |
| 图片 | 当前生成模型、当前提示词、图片或视频参考                      |
| 视频 | 当前生成模型、当前提示词、图片或视频参考                      |
| LoRA | 底模、已挂载 LoRA、触发词、标签盘、当前提示词、图片或视频参考 |
| 画布 | 项目、节点摘要、选中节点、脚本文档、图片或视频参考            |

## 4. 多附件契约

- 单轮最多 8 个附件，支持图片与视频混合；每个附件可单独移除。
- 来源支持本地上传、素材库和（画布域）已有画布媒体。
- 上传后以稳定 `http(s)` URL 进入请求；不得把 data URL 写进会话历史。
- 图片 Studio 也能分析视频参考，不得把视频降级为只分析封面。
- 用户可只附附件发送，客户端使用本地化的“请分析这些参考素材”作为该轮指令。

### 4.1 模型能力真实性

根据 2026-08-05 官方契约核验：

- Gemini：支持原生视频理解，处理视觉与音频流，可回答时间点相关问题；视频通过 Gemini Files API/`fileData` 输入。
- OpenAI 当前助手实现：文本 + 图片；不宣称原生视频输入。
- DeepSeek V4 Pro、Claude 当前 PixelVault 助手路由：文本；DeepSeek V4 Flash Vision Exp
  支持图片但不支持原生视频，菜单标为“图片视觉”。DeepSeek 的两个档位必须按具体
  `modelId` 判断能力，禁止因为同属一个 adapter 而让 V4 Pro 接收图片。

当附件超出当前模型能力时，发送按钮保持不可用并给出明确原因与可切换模型；禁止静默丢弃附件、只传 URL 文本或拿视频封面冒充视频分析。

## 6.5 传输协议（2026-08-25 换成 SSE）

两条流式端点（`POST /api/prompt/assistant/stream`、`POST /api/studio/node-assistant`）
出的是 **`text/event-stream`**，不是裸文本。帧表在 `constants/assistant-stream.ts`，
成帧 `lib/assistant-stream.ts`，读帧 `lib/assistant-stream-client.ts`，编解码
`lib/sse.ts`（与读 provider 的 SSE 共用一份）。

| 帧         | 载荷                              | 约束                                   |
| ---------- | --------------------------------- | -------------------------------------- |
| `open`     | `{}`                              | **必须第一帧**，见下                   |
| `research` | `ResearchReceipt`                 | 最多一次，排在第一个 `text` 之前       |
| `lora`     | `LoraCandidateSearchResult`       | 最多一次，同上；候选为空则不发         |
| `text`     | `{ delta }`                       | ⚠ **增量**不是累积                     |
| `error`    | `{ error, errorCode?, i18nKey? }` | 流中途失败；已发的 `text` 帧留在屏幕上 |
| `done`     | `{}`                              | 正常收尾，用来与「连接断了」区分       |

⭐ **`open` 帧存在的唯一理由**：Next 要等流吐出第一个**字节**才 flush 响应头。
裸文本流在模型开口之前一个字节都没有，函数被平台杀掉时网关只能回 **504**——
用户看到的是错误而不是半截回答（2026-08-24 生产实证）。开流即发 `open`，响应头
当场 flush，之后无论模型想多久、无论是不是引用闸那条整段缓冲的路径，超时最多是
一条**截断的 200**。⛔ 别把它挪到模型开口之后。判据钉在 `lib/assistant-stream.test.ts`。

**换协议顺带删掉的东西**（都是为「没有帧」而生的补丁）：
`lib/research-receipt.ts` 与 `lib/lora-candidate-receipt.ts` 整个删除——回执与候选
原先 base64 塞进响应头，因而受头字段大小上限约束，候选那份还配了三档降级阶梯
（`full` / `no_images` / `minimal` / `dropped`）。⚠ 那套阶梯自带一个**从未实测的
风险**：常量注释里写着「单个头字段在 nginx 一类反代上的默认缓冲是 8KB，这个数没有
余量可言」——真实上限一旦低于 16KB，推荐卡会在生产上静默降级甚至消失。帧没有上限，
这个风险随之消失。

⚠ **仍留在正文里的是协议块**（`[[ask]]` / `[[next]]` / `[[prompt]]` / `[[setup]]` /
`[[lora]]`），客户端照旧用 `lib/assistant-protocol-blocks.ts` 边收边抽，
`lib/assistant-marker-block.ts` 那四条流式安全规则原样保留。把标记也升级成帧是
**下一片**（owner 2026-08-25 定的切法），不是遗漏。

## 6.6 工作台助手读取素材文件夹

图片、视频与音频工作台的 operator 工具环可按名称查找用户自己的素材文件夹，并对其中图片做只读视觉检查。稳定契约如下：

- 必须先调用 `list_asset_folders`，再把同一轮真实返回的 `folderId` 交给 `inspect_asset_folder`；同名文件夹用完整路径消歧，模型编造的 id 直接拒绝。
- 检查范围是所选文件夹本身，不递归子文件夹；当前只处理已完成图片，按最新优先，最多检查 24 张，每批最多 8 张。
- 每批结构化输出必须逐张覆盖实际输入；缺图、重复下标或越界结果整批拒绝，禁止把未送入视觉模型的素材描述成“看过”。
- 结果必须同时给出 `inspectedImages / totalImages / truncated`。日志展开态展示覆盖率，证据格只展示实际检查过的图片，并可点开原图复核。
- 该能力只读取现有文件夹、Generation URL 并调用视觉补全；不创建 generation、不写库、不下载或上传素材，也不改工作台表单。后续动作仍须走既有 `set_*` / `mount_*` 工具。
- 空文件夹不借视觉路由、不调用模型；文件夹所有权在服务端按内部 `User.id` 收敛。

## 6.7 画布对话助手 · 视频提示词（现状与待改，2026-09-03 记）

> 视频卡上的「AI 增强」按钮已在本日升到 Seedance 2.5 口径（见
> `canvas-video-card.md` §7）；画布**对话**助手（`services/node/node-assistant.service.ts`
>
> - `StudioNodeAssistantDock`）**一行未动**。它是画布上写视频提示词的另一条路
>   （`add_node` / `set_prompt`），现状与增强按钮之间有明确落差，先记账再改。

### 现状（读代码核过）

- **没有电影语法与 Seedance 规则。** 系统提示词里关于 prompt 的规则只有：写完整而非
  标签、变体要重述不变量、纯文本、字数上限（`buildNodeAssistantOpsInstructions`）。
  `CINEMATIC_SHOT_GRAMMAR` / `SEEDANCE_25_CONTROL_RULES` 只喂给了增强按钮。
- **看不到视频节点接了什么。** 节点上下文（`lib/node-assistant-context.ts`）不带边、
  不做上游收割；节点行里的 `refs:` 只对能挂参考资产的收集器卡渲染（role + 源节点 id）。
  一个视频生成节点在助手眼里只有 `model / params / prompt`——它不知道上游有
  `@凛`、`@场景1`、`@Video1`、`凛 (@Audio1)`，所以写不出 `@名字` 引用，也不会给参考分工。
- **不知道 @token 的两层。** 没人告诉它「具名参考用 `@名字`，发送时自动翻成
  `@ImageN`」；它若自己写 `@Image1` 也能跑（图例会对上），但参考顺序一变就错位。

### 待改（三件，都是复用不是新造）

1. **规则注入**：视频生成节点的 prompt 规则追加同一份 `CINEMATIC_SHOT_GRAMMAR` +
   `SEEDANCE_25_CONTROL_RULES`（import，不复制文案），并说明 @引用两层与「一个参考
   一个职责」。落点 `node-assistant.service.ts` 的 ops 指令段；注意上下文预算
   （`streamGatewayWithContextCompaction` 的截断顺序，别让规则把节点清单挤掉）。
2. **视频节点行加 `sends:`**：seedance 节点的上下文加一个只读字段——直接调
   `summarizeVideoSendReferences(buildVideoSendPreview(...))`，渲染成
   `sends: @凛 (character), @场景1 (background), @Video1, 凛 (@Audio1)`。⛔ 一个 URL
   都不进 payload（与 `refs:` 同一条铁律）。落点 `lib/node-assistant-context.ts` +
   `types/node-assistant.ts` 的 schema；需要把 `edges` 与模式解析
   （`resolveVideoModelForMode` + `getNodeModeForModel`）带进上下文构建，客户端组装
   `autoNamePrefix` 要用和编排器同一组 i18n key（`videoComposer.autoName.*`）。
3. **口径对齐测试**：`node-assistant.service.test.ts` 断言视频节点规则段与
   `sends:` 行；`node-assistant-context.test.ts` 断言无边时不渲染 `sends:`、
   有边时与 `buildVideoSendPreview` 的 `images/videoUrls/audioEntries` 一致。

### 边界

- 不动 `add_node` / `set_prompt` 的 op 契约；不给助手新增「替我增强」这类 op——
  增强按钮已是那条路，两处各写各的 prompt 会分叉，助手应**写出符合同一规则的 prompt**。
- 图片节点的 prompt 规则不在本片范围。
