## 3 · ⚠ 骨架必须带着修的四个功能缺陷（本会话确定性复核，非 agent 转述）

这四条不是排版问题。改版会重写壳，**不在骨架里带着修就会原样继承进新壳**。

### ① `expandedNodeId` 悬空 → 面板关掉后画布进入永久降级态

`setExpandedNodeId(null)` 生产写入点**只有三处**（`StudioNodeWorkbench.tsx:4108` onClose · `CharacterImageInspector.tsx:240` · `BackgroundImageInspector.tsx:110`）——**删节点与切项目时没有任何一处清它**。
而 `heavyOverlayOpen = Boolean(expandedNodeId) || …`（`StudioNodeWorkbench.tsx:604-607`）判的是 id 非空，不是「壳是否真在渲染」。

节点被删 → `nodes.find` 落空 → 壳被 `AnimatePresence` 静默卸载（`NodeDetailPanel.tsx:68-69,114`）→ 但 `heavyOverlayOpen` 恒为 true ⟹ **Esc 链永久早退**（:3695 同文件 :644）、**画布粘贴永久被挡**（:3695）、**节点局部快编 chrome 永久被压**（`LooseImageCard.tsx:147`）。
面板已经不在，系统却认为它还开着。

**骨架条款**：`heavyOverlayOpen` 判据改为「壳是否真在渲染」；`expandedNodeId` 在删节点/切项目时清理。

### ② 焦点被写入夺走（链条四环全部核实闭合，⬜ 待真机复核）

| 环  | 事实                                                                                  | 出处                                |
| --- | ------------------------------------------------------------------------------------- | ----------------------------------- |
| 1   | 初始聚焦 effect 依赖数组是 `[node]`，cleanup focus 回来源、effect 体 focus 到收起按钮 | `NodeDetailPanel.tsx:97-108`        |
| 2   | `node` 来自 `nodes.find(...)`，直接吃 React Flow store                                | `NodeDetailPanel.tsx:68-69`         |
| 3   | `updateNodeData` 是 `{...node, data:{...}}` **整体换新对象**                          | `use-node-workflow.ts:1303-1312`    |
| 4   | `NodeFieldEditor` 的 onChange 直接 `updateField → updateNodeData`，**无本地草稿态**   | `NodeCardControls.tsx:55-61,72`     |
| ＋  | React Flow 是受控模式，`nodes={workflow.nodes}` 直喂                                  | `StudioNodeWorkbench.tsx:3904/3915` |

⟹ 每敲一个字符 → node 换身份 → 焦点被拉回「收起」按钮。受害最深：shotText 四个纯 Textarea、videoMerge 裁剪输入、所有提示词框。

**这是改版第一优先级的真机验证项**——它决定统一骨架要不要顺带引入字段草稿态。

### ③ 红底红图标：壳级 token 缺陷，不是 body 写法问题

`canvas.css:2388-2389`（本会话直读，非转述）：

```css
--node-status-failed: var(--canvas-danger);
--node-status-failed-fg: var(--canvas-danger);
```

两者**同色**。而 `ReferenceManagerPanel.tsx:720-728` 的超容量角标用 `bg-node-status-failed + text-node-status-failed-fg` ⟹ 红底红图标，对比 **1:1**，图标不可见，且它正落在这个作用域内。

同族的 video 失败条另用裸 `text-red-100 / bg-red-500/10 / border-red-400/30`（`VideoComposer.tsx:2169-2173`）压在**浅色**画布域上。

**骨架条款**：失败配方统一后必须跑 `contrast-check`（禁目测、禁信 review agent 算术）。

### ④ 模型选项为空 → 整段静默塌掉，违反 Hard Rule 8

`NodeCardControls.tsx:91-93`：`if (options.length === 0) return null` —— 无占位、无「模型未配置」、无配置入口。而「生成试听」按钮不受影响、照常可点，点了必失败。
生产上唯一暴露面是音色面板（另一个消费方 `GenericDetailBody` 已死）。

**骨架条款**：路由到 `QuickSetupDialog` 内联配置，不禁用 UI、不静默塌段。

### 4.0 ⓪ 的确认内容（2026-08-03）

**槽序归骨架**：十族的信息递进顺序一致 —— 身份 → 主体 → 材料 → 编排 → 关系 → 证据 → 动作。
**栏比与分栏归各族**：分几栏、栏比多少、哪些槽入哪栏，由各族按自己的内容量决定。

由此得到两条可验收的骨架条款：

1. 同一个控件不得在不同族落到不同的**槽**（今天三段来源行在背景族落左栏、在散图/镜头图落右栏——那是**槽内位置**漂移，不是分栏差异，属违规）。
2. 各族可以让某个槽为空，但**不得跳序**（例如把动作坞排到证据抽屉之前）。

### 4.2 ⑥ 的确认内容：参数收成一颗按钮（owner 2026-08-03 提出）

owner 原话：「这些不可以放在一个按钮中吗。点击后出现这些配置。我记得没点开扩大之前配置就是这样放在一个按钮里面。」

**核实属实**（`VideoComposer.tsx:1344-1370`，density='card' 分支）：紧凑侧车的参数按钮标签**就是**规格摘要本身 ——
`summaryParts.join(' / ')`（分辨率 / 时长 / 画幅，`:1103-1110`），没设过时回落 `tc('sidecar.editParameters')`；
点开是 `ResponsivePopover`（桌面浮层 ↔ 手机抽屉，已是响应式原语），内含 duration 滑条 + 画幅选择器等。

**采纳，且作为槽 4「编排台」的全族统一形态**，不只对视频。它一次解决四件事：

| 解决                                                                                                                                  | 依据                                                                 |
| ------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------- |
| 规格重复彻底消失 —— 全屏只有一处说规格，就是按钮标签，不存在「删哪一份」                                                              | 台账 §21.3 的三组重复中最大的一组                                    |
| 视频面板溢出解决 —— 6 段折叠体约 390–730px 收进浮层，主动作坞回到首屏                                                                 | 实拍 F1e 生成按钮在滚动线以下；违反 7 月已确认「主动作无需滚动可见」 |
| 空态零信息量解决 —— 标签在空态是「编辑参数」（动作邀请），不是「自动·自动·自动」                                                      | 实拍 F1e 左栏台座                                                    |
| 顺手消掉一处不合规 —— 6 个 `.node-collapsible` 用 `grid-template-rows` 过渡，违反「只动 transform/opacity」；收进浮层后它们整个不存在 | 台账 §13.2；此项同时解掉待拍板 ⑨ 的一半                              |

**兑现的已确认标准**：page 文档「紧凑态与扩大态消费同一份 composer 数据」—— 现在连**控件**都同一个，两态零学习成本。

**明写的代价**：方向 A 承诺「spacious object studio」，参数收进浮层 = 扩大态在**参数**这件事上退回紧凑态。
这个交换成立的理由：参数属 `references/interaction.md` 的「D 精密档」，摊开不提升可用性、反把主动作推下折线；
腾出的约 400px 给 relations-strip 与 evidence-drawer —— 那才是紧凑侧车给不了、只有扩大态能给的东西。

**③ 与 ⑥ 合起来才完整**：③ 让**外层** AI 表单默认展开（右栏不再空白），⑥ 把**内层**参数折叠体换成一颗按钮
（内容不再瞬间涨 700px）。两条各治一半 —— 单独做 ③ 会让首屏密度失控，单独做 ⑥ 治不了镜头图/关键帧的空白右栏。
合起来「约 700px 零过渡硬跳」这个面板内最大的病彻底消失，且没有引入任何新的展开动画。

**⬜ 两个待验风险**（进阶段 5 原型时必须验）：

1. **浮层叠浮层**：参数 popover 开在 `role=dialog aria-modal` 的详情面板之上，focus trap 要验不打架。

⚠ **订正记录（必读，别再犯）**：agent 初次把第一句读成「明暗不该作为区分轴，留给三方向各自试」，

后果是三份原型全部出现深色：B 的原型页 `body` 是 `#191c21`；A 的媒体窗是 `#161B23`（源码注释自称

**正确的读法就是字面意思：不要走暗色。** 这与 §6.1 的「壳级 A' 浅壳」是同一个决定的两半。

因此：

**边界（owner 2026-08-03 逐项确认）：全部不允许 —— 面板 · 媒体井 · 遮罩三处都不能深。**

- **面板**全浅。
- **媒体井**（图/片摆在上面那个框）不能深。⚠ 连带代价：浅图、透明 PNG 在浅井上边界不清。
  合规解法只有「比面板略深一档的**中性浅灰**井」（如 `#E9EBEE` / `#DEE1E5`）＋ 实边框，
  或透明底走棋盘格 —— **不许**用深井解决对比问题。
- **遮罩**不能深。
- 玻璃显形的手段归**结构**，不靠明暗对比。
- ⚠ **物理约束要写明白**：画布底是近白 `#F1F1F1`、点阵对底仅 1.54:1。白雾压近白透不出东西，
  这正是三份原型都改用深遮罩的原因。遮罩必须保持中性/浅色 ⟹ 玻璃显形只剩三条路：
  ① 遮罩**不糊**（保留画布形状，只降明度）· ② 遮罩不透明度大幅下调（0.72 → 0.35 一档）·
  ③ 面板不铺满、边缘大面积露底。**别再给出「深遮罩」这个选项。**
- 画布舞台底不动（超出「仅详情面板这层解冻」的授权）。

**返工范围（owner 确认）：只改材质层，结构不动。** 三个结构论点（定舞台 / 分幕 / 抽屉台）、
已做好的交互与状态覆盖全部保留；改的是 B 的页壳 `#191c21`、A 的媒体井 `#161B23`、
三份的深遮罩及其连带的玻璃路径。

### 6.3b ⚠ 玻璃**整体取消**（owner 2026-08-03，基于实测证据）

owner 原始诉求是「背景想加透明玻璃质感」。三方向原型实测后 owner 改判：
**「干脆不做玻璃，改用实面 + 投影分层。」**

**支持这个改判的实测证据**（复核在浏览器里逐份读 computed style 得出）：

- 三份**没有一份**真的做到「透过面板看见画布」。面板本体的 blur（A 22px / B 26px / C 20px）
  叠在已被遮罩压过的画布上，透过面板的点阵对比合成后**全部掉到 1.1 以下且结构被抹平**。
- 三份里「看得见画布」的地方，**实际都发生在面板之外的边缘带**，与面板材质无关。
- C 声称的「靠占得少显形」被实测推翻：同一 1368px 舞台，C 面板 **1214px**，
  对照组「现状白板」**1180px** —— 它反而占得**更多 34px**。几何红利只在内容少的族兑现
  （镜头图 522 / 角色 778），恰好是最不需要看画布的那几族。
- 叠加 §6.3「遮罩不能深」之后：浅遮罩透不出内容 + 面板 blur 抹平剩余 ⟹ **物理上做不到**。

**由此确立**：

- 详情面板是**实面**（不透明），不用 `backdrop-filter`。
- 层次靠**投影 + 留白 + 尺度**，不靠透视。
- ⚠ 必须同时解掉复核查出的**层次倒挂**：现状模态面用 `--canvas-glass-shadow`（y=4px），
  而底下的底部胶囊与近场工具条用 y=10px 两层投影 —— 最高层反而更贴地。实面之后投影是**唯一**的
  层次手段，这条不修就没有层次可言。
- ⚠ 仍受 §6.4 禁区约束：**不许把层次押在 1px 发丝边 + 单层投影上**。
- 遮罩随之退化为纯粹的「推远画布 + 提供关闭区」：中性浅色、不糊、不深。
