## 1 · 判错过什么，模式是什么

**① 「不消费」讲浅了，差点删错东西的理由。**
我先说 `shotText→静帧` 这条边「下游不消费，是装饰边」。owner 追问「是模型那边，还是目前项目没做」——查证是**项目没做**（一个三目：`isVideoMediaNode ? harvest : ''`）。但真正该说的是**第二层**：就算接通也不该接，因为 shotText 拼的是「场景/动作/镜头/构图」，其中「镜头」是运动词（缓慢推入/过肩），那是写给视频的，喂图片模型是噪音。
👉 **模式：说「没做」之前先问「做了对不对」。** 「未实现」和「不该实现」给出同一个当下结论，但决定了要不要写进 backlog。

**② 「已通过就别挂按钮」——前提错了。**
包 4 第一版对 `approved` 直接 `return null`，理由是「不该常年挂着两个按钮」。但那条工具条**选中才出现**，根本不是常年挂着。代价是手滑点了「通过」再也退不回来。
👉 **模式：为「不做某事」写的理由，也要验它的前提。** 这条已用 5 条测试锁住并写明理由，防止有人按同样的推理再删回去。

**③ 用正则匹配按钮，误改了 owner 的数据。**
真机验收时用 `/生成|发送/` 找发送按钮，命中了「解**绑视频生成**」，**断掉一条真实连线**。当场撤销恢复（边 25→26）。
👉 **模式：真机上找控件一律用精确相等**（`aria-label === '发送'`），永不用包含/正则。

**④ 全量 tsc 和 vitest 并行起跑 = 自造 flake。**
前三轮全量每次都有 1 条超时失败，且**在文件之间漂移**（LoraWorkbench / i18n-completeness 轮流）。改成串行后连续三轮**零失败**。
👉 已写进 memory [`project-known-vitest-failures-2026-07-31`]。判据只有一条：**单跑该文件是否绿**，别按文件名归因。

**⑤ 隐藏标签页的观察会骗人。**
MCP 标签页 `visibilityState: 'hidden'`，rAF 冻结 → `g.react-flow__edge` 计数恒为 0。**边一律读持久化数据不读 DOM。** 这条是仓里既有教训（memory `reference-hidden-tab-raf-frozen`），本轮再次命中。

## 2 · 关键结论是怎么推出来的（规格只写结论）

**「审核粒度按 URL」不是随便选的。** owner 拍「按图」时说「卡这个设计应该被我舍弃了，没有删除干净吗」——**事实是 G5 从来没执行过删除**，是 owner 自己 2026-07-31 把它归到卡片总线契约随之后置的（`IdentityCollectorCard.tsx` 仍在，9 文件引用；收集器机制 `isPrimary`/`onStage` 散在 25 文件）。
所以「按图」落成**按 URL 键控**，对 G5 两种结局都免疫：只换卡面呈现 → 门禁零改动；连收集器机制一起废掉 → 按 URL 自然退化成按节点。**下一个会话若要动身份卡，这个选择不会成为阻碍。**

**「祖父条款」是唯一非灾难的默认。** `mediaReview` 查不到的 URL 一律 `approved`。反过来（查不到＝待审）会让**所有存量项目的所有图当场停止喂下游**。已写成断言，别改。

**「模型 id 不冒充名字」用精确相等而非模式匹配。** 判据是与该节点自己的 `model.modelId` 一字不差——真机验证过相等成立。**用户完全可以把一张图就叫那个名字**，模式匹配会误伤。
