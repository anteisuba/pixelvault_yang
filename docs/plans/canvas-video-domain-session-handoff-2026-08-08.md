## 一、我判错过什么，以及模式是什么

⭐ **最值钱的一节。下个会话最容易重犯同一个错。**

**1. 连续两次「用推断填补未知，而不是去读官方规则」**（BytePlus 激活失败那段）

- 第一次推断「是 `Model hashrate billing` 开关导致的」——依据是两张截图之间只有这个开关变了。owner 关掉后**错误一字未变**。
- 第二次推断「是 `Select all` 42 个模型里有一个需要资源包，拖垮了整批」——也错。
- 真因是查官方文档才知道的：**Seedance 全系在 BytePlus 必须先买任一 Seedance 资源包才能激活**，绑信用卡不构成条件。
- **模式**：面对一个陌生平台的报错，我连着两次从「观察到的差异」反推因果，样本量都是 1，而**官方文档里白纸黑字写着规则**。→ 陌生平台报错，先搜官方文档，别从截图差异做因果推断。

**2. 看到函数名对得上就当它在跑**（`groupModelsByProvider`）

- 我拿它当「第一层按渠道分组」的现状证据写进文档，**它是死代码，全仓零消费**。真正在渲染的是 `BaseModelPickerPanel`。
- 结论方向恰好没错（第一层确实是渠道），但**证据是假的**。
- **模式**：这跟 memory 里那条 `reference-verify-component-is-rendered`（说 UI 会给用户反馈前先确认组件真有人渲染）是同一个坑。**我记着那条还是踩了** —— 因为那条讲的是「组件」，我以为「函数」不适用。→ 引用任何代码当证据前，先 grep 它的消费点。

**3. grep 一层就下结论**（"组件层零消费 send contract"）

- 我只 grep 了直接 `import`，实际是 `buildVideoSendPreview` → `use-video-composer` 间接消费的，槽位上限一直是跟着模型走的。
- **模式**：传递链上任何一环都可能是真正的消费者。→ 结论是「零消费」时，至少再追一层。

**4. 拿代码标识符当用户可见文案**

- 我说「节点姓 Seedance，用户不会想到能切 Kling」。i18n 实读：`nodeTypes.seedance` 的显示名是「视频生成」，**用户从没见过 seedance 这个词**。
- **模式**：`AI_MODELS` / `NODE_TYPE_IDS` 这类标识符跟用户看到的字是两回事。→ 说「用户会看到 X」前查 i18n。

**5. 把区域代号按常识翻译**

- BytePlus 的 `ap-southeast-1` 我写成「新加坡」，控制台实显 **Asia Pacific (Johor)**（马来西亚柔佛）。官方文档只给代号，没给城市。
- **模式**：补充官方没写的细节时，我的「常识」就是猜测。→ 官方没写就标「官方未写」，别替它补。

**6. 把「当前恰好如此」当成「应该如此」**（那条被我自己推翻的测试）

- 我写了条断言「同一模型不得同时出现在两张价格表里」，理由是防数据漂移。补齐 fal 价格后必然重叠——而**重叠本身不是问题**（两表口径不同，一个营销一个决策）。
- **模式**：立不变量时要问「这是本质约束还是当前巧合」。→ 现在改成守「单位一致」，那才是本质。

## 二、关键结论是怎么推出来的（规格只写结论，不写推理链）

**1. 三层结构只需要一个新字段，不是四个**

我先假设需要 `series / variant / channel / endpoint` 四个，然后逐个验证：`MODEL_FAMILIES` 实测 100% 覆盖 20 个视频模型且正好分成 7 个系列 → series 现成；channel 就是 `adapterType`；endpoint 与 `referenceMode` 一一对应 → 也现成。**只有 variant 没有来源。**

→ **不做这轮验证就会白加三个字段，还要给 20 个模型条目补值。** 下个会话若想再加维度，先问「现有数据里有没有等价物」。

**2. reference 变体不必露出给用户**

这是 owner 两条指示合起来的**副产品**，不是他直接说的：模式移到节点上（指示 A）+ 三层是系列/型号/渠道（指示 B）→ 「选了全能参考」本身就决定走 `reference-to-video` 端点 → 用户只需要看见「Seedance 2.0」。

→ **别把 reference 当成第二层的一个选项**，它在 UI 里应当完全不出现。

**3. (型号 × 渠道 × 模式) 唯一性是地基不是健壮性检查**

我先假设它成立，写测试验证，实测通过。撞车意味着有两个条目除 id 外完全同构，那时模式切换会按数组顺序**随机**挑端点 —— 用户以为在用全能参考、实际发首帧请求。

→ 接新渠道（BytePlus）或新型号时这条会红，**红了要改数据不要改测试**。

**4. homepage 价格表判定为「过时」的推理链**

fal 官方 $0.3034 vs homepage $0.1 差 3 倍 → 但 2.5 只比 2.0 贵约 50%，差不出 3 倍 → 不是版本差异；Veo 那条能对上 fal 的「不含音频」档 → 说明表至少部分是按不含音频填的；但 Kling 对不上**任何**档 → 只能是过时。
