## 结构：九段长卷

页面是**普通文档流**，用文档自己的滚动条。每段高 `vh`，里面用 `position: sticky` 钉住一屏舞台；滚过的距离除以「段高 − 一屏」就是这一段的 `progress`（0–1），演示按进度求值。

| --- | --------- | --------- | --------- | ----- | -------------------------------------------------------------------- |
| 1   | `opening` | `opening` | 100vh     | —     | 口径行 + 两行标题 + 真实归档作品墙（随滚动向两侧散开）+ 供应商跑马灯 |
| 2   | `image`   | `feature` | **250vh** | ✅    | 01 图片 — 写 prompt → 四家出图 → 结果 + CTA                          |
| 3   | `lora`    | `feature` | **250vh** | ✅    | 02 LoRA — 挂载 → 触发词 → 权重轴四张对照图                           |
| 4   | `audio`   | `feature` | **200vh** | ✅    | 03 声音 — 三句台词落位 → 波形画出 → 输入行就绪                       |
| 5   | `video`   | `feature` | **250vh** | ✅    | 04 视频 — 三个参考落槽 → 写 brief → 发送键亮 → 出片                  |
| 6   | `canvas`  | `feature` | **250vh** | ✅    | 05 画布 — 助手 → 剧本 → 节点，三步随进度交接                         |

- **段首 `scroll-snap-align: start`**（`proximity`，不是 `mandatory`）：键盘与触控板一格一段，**段内滚动自由**。
- **每段结束态停在自己的「去用这个」上**（`.fn-cta`，去处见 `HOME_V4_FN_ROUTES`）。CTA 永远在 DOM 里，只是结果态才揭开——结果态才出现的按钮会在读者正盯着结果的那一刻顶一下舞台。
- **模型阵容并成了一段**。v4 的五个整屏纵向轮播站（图片 7 / LoRA 6 / 视频 6 / 音频 2 / 3D 4）要读者翻二十五次才看得完，而阵容是拿来**扫**的。现在每模态一行横滑卡片，封面点进对应模态的工作台，卡下的「详情」开强弱 sheet。这一段**不参与 scrub**：横轴已经吃掉了滚动。

## 关键帧表（`HOME_V4_BEATS`）

六段演示是**按进度求值的状态机，不是时间线**。表里没有一个毫秒——段走多快由读者的滚轮决定。骨架统一按 UX 板的节拍读：**0.0 空态 · 0.3 输入完 · 0.7 出图 · 1.0 结果 + CTA**，各段在这个骨架上自定分镜。

| 段     | 0.0     | 0.3                      | 0.7                      | 1.0                  |
| ------ | ------- | ------------------------ | ------------------------ | -------------------- |
| image  | 空态    | prompt 写完              | 四格揭开 3 格            | 4 格 + CTA           |
| lora   | 空态    | 5 个挂载 + 3 个触发词    | 对照图 3 张              | 4 张 + CTA           |
| audio  | 空态    | 3 条气泡落位、2 条有波形 | 3 条波形齐 + 输入行就绪  | + CTA                |
| video  | 空态    | 3 个参考 + brief 写完    | 发送键亮 + 成片          | + CTA                |
| canvas | 第 1 步 | 步位 0.59                | 步位 1.53                | 第 3 步 + 成片 + CTA |
| vault  | 空库    | 落库 3 + 库存 7          | 角色锚亮 + 复用位填 0.75 | 填满 + CTA           |

求值器：`src/lib/home-v4-beats.ts`（纯函数，不碰 DOM）。测试在这四个点上逐段钉住结果：`src/lib/home-v4-beats.test.ts`。

**演示元素一律预渲染**，只用 `opacity` / `transform` / `clip-path` 揭开。⛔ 任何一段都不靠「到时候往 DOM 里加一行」表现进度——那是布局变化，滚一下重排一次。飞递 ghost（v4 资源库的 FLIP 幽灵）因此整删：它要读布局、要塞元素、要定时器收尾，在 scrub 下每来回滚一次就重放一遍。

## 降级（第一条，不是最后一条）

`prefers-reduced-motion` 或 **≤767px**：引擎根本不启动，每段停在 `REST_PROGRESS = 1`（**结果态**，不是空态），不钉住、不 scrub、段高收成一屏。手机上没有 pin，所以没有 pin 抖。

⚠ **挂载之前也是降级态**——所以首个 HTML 响应里六段演示画的就是「做完的样子」，没有 JS 的访客看到的是内容，水合也不会错位。

## 硬约束

1. **服务端优先**：`page.tsx` → `HomeV4Shell`（server）→ `HomeV4Deck`（唯一 client 边界）。标题、模型名、段表都在首个 HTML 响应里，页面保持 `revalidate = 3600` 可边缘缓存。长卷把这条拉得更紧：未挂载 = 结果态，所以首个 HTML 里演示也是完整的。
2. **域内自足**：`.home-v4` 之外不声明域 token。画布皮肤曾经这样漏进两个助手 dock。
3. **CJK 选面用 `.home-v4[data-locale='ja']`，不要用 `:root[lang^='ja']`**——`<html lang>` 由根 layout 写，客户端导航时不重渲染，切到日文后 `lang` 还停在旧值，日文会被 Noto Sans SC 的简体字形画出来。域根自己带 `data-locale`，随语段重渲染，零脚本就对。（`<html lang>` 本身的陈旧影响读屏，由 `src/components/layout/LocaleHtmlSync.tsx` 单独补。）
4. **模型阵容走真目录**，不手抄清单：名册 `HOME_V4_STATIONS`，名称 `MODEL_MESSAGE_KEYS`，供应商 `getProviderLabel`。首页宣传产品跑不了的模型是硬伤，而手抄的清单必然腐烂。
5. **动画库**：首页域是全项目唯一允许 GSAP 的地方，且必须动态导入不进主 chunk。**v5 一行 GSAP 都没有**——钉住用 `position: sticky`（零依赖、零脚本、浏览器自己合成），「允许」不是「需要」。`home-v4.test.ts` 有一条守着：`src/**` 里出现静态 `import … from 'gsap'` 就红。要用请 `await import('gsap')`。
6. **中文排版三条**（都踩过）：标题行高 ≥1.14（1.0 会重叠，CJK 字身满高）；`max-width: Nem` 按容器自己字号算，别拿它约束大标题；必须 `word-break: keep-all; line-break: strict`，否则中文会在任意两字间断行。判断行距**不要看 `getClientRects`**——它算回退字体的完整 ascent+descent，会误报重叠。

### 帧预算

段内每帧只允许写 `transform` / `opacity` / `clip-path`。滚动事件里**只置脏标记并请求一帧**，所有 `getBoundingClientRect()` 在那一帧里读完再一次写 state；⛔ 绝不在滚动回调里边读边写布局。进度进 state 前量化到 1/240，不量化每帧都是一次 React 重渲染。

## 导航

- **桌面（左缘）**：一段一条细进度轨，轨里的填充 = 这一段的 `--p`（`scaleY`，⛔ 不改 height）。hover 整条区域展开段名。点一段 = 把那一段滚到 **progress 1.0**（「给我看这一段做完的样子」）。
- **手机（<768，底部）**：**缩略图条**（owner 批注 51 / 52）。一段一张自己的画面，56×44，当前段亮起，横着滑。⛔ **不复用桌面的进度轨**——拇指区里 3px 宽的轨既点不准也认不出。段名保留给读屏。
- **键盘**：↑ ↓ / PageUp PageDown **先把当前段走完，再去下一段**。其余键（空格、Home/End、Tab、找字）一律留给浏览器——一个把所有输入都吞掉的首页是 v4 最贵的那个决定。
- **锚点**：每段 `id="home-<段 id>"`，`/#lora` 可分享，落在**段首**（与点目录的 1.0 是两件事）。`scroll-margin-top: var(--bar)` 让开浮岛。

## 矮视口（owner 批注 50）

`@media (max-height: 900px)`：钉住区永远只有一屏高，所以矮唯一能做的是让**内容收**，不是让页面长。`.page-inner` 收内距与 gap、`.fn-stage` 收到 `calc(100svh - var(--bar) - 48px)`、标题降一档、模型卡收窄。⛔ 不允许溢出到浮岛底下。

## 功能段 01 · 图片 / 02 · LoRA

- **≥1100px 左栏标题**（owner 2026-09-11 定）：`HomeV4FnFrame` 的 `rail` 把标题放进左栏（`clamp(260px, 22vw, 320px)`），工作台放宽到 939px 并吃满整屏高度；`.page-inner.rail` 用 `safe center` + 顶部 84px，溢出只往下走，标题永远在浮岛（底 67px）下面。起因：1470×803 下这两页工作台比屏幕还高，居中把溢出上下平分，标题钻进浮岛。其余四段内容够矮，保持居中。
- 01 图片：四宫格 2×2 方图，宽度取 `min(580px, 屏高 − 187px, 工作台内宽 − 327px)`，输入列 314px，图片是段的主对象。「N 个模型」chips 作为 `aside` 进左栏（点它去模型阵容那一段），1100px 以下回到工作台下方。`next/image` 桌面 `sizes` 为 290px。**四格的错开不再是 CSS `transition-delay`**——错开量是读者滚过的距离。
- 02 LoRA：出图 3:4，列宽取 `min(220px, (屏高 − 213px) × 3/8, (面板内宽 − 431px) / 2)`；机架定高 363px，库列上限随屏高在 150–286px 之间收。`sizes` 为 220px。
- 1100px 以下沿用居中堆叠：工作台 860px、四宫格 500px。`≤768px` 改为输入区在上、四宫格在下，四宫格宽度回落到 100%，不得沿用桌面固定宽度造成横向溢出。

## 相邻域

登录页（`/sign-in` `/sign-up`）**不共享**本域皮肤：它有自己的 `src/app/auth.css`（`.auth-surface`），文案挂自己的 `Auth` 命名空间，载体 `AuthCard.tsx` 与 `AuthDialog` 是同一张卡。首页顶栏的登录按钮登录前后长得一样、只换目标，为的是边缘缓存的页面不必等 Clerk 才能画。

## 已知缺口

- **模型卡点封面不预选模型**。站表的 `key`（`gpt` / `flux` …）是首页自己的 id，不是目录里的 model id，凭它拼 `?model=` 就是手抄；工作台也还没有读这个参数的入口。现在封面链到对应模态的工作台（`HOME_V4_STATION_ROUTES`）。要做预选，先要目录侧给一条 id 映射 + 工作台侧读参数。
- **首屏作品墙仍是 10 格 DB 取数，不是 UX 板说的「固定 6 张 + LQIP」**。墙是活的（`getHomeShowcaseShots()` + 置顶 / 黑名单常量），砍到 6 张是**版式决定**，需要 owner 看过实物再拍；LQIP 也要先有 blur 占位的生成路径（作品图是 CDN 远端 URL）。已做的是两件无风险的：只有首两张抢 `priority`，全部 `decoding="async"`。
- 音频站只有 2 个模型，横滑那一行明显比图片行短；等音频域把模型接上，不为此改版式。
- 英 / 日排版未逐段真机复核过（三语文案齐全，键有测试守）。
- 页脚「资源 / 公司」类链接在 v3 时代是 `#` 死链；v4/v5 页脚只保留 tagline + 条款 + 隐私三条真链，那批占位**已随 v3 删除**，没有恢复计划。
- 视觉基线：`e2e/` 目前没有首页 Playwright 基线，本轮没有截图可更新。
