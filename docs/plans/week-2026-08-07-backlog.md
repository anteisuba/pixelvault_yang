### 对标调研（2026-08-07 实地跑过，owner 登录态）

owner 确认：**libtv = <https://www.liblib.tv/>**（LibTV，LiblibAI 的视频线，**不是** liblib.art 的星流 Agent —— 我最初按星流查的那版已作废）。

#### 共同结构（两个产品高度同构，且和 PixelVault 架构一致）

首页 = **一个自然语言输入框 + Skill/技能库 + 最近项目列表**。没有参数面板。

- UPDream 输入框：「输入创意想法，按 **`/`** 调用技能开始创作」
- LibTV 输入框：「请输入你的创作灵感，或从下方挑选一个 **Skill** 开始」
- 项目打开 → 独立画布页（LibTV: `/canvas?spaceId=&projectId=`），**左画布 + 右对话面板**
- LibTV 顶部有「画布 1」下拉 → **一个项目可以有多个画布**
- LibTV 左下角固定「资产管理」入口 = 素材库

⭐ **Skill 是可复用、有作者、有使用次数的社区资产**。UPDream 官方技能「短视频脚本创作助手」的能力清单，几乎就是 PixelVault 两阶段剧本流的镜像：生成大纲 → 扩展为分场景脚本 → 优化对白节奏 → **为脚本生成配套的分镜描述和画面提示词**。差别是他们把这条链做成了**可分享的技能**，我们是硬编码的功能。

#### ⭐ LibTV 的对话→生成协议（实拍，直接回答 A2 / A4 / B 三个问题）

以画布项目「AI小剧场」的真实对话为样本，完整链路是：

1. **用户给模糊需求**：两张附图 + 「看下这两个图片的 deepseek 设计的区别。然后设计其他模型的。」
2. **AI 不生成，先分析**：列出图1（表情包风格）4 条特征 vs 图2（三视图风格）4 条特征。
3. **AI 反问**：「你想用哪种风格来设计其他模型？」
4. ⭐ **「已询问」折叠块**：结构化沉淀问答对，可折叠回看 ——
   - Q「ChatGPT、Gemini、Kimi 的角色设计用哪种风格？」→ A「图2风格 — 精致chibi三视图（正式设计稿）」
   - Q「接下来优先设计哪些角色？」→ A「ChatGPT娘 · Gemini娘 · Kimi娘」
5. **确认后才执行**：「好的！用图2的精致chibi三视图风格，同时设计三个角色！并行生成…」
6. **结果用表格汇总差异**：`| 角色 | 配色 | 标志元素 |`，三行三个角色。
7. **结构化的下一步选项**（不是自由文本）：
   - 「✅ 全部满意 → 继续生成各角色的成人版全身立绘」
   - 「🔄 某个需要改 → 告诉我具体调整方向」
8. ⭐⭐ **「图片待确认后生成」占位卡**：AI 提出方案后，对话流里插入一张**灰色图片占位卡**，卡内文字就是「待确认后生成」。**方案已定、图未生成、等用户点头。**
9. ⭐ **节点引用胶囊**：用户消息可嵌入画布节点 —— 形态是 `[🖼 ChatGPT娘 精…] 感觉都是女仆装没有分出特点。`，即**缩略图 + 节点名（截断）+ 自然语言**。
10. **每轮结束都带确认闸**：「效果满意吗？ ✅ 满意 → 确认为正式设计 / 🔄 需要调整 → 告诉我方向」

#### 三条结论

**B 的授权边界 → 答案是第三种，比原先四个选项都好。分界线不是「进不进画布」，而是「花不花钱」：**

> **节点结构立即落画布（免费）；像素等确认（花钱）。**

⚠ 我最初根据对话里的「图片待确认后生成」占位卡，误判为「未确认的东西根本不进画布」。**实测推翻了这一点**（2026-08-07 亲手跑了一次生成，见 `libtv-canvas-ui-teardown-2026-08-07.md` §九）：AI 一决定要生成什么，**立刻**在画布上建好空节点、接好连线、填好标题和完整提示词、挂好参考图，视口还自动跟过去 —— 这一切**都在确认之前，且不花一分钱**。只有点了生成按钮才扣积分、才出像素。

为什么这个分法更好：

- 用户**立刻看到 AI 的计划在画布上的空间结构**（要建几个节点、怎么连），而不是读一段文字描述。
- 提示词可以**在生成前审阅和修改** —— 它已经填在节点里了。
- 不会误烧积分，因为贵的那一步单独设闸。
- 撤销栈也不脏：空节点删掉就是，没有"半成品像素"要清理。

且确认动作是**结构化选项**（满意/需调整）而非自由文本，「确认」这个信号对机器是明确的。

**A2 的「讨论收敛」信号 → 就是那两个结构化选项。** 不需要猜用户什么时候聊够了：每轮 AI 主动给「✅ 满意 → 下一步」和「🔄 调整 → 说方向」，点了 ✅ 就是收敛。这同时解决了「什么时候出结果」和「结果对不对」两件事。

**A4 的 `@` → LibTV 的范围比「指定素材」宽得多，而且吃掉了模型选择器。**

实测输入 `@` 弹出的是一个**分组下拉**：

```
节点

  🖼 ChatGPT娘 精致…
  🖼 ChatGPT娘 男友…
  ⋯  加载更多                ← 分页，不是全量塞进去
模型
  Seedream 3.0 Pro
  悠船 V8.1 / 悠船 V7
  General image V2 / Lib Image
```

两条判断：

1. **`@` 是统一的寻址语法，不是「插入素材」的快捷方式。** 节点、模型、工作流、资源都是可被同一套语法引用的对象。「@ChatGPT娘 用 @General image Pro 再来三个变体」一句话就说完了引用 + 选型 + 数量。
2. ⭐ **模型下拉框被 `@` 吃掉了。** 图片模型和视频模型混在同一个列表里，靠会员标区分档位 —— 没有「先选模态再选模型」这一层。这对 PixelVault 是个值得掂量的方向：我们现在模型选择是独立控件。

PixelVault 若只做「@ 素材」会比对手窄一档。

### ⭐ C4 已定位：不是上传压的，是网格显示压的

逐行读过链路，硬事实：

1. `CLIENT_UPLOAD_MAX_BYTES = 15MB`（`src/constants/uploads.ts:29`），注释明写 **「Files at or under this are sent _as-is_ (no re-encode, no quality loss)」**。
2. `prepareImageUpload`（`src/lib/prepare-image-upload.ts:55`）第一行就是 `if (file.size <= maxBytes) return file` —— **15MB 以下原样上传，压缩函数根本不执行**。
3. 素材页走的正是这条路径（`KreaAssetBrowser.tsx:893`）。
4. 而且这个坑**曾经修过**：`uploads.ts:26` 注释「The old 3 MB base64 path crushed quality — every good image got re-encoded down; this preserves it.」

→ 所以「上传被压缩」在 15MB 以下不成立。真凶有两个候选：

- **候选 1（高置信）：网格经 next/image 优化。** `KreaAssetBrowser.tsx:1527` 用 `sizes={DENSITY_IMAGE_SIZES[density]}` 且**没有 `unoptimized`** → 走 Next 图片优化，默认 **quality=75** 并按密度降分辨率。对比 `AssetDetailSheet.tsx:737` **有 `unoptimized`** = 详情页是原图。**网格糊、点开清楚 → 就是这个。**
- **候选 2：超过 15MB 的图确实被压。** 4K/RAW 导出可能超；此时质量从 0.92 逐级降到 0.6，再开始按 80% 缩边（`compress-image.ts:138-146`）。

→ **验证方法（一分钟）**：上传一张 <15MB 的图，在素材页网格右键「在新标签页打开图片」，看 URL 是不是 `/_next/image?...&q=75`；再点开详情对比清晰度。是则候选 1 坐实，修法是给网格配 `quality`（Next 16 需在 `next.config` 的 `images.qualities` 白名单里声明）。

⚠ 提醒：C1「图片被截断」和 C4「画质低」很可能是**同一个网格瓦片组件**的两个症状，一起改。

### 不能破坏

双维组织（系统分类区块 + 私人文件夹树）· 密度持久化 · 上传只在「本地素材」区块（含粘贴上传）· 素材页不生成。
