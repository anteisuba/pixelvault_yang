## 1. 图片：Midjourney 与画布选型

### 1.1 Midjourney 现状（接入）

| 项              | 事实                                                                                                 |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| 官方公开 API    | **无**（2026-07 仍无面向开发者的 REST/SDK）                                                          |
| 企业 API        | 2025-07 起 [Enterprise API Survey](https://updates.midjourney.com/enterprise-api-survey/)，**未 GA** |
| ToS             | **禁止**自动化、未授权第三方 app/脚本；违者可封号                                                    |
| 第三方 “MJ API” | Discord/Web 包装，**违 ToS**，不稳定，不适合 PixelVault 生产                                         |
| 与本仓架构      | 需要官方 auth、文档化异步契约、计费；当前不满足 `integrate-pixelvault-provider` 门槛                 |

**决策：不做生产级 Midjourney 生成接入。** 可跟官方 Enterprise 申请；产品上可用「审美参照」或外链 Web，不可冒充已接入。

### 1.2 Midjourney 的产品优点（用户要的是什么）

- **默认审美高**：构图/光影/氛围一体，废片相对少（V8.x 继续强化美学与个性化）。
- **复杂场景与风格稳**：概念、幻想、电影感强。
- **个性化**：账号偏好/评分越多越贴用户审美。
- **创作闭环**：选图、变体、整理（偏人用工具，非 API 流水线）。

**短板（相对画布）：** 无合规 API、文字/精确可控常弱于部分旗舰、难做跨镜一致性工程化。

用户说「我要 Mid」时，多数是：**好看默认 + 角色/系列感**，不是品牌字符串。可用合规模型 + 画布默认模型锁定 + 参考图/LoRA 逼近。

### 1.3 画布镜头 / 关键帧：已接入图模怎么用

画布要的是 **可参考、跨镜一致、能接视频**，不是单次 MJ 味。

| 模型（catalog 可用）               | 气质                           | 画布建议位                 |
| ---------------------------------- | ------------------------------ | -------------------------- |
| **Seedream 5.0 Pro**（fal / 火山） | 艺术向、成片感，较接近「好看」 | **叙事/概念镜头默认**      |
| **FLUX.2 Pro**                     | 写实、光影稳                   | 写实镜头、环境、干净关键帧 |
| **GPT Image 2**                    | 听话、结构清、多参考           | 复杂调度、强提示词服从     |
| **Gemini Pro Image**               | 综合理解                       | 备选旗舰                   |
| **FLUX Kontext**                   | 编辑/跟参考改                  | 已有帧上微调               |
| **Illustrious / Runner+LoRA**      | 二次元、角色锁                 | 日系角色戏                 |
| **Seedream 5.0 Lite**              | 便宜快                         | 试构图                     |
| **Recraft**                        | 设计/矢量                      | **不**主攻叙事镜头         |

**推荐策略：**

```text
全画布默认一个主模型（跨镜一致 > 单镜炫技）
  叙事/概念  → Seedream 5.0 Pro
  写实       → FLUX.2 Pro
  二次元     → Illustrious 或 Runner+LoRA
  强执行剧本 → GPT Image 2 / Gemini Pro Image

节点角色：
  角色设定图 → 与片种一致（写实 FLUX/Seedream；二次元 LoRA 线）
  背景       → 与默认同族
  镜头 shot  → 默认主模型 + 上游角色/背景作参考
  关键帧 frame → 与镜头同模型（避免风格跳）；进视频前可要「干净构图」
  草图       → Lite / 低成本档，定稿再升 Pro
```

**不要：** 等 MJ；每镜换不同旗舰；用 Recraft 当叙事默认。

## 2. 视频：Comfy vs 云 vs 选型

### 2.1 Comfy「参考视频 + 图」

| 层面                            | 结论                                                                           |
| ------------------------------- | ------------------------------------------------------------------------------ |
| ComfyUI 生态                    | **能做**（V2V / Video Restyle / WAN Reference-to-Video / Pose+AnimateDiff 等） |
| PixelVault Comfy runner（现状） | **仅图**（SDXL 配方/LoRA/img2img），**无视频 workflow**                        |
| 扩 runner V2V                   | 新模板 + 大模型 + 视频上传/异步/计费 = **新能力线**，非加 checkpoint           |

### 2.2 云视频：谁最接近「参考视频 + 图 → 同款」

| 模型                                         | 图      | 视频参考            | 距离       | 备注                          |
| -------------------------------------------- | ------- | ------------------- | ---------- | ----------------------------- |
| **Seedance 2.0 Reference**（标准/Fast，fal） | ✅ ≤9   | ✅ ≤3 段            | **最近**   | `@ImageN` / `@VideoN`；可音频 |
| Seedance Reference 火山                      | ✅      | 需对齐 Ark 字段     | 同族       | 国内直连                      |
| Seedance 普通 I2V                            | ✅      | ❌                  | 远         | 只从图动                      |
| Kling V3 Pro                                 | ✅ I2V  | ❌ 非运动参考主路径 | 远         | 延长 ≠ 换皮同款               |
| Happy Horse                                  | ✅ I2V  | ❌                  | 远         |                               |
| Gemini Omni Flash                            | ✅ I2V  | ❌                  | 远         |                               |
| Veo 3.1（catalog 已下线）                    | ✅ 多图 | ❌ 不吃视频         | 中（身份） | reference-to-video ≈ 图参考   |

官方 Seedance Reference（fal）要点：多图 + 最多 3 视频（合计时长等有限制）+ 可选音频；prompt 用 `@Image1` `@Video1`…  
**是多参考生成，不是像素级 V2V。** 话术宜用「按参考视频运动 + 参考图外观」，勿承诺 100% 同款。

**产品默认：** 动作迁移 / 同款运镜 → `SEEDANCE_20_REFERENCE`（质量）或 `…_FAST_REFERENCE`（成本）。

## 3. Seedance Reference 代码路径（画布）

### 3.1 端到端

```text
图源节点（角色/背景/镜头/特写/关键帧…）
视频源（videoReference 上传 | 上游成片 | videoMerge）
可选 voice
        │ 边 → Seedance 视频节点
        ▼
StudioNodeWorkbench 生成
  harvest 图/视频/音频
  @名 → @ImageN + legend
  有参考 → resolveEffectiveVideoModel → *_REFERENCE
        ▼
submitVideoAPI → generate-video.service
  图：再传 R2；视频/音频 URL 原样转发
        ▼
Worker providerInput
        ▼
buildSeedanceReference
  image_urls / video_urls / audio_urls
  缺 @Video 时自动 prepend
        ▼
fal …/seedance-2.0[/fast]/reference-to-video
```

### 3.2 关键文件

| 职责                        | 路径                                                                            |
| --------------------------- | ------------------------------------------------------------------------------- |
| 发送预览（镜像 generate）   | `src/lib/node-video-send-preview.ts`                                            |
| Composer / tokens / max cap | `src/hooks/node/use-video-composer.ts`                                          |
| 提交装配                    | `src/components/business/node/StudioNodeWorkbench.tsx`                          |
| 上游视频 harvest            | `harvestUpstreamVideoUrls`（`node-workflow-graph.ts`）                          |
| 有效模型（Reference 切换）  | `src/lib/video-model-resolver.ts`                                               |
| 客户端 API                  | `use-node-media-generation.ts` → `submitVideoAPI`                               |
| 服务端                      | `src/services/generate-video.service.ts`                                        |
| 参考视频上传                | `src/services/video-reference.service.ts`                                       |
| fal body                    | `workers/execution/src/models/fal/video-request-builders.ts`                    |
| 图 cap 常量                 | `provider-capabilities` / `reference-image-capabilities`（Reference max **9**） |
| 节点类型                    | `videoReference`（只上传）；`seedance`（生成）                                  |

### 3.3 正确接线（用户）

```text
[videoReference 或上游视频] ──┐
[≥1 张角色/场景/关键帧] ───────┼──► Seedance 视频节点
[可选 voice] ────────────────┘
```

- 品牌选 Seedance 即可；**有参考输入时提交会切到 Reference endpoint**。
- **必须至少 1 张图**（`requiresReferenceImage`）。
- 参考片：短、约 480–720p、单文件体积限制见 `REFERENCE_VIDEO_MAX_BYTES`。

### 3.4 独立 Studio 视频页

**无**与画布同等的 `videoUrls` 装配。「参考视频 + 图」主战场 = **画布 Seedance 节点**。

## 4. 预览 vs 实发：对齐与灰区（设计必读）

### 4.1 对齐良好

- `buildVideoSendPreview` 与 `handleGenerateMediaNode` 视频分支：**同序 harvest / 组装 / legend / @ 翻译**。
- 「查看发送内容」中的图列表、视频槽、音频槽 ≈ 将发送数组（在 cap 正确时）。
- Worker 对 Seedance Reference 写出 `image_urls` + `video_urls` + `audio_urls`；有单测。

### 4.2 灰区 / 坑（产品设计要盖住）

| #   | 问题                                                                                                                  | 影响                                                          |
| --- | --------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| 1   | **图 cap 常按节点当前 modelId 算**；非 Reference 的 Seedance 继承 fal 默认 **max=1**，提交才切 `*_REFERENCE`（max=9） | 多图在客户端被裁成 1，预览 overflow 与真实 Reference 能力不符 |
| 2   | Composer `hasReferenceInputs` **不含纯视频源**；提交侧 `videoUrls>0` 算参考                                           | 仅挂参考视频时 UI 模型态与提交不一致；且无图会校验失败        |
| 3   | 预览把 `translatedPrompt` 与 `legend` **分开显示**；实发是 `legend + "\n\n" + 正文`                                   | 用户可能不知道图例会进最终 prompt                             |
| 4   | Worker 可对视频 **再 prepend `@VideoN`**                                                                              | 与预览字符串可能略有出入                                      |
| 5   | 图会 **重传 R2**；视频/音频 URL **原样转发**                                                                          | URL 须公网可达（上传链路必须正确）                            |
| 6   | 仅 1 张图时 worker 可能只带 `referenceImage` 不带数组                                                                 | 功能 OK；排障勿误判                                           |
| 7   | 最终模型非 `*_REFERENCE` 时 **丢弃 video_urls**                                                                       | 预览仍可能列出视频；Kling 等不会用运动参考                    |
| 8   | 节点 `data.model` 仅在空 model 时按参考解析；**接边后不自动写回 Reference id**                                        | 提交 resolve 救 endpoint，不救 cap（见 #1）                   |

### 4.3 UI 状态建议

| 状态             | 表现                               |
| ---------------- | ---------------------------------- |
| 无图无视频       | 普通 T2V                           |
| 仅有图           | I2V / Reference（仅图）            |
| **仅有视频无图** | **阻塞**：要求至少一张图           |
| 图 + 视频        | Reference 主路径；展示 图N / 视频N |
| 图超 cap         | 明确 overflow「未送出」            |
| 切到非 Seedance  | 视频槽说明「不用于运动参考」       |

### 4.4 工程收敛（未做，可选）

1. cap / 预览 max 使用与 submit 相同的 **有效 Reference modelId**。
2. `hasReferenceInputs` 纳入 `isVideoSourceNode` + 有效 `mediaUrl`。
3. 有参考边时写回 / 展示 `*_REFERENCE`。
4. 发送预览增加「最终完整 prompt」只读块。
