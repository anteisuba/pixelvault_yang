## 事实与状态矩阵

### 核心事实

- **核心用户**：在画布上编排多模态生成的创作者
- **核心对象**：一个节点（图片 / 视频 / 声音 / 文本 / 身份）
- **最高频任务**：看清这个节点当前是什么 → 改它的输入 → 重新生成
- **默认入口**：近场工具条的 ⤢（全画布共 5 个开面板入口，**全在画布上**）
- **输入 → 处理 → 结果**：参考图/上游连线 + 提示词 + 模型参数 → 生成 → 媒体落回本节点

## 已确认结构契约（从既有拍板复制，不得概括）

1. **卡内是纯媒体**（规格 §12.1）—— 这条约束的是画布上的卡，详情面板不受此限
2. **详情留给 ⤢**（多处代码注释）—— 近场工具条只放「看/拿走/主动作」，细节进面板
3. **审核动作（通过/打回）在底部编辑框的参数条**，不在近场工具条（owner 2026-07-31）
4. **有媒体窗的族靠窗内说状态、没有的族靠盖章说** —— 这是对的分工，不是缺陷
   （台账 §17.5，`hideStatusBadge` 不是漏配）
5. **状态强度梯度**：`idle` 无章 → `done` 无章 → `ready` 最轻 → `running` 唯一带动效
   → `failed` 唯一的红（台账 §17.3）
6. **动效词汇两层**：全局 canon 管通用 UI、画布 token 管画布专属，各自内部一致
   （台账 §20.2，owner 拍板 B）

## 事实审计结论（台账 §21，新会话不要重查）

### 布局

- ⚠ **面板外框不会跳** —— 尺寸**写死** `1180px × min(88svh, 860px)`。「切换族导致面板
  变尺寸」这个担心不成立；而且节点→节点直接切换在真机上**够不着**（5 个入口全在画布
  上、被遮罩挡住）
- ⚠ **`--width-node-detail-panel` / `--width-node-detail-panel-wide` 两个 token 是死代码**，
  src 里零消费者 —— 宽版/窄版之分早已不存在
- 左右两栏走共享的 `canvas-object-studio-grid`（**1.18fr / 0.82fr**）

### 已知最大结构问题

- **AI 表单折叠**：约 **700px 瞬间出现/消失，零过渡**。这是面板内最大的一次跳，
  且全面板**一处 layout/FLIP 都没有**
- 音色面板两档来源 tab 是**整树替换**
- ⚠ `.node-collapsible` 的 `180ms ease` 是**第五套**动效词汇（前四套见 §20.2）

### 视频详情面板（owner 点名「需要重点设计」的那张）的重复

- **时长 / 画幅 / 分辨率**在左栏标题行（`studio.filmMeta`）与右栏「模型参数」**各说
  一遍**。⚠ 空态下左边那行是「自动（由模型决定）· 自动 · 自动」——**六个字零信息量**，
  却占着「当前影片」这个最该说结果的位置
- 「已引用 X / 已连接 Y」**左右两栏各渲染一次**；「已连接数」同屏出现 **4 次**
- 生成模式（参考 / 文生）用两套不同文案说 **3 遍**
- 有一条 **zh 未翻译的英文串**落在底部 dock

### ⚠ 三段来源行「素材库 / AI 生成 / Studio」不能简单删

owner 一度要求删掉，查完发现会连带打断三件事（台账 §21.1），已改为「先不删，重点设计」：

| 按钮        | 它其实是什么                                                                                                                                                                                 |
| ----------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **AI 生成** | **唯一**的 `editTarget` 切换器。而「右栏默认展开 AI 表单」**只给了散图一家**（`defaultEditTarget="ai"` 全仓只在 `LooseImageDetailBody.tsx:77`）—— 删了它，镜头图/背景/关键帧三族右栏永久空白 |
| **素材库**  | 全画布**唯一**能把素材库的图落进某个已有节点自身 `mediaUrl` 的入口                                                                                                                           |

⚠ 它**不是 tab 组**：只有中间那颗有内联内容，另两颗是立即动作（弹窗 / 跳路由）。
批 1 已经纠正过一次这个误解，批 1 原型里白纸黑字写过「不砍三格（素材库/Studio 是真功能）」。

## ⚠ 关于「透明玻璃质感」：它已经有了，是被白雾吃掉了

这条会改变 owner 的起点，务必先读：

```css
/* canvas.css:2372 —— 详情面板的面，本来就是玻璃 */
.domain-canvas .canvas-modal-surface {
  background: color-mix(in srgb, var(--canvas-card-bg) 88%, transparent);
  backdrop-filter: blur(28px);
  box-shadow: var(--canvas-glass-shadow);
}
/* canvas.css:2355 —— 但它背后压着一层白雾 */
.domain-canvas .canvas-modal-scrim {
  background: rgba(255, 255, 255, 0.72);
  backdrop-filter: blur(20px);
}
```

玻璃 → 白雾 → 近白画布底。**玻璃透过去看到的还是白**，所以它看着像一块实心白板。

⟹ 设计问题不是「加玻璃」，是「**要让玻璃看得出来，背后得有东西可透**」——
这是遮罩与层次的**结构**问题，不是材质问题。可能的方向（阶段 5 再展开，本简报不选）：
遮罩降低不透明度让画布透出来 / 遮罩不糊 / 面板不铺满让边缘露底 / 画布底本身给对比。

⚠ 画布 chrome（顶栏 / 底部胶囊 / 左面板）用的是 `--canvas-glass: rgba(255,255,255,0.84)`

- `blur(28px)` —— 与面板同族。**材质语言本来就是统一的**，缺的是让它显形的层次。
