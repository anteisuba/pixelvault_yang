# LibTV 画布 UI 拆解（2026-08-07 实拍）

> 对象：<https://www.liblib.tv/> 的画布（`/canvas?spaceId=&projectId=`），owner 登录态下逐屏实测。
> 用途：`week-2026-08-07-backlog.md` 的 A（助手分域回复）/ B（助手→节点）两条的设计参照。
> ⚠ **全部为观察记录，不是设计决议。** 采纳与否另行拍板。
> ⚠ 未触发任何生成（不消耗 owner 积分），故「生成中 / 生成完落画布」的动效未观察到。

## 一、节点类型谱系

「添加节点」菜单（实拍，非推测）：

**添加节点**

| 类型       | 标记   | 备注                                    |
| ---------- | ------ | --------------------------------------- |
| 文本       |        |                                         |
| 图片       |        |                                         |
| 视频       |        |                                         |
| 视频合成   | `Beta` |                                         |
| **导演台** | `NEW`  | 未展开，疑似运镜/调度                   |
| 音频       |        |                                         |
| 脚本 ▸     |        | 子菜单：脚本 `NEW` / 脚本（旧版）`Beta` |
| 素材库 ▸   |        | 子菜单：**风格库** / **特效库**         |

**添加资源**：上传 · 从生成历史选择

对照 PixelVault 六族：文本/图片/视频/音频四个模态节点一致。他们多出的是**视频合成**、**导演台**，而且**脚本和素材库本身就是节点类型**（我们是独立面板）。「脚本」新旧两版并存说明刚改版过。

## 二、节点的三种视觉状态（画布 10% 全貌实拍）

画布上约 30+ 个节点，横向推进式布局 + 向下分支，明显是自动布局（等间距、分层对齐）。

1. **已生成**：渲染缩略图 + 顶部标题栏（图标 + 名称）+ 右上角尺寸标注（`2752 × 1536`）。
2. **空 / 未生成**：纯深灰矩形，中央一个山形占位图标，无缩略图。
3. **对话内待确认**：这一类**不在画布上**，只存在于对话流里（见 §五）。

⚠ 修正一次误判：10% 时图片节点**仍然渲染缩略图**，没有 LOD 降级。全貌里那些灰矩形是本来就没有图的空节点，不是画质降级。两类混在一条链上，一眼能看出哪些位置还没产出。

## 三、节点选中态 —— 一次浮出四层 UI

点击节点后同时出现：

**① 顶部悬浮动作条**（贴在节点上方）

```
人像质感调节 NEW ▾ | 全景 | 多角度 | 打光 | 九宫格 ▾ | 高清 ▾ | 宫格切分 ▾ | ✏️ ✂️ ⬇️ ⤢
```

⭐ **动作不做成节点，而是选中后浮出的工具条。** 这和 PixelVault「名词做节点、动词做动作」的原则同向，但他们把动作**挂在节点上**而非放进节点族。

**② 节点下方挂提示词面板**

- 标签行：`+参考` · `标记` · `风格` · `聚焦`（给提示词加修饰层的入口）
- 参考图缩略图
- 提示词正文（可滚动）+ 右上角展开按钮 ⤢

**③ 两侧连接点 ⊕**，且该节点的出边高亮成蓝色。

**④ 右侧对话输入框自动插入该节点的引用胶囊**（`🖼 ChatGPT娘 精…`）。

⭐ **④ 是最值得注意的一条：选中节点即自动进入对话上下文，不需要手动 `@`。** `@` 是补充手段，不是唯一入口。

## 四、提示词编辑器（展开态）

⭐⭐ **提示词是富文本，引用胶囊内嵌在句子中间**：

> `Chibi character design sheet three views (front, side, back), same refined chibi art style as` **`🖼 图片 1`** `— detailed shading, soft gradients, elegant lolita-style outfit, 2-3 head ratio. ChatGPT OpenAI model personification. Color scheme: black and white with teal-green accents. …`

即「像 @某张图 那样的风格」直接写在提示词里，而不是把参考图挂在提示词外面当附件。这是 owner 「提示词自动填入」+「@ 引用素材」两个诉求的合并形态。

底部控制条（左→右）：

| 控件                 | 观察                                                  |
| -------------------- | ----------------------------------------------------- |
| `General image V2 ▾` | 模型选择**在提示词面板内**，不是全局                  |
| `16:9 · 2K · 1张 ▾`  | ⭐ 比例/分辨率/**数量**压成**一个**下拉，不是三个控件 |
| `👥+`（带蓝点）      | 疑似角色/参考挂载，未展开                             |
| `🌐`                 | 翻译（中↔英提示词）                                   |
| `⚡ 12`              | ⭐ **生成前就显示积分消耗**                           |
| `⬆`                  | 生成                                                  |

「1张」正对应 backlog D0「一次生成多张图」——他们把**数量做成了和比例、分辨率同级的常规参数**，不是特殊功能。

## 五、对话 → 生成协议

见 `week-2026-08-07-backlog.md` §B 的七段协议。核心三件：

1. **「已询问」折叠块** —— 结构化沉淀问答对，可回看。
2. **「图片待确认后生成」灰占位卡** —— 方案已定、图未生成、等点头。**未确认的东西不进画布。**
3. **每轮结尾的结构化确认选项** —— `✅ 满意 → 下一步` / `🔄 需要调整 → 告诉我方向`，确认信号对机器明确。

## 六、缩放行为

缩放菜单：`可编辑百分比输入` · 放大 ⌘+ · 缩小 ⌘- · 适合屏幕 ⌘0 · 缩放至 50% / 100% / **800%**。

**两套缩放策略分得很干净：**

| 随缩放变化                 | 反缩放（屏幕固定尺寸）                     |
| -------------------------- | ------------------------------------------ |
| 节点图片、连线粗细、网格点 | 动作条、提示词面板、节点标题、尺寸标注文字 |

50% 时节点图片小了一半，而动作条与标题字号纹丝不动 —— 相对节点显得更大。800% 时连线变成粗带、网格点间距拉开。

- 缩放锚点是**视口中心**，不是选中节点（800% 时直接飞到空白区）。
- ⭐ **迷路保护**：视口内没有任何节点时，底部弹出 `当前视窗没有节点` + **`返回节点`** 按钮 + 关闭 ×。

## 七、画布外壳

| 位置   | 控件                                                                                |
| ------ | ----------------------------------------------------------------------------------- |
| 顶部   | 项目名（可编辑）· **工作流** · **故事板** · 发布与分享 · 积分超市                   |
| 顶部左 | 项目名 + **「画布 1」下拉** —— 一个项目可有多个画布                                 |
| 画布   | 添加节点 · 移动 · 打开工具箱 · **素材库** · **角色库** · 历史记录 · 快捷键 · 教程   |
| 左下   | 资产管理 · **整理画布 `Alt+Shift+F`** · 小地图 · 隐藏节点连线 · 网格吸附 · 缩放选项 |
| 对话   | 输入框 + 添加附件 · **选择模型** · **Skill**                                        |
| 其它   | **退出跟随**（疑似视口跟随 AI 生成过程自动移动）                                    |

⚠ **更正一处早前判断**：`@` **没有**取代模型选择器 —— 输入框旁有独立的「选择模型」按钮，`@` 能引模型只是额外快捷方式。

⭐ **「角色库」独立于「素材库」**，是并列的一级入口（对应 PixelVault 的 cast / 角色卡）。

⭐ 对话面板是**覆盖式**：收起后画布节点坐标完全不变，不挤压主工作区（对应我们「桌面主工作区不被挤压」那条验收线）。

## 九、生成全流程实测（owner 授权，实扣 12 积分）

输入：选中「ChatGPT娘 精致chibi三视图」节点后，在对话框发中文口语 —— `[🖼ChatGPT娘 精…] 基于这个角色，只生成 1 张：把配色换成蓝白色系。不要生成多张。`

观察到的完整时序：

| 阶段 | 画布上发生什么                                                                                 | 积分        |
| ---- | ---------------------------------------------------------------------------------------------- | ----------- |
| ①    | AI 回「好的，只改配色，其他完全保持不变！」                                                    | 185 不变    |
| ②    | ⭐ **立即建空节点**：标题 `ChatGPT娘 蓝白配色版`，深灰占位，**连线已从源节点接好并高亮成蓝色** | 185 不变    |
| ③    | ⭐ **视口自动缩放到 100% 并平移到新节点**（「跟随」）                                          | 185 不变    |
| ④    | ⭐ **提示词已填好**、参考图已挂载（缩略图带 ① 角标，对应正文里的「图片 1」）                   | 185 不变    |
| ⑤    | 对话里挂「图片待确认后生成」占位卡 + 结构化确认选项                                            | 185 不变    |
| ⑥    | 点生成 → 节点中央出现胶囊 **「生成中 6%… 取消」**（进度 + 取消同一胶囊内联）                   | **185→173** |
| ⑦    | 完成 → 图片填入；**右上角出现尺寸标注 `2752 × 1536`**；**顶部动作条浮出**                      | 173         |

### ⚠ 关键更正

早前根据「图片待确认后生成」占位卡，我判断「未确认的东西根本不进画布」—— **错的**。节点结构（节点 + 连线 + 标题 + 提示词 + 参考图）**全部在确认前就落了画布**，且免费。**真正的闸只设在花钱的那一步。**

### 提示词自动填入的质量

用户输入（中文口语）：

> 把配色换成蓝白色系

AI 产出（自动填进节点）：

> Chibi character design sheet three views (front, side, back), based on **🖼图片 1**, keep everything exactly the same — same hairstyle, same maid outfit design, same chibi proportions, same pose, same art style. Only change the color scheme: replace all black parts with deep navy blue, replace teal-green accents and hair highlights with sky blue or light blue, replace green eyes with blue eyes, replace green ribbons with blue ribbons, **white apron stays white**. Overall blue and white color scheme. Clean white background, highly detailed chibi anime illustration.

⭐ **用户一个字没提的一致性约束，AI 全补上了**：同发型、同服装款式、同比例、同姿势、同画风、白围裙保持白。这不是翻译，是**领域知识补全**。实际出图也确实只变了颜色。

⭐ 它还**遵守了「只生成 1 张」** —— 底部参数条自动设成 `1张`。

### 另外两条

- **空节点没有动作条**，生成完成后动作条才浮出 —— 动作条的存在本身就是「已产出」的信号。
- 生成中态是**节点内联小胶囊**（`生成中 6%… 取消`），不额外占空间、不遮挡节点结构。

## 十、三个一级功能实拍

### 10.1 角色库 —— 官方预置的**剧本角色原型库**

⭐ 关键认知：**不是「我的角色」，是平台预置的角色原型柜。**

- 角色按**戏剧功能**命名：`甜妹/清新少女` · `霸总/精英大佬` · `温柔熟男/理想男友` · `清冷千金/白切黑女主` · `古风男主` · `古风女主` · `恶毒女配/白莲花` · `正派长辈/父` · `正派长辈/母` · `反派长辈/势利亲戚` · `生活方式普通人` · `时尚感亚洲男生`…（横向列表带翻页）
- 标签体系：`女主 女 现代 青年 温柔`（定位 + 性别 + 时代 + 年龄 + 气质）
- ⭐ 每个角色配**四件套**，不是一张参考图：
  1. 全身图（站姿白底）
  2. 面部特写
  3. **表情九宫格**（3×3 九种表情）
  4. 人物呈现板（多角度 + 多姿势组合）
- 一个「**+ 应用至画布**」直接落地
- 顶部有「角色筛选 ▾」+「最近使用」勾选

对照 PixelVault：我们的 cast 班底要用户从零自建；他们给一柜子现成原型，起手门槛低一大截。「表情九宫格」与节点动作条里的「九宫格」是同一套标准资产形态。

### 10.2 故事板 —— 画布的**第二视图**

顶部两个图标其实是**视图切换**：

| 视图       | 形态                              |
| ---------- | --------------------------------- |
| **工作流** | 节点画布（空间视图：节点 + 连线） |
| **故事板** | 清单视图（按类型分组）            |

故事板内部两栏：

- 左栏「**关键元素**」：网格排布，**按角色聚合**（同一角色的多个版本归在一起），空节点在此也显示为占位。
- 右栏「**图片**」：纵向列表，每项带**文件名 + 尺寸标注**（`1068 × 1037`），是原始图片资产。

⭐ 同一份数据两个视图 —— PixelVault 目前只有空间视图。

### 10.3 导演台（`NEW`）—— **3D 当控制器，不当产品**

节点空态设计：层叠图标 + 一句用途说明「**在3D空间中搭建场景并进行多视角截图**」+ 一个 CTA「打开导演台」。（这是「空节点」的标准设计模板：图标 + 一句话 + 单一 CTA。）

打开后是完整的 3D 场景 blocking 工具：

- 顶部：**「导演视角」↔「机位视角」**切换
- 左栏「场景」：对象树 —— `📹 机位1` · `👤 角色A`，带搜索
- 中央：网格地面 + **蓝色人体模型**（带位移 gizmo）+ **相机视锥线框** + 右上 ViewCube「重置视角」
- 右栏「角色」：Tab **属性 / 姿势**；属性含 名称 · 位置 XYZ · 旋转 XYZ · 缩放 XYZ · 统一缩放滑条 · 颜色（色块 + hex）
- 底部工具栏：选择 · 人物 · 摆姿 · 摄像机 · 平面 · **截图** · 图片 · 全屏 · 标注 · 重置

⭐⭐ **它解决的是 AI 生成里最难稳的一件事：镜头语言与空间关系。** 「低角度仰拍、人物在画面右三分之一」用自然语言说十遍都不稳，在 3D 里摆一次机位就精确了，截图当参考图喂给生成。

对照 PixelVault：`project-product-mainline-2026-07` 记着「3D 搁置」。但这里 3D 的定位完全不同 —— **不是产出物，是取景控制器**。这个用法值得重新评估 3D 的优先级。

### 10.4 其它

- 画布顶部有**网络状态指示器**（tooltip「网络不稳定」），因为画布是自动保存的。
- 新建节点后，**右侧对话输入框自动插入该节点的引用胶囊** —— 与「选中节点」行为一致。

⚠ **本次调研在 owner 项目里留下一个空的「导演台 2」节点**（删除操作被安全策略拦截，未能自行清理）。需要 owner 手动删除。未使用 Ctrl+Z，因为撤销栈上一步是花了 12 积分的生成结果。
