## 1 · 地基：视频模型接口有三种形态（实读代码 2026-07-26）

设计一切从这里长出来 —— 组装台的形态由模型决定，不是固定三轨。

| 形态             | 模型                                                                  | 入参形状                                                                                                               | 音频                     | 时长                                  | 分辨率                         | 画幅           | seed        |
| ---------------- | --------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- | ------------------------ | ------------------------------------- | ------------------------------ | -------------- | ----------- |
| **A 多参考聚合** | `SEEDANCE_20_REFERENCE` / `_FAST_REFERENCE`（fal + 火山四个 id）      | `image_urls` ≤9（**至少 1，必填**）+ `video_urls` ≤3（合计 2–15s，≤50MB）+ `audio_urls` ≤3（合计 ≤15s，≤15MB/条）      | reference（音色克隆）    | 4–15 或 `'auto'`                      | 480/720/1080p（fast 无 1080p） | 5 种           | ✅          |
| **B 单张首帧**   | `SEEDANCE_20` / `_FAST` · `KLING_V3_PRO` · `HAPPYHORSE_10` · `LTX_23` | 一张 `image_url` / `start_image_url`                                                                                   | auto（`generate_audio`） | 各自枚举（Kling/HH 3–15，LTX 6/8/10） | 各自枚举                       | 3–5 种         | 仅 Seedance |
| **C 内容数组**   | `GEMINI_OMNI_FLASH`                                                   | `input: [{type:'text'}, {image}…]` 走 **Interactions API**，无三轨概念；`video_config.task` 按有无参考图自动切 t2v/i2v | auto                     | **无参数** —— 模型自定 3–10s          | 只 720p                        | 只 16:9 / 9:16 | ❌          |

### 1.1 四条今天 UI 没表达、必须进设计的硬事实

1. **跨模态总闸 ≤12 个文件**（形态 A）。代码是 `maxImages = 12 - videos - audios`（`video-request-builders.ts:462`），**图片被静默砍**。3 段参考视频 + 3 条音频时，图上限从 9 掉到 6，用户完全看不见。→ 容量表达必须是「有效上限」，不是印死的 9。
2. **换模型改变卡的形态**，不只是改数字。A→B 三轨塌成一轨首帧；A→C 连时长与分辨率控件都要整条消失。
3. **形态 C 的时长控件必须能整条消失。** `supportedDurations: [8]` 是为 UI 诚实钉的名义值，不是承诺。留一个只有一格的滑杆等于假控件。
4. **形态 C 的结果卡不显示像素尺寸。** 竖屏时轮询回报仍是 `1280x720`（适配器注释自认拿不到真实尺寸）。只显示画幅。

⚠ `GEMINI_OMNI_FLASH` 已 `available: true`，画布视频节点吃 `getAvailableVideoModels()` —— **今天就能选中**。所以「模型为轴」不是未来功能，是正在漏的洞。

### 1.2 音频侧真相

- 视频只吃 `audio_urls` 作**音色参考**（且只有形态 A），**不吃成品音轨**；`videoMerge` 全程无 audio 概念（`node-video-merge-compose.ts` 全文无 audio）。
- 所以「台词」在画布里的真身 = **参考音色 + prompt 里的台词文本**，Seedance 自己 lipsync。独立配音轨这条路今天不存在，不许画。
- 可用音频模型只有 `FISH_AUDIO_S2_PRO`（speech）与 `ELEVENLABS_SFX_V2`（sfx）。`AUDIO_KIND.MUSIC` 枚举存在但**零模型接入**。

### 1.3 已有但未用的接口（扩充机会）

`KLING_V3_PRO` 与 `VEO_31` 的模型配置里已带 `extendEndpointId` + `extensionMethod: 'native_extend'`。**这是破 15s 上限的现成接口**，画布没用。

## 2 · 切分原则

> **名词做节点（画布上的对象），动词做节点上的动作或画布级动作。**

理由：一个动词造一个节点 = ComfyUI = 节点爆炸 + 连线地狱。画布的核心用户是做片子的创作者，不是搭管线的工程师（域定义 §1.1）。owner 清单里的「粘贴 / 编辑 / 提示词编辑 / 拆分 / 工作流」全是动词，一律不造节点。

判据：**这个东西会不会被别的东西引用？** 会 → 节点；不会 → 动作。

## 3 · 六族节点

共享外壳：头（族标记 + 名字）· 媒体窗 · 状态（形+词双编码）· 端口（图/音/视/身份，色 + 形双编码）· **唯一主动作** · 选中态 · 近场工具条挂点。四态最小集：空 / 有内容 / 生成中 / 失败。

## 7 · 建设顺序（推荐）

1. **外壳语言**：6 族共享节点壳 + 端口 + 四态。不先定壳，每加一个能力都要重画一次 —— 这正是前三轮反复偏的根因。
2. **组装台按模型为轴重做**，含有效上限（≤12 总闸）的诚实表达。最高频任务 + 今天正在漏的洞。
3. **三个缺口**：画布级粘贴 · 声音卡台词/音效两 kind · 视频抽帧与截段。
4. **助手链打通**：两道门 + 投影补静帧与音频 + 批量真实队列。
5. **续接**（native_extend）与**音乐模型接入**各走独立任务，不塞进这轮 UI。

## 8 · 布局 / 色 / 字（交 CD 的设计地基，本文定，CD 只做精致化）

**布局** —— owner 2026-07-26 拍板：**方案 B（按职责分栏）+ 班底架常驻第二主角**。以下为落定形态：

| 区                                  | 内容                                                                                            | 说明                                             |
| ----------------------------------- | ----------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| **顶栏** `48px`                     | 返回 + 项目名（`15px/600`）+ 项目切换 · **视图切换（画布 / 序列）** · credits / 搜索 / 助手开关 | 视图切换与项目同级，是"换工作模式"不是"工具"     |
| **左侧合体面板** `56 + 240 = 296px` | **一个浮起容器**：最左 `56px` 图标轨 + 右侧 `240px` 内容区                                      | 见下方「为什么合体」                             |
| **中间**                            | 自由无限画布，`48px` 点阵                                                                       |                                                  |
| **底部中间** 浮起胶囊 `≈459×52`     | 选择·手 / 缩放 `− 70% +` / 适应画布 / 撤销·重做                                                 | 横向控件拿到横向空间；Figma·Miro·tldraw 一致惯例 |
| **右侧**                            | 助手 dock，可收起，**默认收起**                                                                 | 左侧已常驻 296px，两侧不同时满开                 |

**为什么 rail 与班底架合体**：两者功能本是一体（图标轨的每一项就是内容区要显示的分类），合成一个容器共用一条投影，既减少浮起物，又让"点图标换内容"在视觉上自明。这是 VS Code 的 activity bar + side bar 结构，认知成本为零。两个独立浮起物并排会显得零碎，也讲不清从属关系。

图标轨自上而下：**＋添加**（唯一的墨色实底主按钮，与下方用分隔线隔开）→ 班底（角色 / 场景 / 音色）→ 素材 → 模板 → 历史。

**班底放左的理由**：素材在左、消费在右，与画布节点左→右锚定、与 composer 的 `@` 引用方向一致 —— 读起来是一条产线，不是四块面板。

**宽度策略（必须实现，否则画布会被挤爆）**：左 296 + 右 dock 约 420 = 716px 被 chrome 吃掉。

| 断点          | 行为                                                                |
| ------------- | ------------------------------------------------------------------- |
| ≥ `1600px`    | 左面板常驻展开 + 右 dock 可同时开                                   |
| `1024–1600px` | 左面板常驻，**但打开助手时内容区自动收起，只留 56px 图标轨**        |
| `768–1024px`  | 左面板默认收成图标轨；底部胶囊保留                                  |
| `< 768px`     | 不渲染完整画布，走**单卡模式**（现状 `md:` 以下已不渲染底部工具条） |

**颜色**：沿用 [`canvas-skin-spec-2026-07-26.md`](canvas-skin-spec-2026-07-26.md) v0 数值（浅底 `#F6F7F9` + 白卡 + 单强调 `#2B5CE6`，深色版同名 token 覆盖）。族色低饱和 + **形状同时编码**（图=方 / 音=圆 / 视=空心方 / 身份=圆环），因为状态不许只靠颜色。

**字体**：界面走脊柱 Geist Sans，**不新增 webfont**；容量计数、时长、时间码用系统等宽栈并全局 `tabular-nums`（9/9 → 8/9 时数字不能跳）。三级字号封顶：13 正文 / 14 卡名 600 / 11 meta。
**明确不继承** 2026-07-10 那轮的手写字体线（鸿雷行书 / Zen Kurenaido / Caveat）—— 画布是工具面，气质来自卡与投影，不来自字。
