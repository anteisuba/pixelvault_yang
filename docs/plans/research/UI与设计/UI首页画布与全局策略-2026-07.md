## 1. 你其实已经有两套「对的锚」

### Homepage（满意）— 学方法，不抄整页

Homepage 通常强在：

- **排版是强调手段**（字号/字重/字距），不是装饰堆叠
- **内容/作品优先**，chrome 弱
- **黑白灰 + 细线**，少玻璃/渐变/card 套 card
- 区块节奏清楚

这些是 **品牌方法**，可以进「全局壳 + 品质底线」。  
**不要**把首页大标题字号、营销留白直接贴到画布节点密度上——会空、会废。

### 画布（方向对）— 学结构，修执行

方向对通常意味着：节点/编排器/主次分区已经像「工作台」。  
「Codex 不对」通常是：

- 密度乱（该紧的松、该松的挤）
- 表面层级糊（全黑一块，无底/板/浮层）
- 控件皮肤像 shadcn 默认深色模板
- 状态色/边框/字重无系统
- 一次改太多，结构被顺手重写

## 2. 画布 UI 怎么优化（实操）

### 2.1 不要做的事

- 「把画布 UI 重构得更现代」整包交给 Codex
- 直接套 Homepage 的大留白/大标题
- 未确认就改交互契约（节点数据、生成、边）
- 用纯黑 `#000` + 低对比灰字硬撑「高级」

### 2.2 建议流程（每次一周可验的小环）

```text
1) 冻结：只优化「观感与密度」，不改业务 API
2) 真机截 5 态：空画布 / 有图节点 / 视频+右侧编排 / 选中多节点 / 375px
3) 对照 Homepage 方法打分（下表），只列 Top 5 问题
4) 一次只修 1 类：表面层级 | 字号阶梯 | 间距 | 边框| 控件
5) 截图前后对比 + owner 过目 → 再下一类
6) 写入 pages/canvas 或 skin-spec 片段，禁止无文档散改
```

### 2.3 画布专用检查表（对照 Homepage 方法）

| 维度   | Homepage 参考  | 画布应表现                                          | 常见 Codex 翻车     |
| ------ | -------------- | --------------------------------------------------- | ------------------- |
| 主对象 | 作品最大       | **节点媒体/画布**最大，侧栏次之                     | chrome 与节点抢对比 |
| 表面   | 纸/线分层      | **canvas 底 < 卡面 < 浮层/编排器 < 弹层** 至少 3 级 | 一片黑              |
| 字     | 标题狠、正文稳 | 节点名/参数 **12–14 系统**，禁止乱 10/16 混         | 字重全 600          |
| 线     | 1px 发丝       | 卡边、选中环 **一种**强调                           | 双描边+发光         |
| 密度   | 营销可疏       | 工作台 **紧但不糊**；8px 网格                       | gap 随缘            |
| 强调   | 少而准         | 选中/运行/错误 各一语义                             | 四色霓虹            |
| 组件   | 克制           | 复用 shadcn **行为**，皮用 canvas token             | 新造圆角按钮语言    |

### 2.3 切片顺序（推荐）

1. **Token 只做画布域**：`--canvas-bg / panel / border / muted / accent`（可浅可深，但要级差）
2. **Node 卡**：媒体窗比例、标题行、状态点 — 不动生成逻辑
3. **右侧编排器 / 检视**：与卡同一表面语言
4. **顶栏/底栏/加号菜单**：减弱「另一套产品」感
5. **空态/生成中/失败**：同一反馈语义
6. **375**：限编策略已有调研则只对齐已确认行为

每切片：**截图 + 禁改业务文件列表** 交给实现 agent。

### 2.4 给 Codex/Claude 的硬约束模板

```text
只改 canvas 域视觉 token 与指定组件 class。
对齐：首页的克制层级方法（细线、排版主导），不要复制首页布局。
禁止：紫渐变、玻璃、重阴影、任意 #hex 新色、重写节点数据结构。
本切片只改：【例如 NodeShell 表面与边框】。
改完对照这 3 张截图说明差异。
```

## 3. 全局 UI 怎么在两锚上改（战略）

### 3.1 全局该统一什么 / 不该统一什么

按 `brand-dna`：

**统一（壳 + 行为）：**

- 侧栏/导航位置与行为
- 默认 **应用背景 / 面板 / 边框 / 正文 / 静音字**（semantic）
- 焦点、错误、成功语义
- 字体栈策略（可与 homepage 标题策略协调）
- 圆角/间距 **primitive 阶梯**（可被域覆盖）

**不统一（域皮肤）：**

- Homepage 营销节奏 vs 画布密度
- LoRA 装配台 vs Gallery 瀑布
- 强制全站同一 card/pill

### 3.2 推荐顺序（降低翻车）

```text
Phase 0  文档：从 Homepage + 画布各抽「10 条方法」→ 壳层 brief（不是整站 Figma）
Phase 1  只改 layout 壳：AppSidebar / MobileTabBar / 默认 bg-background
         Studio/画布先「吃壳的 semantic」，局部仍可用 domain 覆盖
Phase 2  Studio shared chrome 对齐壳（dock/lightbox）
Phase 3  画布细节切片（§2）在新壳下继续磨
Phase 4  LoRA / Gallery / Assets 逐域「吃壳 + 保留域结构」
Phase 5  删除无文档的纯黑特例与 magic color
```

**禁止：** 一天内 globals 换肤 + 全站搜 class 替换。  
**禁止：** 用 Homepage 的白纸直接盖画布无限空间（需独立 canvas 底色决策）。

### 3.3 关于「现在全局是黑底」

可选战略（需 owner 选一，再实现）：

| 方案                | 壳层                     | 工作台                 | 适合                                   |
| ------------------- | ------------------------ | ---------------------- | -------------------------------------- |
| **A. 浅壳深台**     | 近白/浅灰导航与内容默认  | 画布/Studio 略深工作面 | 接近 Homepage 纸感，专业工具仍「沉浸」 |
| **B. 统一中性深壳** | 炭灰非纯黑，有级差       | 同系更深/更浅面板      | 少割裂，要认真做表面梯度               |
| **C. 跟随系统**     | light/dark 两套 semantic | 域可覆盖               | 工程量大，后置                         |

建议：**先 A 或 B 定壳**，与 Homepage 同属「中性、细线、排版」家族，而不是第三套 AI 纯黑。

Homepage 可继续最浅/最营销；**登录后壳**与 **Homepage 不必像素同色**，但 **对比度阶梯与字体方法一致** 就会像同一产品。

## 4. 为什么 Codex 画布 UI「感觉不对」

| 原因                           | 对策                                          |
| ------------------------------ | --------------------------------------------- |
| 训练默认 = 深色 dashboard 模板 | 给 **反 slop 禁区** + Homepage 截图作方法参考 |
| 无表面 token 则乱发明灰        | 先锁 4–5 个 canvas semantic                   |
| 一次改整页                     | 切片 + 禁改路径                               |
| 不懂创作台密度                 | 检查表写清「媒体最大、chrome 弱」             |
| 与壳两套黑                     | 先壳后域，避免双黑打架                        |

**实现分工建议：** 画布视觉切片可用 Claude/Codex，但 **只准对照 brief**；方向仍由你截图否决。

## 5. 最小「双锚 → 全局」方法卡（可贴进每次任务）

从 Homepage 固定提取（示例，可改）：

1. 主内容对比度高于 chrome
2. 发丝分隔优于重阴影
3. 中性色，强调色极少
4. 标题/正文/meta 三级字阶
5. 圆角一种语言、不过度

从画布固定保留：

1. 画布为舞台，节点媒体优先
2. 选中/运行/错误状态可扫读
3. 编排器与卡同族表面
4. 密度高于 Homepage
5. 不引入营销大标题区

壳层只吸收：**1–3 + 字体与间距 primitive**；密度与布局留给域。

## 6. 建议你拍板的 3 个问题

1. 登录后壳层：**浅壳深台（A）** 还是 **统一中性深壳（B）**？
2. 画布底色：与壳同系更深，还是保持独立「无限布」灰？
3. 下一迭代只做：**壳 Phase1** 还是 **画布表面 token 切片**？（建议二选一，先壳则全局立刻改观，先画布则创作核变顺）
