## 0. 设计判断的出发点（为什么是这三个）

**内容画像**（真机实测 135 条 + owner 账号截图 496 条）：

- 比例谱极端：**0.56（立绘竖条）→ 2.77（三视图横带）**，`aspect-square` 裁切对这类内容是毁容级的。
- 图片绝对主导（~90%），视频/音频/3D 是少数派——但**视频当前零缩略图**（thumb/preview 都空），音频已可把封面放 `previewUrl`。
- 文件夹 = 角色/IP 目录（ba/キサキ、鸣潮/dainia、Mygo、米塔…），两层嵌套是常态，25+ 个夹。
- **未分类占 31%**（156/496）——「收进来」远快于「整理掉」。

**核心矛盾**：这个页面同时是三种东西——

| 身份       | 证据                             | 现状哪里不行                            |
| ---------- | -------------------------------- | --------------------------------------- |
| **收件箱** | 生成回流 + 未分类 31%            | 没有「新回流」概念，新东西静默混进网格  |
| **档案馆** | 角色/IP 夹 + 跨项目复用          | 树挤在右栏小字里，夹没有脸              |
| **检视台** | 找到后要看清（比例/画质/prompt） | 方形裁切 + 384px 派生图 + 详情 Sheet 窄 |

现状把三个身份压进一个均质界面，三个都不到位。**三方向的分野 = 谁当第一结构**。差异在空间拓扑、页面结构、详情模式，不在配色。

## 1. 共识层（三方向共享，不构成方向差异）

1. **不加第二个永久左栏**（owner 需求 5）。全局导航是唯一左栏。
2. **justified rows 真实比例网格**（需求 3）：行内等高、行高由密度档控制、真实宽高比参与排版。算法契约见 §5。
3. **声音封面卡**（需求 4）：1:1 封面参与排行，回退链 = 用户设置 → 生成请求/声音角色封面 → provider 封面 → 系统默认；卡面 = 封面 + 播放键 + 时长 + 类型徽标，不伪装波形数据。
4. **视频卡**：poster 帧 + 时长角标 + hover 静音预览（⚠ 工程依赖：视频缩略图管线目前不存在，需在施工阶段补 poster 派生；原型用 `<video preload="metadata">` 模拟）。
5. **3D 卡**：poster 参与排行 + 立方体角标。
6. **回流**（需求 1）：三方向都有「N 个新资源」反馈，形态不同（见各方向）。
7. **选择态**：瓦片 checkbox + 底部动作条（现有 7 动作语义保留）。
8. picker 三契约、密度持久化、上传即资产入口等「不能破坏」清单照旧。

## 2. 方向 A「灯箱馆 Light Table」——检视第一

> 隐喻：画廊黑墙上的发光灯箱。chrome 消失，作品自发光。

**空间结构**：零常驻面板。顶部一条 56px 薄杆（题名+总数 · scope 胶囊 · 搜索 · 类型滤片 · 上传/选择/密度），其下整个视口都是 justified 大河，按时间轻分段（细字日期锚，新回流落在「今天」段头，带淡入徽标）。

**信息主次**：作品 ≈ 全部。文案与控件只有一层，元数据默认零露出，hover 才浮底部渐隐条（模型 · 尺寸）。

**文件夹位置**：顶部 **scope 胶囊**「全部素材 ⌄」——点开是可搜索的树形下拉（智能视图 + 夹树 + 计数），选中即切换范围，胶囊显示当前位置（`鸣潮 / dainia`）。重度整理走「移动到…」overlay（可搜索树，回车确认）；拖拽瓦片到 scope 胶囊可展开投放树（增强路径，非唯一路径）。

**详情关系**：点击 = **全屏灯箱**。黑场 94%，原图 `object-contain`（终于用上一直躺在 R2 的原图），`←→` 连续翻阅，底部 filmstrip，`i` 展开右侧元数据栏（prompt 全文/参数/动作）。esc 点场关闭，焦点回瓦片。

**真实比例网格**：行高档 S200 / M260 / L340；同 §5 算法。

**优点**：看图爽感天花板；作品即海报，最符合「成熟专业、作品主角」；灯箱终结「详情页永远 384px」的历史；移动端天然适配（灯箱即全屏）。
**风险**：整理效率是三案最低（树藏在下拉里，两跳）；25+ 夹的可见性最低；重度归档周依赖「移动 overlay」的键盘效率。
**适合**：如果 owner 把 Assets 首先当「翻看自己作品的地方」。

## 3. 方向 B「大厅与展馆 Atrium」——收整第一

> 隐喻：美术馆日光大厅。新到的作品在卸货区，馆藏各有门牌。

**空间结构**：单页三段纵向叙事——

1. **回流带**（有 7 天内新完成时出现）：横滚一行大瓦片，段标「新回流 · 12 · 全部归档」，每瓦角标来源（Studio/画布/LoRA/上传），hover 出「移动到夹」快捷菜单——收件流的核心动作在瓦片上就地完成。
2. **馆藏门牌**：每夹一张门牌卡（最近 4 张真实比例迷你拼贴 + 夹名 + 计数 + 子夹 chips）。「未分类 156」永远是第一张卡（琥珀待办徽标）。横滚一行，超出「查看全部」。
3. **全部素材**：justified 大河（同 A 的网格语言），无限滚。

**信息主次**：分类结构本身是内容。文件夹第一次有了「脸」（拼贴门牌），不再是右栏里的一行小字。

**文件夹位置**：**页面本身**。点门牌 → 夹内页（面包屑 `素材 / 鸣潮 / dainia`，子夹小门牌置顶 + justified 全网格，URL 可回退）。无任何树面板。

**详情关系**：保持现有 AssetDetailSheet（本轮非目标），原型示意右滑。

**真实比例网格**：回流带 = 等高 180 横滚；门牌拼贴 = 迷你 justified；全部流 = 同 §5。

**优点**：owner 需求 1+2（回流+分类）的最直接表达——回流有专席、未分类是可视化待办、夹有脸；移动端叙事天然（段落纵滚）；无 overlay/面板职责纠缠。
**风险**：「全部素材平铺」被推到第三屏；夹很多时门牌行需要排序/折叠治理；进夹是二级导航（多一跳）；连续跨夹拖放整理弱（依赖回流带快捷菜单与批量移动）。
**适合**：如果 owner 把 Assets 首先当「资产的家，回流与归档的枢纽」。

### 3b. B 的文件夹体系（2026-08-11 owner 选 B 后追问的两题，已做进原型）

**题一 · 大分类 → 小分类的路径**，三条并存、各管一种场景：

| 路径                                                                                                      | 场景                 | 成本      |
| --------------------------------------------------------------------------------------------------------- | -------------------- | --------- |
| **门牌 chips 直达**：父夹门牌上直接列子夹 chip（`鸣潮` 卡上点 `弗洛洛 28`），一步进子夹；超 2 个折叠 `+N` | 常用子夹，肌肉记忆   | 1 击      |
| **夹内页子夹区**：进父夹后子夹小门牌置顶，逐层下钻，面包屑 `素材 › 鸣潮 › 弗洛洛` 可逐级回退              | 浏览式找、不记得名字 | 2 击      |
| **搜索直达**：顶部主搜索输入即出「文件夹」结果组（**跨层级扁平搜**，子夹带父路径 `鸣潮 /`），点行直达     | 夹很多、记得名字     | 输 1–2 字 |

**题二 · 夹多了怎么管理**，四层治理：

1. **馆藏行只放头部**：首页横滚只显示常用/置顶的前 6–8 张门牌 + `+N 查看全部` 门牌——夹从 16 涨到 100，首页不变长。
2. **馆藏总览页**（`素材 › 馆藏`）：全部夹的门牌网格 = 夹的专属管理页。搜索（跨层级）、排序（最近使用/名称/数量，复用 `AssetFolderTree` 已有的 `sortFolderNodes` 逻辑）、新建/重命名/删除、**拖素材到门牌归档、拖门牌进门牌变子夹**。100 夹 ≈ 两三屏门牌，比 100 行树好扫（有拼贴脸）。
3. **常用置顶**（pin）：钉住的夹永远在馆藏行最前（工程：`Project.pinnedAt`，中期项，与旧 memory 文件夹治理路线一致）。
4. **搜索兜底**：任何深度的夹，输名字 1–2 字直达（上表第三条）——**夹数量增长时唯一 O(1) 的路径**，所以搜索必须是一等公民。

远期（不在本轮）：Saved Search 智能夹 / 标签系统——门牌墙结构天然能容纳「智能夹门牌」（虚线边框区分），不用改骨架。

已在原型验证：chips 直达（`弗洛洛`）、三级面包屑回退、总览页 16 夹 + 搜「弥」跨层命中子夹 `爱弥丝`、主搜索「妮」出 `达妮娅 · 鸣潮 /` 结果行。

### 3d. 「还不够紧凑 / 右侧大片空白」的三个真实成因（2026-08-11 第二轮，已修）

owner 指的空白不是间距问题，是**布局没铺满容器**。实测三处，逐条修掉后行宽 1812–1816 / 容器 1817（≥99.7% 铺满，零横向溢出）：

| #   | 成因                                                                             | 修法                                                                                                                                  |
| --- | -------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | 我给 `main` 加了 `max-width:1600px` —— 1920 屏上右侧整块空 300px                 | **去掉宽度上限**，内容跟随视口（现状页也是满宽）                                                                                      |
| 2   | 超宽图（三视图 ar 2.77）**独占整行**，但高度受目标行高限制 → 行右侧留 500px 大洞 | **取消独占规则**，超宽图与常规图同排参与 justified；ar 不裁不 clamp（安全阀放宽到 [0.4, 3.2]，真实数据 0.56–2.77 全部原样）           |
| 3   | 末行不铺满 + 宽度按 `main.clientWidth-56` 手算（padding 实为 88，算错 32px）     | 末行**默认铺满**，仅当铺满会超过目标行高 1.5 倍时才回落；宽度改用容器自身 `clientWidth`；`scrollbar-gutter:stable` 防滚动条出现后回流 |

另外两项：

- **文件夹行按容器宽度自适应张数**（`fit = ⌊(W+gap)/(卡宽+gap)⌋`，末尾预留「查看全部」与「新建」两张），卡片 `flex-grow` 吃掉余量——16 夹时首页显示 8 张 + `+8 查看全部`；窗口变窄自动减少，永远铺满一行不留尾巴。
- **密度控制补回顶栏**（现状有 4/6/8，我漏了）。在真实比例网格里它控制**目标行高** S150 / M196 / L260，不再是固定列数。实测 S 档每行 13/9/11/6 张，行宽照样铺满。

## 4. 方向 C「装配抽屉 Bench」——操作第一（owner 已选结构 A 的我流实现）

> 隐喻：器材室的精密工作台。看得清、够得着、拖得动。

**空间结构**：中央 justified 大河 + 右侧 320px **双窗格抽屉**（可折叠、可 pin）。与「目录/详情二选一 tab」不同：

- **上窗格 · 目录**：搜索 + 智能视图 + 夹树（拖放目标，drag-over 高亮+自动展开）+ 新建。
- **下窗格 · 检视**：单击瓦片即时更新——中图预览 + 模型/尺寸/日期 + prompt 两行 + 动作行（收藏/移动/下载/删除/完整详情）。无选中时显示当前范围统计；多选时变批量面板（已选 N + 批量动作）。
- 分割线可拖。**树与详情同屏并存**——拖放整理时目标树永远在，点选检视时不用切走目录。这是对「Dock 双 tab 会让拖放与详情互斥」的直接回答。

**信息主次**：网格与抽屉 7:3。中央看，右侧管。

**文件夹位置**：抽屉上窗格常驻树 + 顶栏 scope 面包屑（抽屉折叠时仍可切范围，同 A 的下拉）。

**详情关系**：**单击 = 抽屉轻检视，双击/回车 = 灯箱深检视**（Bridge/Eagle 的成熟双档模式）。灯箱同 A 语言。

**真实比例网格**：同 §5；抽屉展开时默认**浮层覆盖**（网格不重排），pin 后挤压网格并记忆（≥1600 默认 pin）。

**优点**：整理效率三案最强（常驻树+拖放+即时详情三者并存）；与 owner 已选的「右侧上下文 Dock」结构血缘最近、风险最低；专业工具用户（Eagle/Bridge）零学习成本。
**风险**：与 Codex V2 同一空间命题，owner 对比的将主要是视觉档次与窗格细节；抽屉 pin 时 1440 下网格约 1050px；上下窗格与完整详情 Sheet 的职责必须去重（抽屉=轻检视+高频动作，Sheet=全量元数据）。
**适合**：如果 owner 把 Assets 首先当「每周要花时间整理的工作台」。

## 5. 真实比例网格 · 算法契约（共识层附录）

- **justified rows**：贪心装行，行目标高 H（密度档），行内按 ar 分配宽度、等高；末行不放大。
- **ar clamp [0.5, 2.2]** 参与排版：0.56 立绘不裁；>2.2 的横带（三视图 2.77）**独占整行、完整显示**，不裁。clamp 只影响行内布局计算，裁切量最大 ~0.5%（对 0.5 以下不存在的比例），实际语义 = 不再无意裁切。
- 无尺寸的存量记录（实测 14/135）按 1:1 兜底参与排行。
- 音频恒 1:1 封面卡；视频/3D 按真实 poster 比例。
- 密度档控制**行高**，不再是固定列数；375px 下行高降档、每行 2–3 张。
- C4 尾项依赖：瓦片渲染高度上界 = L 档行高 340 × DPR2 = 680px 短边 → 存量 384px 回填的目标尺寸在选向后按此定，不再拍数。

## 8. 给 owner 的选择问题

三个原型都能继续深化到 1440 高保真三态（默认/组织展开/详情）+ 1280 + 375 + picker。**选一个方向，或说出组合原则**（例：B 的回流带 + C 的抽屉；A 的灯箱作为所有方向的深检视层——A 的灯箱与 C 的抽屉不互斥）。
