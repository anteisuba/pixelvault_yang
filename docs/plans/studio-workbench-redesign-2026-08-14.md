## 1. 这张图最重要的一条：生成参数是个矩阵，不是两个功能

图里写着 `每个模型 1 张`，选中四个模型，按钮是 `同时生成 4 张`。**模型是一个轴，张数是另一个轴，总数是乘出来的。**

这推翻了 backlog 里把 D0 拆成「一次多张」+「多模型各一张」两件事的写法。它们是同一个控件的两个轴，分开做会做出两套控件、两套结果视图。

**代码上的后果（⚠ 代码阅读所得，属候选，动手前真机验一次）**：

| 现状                                                                                     | 矩阵要求                                         |
| ---------------------------------------------------------------------------------------- | ------------------------------------------------ |
| `activeRun.mode: 'single' \| 'compare' \| 'variant'` 二选一（`use-unified-generate.ts`） | 表达不了「4 模型 × 2 张」                        |
| `generateVariants`（1 模型 × N seed）与 `generateCompare`（N 模型 × 1 张）两条独立路径   | 应收敛成一条：items = 模型集 × 张数              |
| `RunItem` 已经**同时**带 `modelId`、`seed`、`index`                                      | ⭐ 数据结构已经够用，**要拆的只是上面那个 mode** |
| 结果视图 `VariantGrid` / `CompareGrid` 各一套                                            | 一套栅格，格子上标模型名 + 序号即可              |

→ 判据：真机各跑一次 variant 与 compare，确认两套栅格的差异只在标签上；若差在交互（如 compare 不允许选 winner）则本条要改写。

## 2. 域定义（**待 owner 拍板，五条**）

### 2.1 工作台是一个域还是四个路由的壳

今天是 `/studio/image`、`/video`、`/audio`、`/3d` 四条独立路由，共用 `StudioProvider` 与一个模式选择器。图里只画了图片。

- **A（推荐）**：工作台 = 一个域，四模态是域内切换；这张图是图片模态的形态，视频/音频各自的参数不同但外壳同构。
- **B**：这张图只管图片，其它模态不动。→ 代价是同一个壳有两种长相。

### 2.2 顶导四域 vs 今天的左侧图标 rail

⚠ **这张图顺带提了一个导航重构**：顶部 `画布 / 工作台 / LoRA / 素材` 四个 tab，而线上是左侧一条图标 rail（十来个入口）。四个 tab 正好对上项目的四个域。

这已经越出 D1，撞上 backlog 的 **I（侧边栏 UI 升级）**，而 I 的硬前置是 **J1 补视觉基线**（侧边栏是全局共享件，没基线不敢动）。

→ **建议：本包只管工作台内部，顶导按现状画；四域顶导单独立项，排在 J1 之后。** 若 owner 要一起做，那 J1 必须提前。

### 2.3 出资方（平台 / BYOK）要不要变成显式状态

图里左下写着 `自带 API key` 与 `约 $0.15`。今天这个区分在代码里是隐式的（`isPlatformFunded`，只在服务端计费与并发闸里读），用户看不见。

这条不只是显示问题 —— 它**决定并发能开多大**：

- 平台出资：受 `PLATFORM_GENERATION_GUARD.MAX_ACTIVE_JOBS_PER_USER = 4` 管。四模型 × 一张正好顶满；× 两张必然有一半吃 429。
- BYOK：不受这个闸管，四路并发合法。

⭐ 也就是说 owner 图里那行 `自带 API key` 恰好解释了为什么敢标 `4 个模型并发` —— **这张图内部是自洽的**。但要把它变成产品，必须回答：平台出资时这个界面长什么样（灰掉超额的格子？降档？还是照发让它逐格失败）。

### 2.4 缺 key 的模型怎么显示

图里 `Seedream 5.0` 与 `Recraft V4.1` 是浅色描边，其余四个是深色实心。**从图上分不出这是「未选中」还是「缺 key 被禁用」。**

⚠ 如果是后者，撞 **Hard Rule 8**：缺 API key 不禁用 UI，要路由到 `QuickSetupDialog` 内联配置。这条必须在关键切片里写死，否则实现者只能猜。

### 2.5 成本预览的数据够不够

`约 $0.15` 需要每模型单价。`src/constants/models/unit-prices.ts` 确实存在，但：

- 目前 **12 条，以视频为主**；文件头明写「图片/音频那批还没核实」。
- 它自己的策略是 **宁可留空，不填没核实过的数字**（理由写在文件头：一个错的数比没有数更糟）。

→ 所以今天多数图片模型**报不出价**。两条路：①先只对有价的模型显示，缺的留空；②先补那张表（要附 `source` 与 `verifiedAt`）。⛔ 不许为了让它有数而填近似值 —— 那是 384 那个病。

## 4.7 拉框 vs 手绘 —— owner 拍板「都做」，但成本不对称

⭐ **手绘（画笔涂抹）已经实现了。** `components/business/studio/StudioInpaintEditor.tsx`：画笔 / 橡皮 / 笔刷大小 / 20 步撤销 / 长边压到 1024 再导出，产出 `maskDataUrl` + prompt；真消费者是 `CanvasImageEditWorkspace.tsx:704`，链路 `LooseImageCard` → `CanvasImageSelectionToolbar` → 它。
⚠ **但「链路存在」不等于「跑得通」** —— owner 未测过，真机可跑性属未验证。

**四种「在图上画」不是一件事**：

| 画什么              | 产出           | 状态                                        |
| ------------------- | -------------- | ------------------------------------------- |
| 画笔涂抹选区        | mask 位图      | ✅ 已实现（可跑性待验）                     |
| 拉框选区            | mask（矩形）   | ⬜ 没有                                     |
| 套索 / SAM 吸附对象 | mask（不规则） | ⬜ 前端没有；SAM 3 后端在 `extract-element` |
| 画箭头写字当指令    | 像素上的痕迹   | ⛔ 2026-07-11 否掉，理由未变                |

前三行输出同一种东西（mask）、走同一个后端 → **多做一种是 UI 工作量，不是架构工作量**，所以「都做」很便宜。

**为什么有了画笔还要拉框**（两者回答不同问题，不是重复）：

- 画笔 = 精确选区，适合「这一块不规则区域重画」。
- 拉框 = **带注释的定位**，适合「这个位置不好」。owner 原话就是定位语气。
- ⭐ 硬理由：owner 07-10 那个三视图样例（一张图标好几处、一次全改）**必须是框** —— 框才能编号 ①②③、才能列成注释清单、才能逐条改删。涂抹出的一团 mask 编不了号也列不了表。

**分工**：拉框（多框 + 编号 + 注释清单）→ 图上只画编号、文字进 prompt → `object-replace` 一次全改，痕迹不落像素，且天然就是编辑历史。画笔 → 单块 mask + 一句话 → `inpaint`，作为「这个框要精确一点」的降级入口，两者同一面板内切换、共用 mask 输出。

### ⚠ owner 那句「视频/图片/音频模型各不一样」—— 真正的差别在数据，不在 UI
