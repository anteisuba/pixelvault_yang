# Fish Audio 断句与情感失准 —— 查证记录（2026-08-30）

owner 报：配音间生成出来的语音**断句**和**情感**都有问题。本文只记查到的事实与依据，
修法在最后一节，尚未动代码。

## 一、实锤（有文档依据，可直接对照代码）

### 1. 八个情感标记里有三个**不是 Fish 认识的标记**

`AUDIO_STYLE_PROMPTS` / `AUDIO_EMOTION_PROMPTS`（`src/constants/voice-cards.ts`）发出去的是：

| 我们发的           | 文档里有没有       | 文档里对应的正确写法                           |
| ------------------ | ------------------ | ---------------------------------------------- |
| `[calm]`           | ✓ 基础情感         | —                                              |
| `[excited]`        | ✓ 基础情感         | —                                              |
| `[angry]`          | ✓ 基础情感         | —                                              |
| `[sad]`            | ✓ 基础情感         | —                                              |
| `[surprised]`      | ✓ 基础情感         | —                                              |
| `[whispers]`       | ✗                  | **`[whispering]`**（Tone & Delivery Controls） |
| `[narrating]`      | ✗ 任何一类里都没有 | 无直接对应，见修法                             |
| `[conversational]` | ✗ 任何一类里都没有 | 无直接对应，见修法                             |

⭐ **耳语 / 旁白 / 对话正是配音间最常用的三档**，而它们发的都是文档外的词。S2 号称支持
15,000+ 自由描述，所以不至于报错，但「能解析」和「按预期演」是两回事——`[whispers]`
差一个词形，`[narrating]` / `[conversational]` 则是我们自己造的。

⚠ `voice-cards.ts` 里那条注释说「canonical words（`excited`、`whispers`）比描述性短语
落地硬得多」——那是当时的实测结论，但它挑中的 `whispers` 并不是文档给的词形。

### 2. 停顿用的是 `\n\n`，而 Fish 的停顿标记是 `[break]` / `[long-break]`

`generate-audio.service.ts` 的 `applyPauseMarkers()` 在选中的句子后面追加 `\n\n`：

```ts
return pauseIndexes.has(index) ? `${normalized}\n\n` : normalized
```

文档的 Pause & Break Markers 一节写得很明确，Fish 认的是 **`[break]`（短停）**与
**`[long-break]`（长停）**。换行符不在任何一类标记里，也没有任何一处文档说它会产生停顿。

⚠ 影响面：这条只作用于工作台的「停顿位置」参数，**配音间没用到**（不发 pauseMarkers）。
所以它不是 owner 这次听到的断句问题的成因，但它是同一个域里的真 bug。

### 3. ⚠ 已被 08-30 的接入审计推翻：温度那条只在同步路径成立

**下面这段留作记录，但结论对配音间不成立。** `providerInput` 里根本没有
`expressiveness`，worker 也不做映射——配音间恒走 worker，temperature 一律是 Fish 默认
0.7，四档表现力**点了等于没点**。详见
`docs/plans/fish-audio-integration-audit-2026-08-30.md` 第二节第 1 条。

~~一旦带情感，温度被拉到 0.9（Fish 默认 0.7）~~

`resolveExpressivenessTier()`：显式档位优先，否则**有情感 → dramatic**。而
`EXPRESSIVENESS_TO_FISH_TEMPERATURE[dramatic] = 0.9`。

文档对 `temperature` 的说明是「Higher is more **varied**, lower is more **consistent**」。
也就是说：我们一旦识别出情感，就把模型推向「更随机」——而用户点「耳语」要的是**确定地
压低嗓子**，不是更多变化。这两件事方向相反。

配音间的默认「表现力 = 自动」正好走这条路，所以**每一条带情感的台词都是 0.9**。

### 4. 标记不跨句，而没有标点的文本只会拿到一个标记

文档：「Markers apply locally to the text that follows them. **They do not persist across
sentences.**」

`applyAudioStylePrompt` 的正则是 `/(^|[.!?。！？]\s*)(\S)/g`，只在**句首**插标记。实测重放
owner 那两条：

```
"而此刻，馆里的灯一盏盏亮了。"
→ "[narrating] 而此刻，馆里的灯一盏盏亮了。"

"形のない気持ち忘れないように 決まりきったレイアウトを消した ふと口ずさんだ…（60+ 字，全用空格分隔，无标点）"
→ "[whispers] 形のない気持ち忘れないように 決まりきったレイアウトを消した ふと口ずさんだ…"
```

⭐ 第二条是歌词，**通篇没有句末标点**，于是六十多个字只有开头一个标记。按文档「不跨句」的
说法，耳语的效果会在头一句之后就散掉——这和 owner 说的「情感有问题」对得上。
同时，没有标点也意味着 Fish 没有任何断句依据，只能按 `chunk_length`（默认 300）自行切，
断句自然也不受控。

## 一·五、A/B 实测与**一次方法论翻车**（2026-08-30）

### ☠ 先读这段：用音频长度做 A/B 是错的

第一轮我跑了九组（每组 n=1），量 mp3 字节数，得出「逐句插标记 +28%、空格 +7%、
`[whispers]` 与 `[whispering]` 差 8.6 个百分点」等结论。**这些结论全部作废。**

第二轮补了重复样本，先量噪声底——**同一段文本、同一音色、同样不带任何标记**，跑五次：

```
68544  72306  78157  71052  73977      极差 9613，约 ±7%
```

`temperature` 默认 0.7 是**采样**，Fish 的输出本就不确定。于是那个「+28%」其实是
**一个倒霉样本（87770）比一个走运基线（68544）**，两个都是噪声的极端。

### 补足重复后的真实结果

| 组                      |   n | 样本（bytes）                         |  均值 | 区间        |
| ----------------------- | --: | ------------------------------------- | ----: | ----------- |
| 基线·无标记             |   5 | 68544 / 72306 / 78157 / 71052 / 73977 | 72807 | 68544–78157 |
| OLD·逐句+空格（原行为） |   3 | 73141 / 71052 / 80665                 | 74953 | 71052–80665 |
| NEW·只插一次无空格      |   3 | 77739 / 70216 / 69380                 | 72445 | 69380–77739 |

**三组区间几乎完全重叠。** OLD 比基线 +2.9%，NEW 比基线 −0.5%，NEW 比 OLD −3.3%——
全部远低于 ±7% 的噪声底。**在这个样本量下，任何一组都不可区分。**

### 这一轮真正立住的发现

⭐ **Fish 的输出不确定，且幅度不小（长度 ±7% @ temperature 0.7）。**
这本身就是一条重要情报：

- 任何「听一次觉得不对」都可能只是采样运气，**包括 owner 报的这次**。
- ⚠ 我原本写「识别出情感就把 temperature 拉到 0.9，会放大方差」——**那条不成立**：
  配音间走 worker，而 worker 路径上表现力整个丢了（见接入审计）。实际一直是默认
  0.7。所以「情感不稳」目前**没有**这条解释，方差就是 0.7 本身带来的。

### 这个指标该怎么用

字节长度只能抢答一件事：**标记有没有被当成字念出来**（那会多出整整一个词的时长，
远超 ±7%）。实测没有任何一组出现这种量级的跳变，所以至少可以说：
**`[whispers]` / `[narrating]` 这些文档外的词没有被读出来**，它们被吃掉了。
至于吃掉之后有没有按预期演，长度答不了，**只能听**。

## 二、待验证（有嫌疑，但文档没写，不能当结论）

### ~~A. 标记后面那个空格~~ —— 已被第一·五节证实

原怀疑：`[tag] ` 里那个空格在中日文里是凭空多出来的，可能被当成分词边界。
**实测 2 vs 3：只差两个空格，+7%。成立。**

### ~~C. 每句都重复同一个标记算不算 overuse~~ —— 已被第一·五节回答

**实测 2 vs 4：多插的那一个标记单独 +21%。算。**

### B. `normalize: true` 会不会动方括号里的内容（仍未验）

文档没有提 `normalize` 与标记的交互。这一组**没有跑**——上面九组全是 `normalize` 默认开。
要验就再加一组 `normalizeText: false` 的同串对照。

### D. 变长到底是「多了停顿」还是「语速变慢」（仍未验）

字节数只能说明**总时长**变了，分不清是插了停顿还是整体放慢。2 vs 4 那 +21% 用情感解释
不通（同一个标记），但严格说仍需 owner 听一遍才能定性。

## 三、修法建议（未实施，待 owner 定）

1. **改掉三个错标记**（低风险，直接对文档）：
   - `whispers` → `whispering`
   - `narrating` → 文档无对应。S2 支持自由描述，可用 `[calm]` 起句 + 让「旁白」这一档
     改成描述式，例如 `narrating calmly`；或干脆把这一档重新定义成 `[soft tone]`。
   - `conversational` → 同理，可用 `[relaxed]` 或描述式 `casual conversational tone`。
     ⚠ 这三档改了会**改变所有历史用法的音色表现**，属于产品口径变更，要 owner 拍。
2. **停顿改用 `[break]` / `[long-break]`**，删掉 `\n\n` 那条路。
3. **重新想「有情感 → dramatic(0.9)」这条推导**。要「更像那个情感」应该靠标记，不是靠
   提高随机性。倾向改成有情感时仍走 `natural`(0.7)，把 dramatic 留给用户显式选择。
4. **没有句末标点的长文本**要么在 UI 上提示（歌词/无标点文本建议分行分句），要么在
   服务端按空格/换行补插标记。这条需要设计判断，不宜静默加工用户的文字。
