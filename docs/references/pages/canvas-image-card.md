## 0 · 作用域

`.domain-canvas` 内的图片节点（`NODE_TYPE_IDS.image`，含 role 与散图）。全部 token 走 `--canvas-*`，**不改任何 `--node-*` 旧值**。不引入 Tailwind arbitrary values（Hard Rule 5）。

## 2 · 卡宽

**宽度按媒体真实比例计算，钳制在 `min 180px` / `max 480px`。高度由比例导出。不提供拖拽把手。**

```
--canvas-card-w-min: 180px;
--canvas-card-w-max: 480px;
```

⚠ **规格 §6 的 `--canvas-card-w: 250px` 作废** —— 那是取样参考站单张卡得到的假固定值。固定宽会把 9:16 压成邮票、把 21:9 拉成细条，与「卡即媒体」的前提冲突。

参考尺寸：`9:16 → 180×320`（触下限）· `16:9 → 400×225`（自然宽）· `21:9 → 480×206`（触上限）。

### 端口显隐：只有真正的空态不露 ✅ 已拍板（owner 2026-07-27 定空态，2026-07-28 缺陷④扩到六态）

空卡两个端口**都不显示**（现状 `ImageSourceStarter.tsx` 已如此）。

**理由**：空卡还没有内容，露出**出**端口等于承诺一件做不到的事 —— 连上去也没有图可给。既然出端口不能露，入端口单独露反而制造「这一半能用那一半不能」的不对称。整卡即 dropzone 已经是足够强的「往这里放东西」的提示，不需要端口再提示一次。

⚠ **2026-07-28 真机实测缺陷④修订**：上面这条理由只对**真正的空态**成立——「生成中」是「有东西要来」，不是「没有内容」。旧实现没做这个区分，生成中的卡照样走空态渲染，两个端口都不出，后果是 composer 刚建好的入边找不到锚点（React Flow 报 `Couldn't create edge for target handle id: "null"` 并刷屏，边在生成期间不可见——等图落地卡有了端口边才会自己接上，过程中是断档）。**上传中 / 失败 / 生成中 / 就绪 / 就绪·hover 都露端口，只有最初那个「什么都没发生」的空态不露。**

有图之后端口正常显示（`NodeShell` 默认 `showSourceHandle / showTargetHandle = true`）。

**硬要求三条：**

1. **上传中必须显示真实百分比。** 规格 §5 的「生成中 `↻`（无百分比）」只适用于**生成**（拿不到进度），上传有进度，不得沿用。
2. **失败必须给原因**，不得只灰不说（§11-⑥）。
3. **生成中不显示百分比**——理由与①相反：生成期间前端拿不到真实进度，规格 §5 明确禁止假造一个。

## 4 · 上传并入节点

**「上传」不再是独立入口。**

- 添加节点菜单**删掉「上传」**，只留「添加图片节点」
- 建出的空卡**本身即 dropzone**
- **拖文件到画布空白处** → 直接建图片节点并就地开始上传（不经菜单）
- 拖文件到**已有空卡** → 填进该卡

⚠ **「点卡中间开文件选择器」已撤销**（owner 2026-07-27）：生成提示词框的 `+` 槽已经提供了上传入口，卡上再放一个是重复。**空卡不再响应点击上传**；拖放与粘贴（§4.1）保留，卡底部的「素材库 / AI 生成」两个按钮也保留。

§3 五态表里「空」态那行的主动作因此从「整卡即 dropzone（点击开文件选择器）」收窄为**只是 dropzone**。

### 4.1 · 画布级粘贴 ✅ owner 2026-07-27 拍板要做

**现状：没做。** 全仓只有输入框内的 `onPaste`（`MentionInput` / `CharacterImageReferenceControls` 的粘贴 tab / `NodeMediaInspector`），**画布本身零监听**。上传节点与拖文件进画布都已实现（`ImageSourceStarter` · `StudioNodeWorkbench` 的 `handleCanvasDrop`），粘贴是这条链上唯一缺的一环。

owner 原话：「**画布级粘贴做。并且有上传中的 UI。上传后直接是图片节点。**」

| 项                  | 定义                                                                                                                                                    |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **触发**            | 画布获得焦点时 `Ctrl/⌘+V`，剪贴板含图像数据                                                                                                             |
| **⛔ 不抢输入焦点** | 焦点在任何输入框 / `contenteditable` / 已打开的模态里时，**画布不接管** —— 那是输入框自己的粘贴（现有三处行为不变）                                     |
| **落点**            | 鼠标当前位置；鼠标不在画布内时用视口中心。与 `handleCanvasDrop` 的落点换算**复用同一条路径**，不另写                                                    |
| **立刻建节点**      | 粘贴瞬间就在落点建出图片节点，**先进「上传中」态**，不是等传完才出现 —— 否则用户看不到东西发生                                                          |
| **上传中 UI**       | **复用 §3 五态里的「上传中」**：半透明白 + 扫光 + 居中 `上传中 N%` + `×` 取消。真实百分比（`use-node-reference-upload` 走 XHR，已有进度），不许假进度条 |
| **失败**            | 复用 §3「失败」态：给**具体原因** + `重试`。⚠ 一次失败不标脏整个节点（`ImageSourceStarter:167` 已有这条纪律）                                           |
| **成功**            | 直接成为就绪态图片节点，媒体铺满 `padding: 0`                                                                                                           |
| **多图**            | 剪贴板含多张时**逐张建节点**，沿落点错开排布，不合并成一个节点                                                                                          |

**零重造**：上传、进度、取消、失败重试、落点换算、建节点，六件全部已存在。这一片真正新增的只有**一个 paste 监听 + 把剪贴板 `File` 喂进已有链路**。

## 5 · 点卡扩大 = 模态

| 部件               | 值                                                                                       | 出处                          |
| ------------------ | ---------------------------------------------------------------------------------------- | ----------------------------- |
| 遮罩               | `rgba(255,255,255,0.72)` + `backdrop-filter: blur(20px)`                                 | §8 玻璃族同材质。**不用黑纱** |
| 模态面             | `#FFFFFF` · 圆角 `16px` · 边 `1px rgba(0,0,0,0.08)` · 投影 `0 4px 20px rgba(0,0,0,0.10)` | §8 左侧合体面板同配方         |
| 图的衬垫           | `--canvas-bg #F1F1F1` + `1px rgba(0,0,0,0.08)`                                           | §0.5-④                        |
| 左右分栏           | `1px rgba(0,0,0,0.08)` 竖分隔，**不做二次投影**                                          | §8                            |
| 主动作「下载图片」 | `--canvas-action #0A0A0A` 墨底白字                                                       | §0.6                          |

**设计意图**：让图跳出来的手段不是加暗，是**把图放进比模态面略深一档的凹槽**（`#F1F1F1` 衬垫 vs `#FFFFFF` 面）。

细节：纯白/浅色图的边界由 `.08` 发丝边交代；透明 PNG 的棋盘格**只用 `#FFFFFF` / `#F1F1F1` 两色**，不引入第三个灰。

**右侧信息栏**：图片信息（尺寸 / 大小）+ **生成信息（模型 / 提示词 / 来自哪个节点）**。后者是本项目相对参考站的差异 —— 我们有完整生成元数据。

### 通则（跨族适用）

> **改参数的详情 → 原地长大**（必须一直看见入边）
> **看内容的详情 → 走模态**（要大、要压掉画布干扰）

### P1 · 装现有 AI 能力

### P2 · 区域标注 + 指令

⚠ **不是自由画笔。** owner 要的是「**对图片某个部分标注，然后说想改什么地方**」：

- 框选区域 → 区域上落**编号角标**（①②③），右侧同步出现一条「①：\_\_\_\_」指令行
- 多区域 = **指令列表**
- 提交两条路：指令列表拼进 prompt（通用模型）· 区域转 mask（支持局部重绘的模型）

直接复用既有设想（`project-image-edit-extensions-ideation`），不重新设计。

**纯几何变换**（裁剪 / 缩放 / 翻转）不进编辑器，做成近场工具条的一次性动作。
