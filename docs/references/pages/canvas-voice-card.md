# 画布 · 声音卡（施工基准）

> 五族卡内改造的**第二族**。owner 2026-07-27 确认关键切片。
> 数值唯一来源：[`canvas-skin-spec-2026-07-26.md`](../../plans/canvas-skin-spec-2026-07-26.md)。
> 相关：[图片卡](canvas-image-card.md) · [生成提示词框](canvas-generate-composer.md)
> 现状实现：`src/components/business/node/nodes/VoiceNode.tsx`（294 行）

## 0 · 它在画布上的角色

承载一段音频（音色样本 / 音效 / 音乐），主要用途是**连给组装台或身份卡当音色 donor**。用户在这张卡上真正要知道四件事：**能不能听 · 多长 · 是谁 · 是哪一类**。

**流程**（owner 2026-07-27）：**从音频库选择音色 → 生成一段参考音频**。所以空态的主动作是「选音色」，不是「上传」。

## 0.5 · 域定义 ✅ owner 2026-08-10 拍板

> **这个节点交付的是「一段参考语音」——一个音频片段。有就是有，没有就是没有。**

⚠ 这不是新定义，是把代码拽回 §0 本来就写着的那句「承载一段音频」。代码这一年漂成了
**音色身份**（面板文案「只描述声音是谁、来自哪里、听起来怎样」、参数是合成参数、名字叫
音色节点），而下游 `readVoiceUrl` 从头到尾只取**一个 url**。身份在收割链上一点用都没有。
2026-08-10 的「绿灯却发不出声」就是这条错位的必然产物，不是偶发 bug。

**一个产物，三种来源**（三条都合法，没有主次）：

| 来源          | 怎么来                                       | 代价              |
| ------------- | -------------------------------------------- | ----------------- |
| `library`     | 声音库那条音色自带的试听，**直接取用**       | 不花钱、不用等    |
| `synthesized` | 用某个音色现场合成一段（既有的「生成试听」） | 花用户 key · 要等 |
| `uploaded`    | 用户上传自己的音频                           | —                 |

抽查公开库 300 个音色只有 ~2% 没有自带试听，所以 `library` 是常态路径，
`synthesized` 是那 2% 的兜底 —— **不是反过来**。

**音色身份（`voiceId`）降级为溯源信息**（owner 选 A）。它只回答「这段语音是谁的声音」，
并继续供配音链 `reference_id` 说台词。⚠ 选 A 而不是「只留片段、配音也走片段克隆」的原因：
后者要换掉唯一能跑通的说台词链路，为了模型纯净去拆能跑的东西，撞工程原则 3。

**`ready` 的唯一判据 = 有没有那段语音**（`readVoiceUrlFromData`）。
「选没选过音色」由 `voiceId` 自己表达，不再挤进 `ready`。卡面、面板、收割层三处共用
这一个判据，不许任何一处自己再写一条链。

**合成参数按来源露出**（owner 2026-08-10）：语速 / 音量 / 情绪只作用于**合成**。
取用 `library` 片段时它们对那段音频毫无作用，**不显示** —— 显示就是在暗示可以调。

> ⚠ **落地后发现这条有代价，待复议**。`NODE_TYPE_IDS.voice` 映射到
> `NODE_MEDIA_KIND_IDS.audio`（`constants/node-types.ts:287`），也就是**音色节点本身
> 就是一个音频生成节点**：`StudioNodeWorkbench.tsx:1627` 在 `isAudioMediaNode` 时会把
> 这三个参数真的送进生成请求。所以「按存储来源隐藏」会连带藏掉「这个节点以后还要用
> 它说台词」的参数控制。
> 判断本身没错（调不动一段已录好的音频），但参数**不属于当前这段片段、属于下一次合成**。
> 更准的做法是把它们挪进**合成动作**里（点「重新合成」时才出现），而不是按 `voiceClipSource`
> 隐藏。当前实现是按来源隐藏 —— 这是 owner 拍板的字面版本，复议前不要当成定论。

**文案不许声称「生成」**（2026-08-10）：常态路径是取用，不是合成。三语已改成来源中性
（`toasts.sampleGenerated` = 「试听音频已就绪」/「準備しました」/ en 本来就是 "ready"；
按钮 `voiceDetail.generateSample` = 「获取试听」/「サンプルを取得」/ "Get sample"）。
⚠ 两个**键名**（`generateSample` / `sampleGenerated`）仍带 generate 字样，与值不符 ——
键名没跟着改是有意的：改 i18n 键要同时动三个 256KB 的 JSON，风险大于收益，
且用户看见的是值。别按键名去推断行为。

### 字段收敛

| 现状                                                                     | 收敛后                                                                                                                                          |
| ------------------------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------------------------------------------- |
| `voiceSampleUrl`（库样本/合成）+ `voiceReferenceAudioUrl`（上传）        | **`voiceClipUrl`** 一个字段                                                                                                                     |
| `voiceSource`（manual/fishAudio/referenceAudio，混了身份来源与音频来源） | **`voiceClipSource`**（library/synthesized/uploaded）                                                                                           |
| `audioClip`                                                              | **不动** —— 它是音频族的产出字段（`StudioNodeWorkbench` 给 `isAudioMediaNode` 写，`role:'speech'`），不是音色节点的字段，继续作为收割链的另一档 |
| `voiceId` / `voiceName` / `voiceCoverImage`                              | 不动，语义改判为溯源                                                                                                                            |

⛔ **旧字段不许从 Zod schema 里删**。水化顺序是**先 parse 再 migrate**，字段一旦不在
schema 里，parse 阶段就被 strip 掉，迁移再也看不到那段音频 —— 存量项目的声音会静默清零。
按既有三个 `node-workflow-migrate-*` 的写法：schema 留着旧字段，迁移在 parse 之后于
数据层改写，纯函数、幂等、每次加载都跑。

### 不在本轮

- `voiceReferenceCoverImage` / `voiceCoverImage` 两个封面合一（同一个错位的另一投影，但独立一轴）
- 「音色节点」这个**名字**已与定义不符（它交付的是语音不是音色），改名要动三语 i18n

## 1 · 尺寸 —— `240 × 84`

```
12 padding + 36 播放键 + 8 gap + 16 meta + 12 padding = 84
```

每个数都落在规格 §6 的允许台阶（`4/8/12/16/24/32`，不许 6/10/14/18）。

**宽度固定 240** —— 声音没有画面比例，不需要图片卡那套 min/max 钳制。

### 立成通则（跨族）

> **卡的尺寸由内容决定。** 图片按比例、声音按内容、组装台按控制区。
> **没有「所有卡等高」这条约束** —— 图片卡定案（随比例、180–480）之后它本来就不成立了。

## 2 · 卡内分区 ✅ 定稿（owner 2026-07-27，v1 的四件并排布局已作废）

```
◉ chatgpt                       ← 卡外：族图标（音族=实心圆）+ 名字，原地可编辑
┌──────────────────────────────┐
│▓▓▓▓▓▓│                        │
│▓ (▶) │   ∿∿∿∿∿∿∿∿∿∿∿∿        │   ← 一条平滑曲线
│▓▓▓▓▓▓│   Fish Audio · 语音     │
└──────────────────────────────┘
   84              156
```

| 部件        | 规格                                                                                                                                                                |
| ----------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **封面**    | `84 × 84`，**齐卡高、齐边、`padding: 0`**。压一层 `rgba(10,10,10,0.18)` 让圆形槽读得出来。来源 = 音频库条目封面；无封面回退 `--canvas-fill-control` + 族字形        |
| **圆形槽**  | `r = 17`，压在封面**中央**，`rgba(255,255,255,0.92)` 底。**一个槽四种含义**，见 §3                                                                                  |
| **波形**    | 右侧内距 `16` → 长度 `128`。**平滑曲线**（二次贝塞尔，16 个半周期，峰值 ±13），`stroke-width: 1.5`，基线距卡顶 `32`。未播 `#A1A1A1`，已播 `--canvas-accent #2B5CE6` |
| **meta 行** | `provider · kind`，`12px/1.35 · --canvas-ink-muted #737373`，基线距卡顶 `68`                                                                                        |

⚠ **卡名移到卡外**（§12.1）。现状 `VoiceNode.tsx` 把名字画在卡内左侧，要迁出去。
⚠ **没有时长**（owner 2026-07-27 定）。要看时长走 hover 提示或展开态。

### 三条设计理由（改动时别退回去）

1. **封面齐边铺满**，不是浮在白底上的小方块 —— v1 的 `60×60` 小方块是「四件零件平权并排」的一部分，那正是被判定为丑的根因。
2. **播放键压在封面上**，与图片卡「唯一主动作居中浮层」是**同一个模式**。两族共用一条规则，不是各自发明。
3. **波形是曲线不是柱条也不是折线**：柱条视觉重量大、像柱状图，在 84 高的小卡上喊得太响；折线尖角太硬，与动效气质（`cubic-bezier(0.22,1,0.36,1)`）不合。曲线读起来是**装饰性声纹**而非「振幅分析」，这反而缓解了波形轮廓是伪造的那个问题。

### ⚠ 贝塞尔控制点 ≠ 视觉峰值（基准初版写错了，2026-07-27 更正）

上表「峰值 ±13」**不能照字面写进控制点**。二次贝塞尔在「起止点同高、控制点在段中点」这种构造下，曲线实际顶点只到**控制点纵坐标的一半**。

> 要得到**视觉峰值 ±13**，控制点偏移必须写 **±26**。

关键切片 SVG 用的就是 22–26 这一档；初版基准只写了「峰值 ±13」，实现照字面取 13，画面上振幅只有 ±6.5（偏平）。实现侧照此修正即可，其余参数不变。

### 关于波形 —— 已知它是伪造的，owner 决定保留

`VoiceNode.tsx:21` 注释自述：「waveform, **not a real audio analysis**」—— 轮廓是确定性伪随机柱阵，**填充**（到 `currentTime / duration`）才是真信息。

owner 2026-07-27 决定**保留**，理由是视觉特色。记录两点：

- 波形轮廓对「判断这是哪个音色」**零帮助**（音色差异不体现在振幅包络上），它的价值是观感与进度。
- 想让它变真成本不高（参考音频只有几秒，`decodeAudioData` + 降采样是毫秒级）。**换取值源即可，接口不用动。**

## 3 · 五态 —— 封面上那个圆形槽承担全部

**一个槽四种含义，永不冲突** —— 空 / 生成中 / 失败这几态本来就不能播。

| 态         | 封面                                                                                      | 圆形槽                | 右侧                                                                                               |
| ---------- | ----------------------------------------------------------------------------------------- | --------------------- | -------------------------------------------------------------------------------------------------- |
| **空**     | `--canvas-fill-control` + 族字形；**卡边用 `--canvas-stroke-focus #737373` + 虚线 `6 5`** | —                     | 「从音频库选择音色」次级按钮（边 `.15`），宽 `126`                                                 |
| **生成中** | 封面图                                                                                    | `↻`                   | 「生成参考音频中」+ meta 行。⚠ **不给百分比** —— TTS 拿不到进度（与「上传中」不同，那个必须给）    |
| **就绪**   | 封面图                                                                                    | **▶**                 | 波形曲线 + meta 行                                                                                 |
| **播放中** | 封面图                                                                                    | **⏸**                 | 曲线分色：已播段 `--canvas-accent #2B5CE6`，未播 `#A1A1A1`，两段共用同一条曲线的前后半，过渡处连续 |
| **失败**   | 封面图                                                                                    | `▲` `--canvas-danger` | **具体原因** + 「重试」次级按钮                                                                    |

**就绪态不显示额外状态浮标** —— 有音频即就绪，与图片卡同一条规则。

`--canvas-accent` 用于已播段是**正用**（§0.6 定 accent 为「选中 / 活跃」专用，播放进度正是活跃），不是新增彩色落点。

**就绪态不显示状态浮标** —— 有音频即就绪，与图片卡同一条规则。

`--canvas-accent` 用于已播段是**正用**：规格 §0.6 把 accent 定为「选中 / 活跃」专用，播放进度正是「活跃」。不是新增彩色落点。

## 4 · 端口与关系

**音族端口 = 实心圆 `#7C6F86` 灰紫**（规格 §7，形状主编码、色辅编码；已避开强调蓝色相区）。

**「它是音色 donor」靠连线表达，卡上不加字** ✅ 已拍板。连出去了就是在供给，关系由连线承担 —— 这正是 S3 连线语言存在的意义。卡上再写「已供给 N 处」是重复，且要维护动态文本。

## 5 · 不在本文范围

- `AUDIO_KIND` 的二级切换（语音/音效/音乐）—— 音频域有独立基准 `docs/plans/audio-domain-design-2026-07.md`，本文只负责 kind 在 meta 行的**显示**
- 身份卡上的「听觉身份」入口 —— 与本设计的「靠连线供给音色」是两条路，等**身份卡那一轮**统一，本轮不动
- 音乐 kind：`AUDIO_KIND.MUSIC` 枚举存在但**零模型接入**，UI 不为它单独做形态
