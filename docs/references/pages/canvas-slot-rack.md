## 一、域职责与核心对象

**核心对象**：一个生成节点（视频 / 图片 / 音频 / 文本）**这一次要发出去的素材集合**。

**这个件负责回答三个问题**，且只有它回答：

| 问题                 | 今天散落在哪                                                       | 收敛后                         |
| -------------------- | ------------------------------------------------------------------ | ------------------------------ |
| 我挂了哪些素材？     | composer chip 行 · 正文 `@token` · 详情面板「已引用 N / 已连接 M」 | **槽架**                       |
| 一共多少、满没满？   | 底部 inputs 计数 · 详情面板另一套数                                | **槽架（任一折叠级都读得到）** |
| 这次真的会发出去吗？ | 只有「查看发送内容」里能看到                                       | **槽架（不发送的标出来）**     |

**首要任务**：把素材挂上去 / 取下来 / 看清楚会发什么。

**核心变更一句话**：同一批素材今天有**四本账**，彼此对不齐。改成一本——**具名槽架当家，正文回纯文本，发送时注图例**，其余三个面降级或退役。

## 四、结构契约（阶段 1 的实现规格）

### 4.1 三合一

`ReferenceManagerPanel` + 详情面板「已引用 / 已连接」架 + 「管理素材」按钮 **合并为一个具名槽架组件**。三个入口退役，不留兼容层。

### 4.2 三级折叠：折缩略图，不折账

```
静息摘要（图 4 · 音 1 · 视 1 · 总额 6/12）
  └ 分类行（图片 4/9 ▾ | 音频 1/3 ▾ | 视频 1/3 ▾）
      └ 缩略图槽位
```

**规则**：任一级都读得到「有多少、满没满」。折叠**只折缩略图，不折账**。

出处：report §8.9-1（owner「腰带做成折叠：点击出分类，图片再点出 9 张」）。

### 4.3 两档密度 = 同一个件的两个默认折叠深度

**不是两套渲染**：紧凑档（composer）默认折起，完整档（详情面板）默认展开。同一个组件、同一份名单、同一套计数。

⭐ 三级折叠的连带收益：`+N` 披露层随之取消（原 §8.3-1 的设计问题自然消解）。

### 4.4 分类区从能力契约派生 —— 硬纪律

**事实源 = `node-video-send-slots`。不许在组件里手写分类清单。**

⚠ 原型逐格手写导致**四处漏视频区**（含详情面板档，正好戳穿「两档同一份名单」的论点）。契约里 `slots.videos` 一直是 3，漏了就是能力被 UI 藏掉。出处：report §8.13 教训段。

### 4.5 容量检查收进「落槽」那一个函数 —— 硬纪律

**任何入口都只能经由那一个函数落槽。**

⚠ 原型给 `@` 加了新入口就漏一道闸：图片区 9/9 已满仍被塞成 10/9、总额 13/12。而加号那条路拦得好好的。出处：report §8.16 🔴 段。

**拒绝时的表达**：说对是哪条限制——分项满说分项，分项没满但总额尽说总额；**菜单不关**，用户能立刻换一个。

### 4.6 具名槽 × 匿名槽的视觉语法

两条语法**连长相都不是一类**，杜绝「图1 被读成第一帧」：

- **名字戴在位上**：首帧 / 尾帧 = 实色帽子，**位置先说话**
- **序号盖在图上**：图N = 缩略图角上轻徽标，**内容先说话**

⚠ 切到全能参考时**帽子掉下来变图N**（形态即说明）。具名槽语法留在件里——provider 一开（BytePlus 同源、能力表有首尾帧）契约打开槽自己长出来，不用重画。

**为什么全能参考今天不能设关键帧**（不是 UI 选择，是 provider 三场景互斥）：`video-model-send-plan.ts` 的 `supportsFirstLast = !referenceMode && …` 注释明写「火山明说三种场景互斥」；参考端点里所有图是**同权参考**。画首尾帧 = 伪装未接通能力。出处：report §8.9-4。

### 4.7 模式不支持的区：输入面消失 + 安静折叠条

解「区不渲染」与「素材不许销毁」的张力——**把输入面与留存分开**：

- **输入面**：模式不支持的区真不渲染（没有加号、没有槽位）——不假装能力存在
- **留存**：素材退到一条安静的「本模式不发送 · 图 7 · 音 1 · 视频 2」折叠条，展开才见，带既有「不会发送」徽标——不让用户的劳动凭空消失

出处：report §8.8 新解段。**这是全稿最需要动效的一件事**（见 §十一-3）。

### 4.8 摘要行的两个口径

切到关键帧后摘要行显示「**持有 12 · 本次发送 2**」——两个口径在同一行说清。出处：report §8.12 残留修复段。

## 五、正文、文本与 `@`

### 5.1 正文回纯文本

`@` 图 / 音 / 视频 → **落槽，正文一个字不留**。发送时走既有 `buildShotReferenceLegend` 注入图例，**发送链路不变**。

### 5.2 文本走正文引用胶囊，不进腰带

**判据是物种，不是惯例**：图 / 音 / 视频是二进制素材，除了当槽没有别的去处；文本与提示词**同质**，最终合成同一个字符串。所以文本当槽是「为统一而统一」。

|               | 契约                                                                                                                                |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------- |
| 形态          | 正文里嵌不可编辑胶囊 `▤ 深夜便利店-吧台`，**腰带不设文本区**                                                                        |
| 不复制        | 内容只有源节点那一份；胶囊是引用不是副本                                                                                            |
| ⭐ 位置即顺序 | 今天 `mergePromptWithUpstreamText` 的先后**写死在代码里**，用户无从决定「我的话在前还是分镜文本在前」。胶囊在句中的位置就是拼接位置 |
| 三个动作      | 跳到源节点 · **展开为文字**（脱钩，槽位同时消失，任何时刻只有一本账）· 移除引用                                                     |

⚠ **实现提醒**：contenteditable + 内嵌胶囊必须过**中文 IME 与触屏软键盘**——光标、选区、退格删胶囊的行为须真机验证。出处：report §8.14。

### 5.3 文本节点的 `@` = 给 LLM 的多模态输入

**不是间接引用**——LLM 本来就能分析图片与视频出文字。能力矩阵**已建成**（`ASSISTANT_MEDIA_CAPABILITIES`）：

| 线                                      | 图片 | 视频          |
| --------------------------------------- | ---- | ------------- |
| Gemini                                  | ✓    | **✓（唯一）** |
| OpenAI                                  | ✓    | ✗             |
| DeepSeek / Anthropic / 其余 13 个适配器 | ✗    | ✗             |

- 容量口径**不同**：上限 **8**（`ASSISTANT_MEDIA_LIMITS.maxReferences`）≠ 视频的 12。⚠ **别复用 `node-video-send-slots`**。
- 能力闸表达：模型旁常显能力标签；换到读不了的模型时素材**不销毁**、就地标「读不了」+ 原因、加号隐藏（与切模式保留素材同一条纪律）。
- ⚠ **视频 50MB 上限要在 UI 说出来**，别静默失败。
- `AssistantMediaReference.source` 已含 `'canvas'` —— **是复用不是新链路**。

出处：report §8.17。

### 5.4 `@` 菜单解剖

`搜索` + **`已引用`（置顶）** + `素材引用`（按模态分组：图片 / 视频 / 音频 / 文本）。

**已引用的再 `@` 一次 = 定位高亮，不重复添加**（重复添加会**发两遍**）。

**落点清单**（阶段 4 逐个接）：视频 composer · 图片 composer · 音频 composer · 详情面板 prompt · **助手会话输入框**（`94c86e9c` 自陈还没接）。

**判据（brand-dna）**：复用行为和可访问性，**不强制复用皮肤**。槽架是 `business/` 层组件，可拥有完整域级皮肤；不得把它的 class/token 提升到 `ui/` 或全局。

**第二个消费者出现且视觉需求一致后，才提取共享视觉 variant**——图片 / 音频 composer 套同款槽架是 A 收口那一步的事，不预先抽象。

## 八、三个标志性组件

1. **槽架（腰带）**——三级折叠、账只有一本、容量红线在入口。本页身份的主体。
2. **具名槽帽子 / 匿名槽角标**——两套长相不同的命名语法，切档时帽子掉下来变角标。

## 十、响应式

- **≤680 单列**（沿详情面板既有断点）。
- **触屏无 hover 依赖**：反查、移除、命名全部要有非 hover 通路。
- 软键盘策略沿用全局：**只在直接点输入框时弹**，autofocus / 弹窗自动聚焦一律抑制。
- ⚠ 断点判据注意 `useIsMobile` 是 **1024** 不是 768——凡与它配合的容器 CSS 必须用 `lg:` 不能用 `md:`，否则出现「列位按 768 预留但内容到 1024 才渲染」的空沟。

## 十一、动效（结构性四条）

**判据**：动效在回答「这个结构对不对」→ 现在做；回答「这个界面精不精致」→ 留实现。

**时长曲线不新造**：沿用 `canvas-skin-spec` §9 的 `150 fast / 250 base / 420 slow` + `ease-out cubic-bezier(.22,1,.36,1)` / `ease-inout cubic-bezier(.4,0,.2,1)`。

| #   | 动效       | 规格                                                                     | 为什么是结构问题                                           |
| --- | ---------- | ------------------------------------------------------------------------ | ---------------------------------------------------------- |
| 1   | 折叠       | 腰带 420 · 分类 250 · 箭头 150                                           | 展开九张图时下面怎么让位，直接决定折叠这个决定成不成立     |
| 2   | `@` 落槽   | 替身飞入 250（含 scale 补差）→ 落定显形 → 内嵌环确认闪 420；计数跳字 150 | 正文里字消失、槽位里多一个，中间没有连续性用户会以为字丢了 |
| 3   | 切档掉落   | 被丢弃素材 250 退场 → 折叠条落位 250 → 计数跳字 150                      | **静态图完全说不清「你的东西没丢，退到那条里去了」**       |
| 4   | 取用为文字 | 槽位 250 上滑退场 → 正文 420 扫过一次                                    | 消失得太干脆会读成「删掉了」                               |

**一条纪律取舍**：全部只动 `transform / opacity`，**容器高度瞬时到位不做补间**——`height` 与 `grid-template-rows` 过渡会掉出合成层，正是详情面板退役六个 `.node-collapsible` 的原因。连续性改由内容的 4px 上滑入场承担。若 owner 觉得「跳」，备选是腰带定高 + 内部滚动（外框高度永不变，代价是空态也占高）。

`prefers-reduced-motion` 一律降到 0 并保留终态。

⚠ **动效无法程序化验证**：自动化标签页 `visibilityState: hidden` 会冻结 rAF 与 WAAPI（实测动画 `running` 但 `currentTime` 停在 0）。只能证明「动画挂上了、终态正确」，**顺不顺须 owner 亲自看**。

## 十二、验收路径

1. **两档计数框出来是同一个数**——紧凑档与完整档同源。
