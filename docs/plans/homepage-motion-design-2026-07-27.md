## 0. 一句话结论

首页**不缺动画，缺的是高潮**。已有 10 条命名动效、一套自洽的暗房语汇、甚至已经在用原生滚动驱动动画；但 6393px 的页面里每一拍都是同一种语法——「进视口 → 淡入 + 上浮 + 显影」。没有任何一段是**滚动拥有的**（scroll-owned）。这正是 ScrollTrigger 能买到的东西。

### 1.3 诊断：为什么"不够酷炫"

不是缺动效，是三个结构性问题：

- **单一语法**——10 条动效里 8 条是「进入视口触发一次、0.5–0.7s 结束」。滚动本身不承载任何信息，滚快滚慢看到的是同一个东西。
- **没有主角段落**——7 屏平权，每段权重一样，没有任何一段值得停下来。
- **一处可见瑕疵**——④ 标题揭示（0.72s + 0.12s 延迟）比块级 reveal（620ms）慢，导致正文和 CTA 先到、标题后到，有约 0.2s 的「无头段落」。真机第三张截图抓到了。

## 2. 三个方向

三个方向**不是强度档位，是不同的东西**。选一个。

### 方向 A — 显影台：把现有暗房语汇改成滚动拥有

保留全部现有隐喻，只换驱动方式。hero 钉住（pin），滚动**物理地**驱动一次冲印：一张 tile 从工作墙脱出 → 飞进显影盘 → 从全黑经模糊到清晰 → 同时主标题换行。滚回去，冲印倒放。中段沿用现有 reveal，只把 ④ 标题揭示改成和媒体同拍。

- 用到：ScrollTrigger（pin + scrub）、Flip（tile → 盘）、SplitText（标题换行）
- 改动面：hero 一段 + 一条时间线；版式基本不动
- 气质：和白厅画廊、和 ①②③④ 命名体系完全同源，不会打架
- 成本：中
- 风险：hero 现在只有 576px，钉住需要先加高（见 §3）

### 方向 B — 流水线：一条贯穿全页的生产线

首页真正的故事是「剧本 → 图 / 音 → 视频 → 归档」。现在这条线只在画布段落里以一根 4px 虚线存在（② 活管线）。方向 B 把它升成**贯穿 7 屏的脊线**：一条连续的线从 hero 流下来，每个 feature section 是线上的一个工位，线随滚动自己画出来，到站时对应的媒介从线里"长"出来，最后所有支线在底部 CTA 汇进归档。

- 用到：ScrollTrigger scrub + DrawSVG + MotionPath
- 改动面：**要版式让出一条脊线沟槽**，等于重开首页版式设计
- 气质：最贴产品叙事，也最像获奖站
- 成本：高
- 风险：这不只是动效改版，会把整个首页版式重新打开——超出"加动画"的范围

### 方向 C — 只做首尾，中段不碰

承认中段就是一份功能清单，不该过度动画。全部预算压在两个时刻：**hero** 变成可惯性拖动、持续再生的无限工作墙（Observer + Inertia）；**底部 CTA** 做归档收束——你一路滚过的媒体全部飞回来叠成一摞档案，字面演出"永久归档"。中段 10 条现有动效一行不改。

- 用到：ScrollTrigger、Observer、Inertia、Flip
- 改动面：两段，互不相干，可以分两次上
- 成本：低
- 风险：如果 owner 的不满是"整体不够酷炫"，C 只修了两头，中间 5 屏还是原样

## 3. 无论选哪个都要先解决的前置项

1. **hero 高度**：576px 钉不住，A 方向需要 hero 升到 ≥ 90vh。这是版式决定，需 owner 拍。
2. **动画库边界**：GSAP 只允许进首页域，动态导入不进主 chunk；app 内部（画布 / studio / ui）继续用 `motion`。已写进 CLAUDE.md。
3. **`framer-motion` 与 `motion` 双装**：同一个库两个包名同时在依赖里（12.40 / 12.38），16 处在用。清理一个，独立于本次改版。
4. **④ 标题揭示时序**：0.72s + 0.12s 延迟 > 块级 620ms，造成「无头段落」。任一方向都顺手修。
5. **reduced-motion**：现有覆盖必须原样继承，GSAP 侧用 `gsap.matchMedia()` 接同一套判断。

## 5. 设计轮 R2 — owner 给定结构（**覆盖 §2 三方向**）

2026-07-27，owner 未选 A/B/C，直接给出了想要的结构。原话：

> 第一眼看到的页面有图片展示，有登录注册，然后往下滑页面高度不变，出现的是功能介绍的区域，一个功能一个页面，再往下滑是模型介绍区域。然后是底部。这个滑动需要动画特效，图片展示需要动画特效。以及每个功能介绍的适合也要有功能介绍。

**§2 的 A / B / C 三方向就此作废**，以下为准。

### 5.1 舞台序列

页面从「6393px 连续滚动的长页」改成「一串定格的舞台」：

| 台           | 内容                                                              | 动效要求                              |
| ------------ | ----------------------------------------------------------------- | ------------------------------------- |
| S0 展示台    | 图片展示 + 登录 / 注册                                            | **要**（owner 点名）                  |
| S1–S6 功能台 | 一个功能一屏，共 6 个：图片 / 视频 / 语音 / 画布 / LoRA / 图生 3D | **要**（owner 点名，句意待确认见 F2） |
| S7 模型台    | 模型阵容介绍                                                      | 未点名，跟随整体                      |
| S8 底部      | footer                                                            | 无                                    |

台与台之间的**转场本身**是 owner 点名的第三个动效点。

### 5.2 与现状的差距

现状 8 个段落是连续流式版式（split 左右交替 / band / panorama 四种节奏），高度各不相同、随滚动自然推走。新结构要求「页面高度不变」——**这是版式性质的改变，不是给现有版式加动画**。现有 `rhythm: feature / compact / band / panorama` 四种节奏在定格舞台里失去意义，需要重新定义每台的构图。

现有 10 条动效里，能原样留下的只有 ③ 凑近 inspect（hover）和 ④ 标题揭示；其余 8 条依附于「滚动推走」这个前提，需要重做或退役。

### 5.3 两个开口（**必须先答，否则切片会画错**）

**F1 · 「页面高度不变」的机制**

两种读法做出来是两个东西：

- **(a) 钉住舞台**：外框锁死不动，功能内容在框内互换（淡出淡入 / 推入 / 显影）。滚动条仍在走（要为转场分配滚动距离），但视觉上画面不移动。观感最像获奖站，也最"锁"。
- **(b) 整屏吸附**：每台就是 100vh 的正常区块，正常滚动，但滚到中间会自动吸附对齐到整屏。更接近常规网页，用户还能滑到一半停住。

**F2 · 「以及每个功能介绍的适合也要有功能介绍」**

原句有笔误，两种可能：

- 「每个功能介绍的**时候**也要有**动画特效**」→ 每台各自的入场动效
- 「每个功能介绍的**地方**也要有**功能演示**」→ 每台要有能动的功能演示（比如图片台真的跑一次多模型出图），而不是一张静态图

### 5.4 我要提的两条（不阻塞，owner 拍）

1. **6 屏锁滚偏长**。锁滚每屏都要用户滑一下才过，6 个功能 + hero + 模型台 = 8 次锁定。建议合到 4 台（语音并进画布的管线里、图生 3D 并进图片台的延伸），或者只锁前 3 个主力功能、后面恢复正常滚动。
2. **锁滚的代价要认**：移动端手感容易翻车（惯性滚动和 pin 打架）；`prefers-reduced-motion` 必须有一条完整的线性回退版（现有 6 处兜底得重写）；用户没法快速跳读。这些都能做好，但要算进工期。

### 5.5 owner 对 F1 / F2 / 台数的回答（同日）

| 问      | 答                               | 处理                                            |
| ------- | -------------------------------- | ----------------------------------------------- |
| F1 机制 | 「两种都看不出区别」             | 不再用文字描述，做成**可交互原型**让 owner 实滑 |
| F2 句意 | 「两个都要」                     | 每台既有入场动效，也有能动的功能演示            |
| 台数    | 「**功能页也可以左右滑动切换**」 | 新增横向轴——这条把纵向长度问题直接解决了，见 §6 |

## 6. 设计轮 R3 — 四种滑法可交互原型（已交付）

原型：<https://claude.ai/code/artifact/20a36c0b-c026-4a77-b0de-903623e2e996>

用真图（`public/homepage/archive/*` + `public/showcase/*` 缩到 300px 内联）、真文案（`messages/zh.json` 原文）、真视觉令牌（取自真机 computed style：`#ffffff` 纸底 / `#0a0a0a` 墨字 / `#020203` hero 黑 / 10px 圆角 / Songti 系衬线标题）。顶部工具轨是脚手架，**不是设计的一部分**——刻意做成冷黑 + 荧光绿，避免和页面混淆。

### 6.1 四种滑法与实测代价

|                    | 机制                                    | 纵向总长   | 要滑几下 |
| ------------------ | --------------------------------------- | ---------- | -------- |
| **P1** 钉住 · 纵推 | 外框钉住，6 个功能在框内纵向依次推入    | 8.8 屏     | 8 下     |
| **P2** 整屏吸附    | 每台 100vh，正常滚动 + 吸附对齐         | 7.8 屏     | 8 下     |
| **P3** 钉住 · 横轨 | 外框钉住，滚动驱动 6 个功能**横向**滑过 | 8.2 屏     | 8 下     |
| **P4** 单屏 · 手动 | 功能台只占 1 屏，用户自己左右切换       | **3.1 屏** | **3 下** |

数字是原型里实测的，不是估的。**P4 把首页从 8 站压到 3 站**——owner 那句「功能页也可以左右滑动切换」是这四个方案里唯一真正解决长度问题的。

### 6.2 每台的功能演示（F2「两个都要」）

原型里每台都装了能动的演示，不是静态图：

- 图片台：四个模型格子按序从「生成中」微光 → 显影出图，格子上挂模型名
- 视频台：4 格胶片按序点亮，带帧号
- 音频台：44 根波形条实时起伏
- 画布台：剧本 / 音频 → 图像 → 视频 的节点图，连线虚线在流动
- LoRA 台：2 张灰度参考图 + 1 张彩色结果，标「同一长相」
- 3D 台：图片在 3D 舞台上转台旋转

### 6.3 原型里已解决的两个实现坑（进代码时会再遇到）

1. **段落标签不能靠 IntersectionObserver 定**。IO 回答的是「某一段可见吗」，和「哪一段占着视口」不是同一个问题；两段跨折叠线时它必选错。原型改成按视口中心几何计算（`labelByViewport`），确定性。
2. **入场时序**。块级 reveal 620ms 和标题 clip 0.72s+0.12s 延迟错开会出「无头段落」（§1.3 诊断的那条），原型里统一成一拍。

## 7. 设计轮 R4 — 轴冲突诊断 + 竞品实测 + 三个自由视觉方向

owner 两条反馈：①「左右和上下有点冲突了」②「设计灵感还不够，去 Recent.design / CTA.gallery / Mobbin / Pinterest / Land-book 找参考」③「**做 demo 时要摆脱设计文档的限制**」。

### 7.1 轴冲突的真实病灶

- **P4 的病是滚动孤儿**：用户滑到功能台继续往下滚，横向什么也不会发生，页面直接过去了。6 个功能里有 5 个，只滚不点的人永远看不到。这是结构性的，加提示补不了。
- **P3 没有输入冲突**（纵滚是唯一输入），但有方向错位：手往下推、东西往左走；触控板用户会本能横划，发现没反应。
- **移动端反而不冲突**：纵划=翻页、横划=轮播是标准配置。冲突基本是桌面滚轮独有的。

根因一句话：**我们让两根轴抢同一个输入**。浏览器原生分得清——纵向滚轮给页面，横向手势 / shift+滚轮给 `overflow-x` 容器。

### 7.2 竞品实测（真机 computed style，非印象）

| 站                | 屏数 | 文档层吸附 | 横向轨道 | sticky | 媒体              |
| ----------------- | ---- | ---------- | -------- | ------ | ----------------- |
| Tinker（AI 创作） | 14.7 | none       | 0        | 3      | 1 视频 + 1 canvas |
| Antimetal         | 10.8 | none       | 0        | 5      | 3 canvas          |
| Anam（AI 头像）   | 15.9 | none       | 0        | 2      | 7 视频            |
| Apple MacBook Pro | 48.5 | none       | **4**    | 20     | 14 视频           |

六条发现：

1. **没有一个站锁纵轴**，文档层 `scroll-snap-type` 全是 `none`。P1/P2/P3 在做没人做的事。
2. **全都很长**（10.8–48.5 屏）。「首页要短」是伪命题，P4 追求 3.1 屏方向反了。
3. 唯一做横向的 Apple，用的是**原生 `overflow-x` 容器 + 容器内 `scroll-snap-type: x mandatory`**，文档层一动不动。
4. Apple 横轨只有 **1.7–3.7 屏宽**，永远露出下一张的边（peek）。不是 6 张全宽平铺。
5. Apple 页内有 **47 个 next/prev 按钮**，横向永远配显式控件。
6. 动效重心全在**内容本身活着**（canvas / video），不在滚动机制。

### 7.3 轴冲突三个解法

- **甲 · 原生横轨（推荐）**：功能台是普通区块，内含 `overflow-x:auto` + `x mandatory` 轨道，宽 2.5 屏留 peek，配箭头 + 圆点。纵轴完全不碰，移动端天然对。
- **乙 · 取消横轴**：回归纵向长页，靠每台一个真演示取胜。三个 AI 站的做法，最安全但不新。
- **丙 · 保留 P3 滚动驱动横轨**：无输入冲突，但方向错位、页面仍 8 屏，且四站无人采用。

### 7.4 「demo 摆脱设计文档」——已成为常设规则

已写进 `CLAUDE.md` 的 Design 指针节，并存长期记忆 `feedback-demo-unconstrained`。要点：原型/demo **不受** `brand-dna.md`、`forbidden.md`、`docs/references/pages/*`、现有 token 与页面皮肤约束；闸门只管要合入 `src/` 的代码。

起因即本任务：R3 原型刻意复用真机令牌（`#ffffff` / `#0a0a0a` / Songti 衬线 / 10px 圆角），导致它看起来和现网站一模一样，**除了滑法之外没让 owner 看到任何新东西**。

### 7.5 三个自由视觉方向（均非现有皮肤，均避开 AI 设计套路）

**一 · 接触印相** — 冷纸 `#E8E6E1` / 石墨 `#2A2C2B` / 安全灯红 `#C4342A` / 相纸蓝 `#2E4B6B`；窄体无衬线 + 打字机等宽。动效＝整片小格波浪显影，选中格上实时画出蜡笔圈。合的理由：一句 prompt 出一片再挑一张，字面上就是接触印相。

**二 · 信号台（推荐）** — 冷近黑 `#0C0E11` / 面板 `#15181D` / 每个模型一个色相（`#4EA8DE` `#9B7BD4` `#56C596` `#E0824A` `#D9576B`）；技术无衬线 + 全等宽表格数字。动效＝完成的通道点亮、电平真在动、胜出通道 solo。合的理由：10 adapter / 36 模型的并行度是唯一抄不走的差异，四个对标站都演不了。避坑：饱和度分散在多个模型色相，不是「纯黑 + 一抹荧光」。

**三 · 生成表面** — 无隐喻。页面背景是一张正在生成的图，滚动＝推进降噪步数，**配色从当前图采样、滚到哪就是什么颜色**；chrome 只用纯黑纯白保证可读。合的理由：唯一「媒介即讯息」。代价：最重、最吃性能，字体必须够好。`three@0.182` 已在依赖里。

### 7.6 三方向的结局

owner 全否：「前两个都不对。第三个也一般。」并纠正了流程——**「我是想去设计网站上看，什么效果可以学，然后再做」**。即：先采样真实作品，再动手，不要从自己脑子里编方向。§7.5 三方向作废。

### 9.2 动效（GSAP 3.15 + ScrollTrigger，内联）

owner 明确要求「按 gsap skill 做」。CDN 被 artifact CSP 挡，库必须内联（+115KB）。

### 9.3 三条实现陷阱（都踩过，别再踩）

1. **`scrollLeft` 直接写进 GSAP vars 无效** —— 它不是 CSS 属性，未装 ScrollToPlugin 时被 CSSPlugin 静默丢弃。用代理对象 + `onUpdate` 手写。
2. **`scroll-behavior: smooth` 和 scrub 互斥** —— 每帧写值都被浏览器变成一次平滑动画。用 `el.scrollTo({behavior:'instant'})` 绕过。
3. **类名撞车** —— 视频进度条和视图滑轨都叫 `.vtrack`，后写的规则覆盖前者。已改名 `.vscrub`。

### 9.4 两条被否决的方案（附理由）

- **CSS `animation-timeline: view()`**：`entry 6%→46%` 让动画在元素还在屏幕底部时就演完，正常速度滚动**完全看不到**。改大范围仍不够明显，最终整体换 GSAP。
- **IntersectionObserver**：失败模式不可接受——观察器不触发时 41 个元素永远停在 `opacity: 0`。GSAP 在运行时设起始态，脚本没跑页面只是没动画，内容不会消失。
