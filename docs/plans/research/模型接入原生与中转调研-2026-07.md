## 1. 术语（避免混淆）

| 类型                           | 含义                                                                      | 本仓例子                                                                                                                  |
| ------------------------------ | ------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------- |
| **A. 模型厂商原生 API**        | 请求打到训练/销售该模型的官方 endpoint，key 为厂商发放                    | `api.openai.com`、`generativelanguage.googleapis.com`、`ark.cn-beijing.volces.com`、`image.novelai.net`、`api.fish.audio` |
| **B. 合法聚合/托管（中转感）** | 第三方平台统一队列/计费，背后再跑开源或合作闭源模型；**有正式合作与 ToS** | **fal.ai**（`fal.run` / `queue.fal.run`）、**Replicate**                                                                  |
| **C. 自托管执行**              | 自有/租用 GPU + 固定 workflow，非 SaaS 模型 API                           | **RunPod Serverless ComfyUI Runner**                                                                                      |
| **D. 灰色反代**                | 未授权转发官方 key/账号                                                   | **本仓未使用**                                                                                                            |

下文「中转」= **B**，不是 D。

## 4. 「中转」有没有更好选择？

原则（与 `model-catalog` / owner 习惯一致）：**能官方直连且稳定时优先直连**；聚合用于 **无直连、上线快、统一队列、冷启动由平台扛**。

### 4.1 已有更好原生、且本仓已接 — 维持双轨

| 能力                         | 现中转 | 更好/对等原生              | 建议                                                |
| ---------------------------- | ------ | -------------------------- | --------------------------------------------------- |
| Seedream 5.0                 | fal    | **VolcEngine Ark**（已接） | 国内/成本敏感默认 Ark；国际/统一 fal 账单可继续 fal |
| Seedance 2.0（含 Reference） | fal    | **VolcEngine Ark**（已接） | 同上；行业亦有「大用量 Seedance 走 ModelArk」说法   |

**不要**为「去掉中转」再造第三条字节通道；双轨已够。

### 4.2 现走聚合、存在官方/直连选项 — 可选升级（未做）

| 能力                             | 现路径             | 可能更好                         | 利                            | 弊 / 阻塞                                              |
| -------------------------------- | ------------------ | -------------------------------- | ----------------------------- | ------------------------------------------------------ |
| **FLUX.2 / Kontext / flux-lora** | fal                | **BFL 官方 API**（bfl.ai）       | 更贴近厂商、可能定价/版本更早 | 新 adapter、计费与队列语义；fal 仍是最省事、速度口碑好 |
| **Recraft**                      | fal                | Recraft 官方 API                 | 少一层                        | 单模型单独接，维护成本                                 |
| **Illustrious/NoobAI hosted**    | Replicate 社区模型 | 仅 Runner 忠实 / 或换 fal 上同类 | Runner 已是「真·配方」        | Replicate 适合快试；**不是**字节式「中转盗版」         |
| **Hunyuan3D**                    | fal                | 腾讯云等官方 3D API（若开放）    | 可能价/区域                   | 需单独调研账号与契约                                   |

### 4.3 现走聚合、短中期难换「真原生」

| 能力               | 现路径        | 说明                                                                                                              |
| ------------------ | ------------- | ----------------------------------------------------------------------------------------------------------------- |
| **Kling**          | fal           | 可灵企业/开放平台存在，但区域、资质、API 形态与 fal 队列不同；**换原生 = 新 provider 工程**，非改 endpoint 字符串 |
| **Happy Horse**    | fal           | 阿里系；通常仍经云/聚合开放；无本仓 dashscope 视频面                                                              |
| **LTX 等开源视频** | fal（已退役） | 可 Runner/自托管，但产品未做                                                                                      |

### 4.4 不宜称为「中转」、也不应改成聚合

| 路径                                              | 说明                                                                         |
| ------------------------------------------------- | ---------------------------------------------------------------------------- |
| OpenAI / Gemini / Fish / Eleven / NovelAI / Rodin | 已是厂商原生；**不要**为统一账单硬拐到 OpenRouter 类文本网关（媒体契约不同） |
| Runner                                            | 自托管；「更好」是扩 workflow/checkpoint，不是换成 fal 假装社区底模          |

### 4.5 灰色「中转站」

| 选项                                            | 建议                                          |
| ----------------------------------------------- | --------------------------------------------- |
| 各类 API2D / 逆向 Discord / 未授权 MJ·可灵 反代 | **禁止**（ToS、稳定性、封号、无法 BYOK 审计） |

## 5. 产品与架构建议（调研级）

1. **对内文档/设置 UI** 可标注路由类型：`原生 · 聚合(fal/Replicate) · Runner`，减少「是不是黑中转」误解。
2. **Seedream/Seedance**：把「fal vs 火山」做成明确产品选择（已有 model id 分裂），比再找第三家聚合更有价值。
3. **FLUX**：默认保留 fal 合理；仅当 BFL 有明确价差/合规需求时再开 `bfl` adapter spike。
4. **Kling**：若核心视频体验依赖可灵，再单独立项「可灵官方 API 可行性」；否则 fal 可接受。
5. **新模型默认策略**（建议写进后续 task）：
   - 有厂商官方 HTTP + 可 BYOK → **优先原生**
   - 仅聚合可买 / day-0 → **fal（或现有双轨）**
   - 社区 checkpoint + LoRA 配方 → **Runner**
6. **不要**为「全部原生」拆散统一的 fal 队列与 credit 抽象——成本是更多 adapter 与运维面。
