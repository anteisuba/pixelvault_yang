## 0. 定位与范围 / 非目标

**定位**：助手是工作台上唯一那只「替你拧旋钮的手」。它不生成媒体，它把参数、提示词、参考图和 LoRA 铺到你看得见的控件上，把扳机留给你。v1 把这只手做出来了，v2 只做一件事——**让它像一个 Agent，而不是一个工具面板**。

**v2 的一句话**：模型只认五个动词（看 / 查 / 问 / 改 / 请求生成），用户只看五类卡片（消息 / 问题 / 确认 / 结果 / 证据），每一轮结束自动结一次账。

- ❌ 不改生成模型 / 计费 / 归档 / LoRA 训练流程。
- ❌ 不做音频域（`ASSISTANT_OPERATOR_DOMAINS` 里没有 `audio`，本轮也不加）。
- ❌ 不做 LoRA 域与音频域的手机形态（沿用 v1 现状）。
- ➡ LoRA 域这一侧的「挂载 + 专属提示词」另有施工基准：[`lora-assistant.md`](lora-assistant.md)（本文不重抄，两文的协议口径以本文为准）。

### 宿主范围（owner 2026-09-19）

同一颗 dock 挂三处：**工作台（图片 / 视频）· 画布 · LoRA 装配台**。三份宿主实现差的只有契约里那三样——域、快照、落笔的手，别的一律共用。

**第四样差异：收放法则收不收**（owner 2026-09-19）。宿主契约上的 `collapseOnOutsidePointer` **缺省 `true`**（点面板外就收，拍板 7 原样），工作台与 LoRA 照旧；**画布置 `false`，整体豁免**——那里面板外面就是工作面，平移 / 框选 / 拖节点每一下都会收掉助手。画布上的开合只认右上角那颗 toggle 与 Esc 梯。判据是宿主的性质（「面板外面是不是工作面」）而非域，⛔ 别在 dock 里按域硬判。详见 [`assistant-shell.md` §12 拍板 7](assistant-shell.md)。

**⛔ 配音间不挂助手**（owner 09-19 拍板，D7 Q5 改口）。此前画板里那一帧「配音间壳」作废：台词与语气不是「替你拧旋钮」，它本身就是配音间的主工作流，套一层助手只会多一条谁都不走的路。

### 2.2 模型只见五个入口

五个入口工具的 schema 长这样（要点，不是完整定义）：

| 入口                 | 必填参数                                            | 组内细分怎么定                                                                                                                  |
| -------------------- | --------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `look`               | `action`（枚举）+ 该动作原有的参数                  | `action` 是**封闭枚举**，值 = 本组原工具 id（§2.1 表「看」列）；代码按它派发到原实现，原入参 schema 一份不复制                  |
| `research`           | `action`（枚举）+ 原有参数                          | 同上；「查证 / 找图」两档与 `scope` 的合并在 #16 落地，本组届时只剩两个 `action`（§9）                                          |
| `ask`                | `question` · `options[]`（2–4）· `why?`             | 只有一种形态：单选，无 `action`。多步计划由模型在 turn 上写 `confirmPlan: true` 出 `confirm(multistep)`，不走它                 |
| `apply`              | `action`（枚举）+ 原有参数                          | 一次调用只改**一项**（不是 `changes[]`）——错一项只重发一项，报错仍是模型学得会的 `malformedArgs`；`action` 枚举按域裁剪（§2.3） |
| `request_generation` | `action`（`prime_generate` / `request_generation`） | 参数从工作台快照现取，模型不填模型 / 张数 / 比例（用户在卡上改，§5）                                                            |

真值只有一份：`ASSISTANT_OPERATOR_ENTRY_ACTIONS` 由 `ASSISTANT_OPERATOR_TOOL_VERBS` 过滤得出，五组并集 = 全部工具、两两不交，由测试锁住（⛔ 不在文档里钉死那个数字，见 §2.1）。`step` 帧带必填 `verb`（= 入口名），面板状态词直接读它。

**为什么这样切**：v1 的模型要在 31 条描述里挑一条，挑错的代价是白烧一步 LLM 往返（`maxSteps` 只有 8）。收成 5 条之后，「挑哪个动词」这个判断人和模型都做得对，剩下的「具体哪一支」是确定性的字段派发——那是代码该干的活。

**⛔ 别做的事**：别把 `action` 做成开放字符串。开放了就等于把 31 选 1 换成了 31 选 1 加拼写错误。域裁剪（`ASSISTANT_OPERATOR_ENTRY_ACTIONS_BY_DOMAIN`）继续生效，裁的是**枚举值**而不是工具条目；枚举被裁空的入口不进提示词，`ask` 永远在。

### 2.3 audio 域工具怎么处理

`ASSISTANT_OPERATOR_DOMAINS` 现在是**四个**：`image` · `video` · `lora` · `canvas`（2026-09-19 并入画布，读码点数）。

`mount_audio_reference` 与 `set_sound` 两条**列进「改」组**，但域表里**仍然没有 `audio`**——它们在 v1 里就住在 video 域的工具表里（`ASSISTANT_OPERATOR_TOOLS_BY_DOMAIN[video]`），至今保持原样：`apply` 的 `action` 枚举在 video 域下包含 `mount_audio_reference` / `set_sound`，在 image / lora 域下不包含。

为什么：这两条动的是**视频工作台上真实存在的两颗旋钮**（配音参考、声音开关），不是一个独立的音频工作台。给它们单开一个域，等于造一个界面上不存在的工作台，而域裁剪的全部意义就是「界面上没有的旋钮，模型压根看不见」。

### 2.4 提示词 / 事件 / 卡片如何按同一五分法对齐

| 层           | 五分法怎么体现                                                                                   |
| ------------ | ------------------------------------------------------------------------------------------------ |
| **系统提示** | 工具段由 31 条描述缩成 5 段，每段一句「什么时候用它」+ 一张枚举表                                |
| **SSE 事件** | `step` 帧的 `tool` 字段值域收成五个动词；`verb` 是新的一等字段（§3.1）                           |
| **卡片**     | 「查」→ 证据卡；「问」→ 问题卡；「请求生成」→ 确认卡；「改」→ 消息卡里的一行摘要；「看」→ 消息卡 |
| **加载态**   | 五个动词各一句状态词（§3.6）                                                                     |
| **结论记录** | 「看」的产出进「事实」；「问」的产出进「决定」；「请求生成」的产出进「待办」（§7.2）             |

**为什么要对齐到这个程度**：用户读一屏面板时脑子里只该有一套分类。v1 的问题不是卡片多，是**日志的分类、卡片的分类、提示词的分类互不相干**——同一件事在三处叫三个名字。

### 3.4 问题块：一组 ≤4 题，一次一题，与输入框同框

> ⚠ **本节 2026-09-19（56b 切片 4）整节改写**。此前的「问题卡 · 一次只问一个 · 一帧一题」作废，理由写在下面第一条里。组件也换了：`StudioOperatorQuestionCard` 整文件删，现在是 `StudioOperatorQuestionBlock`。

- **一帧带一组（≤4 题），界面一次只画一道**。⭐ 「一次只问一个」从**帧**的纪律变成**界面**的纪律：旧规矩「模型想问两件事就分两轮」的代价是每答一题都要重跑一整轮工具环，而三道题里后两道的答案与前一道无关（真机：同一道题被问了三遍）。⛔ 别回到一帧一题。
- **坐在输入框上方、同一个 composer 容器里**，不随时间线滚走。未答的问题是当下唯一挡路的东西，滚走了就等于问了个寂寞。
- **块上摆什么**：题头小标签 + 「1 / 3」进度（第 2 题起右上角多一颗「← 上一题」）· 问题一句加粗 · 选项**竖排一行一个**（圆点 + 标签 + 一句灰色说明；推荐项实线框排第一并打「推荐」）· 最后一行「其他，自己写」虚线。
- **⛔ 没有「确定」按钮**：点任一行即选中并进下一题。多一颗确定钮等于让用户为同一个决定按两次。
- **「其他」点开是那一行**就地变输入框（回车 / 箭头提交），⛔ 不跳到下面的输入框 —— 跳下去之后用户得自己记住这句话是在答哪一题。它写的那句话走 `otherText`，⛔ 不混进 `optionIds`。
- **键盘**：`1`–`4` 直选 · `↑`/`↓` 移动 + `Enter` 选中 · `Esc` 收起问题块只打字。⚠ 键盘落在**块自己**身上（块出现时自动聚焦）——落在输入框上的话，用户打的「1」会变成一次选择。
- **下面的输入框始终可用**：直接打字 = 用一句话回答当前这题（走那道题的 `otherText`）。⚠ 这替掉了旧的「不答直接打字」：用户打的那句话往往**正是**答案，当成普通发言送出去的表现是助手下一轮把同一道题再问一遍。不想答就按 `Esc`。
- **已答的先收成小标签**留在块上方（与用户气泡同一侧）。⚠ 它们此刻**还没进时间线**：整组答完才一次性落成几行系统行 —— 这样「← 上一题」只要 pop 一格，⛔ 不用从线程里删条目。
- **`Esc` 收起 = 整组作废**：只留一半的答案发上去，模型会以为用户只关心那一半。⛔ 不落任何系统行。
- **落账规则**（不变）：整组答完后 ① 时间线插几行 `问题 · 你选了 X`（每行自带题面的 `userText`）；② 写进本轮结论的「决定」栏（§7.5）；③ 下一轮请求里作为 `planAnswers` 一次带上去。
- **反问时机由模型判**（决策 4）：系统提示里给的是判据而不是阈值——「用户的说法能对应到两种以上明显不同的做法时才问；能猜到八成就直接做，并在回复里说清你按哪种理解做的」。

### 3.5 正文渲染

**⭐ 56b 切片 1 起，一段回答由三层组成**（画板 `DesignD56bUI` 「快搜回答 · 流完」）：

| 层         | 长什么样                                                      | 判据                                                                                                                                       |
| ---------- | ------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------ |
| **正文**   | markdown，句尾带 `[n]` 角标（小上标，点开高亮对应来源卡）     | 模型在 `message` 里写 `[n]`，号由服务端分配（`AssistantOperatorEvidence.cite`）。⚠ 认不出的号**原样留着那段字**，⛔ 不吞掉也不渲染成死按钮 |
| **媒体条** | 图片与视频封面，横向一排，点开 = 灯箱 / 新窗口                | 只收有 `mediaUrl` 的那几条，⛔ 没封面的视频不留灰格子                                                                                      |
| **来源卡** | 站点图标 + 标题 + 域名，横向可滚；底下一行「深入调查 / 钉住」 | 一条资料一张卡，按 `cite` 去重并排序；`url` 缺席时画成纯文字，⛔ 不是点不开的链接                                                          |

- **⛔ 调查卡退场**（`StudioOperatorResearchCard` 整文件删）：那张卡把证据摆在回答**前面**，读起来是「先看完它的过程，再看它说了什么」。过程折进 `StudioOperatorToolGroup`，候选网格由日志条自己画。
- **资料挂在哪一段回答下面**：判据是**位置**不是 runKey —— 消息条目身上没有 runKey，而「这段话用了哪几条资料」在时间线上本来就是「查完再说话」。实现是 `collectOperatorAnswerSources`：攒着查到的证据，遇到下一条助手消息就挂上去并清零。⚠ 一轮里「查 → 说 → 再查 → 再说」时两次分别挂，⛔ 不按轮堆到最后一句下面。
- **钉住改为钉来源卡**：底下认的仍旧是证据编号（`pinnedEvidence`，§7.3），⛔ 不是「收藏一张卡」。
- **⛔ 不为角标另写一个 markdown 渲染器**：`[3]` 在 markdown 里本来就是普通文字，所以做法是在**渲染出来的 React 子树上**递归替换（`withCitations`，`p` / `li` 两个覆盖叠在 `INITIAL_COMPONENTS` 之上）。只映射段落的直接子节点会漏掉紧跟在加粗后面的那一个。
- **还在流的时候不摆资料**：否则来源卡会在正文长高的过程中一直往下跳。
- **⛔ 分析卡退场**（56b 切片 5，`StudioOperatorReferenceAnalysisCard` 整文件删）：挂进来的图直接进当前多模态模型，回答就是一段普通正文 —— 说这是什么画风、凭什么这么判、提示词里该怎么写，末尾顺手问要不要落到工作台。那张卡把同一件事拆成「一段分工简报 + 一折『参考依据 · N 张图』」，而用户问的是「这是什么画风」。⚠ **`analyze_references` 这条工具本身没有删**：它仍旧是 `set_prompt` 的取材与分工来源，而且历史里那一份 `referenceAnalysis` 还在喂 `readOperatorReferenceProfiles`（「没换过的图复用已核实的视觉事实」那条省钱路）。删掉的是它在界面上的那张卡。
- **视频链接**同一条路：`verify` 取回标题 / UP主 / 时长 / 简介（`video` 证据），模型据此说话。⚠ **关键帧抽取本仓没有服务端能力**（`lib/video-frame-capture.ts` 跑在浏览器里，服务端只复算计划核对时间戳），所以这一档目前是**元数据喂**，⛔ 不许描述没看过的镜头。

- **收尾轮逐段追加**（56b 切片 3）：服务端只发差值（`message_delta`），客户端**追加**到同一条 `streaming` 气泡后面，末尾画一根**不闪的光标**；定稿帧 `message` 按 id 整体覆盖并降旗。⛔ `message` 上的 `partial` 已删 —— 两条「正文还没写完」的表达方式必然分叉。工具轮仍然不发旁白。
- **`motion-reduce` 直接整段落**（owner 2026-09-19）：逐字追加本身就是一种动效，关掉动效的人要的是「写完了再给我」。这一档**不画半截正文** —— 占位行 / 状态词一直留到定稿帧。
- **历史回放不重播流式**：历史条目没有 `streaming`，所以既没有光标也没有增量。
- **渲染 markdown**：复用仓里已有的 `src/components/ui/markdown.tsx`（`react-markdown` 已是依赖）。⛔ 不为助手另写一个渲染器。还在写的长正文不折叠。
- 长回话折叠（首句 + 「展开全文」）逻辑保留，判据仍数换行数；仅定稿后生效。

### 3.6 加载态：五个动词各一句

| 动词     | 状态词           |
| -------- | ---------------- |
| 看       | 正在看图…        |
| 查       | 正在查 N 个来源… |
| 问       | 正在想问题…      |
| 改       | 正在改参数…      |
| 请求生成 | 正在准备生成…    |

- 形态：**头像旁一行小字**，不转圈、不用骨架屏。
- **去掉顶部进度带**（决策 14）。为什么：进度带占了 40px 的常驻高度去说一句「3/6」，而这句话在状态词里顺带就说了（「正在查 3 个来源…」本身就是进度）。
- ⚠ 进度带上挂着的两个东西要各找去处：**齿轮设置入口** → 头部右上（§4.1）；**续跑 chip** → 结论记录块的尾部一行。

#### 3.6.1 调查那一行（两档 · 56b 切片 2）

**⭐ 进度是加载态，不是常驻卡**（owner 2026-09-19）。一张常驻卡的问题是它跑完之后还在那儿占一整块，而那时唯一要读的东西是下面那段回答。

| 态   | 长什么样                                                               | 判据                                                                     |
| ---- | ---------------------------------------------------------------------- | ------------------------------------------------------------------------ |
| 跑着 | 一行微光 +「深入调查中 · 约 1 分钟」/「查资料中 · 约 10 秒」           | 预估**写在行里**（`ASSISTANT_RESEARCH_ESTIMATE_SECONDS`），⛔ 不做倒计时 |
| 点开 | 就地展开那几条步骤日志，再点收起                                       | 与 `StudioOperatorToolGroup` 同一套开合                                  |
| 跑完 | 灰底一行「搜了 N 条 · 读了 M 页」/「深入调查 · 查了 N 条 · 读了 M 页」 | 折在回答上方，形状与跑着那一行一致                                       |

- 组件是 `StudioOperatorResearchProgress`；判「这一组是不是一次调查」的是 `summarizeOperatorResearchBlock`（有跑完的 `research` 步才算，⛔ 单独的 `read_url` 不算）。**有失败步时退回 `StudioOperatorToolGroup`**：那一行上没有失败的位置，而失败恰恰是那一刻唯一要读的东西。
- 微光走 `animate-pulse` + `motion-reduce:animate-none`（`ui-defaults` 的现有配方，与占位脉冲同一支），⛔ 没有为这一行新造渐变扫光。

**两档**（`ASSISTANT_RESEARCH_DEPTHS`）：

| 档              | 打什么                                                      | 大约多久  |
| --------------- | ----------------------------------------------------------- | --------- |
| `quick`（缺省） | 一轮网搜 + **服务端读前 `quickReadPages`（3）页全文**       | 几秒      |
| `deep`          | 现有规划器 / 扇出多轮 + 全部连接器（wiki / B站 / danbooru） | 约 1 分钟 |

- **入口两处**：模型按用户的说法判（「深入查 / 尽量全 / 一定要准」，判据写在工具说明里，⛔ 不设死阈值），或回答底下那颗「深入调查」按钮那一轮带进来（`expandSources` 一律按 `deep` 算）。
- **快搜读页不新增证据条**：读到的正文原地顶掉那几条的 `snippet`（放宽到 `maxReadUrlExcerptChars`），所以来源卡与正文角标仍旧一一对应。读不出来就留着摘要，⛔ 不在日志上假装读过。
- **用户设了来源名单时快搜那条收窄不生效**：名单是用户的决定，而「网搜」很可能根本不在名单里 —— 照收窄的表现是他指定的源一个都没打、回来一句「查不到」。
- ⛔ **不弹确认卡**（owner 定）：花的是搜索额度不是生成费。

#### ⋯ 菜单

| 项       | 行为                                                                                                                              |
| -------- | --------------------------------------------------------------------------------------------------------------------------------- |
| 历史会话 | **打开标题▾ 那个受控下拉**（`setMenuOpen(true)` + `refreshSessions()`），⛔ 不另开一份列表 —— 两份菜单内容必然漂                  |

⚠ ⋯ 关掉自己时会把焦点还给它的触发器，而那一下对刚打开的历史下拉是一次「点了外面」—— 所以 ⋯ 的触发器带着 `HISTORY_BUTTON_ATTR`，历史下拉的 `onInteractOutside` 认得它就不当外部点击。⛔ 别改成 `setTimeout` 躲这一拍：那只是把同一个竞态推迟一帧。

为什么标题和历史是同一个下拉：v1 把它们合并过一次（2026-09-09），结论是对的——用户找「上次那个会话」时脑子里想的就是「换一个标题」。

### 4.2 空态与四张脸的 `face` 契约（D7b ③，owner 2026-09-20）

> Last Verified: 2026-09-20（owner 拍板 D7b ④ · 画板 `DesignD7bFaces`）

**一个壳，四张脸**：骨架 / 输入区 / 卡片形状 / 宽高 / 动效 / 人设与口吻四处**同一份**，每张脸只换三样 —— ⛔ 不做四套面板形态、⛔ 不按宿主换人设。

| 换的那三样   | 在哪儿                      | 说明                                                                                   |
| ------------ | --------------------------- | -------------------------------------------------------------------------------------- |
| ① 起手药丸   | 空态那几行 + 输入框上方那排 | 药丸就是「这个助手会干什么」的自我介绍；最多 **5 颗、两行以内**；点了 = **发送那句话** |
| ② 头部域标记 | §4.1 那颗灰底小胶囊         | 域图标 + 一句当前上下文，**随宿主状态实时刷**；⛔ 不上色                               |
| ③ 空态一句话 | 空态                        | 各说各的活；⛔ 不重复人设名字 —— 名字在头部那颗头像旁已经有了                          |

（第四样是输入框占位词——输入区**唯一**的文案差异。）

#### `face` 契约

`StudioOperatorHost.face`（`contexts/studio-operator-host.tsx`）：

```
{ domainIcon, contextLine(), emptyLine, starterPills[], inputPlaceholder }
```

四份宿主各自实现，面板只读它。⛔ **组件里不许按 `domain` 分叉硬编码** —— 那正是这个契约要消掉的东西，`StudioOperatorDock.web.test.tsx` 有一条源码扫描守着（白名单只有两处真的按域分的东西：手机档有没有这套外壳、会话行上那枚域标签）。

⚠ `contextLine` 是**函数**而不是提前拼好的字符串：宿主把用到的那几格算进 `useMemo` 的依赖，状态一变就换一份新的 `face`，胶囊跟着刷。用一个常量的表现是「改了张数胶囊不动」。

⚠ 静态那三样（图标 / 空态句 / 药丸 / 占位词）走 `useStudioOperatorFace(domain, contextLine)` 按域查表（表在 `constants/`，键按域取，加一个域编译期就红）；**只有 `contextLine` 是宿主自己算的**。抄四份静态文案的下场是它们会漂。

#### 四张脸

| 宿主                         | 域标记那一句                  | 空态那句话                                            | 起手药丸                                                                       |
| ---------------------------- | ----------------------------- | ----------------------------------------------------- | ------------------------------------------------------------------------------ |
| 图片工作台 · 如何生成图片    | `{模型} · {比例} · {张数} 张` | 说你想要的画面，我来写提示词、挑模型、配参考。        | 把这句写成好提示词 · 换个模型看差别 · 照这张参考图来 · 出 4 张对比             |
| 视频工作台 · 如何生成视频    | `{模型} · {比例} · {时长}s`   | 给我一张图或一句话，我来让它动起来。                  | 从这张图动起来 · 首尾帧怎么接 · 时长和节奏 · 镜头运动怎么写                    |
| LoRA 装配台 · 用 LoRA 出对图 | `{底模} · 挂了 {n} 个`        | 告诉我想出什么图，我来帮你挑 LoRA、写触发词、调权重。 | 这个题材该挂哪些 LoRA · 帮我写这张的提示词 · 权重这样对不对 · 试一张看看       |
| 画布 · 全能导演              | `{项目名} · 选中 {n} 个节点`  | 从剧本、参考图或一句话开始，我把它排成分镜、连成片。  | 把这段剧本排成分镜 · 从参考图做角色资产 · 用资产排分镜 · 分镜出视频 · 帮我连线 |

输入框占位词：图片「描述画面，或把参考图挂进来…」· 视频「描述镜头，或挂一张首帧…」· LoRA「想出什么图？」· 画布「继续说，或把素材挂进来…」。

⚠ LoRA 那张脸是 owner 09-20 **改口后**的那一张：核心是**做出自己想要的图**，三件事都要助手辅助 —— 提示词写对（触发词 · 顺序 · 权重语法）· LoRA 挂对（挑哪几个 · 底模兼容 · 常同挂）· 参数调对（权重 · 比例 · 步数）。⛔ 不是原来的「找风格 / 查冲突」。

#### 空态其余部分

- 助手头像（68px）+ **那一句**。⛔ 不再是「标题 + 说明」两段，⛔ 不再重复人设名字。
- 空态**不显示**结论记录区、不显示钉住区。

**⛔ 已删掉的**：`STUDIO_OPERATOR_SUGGESTIONS`（带 `minChanges` 门的语境化药丸表）、`STUDIO_OPERATOR_EMPTY_SUGGESTION_COUNT`、以及三语的 `StudioOperator.suggestion.*` 词条，**整块删**、⛔ 不留兼容层。两张表回答的不是同一个问题：那张是「现在该建议什么」，这张是「这个助手是谁」，而一进来就得四处各不相同——门会让空态在某些域上只画得出两颗。

### 4.3 收起态 = 右上角那颗人设头像（D7b ④，owner 2026-09-20）

> Last Verified: 2026-09-20（owner 拍板 D7b ④ · 画板 `DesignD7bToggle` / `DesignD7bMap`）

收起态四处统一成**右上角一颗 36px 人设头像 + 数字角标**。**头像就是唯一开关**：点它展开，点面板头部那颗（同一颗）或 Esc 收起。

**⛔ 改口的两条**（D7 ④ · Q2 = C 已作废）：位置**右下 → 右上**，形状**近黑圆按钮 → 人设头像**（白底细边）。组件文件 `StudioOperatorCollapsedButton.tsx` 整删，换成 `StudioOperatorAvatarToggle.tsx`。画布顶栏那颗「助手」胶囊（`shell-assistant-toggle`）同时退场——同一位置换成这颗头像，排在「剪辑台」胶囊右侧。

| 元素     | 内容                                                                                            |
| -------- | ----------------------------------------------------------------------------------------------- |
| 头像     | 36px 圆，白底细边；自传头像优先，没有时走 `AssistantAvatarGlyph`（与时间线沟同源）              |
| 数字角标 | **待确认（未答问题 + 未处理确认）+ 未读结果**。⛔ `0` 不画角标，⛔ 也不是红点——它是「等你的事」 |
| 清零     | 前两项答完即减；**未读结果由外壳在打开面板那一刻清零**                                          |
| 展开态   | 同一颗头像坐在面板头部左上槽（22px），角标不画（那件事就在旁边）                                |

#### 一个持久元素，两个锚点

头像是一个**不随开合卸载**的 `fixed` 元素，两个锚点由宿主给（`StudioOperatorHost.anchor`，缺省 `STUDIO_OPERATOR_DEFAULT_ANCHOR` = 四角 24）：

| 宿主              | 头像                                  | 面板                                                   |
| ----------------- | ------------------------------------- | ------------------------------------------------------ |
| 图片 / 视频工作台 | 右上 24 / 24                          | 右上 24 / 24，顶边对齐页面顶部留白                     |
| LoRA 装配台       | 右上 24 / 24（⛔ 从右下挪上来）       | 同上                                                   |
| 画布              | 顶栏那一行，右 16，排在「剪辑台」右侧 | **顶边 = 顶栏底 + 6**，右缘对齐顶栏右缘；⛔ 不再压顶栏 |
| 手机              | 右上 16 / 16（⛔ 不再是右下那颗浮标） | 半屏可拖 Sheet（§4.6），⛔ 不做 morph                  |

位移与缩放是**纯算术**（`operatorAvatarShift`）：收起位左缘 `V - avatarRight - 36`，头部槽左缘 `V - panelRight - width + 12`，两式相减视口宽抵消——所以它**与视口宽无关**，⛔ 不量 DOM、⛔ 不挂 resize 监听。缩放比恒为 `22 / 36`。

#### 动画机制与铁律（owner 09-20 逐条定）

四档相位：`closed → opening →`（**transitionend**，外加一条兜底定时器）`→ open → closing →`（**定时器** `closeMs`）`→ closed`。

| 铁律                                                                        | 为什么                                                                               |
| --------------------------------------------------------------------------- | ------------------------------------------------------------------------------------ |
| **只过渡 `transform`**（头像）                                              | ⛔ 不动 width / height / top / left——那四样每帧都要重排                              |
| 面板从右上角 `transform-origin: top right`，`scale(0.92)` + `opacity 0 → 1` | 与头像**同时长同曲线**（240ms · `--ease-standard`）                                  |
| 关闭 200ms `ease-in`，**定时器**卸载                                        | ⛔ 不靠 `animationend` / `transitionend`：后台页 rAF 冻结，事件永不来，留下幽灵面板  |
| ⛔ 不用 `AnimatePresence`                                                   | 同上一条，2026-08-30 真机实测                                                        |
| **过渡中不开 `backdrop-filter`**                                            | `assistant-glass-panel` 在 `transitionend` 之后才挂；`prefers-reduced-motion` 直接挂 |
| 阴影不做过渡                                                                | 它常驻（`shadow-assistant-panel`），⛔ 不进任何一条 `transition`                     |
| 外壳先出，内容 **80ms 后 160ms** 淡入                                       | 内容与外壳同时出会看起来像一张纸被拍上来                                             |
| `will-change: transform` 只在那 240ms 内                                    | 常驻的 `will-change` 会把图层永远留在合成器里                                        |
| 过渡中面板 `pointer-events: none`                                           | 动着的面板上点中的格子与松手那一格不是同一个                                         |
| `prefers-reduced-motion` 全部直切                                           | 没有中间相位，毛玻璃当场就挂                                                         |

入场起始帧靠 CSS 的 `@starting-style`——⛔ 不用「先挂 closed 再 rAF 翻 opening」那种两帧 setState，低端机上照样漏第一帧。

**⛔ 已删掉的**：此前那张「微状态卡」（头像 + 名字 + 微状态词 + 待办计数 + 参数摘要三行 + 底部状态）与手机那颗独立 fab，**两个组件一起删**，⛔ 不留兼容形态；D7 那颗 44px 近黑圆按钮同样已删。

为什么连那句状态词都不留：收起态的语义收敛成一句话——**有没有等你的事**。「正在查 3 个来源…」这种读数在展开态头像旁仍然有（面板自己画），收起时它是一句没人会为它展开面板的话。也⛔ 不露最近一条消息：那是第二套时间线。

**上行**：文本框（多行自增高）。
**下行**：`+` · 上传 · **素材库** · **LLM 模型 chip** · ……右端发送键。

**「+」菜单三项**（画板 BCards「+」展开态）：

| 项       | 作用                                                 |
| -------- | ---------------------------------------------------- |
| 提及素材 | 唤出 `@` 选择器（v1 `MentionInput`，**单段**，见下） |
| 上下文卡 | 挂一张角色 / 风格 / 品牌卡                           |

**`@` 选择器只列当前工作台**（参考图 / 结果，选中 = 引用它）。一条都没对上时也要
说话（「这儿本来就没有参考图」与「没一条对得上你打的字」两句分开），⛔ 没有「悄悄
什么都不显示」。

**素材库是下行一颗独立按钮**（切片 #7c，owner 2026-09-11「@ 那边取消，最好新做一个
按钮」）：点开 `AssetSelectorDialog`（桌面 Dialog / 手机 Drawer），里面仍是
`AssetPickerBrowser` —— **首屏 10 条**（`STUDIO_OPERATOR_LIBRARY_PAGE_SIZE`）、左侧

库挑图」是用户一眼要找的入口——藏在提及语法后面等于没有入口。⛔ 随之删掉的：

### 4.5 LLM 模型 chip

| 规则           | 内容                                                                                               |
| -------------- | -------------------------------------------------------------------------------------------------- |
| 列什么         | 全部 `NODE_STUDIO_ASSISTANT_ROUTE_MODELS`（**9 条**，读码点数），按 `adapterType` 分组显示厂商标题 |
| 「自动」       | **真选项**，排第一，默认值；副标「按任务挑模型」。选中它走 v1 的自动路由                           |
| 不放什么       | ⛔ 图片模型、⛔ 比例、⛔ 张数——这是 LLM 输入框，画面参数只在生成确认卡里换                         |
| chip 上显示    | 选「自动」时写 `自动`；选具体模型时写模型 label                                                    |
| **持久化去处** | **`AssistantPersona` 新增一列**，用户级一份                                                        |

**为什么持久化到 `AssistantPersona` 而不是会话**：模型偏好是「我喜欢用哪个脑子」，属于人设而不是某一次对话——存会话意味着每开一个新会话都要重选一次，而新会话恰恰是最不想做设置的时刻。`AssistantPersona` 已经是「用户级、一份、四域共用」的那张表（`@unique userId`），语义完全对上。⚠ 代价是「这个会话临时换个模型」不会被记住，接受——那正是它该有的行为。

### 5.1 卡上四颗旋钮

| 旋钮   | 控件 | 取值来源                                      |
| ------ | ---- | --------------------------------------------- |
| 模型   | 下拉 | 当前域可用的图片 / 视频模型                   |
| 比例   | 下拉 | 所选模型支持的比例                            |
| 张数   | 下拉 | 所选模型支持的张数（LoRA 域单次出图，不显示） |
| 分辨率 | 下拉 | 所选模型支持的清晰度                          |

⚠ **换模型会让另外三项的可选值变**：换完之后不合法的值就地回落到该模型的默认值，并在卡上标一行「已按 X 调整」。⛔ 不弹二次确认。

⚠ **候选空或读数空的那一颗整个不画**（2026-09-12 实测第 5 步）：一颗什么都没写的空 chip 比没有这颗旋钮更难读。⚠ 模型那一颗写的是**显示名**（`Models.<key>.label`，与工作台模型选择器同一张词表），⛔ 不是 id。

### 5.2 与工作台参数的同步规则

**工作台是真值，卡是它的一个可编辑视图。**

| 时机                       | 谁写谁                                                                                  |
| -------------------------- | --------------------------------------------------------------------------------------- |
| 卡**出现**时               | 从工作台快照取初值（模型 / 比例 / 张数 / 分辨率四项）                                   |
| 卡上**改一项**             | **立刻写回工作台**（走 `apply` 的同一条 op 通道，带 `inverse`）；工作台控件同步高亮一拍 |
| 卡**未确认**时用户改工作台 | 卡上对应项跟着变（工作台是真值）                                                        |
| 点 `确认生成`              | 用工作台**此刻**的值触发，⛔ 不用卡上缓存的那一份                                       |
| 点 `先不要`                | 卡转「已取消」态；**已写回的改动不回滚**（用户可以用 checkpoint 撤）                    |

**为什么卡上改立刻写回、而不是确认时才写**：如果卡自己攒一份参数，工作台上显示的就和即将生成的对不上——用户点确认前看着 3:2，出来的是 16:9。让卡永远只是工作台的一个视图，这类错配在结构上就不存在。

## 7. 跨轮记忆：每轮结账（方案 A）

### 7.1 现状断点（读码核过）

| 上一轮产生的东西 | 下一轮能看到吗 | 现状                                                           |
| ---------------- | -------------- | -------------------------------------------------------------- |
| 用户说的话       | 能             | 全文（`buildMessages`）                                        |
| 助手回复的文字   | 能             | 全文                                                           |
| 参考图分析结果   | 能             | 事实摘要，每轮重发                                             |
| 生成出来的图     | 部分           | 只有名字和地址（`resultArtifacts`）                            |
| 查证得到的证据   | **不能**       | 只剩标题（`collectStepArtifacts` 明确只记名字地址）            |
| 评审结果和理由   | **不能**       | 只剩一行 `buildPriorSteps` 的 title                            |
| 问题卡选了什么   | **不能**       | 完全没痕迹                                                     |
| 上一轮的计划     | **不能**       | 完全没痕迹                                                     |
| 整份工作记忆     | —              | 只在浏览器内存（`getOperatorState().workingMemory`），刷新即丢 |

### 7.2 数据模型：本轮结论

一条结论记录四栏：

| 栏               | 类型                                           | 内容                                                                     |
| ---------------- | ---------------------------------------------- | ------------------------------------------------------------------------ |
| `facts`          | `string[]`                                     | 「看」组产出的事实（参考图分析、评审结论、读表单）                       |
| `decisions`      | `string[]`                                     | 「问」组产出的决定 + 用户在确认卡上拍的板                                |
| `todos`          | `string[]`                                     | 「请求生成」组挂起的事 + 明确说了「等下再做」的事                        |
| `evidenceRefs`   | `string[]`                                     | 证据编号（`#e12` 形态），指向证据本                                      |
| `pinnedEvidence` | `{refs,conclusion,sourceCount,corroborated}[]` | **钉住的那几条结论**（2026-09-12 实测第三组 B），走 §7.7 那条 PATCH 读写 |

⚠ `pinnedEvidence` 与 `evidenceRefs` **是两列**：后者是这一轮查到的**全部**编号（结论块的证据 chip 行读它、结账时服务端自动写满），把钉住塞进去等于每张证据卡一出生就是钉住态。它带着那一句结论是有意的——刷新之后历史里没有证据卡，常驻条要画的那句话只能由记录自己带着。

外加 `roundIndex` · `createdAt` · `editedByUser`（用户改过的标记，§7.7）· `memoriesWritten` / `incognito`（56a，见 §7.8）。

### 7.3 证据本

**工具全文按编号存**，模型不重发、只按需翻。

| 项           | 决定                                                                                                                                 |
| ------------ | ------------------------------------------------------------------------------------------------------------------------------------ |
| 存在哪       | **复用 `ResearchRun` 表**——它已经有 `conversationId` 弱引用、`evidence Json`、`conclusions Json`、`perSource Json`，就是为这件事长的 |
| 编号         | `#e` + 会话内自增序号，落在 `evidence` 数组每项上                                                                                    |
| 怎么翻       | **新工具 `recall_evidence`**（归「查」组），入参 `refs: string[]`，出参对应条目的正文                                                |
| 不进下一轮的 | 证据正文、评审原文、候选尺寸——它们只以编号出现在结论记录里                                                                           |

为什么复用 `ResearchRun` 而不是新建证据表：它的字段形状与「证据本」逐字重合（含 `basis: source|observation|inference|unknown` 的结论溯源），另建一张只会让同一份证据在库里有两个身份。

### 7.4 Prisma 变更

**选择：在 `AssistantConversation` 上新增一列 `rounds Json`，⛔ 不新建表。**

### 7.5 服务端生成时机

**每轮 `done` 帧发出**之前，服务端用本轮已有的材料写一条结论记录：

1. 从本轮 `step` 的 `verb` 分桶：`look` → `facts`；`ask` 的答案 + `confirm` 的结果 → `decisions`；`request_generation` 未落地的 → `todos`。
2. 「问」的答案由**客户端在下一次请求里带上**（用户是在流结束之后才点的），服务端收到后**补写**进上一条记录的 `decisions`。⚠ 这是唯一一条「回头补写」的路径，别扩大。
3. 结论文字由一次**轻量 LLM 调用**压缩成每栏 ≤ 3 条、每条 ≤ 60 字。⛔ 不让主模型在正文里顺手写——那会让它把结论说两遍（一遍给人、一遍给记录）。
4. 记录随 `done` 帧的 `roundSummary` 载荷一起下发，客户端**直接渲染，不再请求一次**。
5. **以卡结束的那一轮也结账**（a1563804）：停在确认卡 / 问题卡 / 上下文卡上的轮次在 `stopped` 之前先写这条记录 —— 用户点完卡不再新开一轮，不结账那一轮在时间线上就没有结论块。

### 7.6 下一轮注入规则

| 项              | 值                                                                                                   |
| --------------- | ---------------------------------------------------------------------------------------------------- |
| 带最近几条      | **N = 8**（默认值）。判据：一次典型的图片调参对话在 8 轮内收敛；再多就该靠证据本按需翻而不是全量重发 |
| 放在哪          | 系统提示的独立一段 `## 之前几轮记住的事`，⛔ 不混进对话消息                                          |
| 形态            | 每条压成三行（事实 / 决定 / 待办），证据只写编号                                                     |
| 证据正文        | **不带**，模型要看就调 `recall_evidence`                                                             |
| 旧 `priorSteps` | **保留**——它答的是「刚才动了哪几步」，结论记录答的是「得出了什么」，两件事                           |

**旧 `workingMemory` 的去留**：客户端**不再上送**（`request.workingMemory` 从请求 schema 删除，`use-assistant-operator.ts` 里那段 `recordOperatorArtifacts` → 请求组装的链路删掉）。同样的东西改为**服务端从本轮 step 结果现场派生**——服务端本来就手握每一步的完整 `result`，让客户端把它镜像一份再传回来，是为了「省一次查库」而多养的一套镜像逻辑（v1 自己的过度设计清单里就点了这一条）。⛔ 不留兼容字段。

⚠ `src/lib/studio-operator-memory.ts` 的三个纯函数（`collectStepArtifacts` / `attachmentArtifacts` / `resultArtifacts`）**原样搬到服务端**复用，不重写。

### 7.7 时间线渲染

- 结论记录渲染成**分隔块**，不是卡片：左侧一条竖线 + `本轮结论 · 11:26` 标题 + 右上一颗 `改`。
- 三态（画板 BCards）：**默认展开**（三栏 + 证据 chip 行）· **折叠一行**（`本轮记住 3 件事`）· **编辑态**（三栏变可编辑文本框 + `取消` / `保存`）。
- 「改」= 就地编辑三栏 → 保存 → **回写 `rounds` 那一列**并标 `editedByUser: true`。下一轮注入的是用户改过的版本。
- 为什么给「改」：结论是模型压缩出来的，压错一句会一路错下去八轮；给一个 10 秒能改完的入口，比让用户在下一轮用一整段话去纠正便宜得多。
- 证据 chip（`#e12 新海诚黄昏光（2 源）`）点击 = 滚回那张证据卡并展开。

### 7.8 跨会话记忆（56a · 最简版，owner 2026-09-20 拍板）

⚠ 与 §7.2 那条结论记录**是两件事**：结论记录随会话生灭，说的是「这段对话里刚发生过什么」；记忆是**跨会话、跨工作台**的一行字，说的是「你早就知道这个人什么」。

#### 写：每轮结账时一次性写

- 候选**搭结账那一次轻量往返**产出（`AssistantOperatorRoundSummaryDraft.memories`），⛔ 不另开一次 LLM 调用。
- 落库前三道闸，顺序有理由：**敏感类目**（一票否决，静默）→ **本轮内部字面去重** → **与库里字面去重**（同 `userId + scope + kind`，归一化大小写 / 空白 / 中英标点；命中只更新 `lastUsedAt`，⛔ 不改原文——用户可能已经把那行字改顺眼了）。
- 每域上限 200，超了按 `lastUsedAt` 最旧的**静默**删。
- 写失败 ⛔ 不阻塞 `done`（与结账整体同一条判据）。

#### 注入：当前域 + `global`

- 每轮系统提示注入**当前域 + `global`** 的前 N 条，按 `lastUsedAt` 倒序；被印出去的那几条更新 `lastUsedAt`（不 await，⛔ 不占开跑的关键路径）。
- N 与**上下文卡共用一份预算**（`ASSISTANT_CONTEXT_BUDGET.maxEntries`），**卡优先**：卡是用户亲手挂的，记忆是助手自己观察来的。预算被卡吃光时一条都不查。
- **历史回放不注入**：载回旧线程是客户端从库里读，压根不经过工具环。

#### 回执

「本轮记住 N 件事」**保持一行**，N = `memoriesWritten`（缺席时退回三栏条目数）。点它**跳 `/settings/assistant`**（`settingsPath()` 带 `?from=`），⛔ 不展开、⛔ 不逐条编辑。三栏那一档仍然展得开——入口搬到了行尾那颗 ▾。

#### 隐身

⋯ 菜单那颗开关作用于**当前会话**（住操作员 store，⛔ 不落库），请求带 `incognito: true`：这一轮**一条都不写**，结论记录照常算照常下发，回执行改说「这一轮没有记」。⚠ 这面旗**落在那条记录上**，所以用户过一会关掉隐身，历史里那一轮仍然是没记的那一轮。

#### 划界

⛔ 不接 Anthropic 原生 memory tool（05b）· ⛔ 与上下文卡**没有桥**（⛔ 不做「存为卡」，⛔ 不自动降级）· ⛔ 不分组 / 不做时间线分段 / 不画容量表 / 不做负规则 / 不做导出。owner 2026-09-19 打回过一版更复杂的形状。

## 8. 上下文卡与用户偏好

### 8.1 助手提议上下文卡

流程：`propose_context_card`（「问」组）→ 面板确认卡（同时写一行**待确认**）→ 用户点头才进长期记忆；当场没点的，留在设置里的**待确认区**补点。

| 环节         | 规则                                                                                              |
| ------------ | ------------------------------------------------------------------------------------------------- |
| 工具入参     | `kind`（character / style / brand）· `name` · `summary` · `body` · `negative?`                    |
| 服务端       | **不落库**，只吐一帧 `ask`（`kind: "contextCard"`），载荷是卡的草稿                               |
| 客户端       | 渲染成一张问题卡形态：卡片预览 + `存这张卡` / `不用`；**同时**把草稿写成一行 `status: "proposed"` |
| 「存这张卡」 | PATCH 那一行 `status` → `confirmed`（那一行没写成时回落成 `POST … status: "confirmed"`）          |
| 「不用」     | DELETE 那一行 —— 明确的拒绝，⛔ 不留在待确认区里反复问                                            |
| 待确认区     | 设置弹层「上下文卡」页签**顶部**一个区，列出所有 `status: "proposed"` 的卡，每条「存下 / 删掉」   |

⚠ **为什么服务端不落库、而客户端落**（owner 2026-09-11）：写库这一跳必须长在用户那一侧 —— 服务端自己落库等于助手能不经过人就写用户的长期记忆；而「当场没点，后来在设置里补点」这条路要走得通，前提是那张卡还在。两条同时成立只有一种落法：**服务端不写，客户端收到提议帧就写一行 `proposed`，用户点头翻面、放弃删除**。
⚠ `proposed` 那一档**不进系统提示、也不进 `list_context_cards`**（服务端列表默认只回 `confirmed`），所以它不会变成模型的自引用回路（「我记得你说过」而用户从没点过头）。
⚠ 写 `proposed` 那一跳**失败不阻塞**：卡照旧可存可弃，存时回落成直接建一行 `confirmed`。

### 8.2 上下文卡数据模型

`ContextCard` 表**不动**（决策 39），只加一列 `status`（`proposed` / `confirmed`）。`pinnedScopes` 的语义不变：非空且命中当前域 = 每轮进系统提示；空数组 = 只在被 `@` 点名时注入。

### 8.3 用户偏好接进系统提示

系统提示新增一段 `## 关于这位创作者`，装三样：

| 来源                             | 注入成什么                                           |
| -------------------------------- | ---------------------------------------------------- |
| `AssistantPersona.addressUserAs` | 「称呼他为 X」（留空则用账号名）                     |
| `AssistantPersona.useMyWords`    | 「优先使用他在提示词与上下文卡里用过的说法与角色名」 |
| `AssistantPersona.nextStepHint`  | 「每条回复末尾给一条下一步建议」                     |

⚠ 这一段**排在工具表之前**：它改的是说话方式，而工具表改的是做事方式，前者读起来该先于后者。

### 9.1 「查证」内部流程

用户看不见工具，只看见一次「查证」。入口是 `research`（`want: "facts"`），内部四步：

| ------ | -------------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| 改写   | 一句话拆成 2–3 条搜索词，**中 / 英 / 日各一份**                                                    | 画风、角色、术语类的词，英日命中率高得多         |
| 选源   | 按内容类型自动挑：二次元 → Danbooru + Wiki；现实 → 网页 + 图搜；中文热点 → B 站；给了网址 → 直接读 | 让模型「想起」该去哪查，是 v1 那次实测失败的根因 |
| 并发   | 多源同时打，去重，**互相印证的排前**，只有一个来源说的标「单源」                                   | 排序本身就是判断力，不该交给用户逐条读           |
| 给证据 | 结论 + 来源列表 + 日期；每条可点开原文、可**钉住**进本轮上下文                                     | 「谁说的、什么时候说的」是可信度的全部           |

⭐ **结论那一句是归纳，不是摘录**（2026-09-12 实测第三组 A）：收尾**一次**结构化 LLM 往返（persona 的那把脑子、用户语言）把排在最前的几条证据压成 ≤2 句，只许基于证据。解不出来回落到确定性摘录（`summarizeResearchConclusion`）。证据卡、钉住条、结论块的「事实」栏共用这一句 —— 这一步进结账原料的那一行写的就是它，⛔ 不是整条链路观察。

⭐ **题型偏置**（2026-09-12 实测）：改写那一次结构化输出同时标 `questionType`（`style_technique` / `entity_facts` / `general`，常量与词表在 `constants/research.ts`）。画风 / 光影 / 材质 / 技法 / 提示词这类「怎么描述、怎么画」的题，四处一起偏：改写词补技法限定词并删掉生平词、选源换成网搜 + danbooru + B站 +（排最后的）百科、结果排序在同印证数内把生平条目压后、归纳要求先给「可复用的描述词」。⚠ 起因是「新海诚式黄昏光怎么描述」命中的全是导演生平条目。⛔ 另两个题型逐字不变。

⛔ **不合并「找图」**：图搜通常是「我要参考图」而不是「我要答案」，产出形态（网格 vs 列表）与后续动作（挂参考 vs 引用）都不同。`want: "images"` 走 `search_web_images` 那条，出候选网格。

### 9.2 证据卡字段

沿用 v1 的 `AssistantOperatorEvidenceSchema` 六字段（`title` · `url?` · `publisher` · `snippet` · `kind` · `confidence`），细节见 [`assistant-shell.md` §7.1](assistant-shell.md)，本文不重抄。v2 只加两项：

| 新字段            | 说明                                                                                                    |
| ----------------- | ------------------------------------------------------------------------------------------------------- |
| `evidenceRef`     | `#e12` 形态的会话内编号（§7.3）                                                                         |
| `corroboration`   | 印证源数（`2 源印证` / `单源`），由服务端算                                                             |
| `cite`            | **正文里 `[n]` 的 n**（56b 切片 1）——本轮内 1 起、跨 `research` 调用连号，由服务端分配（⛔ 不由模型写） |
| `mediaUrl`        | 能摆进正文的那张画面（`image` 是原图、`video` 是封面）。⚠ **只下发客户端**，⛔ 不进 `observation`       |
| `durationSeconds` | 视频时长 —— 封面右下角那枚角标。取不到就缺席，⛔ 不回落成 0                                             |

⚠ `confidence` 仍由**源的层级**算，⛔ 不由模型写——让模型给自己找的东西打分，它给的永远是 high。

⭐ **四种资料**（56b 切片 1，owner 2026-09-19）：文字 = 正文本身 · 图片 = `image` 证据 · 链接 = 来源卡 · **视频 = 新增的 `video` 证据**（`videoUrl` · `thumbnailUrl?` · `durationSeconds?` · `site` · `excerpt?`，schema 在 `types/research.ts`）。它与 `image` 分开而不是「带时长的图片」：点下去的**去处不同** —— 图开站内灯箱，视频开新窗口跳原站。⛔ 不嵌播放器、⛔ 不转存、⛔ 不解码任何一帧（边界 18 不动）。

- **谁产出**：B站连接器（单稿件与搜索两条路都出 `video`，此前是 text + image 两条同 URL 的证据）· 网搜连接器（命中 `RESEARCH_VIDEO_SITES` 白名单的播放页）。白名单与 `detectResearchVideoSite` 在 `constants/research.ts`。
- **为什么是白名单不是 `/video/` 这种路径启发**：后者会把一篇讲视频的博客判成视频，而判错的代价是界面上多一颗点开不是视频的播放钮。
- **模型读到的是元数据**（标题 / UP主 / 时长 / 简介），⛔ 不是播放地址 —— 与 `image` 档「有意不放图片地址」同一条纪律：给它一条能直接粘的地址，它下一步就会写进提示词。

### 9.3 来源白 / 黑名单

落在 **`ProjectRule`**，新增一列 `kind`：

| `kind`         | `text` 装什么           |
| -------------- | ----------------------- |
| `note`（默认） | 普通项目规则（v1 现状） |
| `sourceAllow`  | 一个域名或来源 id       |
| `sourceDeny`   | 一个域名或来源 id       |

- 白名单**非空时**：查证只打名单内的源；打不到就如实说「你的名单里这几个源没有」，⛔ 不偷偷扩源。
- 黑名单：任何时候都过滤掉。
- 入口：设置弹层「项目规则」页签 + 输入区「+」菜单的「指定来源」（后者只作用于本轮，不写库）。

为什么复用 `ProjectRule` 而不是新表：它已经有 `userId` / `scope`（域）/ `source`（谁记的）三个维度，来源名单需要的正是这三个，且用户心里「这个项目只信官方设定集」本来就是一条项目规则。

四个新工具，全部归「改」组（`apply` 的四个 `field` 值），全部**必须带 `inverse`**。

## 12. 视觉规范 · 方向 B「玻璃仪表·浅色」

> 画布：<https://claude.ai/code/artifact/7003a63a-b804-4937-8c65-18235f886843>
> 前提：**配色与现有浅色产品统一**（owner 明令：不要深色）。脊柱、语义 token、`--primary` 的独占强调地位全部沿用 [`ui-defaults.md`](../ui-defaults.md) §2，⛔ 本域不新增任何调色板。

### 12.1 三层玻璃

| 层       | 用在哪                                        | 原则                                                                                |
| -------- | --------------------------------------------- | ----------------------------------------------------------------------------------- |
| **面板** | 助手覆盖层本体                                | 最不透明的一层：它要压住工作台的内容，读字优先于透视                                |
| **卡片** | 五类卡片、结论记录块                          | 比面板再亮一档、边界靠极细描边而不是阴影：卡与卡之间是并列关系，不该有层级落差      |
| **浮层** | 历史下拉、「+」菜单、模型选择器、确认卡内下拉 | 唯一允许真正半透 + 模糊的一层：它是临时的，透出下面的内容才说得清「我盖在什么上面」 |

⚠ 三层之间靠**明度与描边**分，⛔ 不靠阴影堆叠——浅色底上多层阴影会糊成灰块。

⚠ **画板冲突时以 `Main.dc.html` 为准**（owner 2026-09-11 对稿定）：`BCards.dc.html` 的「玻璃仪表 · 组件表」里「加载态药丸」与「结论记录圆角卡」两格与主稿口径不一致，**按主稿走、实现不改**。组件表是配件目录，主稿才是这些配件装在一起之后的样子。

### 12.2 信号位

- **信号只用近黑实底 + 白字**：确认键、发送键、已选中的人设卡、被钉住的证据。
- 为什么是近黑而不是彩色：这套界面上唯一的彩色预算是 `--primary`，而 `--primary` 已经被工作台的生成键占着；助手面板里再用一次同色，用户分不出「这颗是助手的确认」还是「那颗是真的出图」。近黑是安全的第二重量级。
- 状态语义（成功 / 警告 / 危险 / 应用）仍走 `ui-defaults.md` 的四个 token，⛔ 不自造。

### 12.3 圆角与字体

- **圆角区间 8–18px**：小控件（chip / 图标按钮）取下限，卡片取中段，面板与浮层取上限。⛔ 不用全圆角胶囊，除了 chip。
- **字体沿用产品现有三槽**（`ui-defaults.md` §1）。画板上写的 `Geist` / `Noto Sans SC` 是画板自己的取值，**不迁进产品**——字体是全站脊柱，助手域无权改。

### 12.4 动效

沿用 `globals.css` 的既有配方与时长档。本轮**减少**动效总量：删逐字淡入、删进度带的持续动画。保留的只有三处——卡片入场、折叠开合、按压反馈。每一条带 `motion-reduce:` 降级。

为什么减：v1 一屏里有四种动画同时在跑（逐字、进度环、stagger、按词淡入），叠起来的观感是「界面在抖」，而它们各自单看都没问题。
