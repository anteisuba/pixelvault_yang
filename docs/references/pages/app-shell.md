## 1 · 域定义

侧栏属于 **品牌脊柱**（`brand-dna.md`「应用壳、全局导航位置与导航行为」），**不是业务域皮肤**。因此：

- 它的长相由本文一处定义，**不吸收任何单个业务域的性格**（不像画布，也不像 LoRA）。
- 它的设计目标是 **安静、恒定、永不抢戏** —— 主区永远是作品/画布。

| 负责                                         | 不负责                   |
| -------------------------------------------- | ------------------------ |
| 告诉你在哪 · 让你去别处 · 常驻账户与额度读数 | 任何业务操作、生成、参数 |

**最高频任务**：在 7 个工具之间来回切。整个设计围绕这一条优化。

## 2 · 方向：分段浮岛（owner 2026-08-18 拍板）

**B 的结构 + C 的材质**：

- **结构（B）**：推挤式分段面板；三段「去处 / 工具 / 账户」，段间用留白分不用线；整栏只有**一个**运动主体 —— 会滑的活动指示器。
- **材质（C）**：壳底浅灰，侧栏与主卡各成一片浮在上面；边界靠**几何**（缝 + 圆角 + 投影），不靠发丝线。

落选：A 静轨（主区零回流，但常驻标签消失）· 纯 B（两个白面层次弱）· 纯 C（长列表仍是一坨）。

> 指针：本节是**应用壳**的「侧栏灰底 + 主卡」，与**工作台脊柱**（配音间 / 图像 / 视频 / LoRA 四个工作台共用的 `.workbench-ground` 灰底地台 + `.workbench-card` 白卡，owner 2026-09-03）是两层不同的东西——壳套着工作台，工作台自己再套一层灰底+白卡。工作台脊柱见 `../ui-defaults.md` §2.2 与 `src/app/globals.css`。

## 3 · 尺寸

|                | 桌面 ≥1024                      | 平板 768–1023      | 手机 <768          |
| -------------- | ------------------------------- | ------------------ | ------------------ |
| 轨宽 · 展开    | **144**（容器 160 含 8px 外沟） | — 无竖轨           | — 无竖轨           |
| 轨宽 · 收起    | **40**（容器 56）               | —                  | —                  |
| 行高           | 36                              | 顶栏 44            | 顶栏 44            |
| 图标           | 16                              | 20（面板格）       | 20（面板格）       |
| 收起态点击目标 | 32 × 32（fine pointer 下限）    | 面板格 72 高       | 面板格 72 高       |
| 对比现状       | 192 / 48 → **144 / 40**         | 44 死轨 → **撤销** | 44 死轨 → **撤销** |

⚠ **收起态整个标签不渲染**（`display:none`），不是靠 `overflow` 裁。只裁的话会被
`text-overflow` 截成「G.」「P.」这种单字 —— 2026-08-18 真机上出过。

**⚠ 触屏的 44px 触摸目标下限仍然成立** —— 只是 <1024 不再有竖轨去承载它，改由顶栏按钮
（44 高）与面板格（72 高）满足。

**⚠ 撑宽侧栏的是一个英文字符串，不是布局。** 三语标签实测（14px Geist）：

| locale | 最长标签                | 宽度                      |
| ------ | ----------------------- | ------------------------- |
| zh     | 卡片管理 / 敬请期待     | 56px                      |
| ja     | ギャラリー / プロンプト | 70px                      |
| en     | **Card Management**     | **119px（600 字重 124）** |

所以收宽度的第一步是**改标签**，不是压别的元素：

| key                         | 现状              | 改为        | 理由                                         |
| --------------------------- | ----------------- | ----------- | -------------------------------------------- |
| `en.Navbar.links.cards`     | `Card Management` | **`Cards`** | 路由本来就叫 `/cards`；zh 也只是「卡片管理」 |
| `en.StudioTools.comingSoon` | `Coming Soon`     | **`Soon`**  | 87px 全列第二长，而它是最不重要的一行        |

两处一改，132 / 144 / 156 三档在三语下**零截断**（原型逐档实测）。**取 144**：比日文地板（约 122px）留 ~20px 余量，不至于以后加一个稍长的标签就崩。
⚠ 改 `src/messages/*.json` **禁用正则**，必须逐键对比（跨 256KB 的 `.*?` 会静默删掉别处的键，全量闸门照过）。

## 4 · 令牌（全部 node 确定性计算，禁目测、禁信 review agent 算术）

| 用途              | 值                    | 底        | 对比度    | 判定               |
| ----------------- | --------------------- | --------- | --------- | ------------------ |
| 壳底 ground       | `#e4e7ec`             | —         | —         | 面                 |
| 浮卡 / 浮片       | `#ffffff`             | `#e4e7ec` | **1.24**  | ⚠ **不承重**       |
| 未选中标签 14px   | `#454c55`             | `#e4e7ec` | 7.01      | ✅                 |
| 激活标签 14px/600 | `#0b0e12`             | `#ffffff` | 19.34     | ✅                 |
| 段标题 11px 大写  | `#555d67`             | `#e4e7ec` | 5.38      | ✅                 |
| 激活竖条 3×18     | `#0b0e12`             | `#e4e7ec` | **15.60** | ✅                 |
| Focus 环 2px      | `#0b0e12`             | `#e4e7ec` | 15.60     | ✅                 |
| Hover 底          | `rgba(11,14,18,.055)` | `#e4e7ec` | —         | 与 active **反向** |

### 4.1 · 两条不许推翻的算术结论

1. **hover 和 active 必须反极性。** 初稿让 hover 用「更白的底」、active 用纯白浮片 —— 算出来 **1.1:1**，就是把「hover 任一项都长得像当前项」这个现存 bug 换身浅色衣服重犯。定案：**hover 往暗走（墨 5.5%）、active 往亮走（白浮片）**。
2. **浅壳里「面对面」到不了 3:1。** 白卡 vs 灰底 = 1.24（试到 `#dce1e8` 也只有 1.31）。因此 **任何状态语义都不许压在面色差上**：
   - 壳与内容的分离 → **几何**（10px 缝 + 14px 圆角 + 投影）。几何没有对比度阈值。
   - 状态语义 → 墨竖条（15.60:1）+ 墨色跃迁（7.01 → 19.34）+ 字重（400 → 600）。

**激活态三个信号叠加**：白浮片（材质）+ 墨竖条（承重）+ 字重墨色（承重）。撤掉任意一个承重信号都算破坏本文。

## 5 · 动效

| 动作                     | 时长             | 曲线              | 动的属性            |
| ------------------------ | ---------------- | ----------------- | ------------------- |
| 指示器滑动（切工具）     | 320ms            | `--ease-standard` | **transform**       |
| hover 幽灵块滑动         | 200ms            | 同                | **transform**       |
| 墨色 / 底色变化          | 120ms            | 同                | color · background  |
| 收展 · 桌面（推挤）      | 320ms            | 同                | ⚠ width             |
| <1024 面板落下 / 收起    | Radix Sheet 默认 | 同                | transform · opacity |
| 标签淡出 + 位移          | 120 / 200ms      | 同                | opacity · transform |
| `prefers-reduced-motion` | 0ms              | —                 | 全部瞬时            |

**曲线与时长一律取 `src/constants/motion.ts` / `globals.css @theme` 的 token，壳内不得出现裸 ms。**

⚠ **桌面收展仍动 `width`** —— 这是选 B 结构就付的代价（只有落选的 A 能物理消掉）。缓解：只在收展这一个动作发生，**切工具时不触发**；`will-change` 只在过渡期间挂。

### 5.1 · 交互态（五个，都不靠颜色单打独斗）

| 态            | 表达                                                                                                            |
| ------------- | --------------------------------------------------------------------------------------------------------------- |
| 静息          | 墨 `#454c55`                                                                                                    |
| Hover         | 底色**变暗** 5.5% + 墨色加深 + 图标 `scale(1.08)`；底色由一块**跟着光标在行间滑的幽灵块**承担，不是每行各自开关 |
| Focus-visible | 2px 墨环 inset                                                                                                  |
| 激活          | 白浮片 + 墨竖条 + 600 字重                                                                                      |
| 切换中        | 白浮片 transform 滑向新目标                                                                                     |

**幽灵块细则**：首次进入列表 → 就位后淡入，**不从别处滑过来**；划过当前激活项 → 让位（白浮片赢，不在它下面压暗块）；`pointerType !== 'mouse'` → 不触发（触屏没有 hover，否则会糊一块在那）。

## 6 · 断点行为（一套组件三档）

**只有两档**（owner 2026-08-18 为 <1024 选了方向 M2，不再需要平板第三形态）：

| 断点           | 形态                                                                                                       | 依据                                     |
| -------------- | ---------------------------------------------------------------------------------------------------------- | ---------------------------------------- |
| **≥1024 桌面** | 竖轨 144 ↔ 40，在流中，展开**推挤**主卡                                                                    | 宽度充裕，常驻标签的认路价值大于回流成本 |
| **<1024**      | **没有竖轨**。顶栏 44px，中间一颗「当前位置」按钮，点开从顶部落下一张面板（工具 / 去处 / 敬请期待 / 账户） | 见下方五条                               |

**<1024 为什么不照搬桌面竖轨**（这五条都不是审美问题）：

1. **没有 hover** —— 桌面版一半的交互设计是那块跟随光标的幽灵块，触屏上它不存在。
2. **左上是右手拇指最差可达区** —— 最高频的「切工具」被放在最难够的角落。
3. **宽度比高度贵** —— 44px 竖轨吃掉 375 的 12%，永久占用。
4. **触摸目标要 44px** —— 桌面收到 40/32，手机反而要回到 52/44。**越小的屏轨越宽**，形态本身就不对。
5. **导航层级不同** —— 手机上几乎只有切工具是高频，桌面那种两段平铺是把低频与高频按同权重摆着。

⚠ **断点必须留在 1024。** 别为了让平板拿到桌面竖轨而下调到 768 —— `use-mobile.ts` 记着：
768–1023 挂桌面侧栏会把 studio 内容裁出视口。M2 天然覆盖整个 <1024。

⚠ **<1024 的激活态用墨色填充块，不是桌面的白浮片。** 没有 hover 就不需要反极性那套，
而深色块在 375 上更容易一眼认出。

落选：M1 底部工具坞（切工具一次点击、落在拇指区，但 owner 2026-08-07 刚删过底部 TabBar）·
M3 边缘手势（与画布 pan、画廊/素材横滑直接冲突）。

**⛔ 不得再出现第二套导航组件。** 桌面与移动的条目清单必须来自**同一个数据源**（`src/constants/navigation.ts`）。历史教训：`AppSidebar` 有「敬请期待」组（增强 / 解析 / 故事），`MobileCollapsedRail` 没有 —— 那三个入口在小屏**不可达**，就是两份手工清单漂移的直接后果。

**收起态不渲染「敬请期待」整行** —— 展开器在 44px 轨里点开无处显示标签，badge 本身也被藏，缩成一个箭头没有意义。

## 10 · 禁改 / 红线

- **不动各业务域皮肤**（`canvas.css` / `lora.css` / `home-v4.css` / `legal.css`）。壳换材质**不构成**任何域返工的理由；改完这四张皮肤的外观必须**零变化**，变了就说明脊柱漏进域里了。
- **不撤激活态的两个承重信号**（墨竖条、字重墨色跃迁）。只留白浮片 = 1.24:1，等于没有激活态。
- **触屏 52px 不得压到 44**。
- **不得恢复第二套导航组件**，也不得在组件里手抄第二份条目清单。
- 改任何颜色前跑 `contrast-check`，**禁目测**。
- 壳内**禁裸 ms 与裸色值**，一律走 token（Hard Rule 1 / 5）。
