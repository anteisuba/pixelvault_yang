## 1 · 域职责、核心对象与首要任务

图片工作台负责把一次生成矩阵变成可直接比较、可继续创作的结果，不承担 Gallery 的归档浏览职责。

- **核心对象**：生成矩阵中的 `RunItem`、当前聚焦结果、已定 winner、参考图槽位。
- **首要任务**：按模型横向比较同一轮结果，再对某一张执行详情、编辑、当参考图、下载、问助手或定最佳。
- **关键语义**：`点格子 = 本地聚焦`；`定为最佳 = 显式服务端写入`。浏览不能自动提交。
- **与 Gallery 的边界**：日期、完整提示词、provider、请求数等归档元信息进入详情，不在每个结果格重复。

## 2 · 已确认结构

### 2.1 顶部常驻参考轨

- 有参考图时，`StudioReferenceRail` 在生成前后都存在；不能再依赖“尚无结果”这个条件。
- 每个槽位可直接选择，当前槽位有焦点可见的选中轮廓；禁用槽也显示，以解释为什么未参与生成。
- 当前槽位提供编辑与移除动作；新增参考图仍走左参数栏的既有“图像”入口，本轮不在轨上增加 `+`。
- 缩略图多时在轨内横向滚动；右上区域为覆盖式助手浮标留出命中空间。

### 2.2 中部对照台

- **一行一个模型，行内是该模型的第 1 / 2 / N 张**。矩阵轴必须能从版面直接读出。
- 相邻同模型的 `RunItem` 合并成一行，保留生成请求给出的模型顺序与张序。
- 图格只承载媒体、生成中、失败、winner 角标和聚焦轮廓；**图上不放可点击按钮或元信息尾巴**。
- 行首在图外显示模型名；图格按统一高度对齐，宽度由真实长宽比推导。
- 生成中 / 失败格不可聚焦；失败明确报错，但逐格重试仍是后续能力，不在本切片伪造入口。

### 2.3 底部唯一动作栏

- 只有聚焦已完成结果后出现；整片图墙只有这一份，并在长列表中贴近视口底部。
- 动作顺序：查看详情、编辑、当参考图、下载、问助手、定为最佳。
- 模型名与尺寸放在动作栏，不回填到每个图格。
- `ImageDetailModal` 整片图墙只挂一份，按需异步加载；不再每格复制播放器与编辑依赖。

## 3 · 状态矩阵

| 状态                 | 结果区契约                                                      |
| -------------------- | --------------------------------------------------------------- |
| 无参考、无结果       | 保持既有工作台空态；本文不重做空态。                            |
| 有参考、无结果       | 参考轨可切换 / 编辑 / 删除；当前参考图放大占住舞台。            |
| 生成中               | 按模型分行的占位格 + 真实经过时间；不可聚焦。                   |
| 单格失败             | 该格显示失败原因，其他格继续完成；不把整轮伪装成失败。          |
| 已完成、未聚焦       | 图格可点击并可用 Enter / Space 聚焦；不写 winner。              |
| 已聚焦               | 显示焦点轮廓与全局动作栏；后续动作全部指向当前图。              |
| 已定最佳             | 图上只显示非交互 check 角标；动作栏显示已选择且禁止重复提交。   |
| 进入编辑             | 结果区切换到 `StudioImageEditStage`；参考轨不重复渲染。         |
| 跨图片/视频/音频路由 | `activeRun.outputType` 必须先匹配当前模态，旧批次不得串台渲染。 |

## 4 · 共享与专属边界

**继承并复用**：

- `use-unified-generate` 的 `activeRun`、`selectWinner` 与逐项生成状态。
- `ImageDetailModal`、`downloadRemoteAsset`、`useAskAssistantAboutImage`。
- `StudioImageEditStage` 与参考图上传状态；不重造编辑或上传数据源。
- 全局 semantic token、Button 行为、键盘路径、焦点与 ARIA 语义。

**本页专属**：

- `.studio-result-row` / `.studio-result-tile` 的对照台尺寸规则。
- `.studio-touch-actions` 的 coarse pointer 命中区提升。
- `.studio-reference-stage-image` 的结果区视口约束。

这些样式只能服务 Studio Image 结果区，不能因为 `CompareGrid` 是业务组件就提升为 Gallery 或其他域的皮肤。

## 5 · 三个标志性组件与视觉边界

1. **参考轨**：参考输入在生成前后保持存在，不再被结果挤走。
2. **模型行**：行 = 模型、列 = 第几张，比较结构先于卡片装饰。
3. **唯一动作栏**：动作永远在图外，聚焦与提交分离。

本页不能长成：

- **Gallery 卡墙**：不在每格重复日期、完整 prompt、provider、请求数和收藏/下载按钮。
- **方向 B 主图轮播**：不能为了单张放大而放弃多模型并置比较。
- **方向 C 二选一对台**：不能引入 A/B 两席的新状态或把一次比较限制为两张。

差异来自对象关系与信息层级，不靠换色或复制别的业务域皮肤。

## 6 · 响应式、触控与可访问性

- `lg` 以上沿用 288px 参数栏 + 可滚动结果区；`lg` 以下退回纵向工作台，不新增第二套结果逻辑。2026-09-03 起画布区为白卡、参数栏躺灰底，共用 `.workbench-*`（`src/app/globals.css`）。
- 结果格高度为视口相关的受限值；竖图不能再让一格占满一屏。
- 动作栏在窄宽度允许换行；参考轨缩略图在自身区域横向滚动。
- fine pointer 维持紧凑密度；coarse pointer 的动作按钮最小高度为 44px。
- 图墙使用 listbox / option 语义；完成格支持 Enter / Space 聚焦并保留 `focus-visible`。
- 参考轨使用 tablist / tab 语义；winner 同时用 check 图形与读屏文本表达，不能只靠颜色。

## 7 · 已知边界

1. 失败格还不能逐张重试；今天只有整轮重试能力。
2. 生成中的 `RunItem` 不带目标比例，暂以 3:4 占位，图片落地时可能产生一次宽度变化。
3. 参考轨没有新增入口；新增参考图仍从左参数栏进入。
4. 侧边栏标签遮挡与助手关闭态拖宽手柄属于共享外壳问题，不在本页扩修。
