## 0 · 它是什么

画布的**第二个视图**，与画布本体互斥切换、全屏。它只回答一件事：**这个项目里还有哪些图等我表态，我怎么一次把它们处理完。**

**核心对象 = 一张图**（不是一个节点）。一个挂三张图的收集器节点，在这里就是三条。这与包 4 的数据口径一致——审核态按媒体 URL 键控。

**首要任务**：扫读全部待审 → 逐张通过/打回 → 队列清空。

**非目标**（这几件都已有唯一归属地，审阅视图里一个都不放）：改提示词 · 触发重做 · 连线 · 改名 · 图片放大查看。放进来就是包 4 已经踩过的「同一个对象两处可操作」。

## 2 · 桌面结构

```
┌ 顶栏 ────────────────────────────────────────────────┐
│ [待审|全部|已通过|已打回]  待审 8/12      「全部通过」│
├ 进度条（已表态占比，3px）────────────────────────────┤
├ 名册（240–310px）│ 台面 ─────────────────────────────┤
│ 分组标题        │  大图（16:9 容器，图按自身比例内嵌）│
│  ● 行 名字 [过] │  名字 · 来自哪个节点 · 状态 chip    │
│  ● 行 名字 [过] │  [通过] [打回]                      │
│  …              │  打回理由输入（常驻）               │
└─────────────────┴─────────────────────────────────────┘
```

**名册**：按**来源节点**分组（「角色：小林」「镜1 · 静帧」）。一行 = 一张图 = 状态点 + 名字 + 行内「过」；被打回且填了理由的行加一个「有理由」标记。
**台面**：当前行的大图 + 元信息 + 两个动作 + 常驻理由输入框。

## 3 · 交互契约

- **行内「过」不必先选中**——这是本视图与画布最大的行为差异（画布是「选中才出工具条」）。点它直接改状态，不改变当前选中行。
- **表态后自动前进**：在「待审」档下，一张图被通过/打回后从当前档消失，选中落到**原位置的下一张**（到底则落最后一张）。其余档位不自动前进。
- **通过/打回可逆**：再点一次回到「待审」。与包 4 的可逆性一致，不得做成单向。
- **键盘**：`↑` `↓` 换张 · `Enter` 通过 · `Backspace` 打回。焦点在输入框内时全部让位给输入。所有可点元素保留可见 focus ring。
- **「全部通过」**：只作用于**当前筛选档里可见的待审图**，顶栏右侧、次级视觉重量（不是主按钮）。执行后给一次可撤销的反馈。
- **理由输入**：常驻在台面，不因状态出现/消失。填写即写入，不需要额外「保存」。

## 4 · 数据契约

- **状态读写只走** [`lib/node-media-review.ts`](../../../src/lib/node-media-review.ts)：`resolveMediaReviewState` / `approveMedia` / `rejectMedia`。**本视图不新增第二套状态语义。**
- **图源必须与收割口径一致**：节点自身 `getNodeMediaUrl` + 收集器的 onStage 集合。⚠ 这条是硬约束——网格里看得到的图，必须正是会喂给下游的那些图；另立口径就会出现「审过了但下游没用上」。
- **祖父条款的分组**（「已通过」档）：
  - `mediaReview[url]` **有记录** → 归「你通过的」
  - **无记录** → 归「历史沿用」，副标「从没被人看过，按老规矩算通过」
  - **绝不把后者写成「你通过的」。**
- **计数**：顶栏显示「待审 n / 总数」，总数 = 当前项目全部在册图，不随筛选变化。
- **范围**：只收图。视频、音频不进本视图（审核门今天只管 `image_urls`）。

## 5 · 状态矩阵

| 状态                             | 表现                                                                                                   |
| -------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 待审                             | 状态点 warn；台面两个动作都可点                                                                        |
| 已通过                           | 状态点 pass；「通过」按钮呈已激活态，可再点取消                                                        |
| 已打回                           | 状态点 danger；行上可能带「有理由」；媒体**不删**                                                      |
| 本档为空                         | 台面给一句「这一档还没有图」+ 引导换档                                                                 |
| **队列清空**（待审档全部处理完） | 台面换成收尾态：「这个项目没有待审的图了」+ 一句下游后果（过审的图现在可以喂给视频节点）+ 「回到画布」 |
| 加载中                           | ⬜ 未设计（项目状态本地即得，是否需要另说）                                                            |

## 6 · 响应式

- **桌面**：如 §2。名册最小 240px，低于此宽度先压名册再压台面。
- **375px（⬜ 提案，未上真机）**：不做缩小的两栏 —— 台面上移成主角，名册压成**一条横滑缩略条**（状态靠缩略图边框色读），表态换成两个够大的按钮。
  ⚠ **实现前必须先在真机/`e2e/mobile.spec.ts` 验证**；2026-07-31 与 08-01 两次尝试都因浏览器侧问题没验成，账本 Q6 仍挂着。

## 7 · 继承与共享边界

- **继承**：画布域皮肤（`canvas.css` 的 `--canvas-*`）· 三态语义色（warn/danger/pass，均为既有已算过对比度的 token）· 全局 overlay/focus 行为。
- **专属**：名册行、台面、缩略条为本视图私有；在第二个真实消费者出现前**不提取共享 variant**。
- **不继承**：卡面 chrome（「卡即媒体、卡内无 chrome」是节点卡的契约，与本视图无关）。

## 8 · 三个标志性视觉组件

1. **进度条 + 「待审 n/总数」** —— 全局感的唯一来源，是本视图存在的理由。
2. **名册行的状态点 + 行内「过」** —— 一行同时承担「读状态」和「表态」。
3. **台面的常驻理由输入** —— 本视图唯一的文本输入；不得长成第二个提示词框。

## 9 · 不能长得像谁

- **不像素材库 / 画廊**：那两处是浏览与欣赏，节奏是逛；这里是干活，节奏是清队列。所以没有瀑布流、没有大留白、没有 hover 放大。
- **不像节点定位器**：定位器只「找」，本视图要「表态」。差异来自行内动作与台面大图——定位器一个都不该有。
