# LoRA 提示词设计 — 对标角色/酒馆类工具（2026-07）

> 状态：**调研结论，非实现授权**。  
> 范围：SillyTavern（酒馆）、Character.AI、星野、猫箱、Siya、法典 等「角色设定 + 提示组装」产品逻辑；映射到 PixelVault **LoRA Generate 提示词**（触发词 / 标签 / 搭配 / 助手 / 做同款）。  
> 说明：这些工具多数是 **对话角色卡**，不是 Civitai 图像 LoRA 训练台；可学的是 **「设定分层 + 按需注入 + 用户确认」**，不是照搬聊天 UI。

## 1. 各工具提示/设定机制（摘要）

### 1.1 SillyTavern（酒馆）— 最完整的「组装引擎」

| 机制                                                                            | 作用                                                                   | 对 LoRA 提示的启示                 |
| ------------------------------------------------------------------------------- | ---------------------------------------------------------------------- | ---------------------------------- |
| **角色卡**（name / description / personality / scenario / first_mes / example） | 固定人设与开场                                                         | **角色层**独立于本轮 pose/场景     |
| **World Info / Lorebook**                                                       | 关键词命中时把条目注入上下文；可绑角色；有 insertion order、预算、递归 | **设定条目按需注入**，不是全文常驻 |
| **Author's Note / 系统提示**                                                    | 全局或会话级硬规则                                                     | 质量前缀/禁令/画风宪法，可折叠高级 |
| **Token 预算**                                                                  | 条目与历史争上下文                                                     | 触发词+标签有 **上限**，溢出要提示 |
| **导出嵌入**                                                                    | 卡 + 主 lore 可带走                                                    | 提示配方应可 **导出/做同款**       |

社区共识：Lore 宜 **短而准**；触发词要真会在对话里出现。映射到出图：只有用户写到相关概念、或挂载了对应 LoRA 时，才注入该条目。

### 1.2 Character.AI — 「人设字段 + 样例对话」

| 机制                                                  | 作用                                                                        | 启示                                                         |
| ----------------------------------------------------- | --------------------------------------------------------------------------- | ------------------------------------------------------------ |
| Greeting / 短描述 / **Definition（大段）** / 样例对话 | 人设 + 说话方式；Definition 可很长但 **前部权重更高**（社区称有效窗口有限） | **重要触发词与结构靠前**；长 lore 不要堆在 prompt 尾         |
| `{{char}}` / `{{user}}`                               | 占位符                                                                      | 可用 `{{trigger}}`、`{{char_desc}}` 模板槽                   |
| 钉选记忆 / 聊天记忆                                   | 跨轮一致性                                                                  | 对应 **会话级「本卷设定」** 或挂载栈状态，而非每条消息改人设 |

CAI **不**做图像 LoRA，但教了：人设是 **后台说明书**，用户消息是 **本轮表演指令**——对应 **装配层 vs Prompt 主编辑面**。

### 1.3 星野（国内角色/RP 向产品）

公开资料共性（各版本 UI 不同，取产品逻辑）：

- **角色卡式创建**：人设、开场、世界观/背景分栏，而不是一个无限文本框。
- **对话中持续保持人设**；高级用户仍关心「设定是否被模型忘掉」。

启示：**分栏填写 → 合成最终 prompt** 比「从空白写 Danbooru 长句」更符合大众；专家仍可展开「原始 prompt」。

### 1.4 猫箱

公开资料有限；同类产品通常具备：

- 角色简介 + 性格 + 开场白
- 可能带 **世界/剧本** 选择

启示：降低冷启动——**先选角色/预设，再写本轮动作**；与 Library「使用此 LoRA」进 Generate 同一心理模型。

### 1.5 Siya

中文圈角色产品之一；常见能力形态为：

- 角色创建与对话
- 设定结构化程度因版本而异

启示：若主打 **辅助创作**，需要 **结构化表单 + 一键合成**，并允许高级用户编辑合成结果（与「助手变更卡 → 应用」一致）。

### 1.6 法典

公开、稳定的一手产品文档较少；中文 AI 圈「法典」常指 **设定集/规则书式长文**（世界观、词条、禁则），接近：

- 酒馆 **World Info 合集**
- 或「作者笔记 + 词条库」

启示：PixelVault 可做 **「设定本 / 词条库」**（触发词、质量标签、禁用、画风短句），按规则注入，而不是一个叫法典的聊天页。

### 1.7 「酒馆」在中文语境

多数情况下 **= SillyTavern**（或兼容角色卡生态）。设计对标时以 **ST + 角色卡规范（如 CharCard / lorebook JSON）** 为准即可。

## 2. 共通设计模式（抽象层）

把各工具压成四层——**图像 LoRA 提示应同构**：

```text
L0  系统/质量宪法     （family 方言：Pony score / IL masterpiece / FLUX 自然语言…）
L1  身份与能力层       （挂载 LoRA 的触发词、角色外貌锁、画风锁 — 相对稳定）
L2  按需知识层         （词条/搭配/来源配方片段 — 命中或用户点选才注入）
L3  本轮导演层         （用户 Prompt：动作、构图、光、情绪 — 主编辑面）
L4  负向与参数层       （Negative、Steps… — 默认折叠）
```

| 模式            | 来源工具                   | 在 LoRA Generate 的落点                              |
| --------------- | -------------------------- | ---------------------------------------------------- |
| 字段化人设      | CAI / 星野 / 猫箱          | 挂载后「身份条」：触发词 chips，非埋进一大段灰字     |
| 关键词注入      | 酒馆 World Info            | 词条库：关键词/LoRA id 命中 → 建议注入（**确认后**） |
| 样例对话/样例图 | CAI example / Civitai 样例 | 来源图配方、试用标签；做同款进搭配提醒               |
| Token 预算      | 酒馆                       | 提示长度 cap、注入条数 cap、溢出 UI                  |
| 可导出卡        | 酒馆角色卡                 | 配方导出 / 收藏 prompt / 资产 lineage                |
| 前部优先        | CAI Definition             | 合成顺序：L0→L1→L2→L3，重要身份靠前                  |

## 3. 与图像 LoRA 的差异（必须分清）

| 对话角色工具     | LoRA 出图（PixelVault）                       |
| ---------------- | --------------------------------------------- |
| 上下文是多轮聊天 | 单次（或短会话）**采样 prompt**               |
| 人设防「OOC」    | 触发词防「不像该 LoRA」                       |
| Lore 防世界观崩  | 标签防服装/场景漂移                           |
| 记忆跨 session   | 挂载栈 + 资产 lineage + 可选会话历史          |
| 自然语言为主     | **按 family 方言**（Pony/IL/FLUX/Anima 不同） |

因此：**借组装哲学，借分层与确认；不借「无限聊天才出图」。**  
主台仍应是 **Prompt 大编辑面 + 装配行**（见 `lora-generate.md`），助手/词条是辅助层。

## 4. PixelVault LoRA 提示词：推荐信息架构

结合已有拍板（搭配状态条、助手变更卡、做同款不静默覆盖、Prompt 主编辑面）：

### 4.1 用户可见的三块（由稳到变）

```text
┌─ 装配行 ─────────────────────────────────────┐
│ LoRA chips（触发词一键插入）· 容量 · 底模 · 通道 │
└──────────────────────────────────────────────┘
┌─ 搭配 / 设定条（默认一行）─────────────────────┐
│ 已注入：触发词×N · 词条×M · 来源配方片段？  [展开] │
│ 展开：差异预览 · 应用/撤销 · 词条开关 · 方言提示   │
└──────────────────────────────────────────────┘
┌─ Prompt 主编辑面 ─────────────────────────────┐
│ 本轮导演：动作 / 构图 / 光 / 镜头（用户主战场）   │
│ 可选：显示「将发送全文」只读预览（合成结果）      │
└──────────────────────────────────────────────┘
┌─ Negative / 参数（折叠）───────────────────────┘
```

### 4.2 合成规则（建议产品契约）

1. **发送全文 = L0 + L1(启用) + L2(启用) + L3**，顺序固定，身份靠前。
2. **挂载 LoRA 时**：默认 **建议** 插入触发词到 L1（可关）；**不**自动塞整段样例 prompt。
3. **推荐搭配 / 词条**：只进「待确认」；应用后进搭配条，可撤销。
4. **做同款 / 来源配方**：进搭配提醒；有主台内容时禁止静默覆盖。
5. **助手**：只出变更卡 → 用户应用 → 进搭配条或 L3；**不直接出图、不静默改**。
6. **Family 方言**：切换底模 family 时提示「质量前缀模板已切换」；Pony 提供 `score_9…` 一键，IL 提供 masterpiece 一键，FLUX 偏自然语言说明。
7. **预算**：例如触发词+自动注入总长超过模型 `maxPromptChars` 或站点 cap → 阻断或标红溢出段。
8. **双视图**：默认「写作视图」（用户只看 L3 + 状态条）；一键「发送视图」看最终拼接（对标酒馆「看实际塞进模型的内容」）。

### 4.3 可借鉴的「词条/法典」最小形态

不必叫世界书，产品名可用 **设定本 / 词条**：

| 字段     | 说明                           |
| -------- | ------------------------------ |
| 名称     | 如「校服」「雨夜」「画师风」   |
| 注入文本 | 实际拼进 prompt 的片段         |
| 触发     | 手动 / 关键词 / 绑定某 LoRA id |
| 位置     | 前缀（L1）或随正文（L2）       |
| 启用     | 本会话开关                     |

与酒馆差异：默认 **少自动、多确认**，符合你们「推荐须用户确认」基线。

### 4.4 辅助创作（助手）建议话术能力

- 从自然语言 → **标签化**（IL/Pony）或 **短句**（FLUX）
- 「只改衣服保留脸」→ 结构化差分进变更卡
- 「按当前挂载补触发词」→ 列出将插入的 chips
- 禁止一次生成整页无法审阅的巨 prompt 并直接覆盖

## 5. 竞品对照：你该学的优先级

| 优先级   | 学什么                                        | 主要来源              |
| -------- | --------------------------------------------- | --------------------- |
| **P0**   | 分层（身份 vs 本轮）+ 应用前确认 + 可撤销     | 酒馆 + 你们已有搭配条 |
| **P0**   | 触发词/关键设定 **靠前、可点选插入**          | CAI 前部优先 + 酒馆   |
| **P1**   | 词条按需注入 + 预算                           | 酒馆 World Info       |
| **P1**   | 双视图：写作 / 将发送                         | 酒馆调试习惯          |
| **P1**   | Family 方言模板                               | LoRA 社区 + 底模调研  |
| **P2**   | 导出「角色/风格卡」（外貌锁+触发词+推荐底模） | 酒馆角色卡可移植性    |
| **P2**   | 分栏创建向导（降低小白门槛）                  | 星野/猫箱/CAI 字段化  |
| **避免** | 聊天 UI 取代 Generate 主台                    | 全员聊天产品          |

## 7. 建议落地切片（仅方向）

1. **触发词 chips 行**（挂载后，一点插入光标处或 L1 区）
2. **发送全文预览**（只读）
3. **Family 质量前缀一键**
4. **词条/设定本 MVP**（手动启用，不做复杂关键词引擎）
5. **关键词注入**（有预算后再做）
