# Assets C+F 独立设计简报（交 Claude 对比用，2026-08-11）

> 用途：让 Claude 基于同一组产品事实独立完成 Assets / picker 设计，供 owner 与 Codex V2 对比。
> 权力边界：这是设计输入，不是实现授权；不要修改 `src/**`，不要碰画布并行任务。
> 重要：请先独立形成判断，不要把 Codex V2 当模板。Codex 方案只在文末作为对比材料列出。

## 一句话目标

把 `/assets` 从“方形缩略图 + 常驻文件夹树的素材浏览器”升级成统一私有资产中心：所有完成的生成结果与用户上传资源自动回流，用户能够按真实媒体形态浏览、跨维度查找、分类整理并复用。

## Owner 原始需求

1. 生成出来的资源需要回流到这里。
2. Assets 需要分类管理目前所有资源。
3. 当前尺寸限制死，无法展示生成图片/视频的真实尺寸与比例。
4. 声音资源需要封面。
5. 页面已经有全局左侧导航，不希望再放一列目录导致不美观。
6. 当前 UI 不够美观，需要一个明显更成熟、专业、以作品为主角的设计。

## 已确认的域边界

- Assets 负责找、看、整理、复用私有素材，**不执行生成**。
- 所有已完成生成结果和用户上传资源进入 Assets；生成中/失败任务仍由原创作域负责。
- Gallery 负责公开展示；Assets 不承担公共社区浏览。
- picker 负责尽快找到一个合法素材并返回原任务，不承担完整管理。
- `/assets` 与 picker 不要求同构；共享数据、筛选、网格、选择、上传行为/API/状态/可访问性，分别使用管理型 shell 与任务型 shell。
- picker 必须保留单选、多选、`mediaType` 锁三种契约。

## 当前 UI 结构

- 最左：全局应用图标导航，所有业务域共享。
- 顶部：标题/数量、系统视图图标组、媒体类型图标组、上传、选择、4/6/8 密度。
- 中间：固定列数的正方形资源网格。
- 右侧：约 280px 常驻文件夹树，含搜索、新建、嵌套目录和数量。
- 点击资源打开 `AssetDetailSheet`；批量选择后出现底部操作条。
- picker 桌面端把系统视图和二十多个文件夹放在一条横向滚动 rail，难以扫描。

- `src/components/business/KreaAssetBrowser.tsx`：约 2198 行。
- `AssetSelectorDialog.tsx`：137 行；当前 16 个调用文件 / 19 个挂载点。
- `AssetFolderTree.tsx`：663 行；已有搜索、排序、嵌套、新建、重命名与拖放。
- `use-gallery.ts`：500 行；已有 `search / model / sort / timeRange / provider / type` 过滤能力，但 Assets UI 未完整露出。
- `Generation` 已保存图片/视频 `width`、`height` 与音频 `duration`。
- 当前资源网格使用 `aspect-square + object-cover`，所以图片/视频被裁成方形；这不是源文件尺寸缺失。
- 成功产物通过 `createGeneration` 进入统一记录。
- `sourceSurface` 已存在，但 Assets 列表 select 未返回，UI 也没有来源筛选；当前枚举仅有 `IMAGE_STUDIO / LORA_WORKBENCH / CANVAS / EDIT`，尚未完整覆盖 Video / Audio / 3D / Upload。
- 声音已有默认封面回退、详情设置封面 API，并可把封面引用放在 `previewUrl`；规则尚未统一成正式页面契约。
- 新上传缩略图已使用 768px；存量 384px 缩略图仍待网格几何确定后安全回填。

- `useGallery` 返回错误，但当前页面没有完整消费为可恢复错误态。

## 需要解决的信息架构

分类不是一棵互斥目录树，而是可叠加维度：

1. 媒体类型：图片 / 视频 / 声音 / 3D。
2. 来源入口：Image / Video / Audio / 3D / LoRA / Canvas / Edit / Upload（最终枚举需与实际入口核对）。
3. 人工组织：文件夹 / 未分类。
4. 智能视图：全部 / 最近 / 收藏 / 已发布 / 上传。
5. 检索：提示词、模型、provider、时间；来源筛选需补数据契约。

## 媒体展示要求

### 图片与视频

- 默认列表必须完整表达原始宽高比，不得无意裁切。
- 推荐研究 justified rows、真实比例 masonry 或其他能保持阅读顺序的方案。
- 密度应控制目标行高/卡片尺度，不应继续等价于固定 4/6/8 方格列数。
- 像素尺寸放在 hover、选择态或详情中，不长期压住作品。
- 视频需要清晰的视频类型、时长和播放入口。

### 声音

- 每条声音在列表中必须有可辨认封面；自定义封面可以是可选项，但展示层不能出现空白。
- 建议回退优先级：用户设置 → 生成请求/声音角色封面 → 模型/provider 封面 → 系统默认封面。
- 显示播放入口、时长和声音类型。
- 没有真实波形数据时，不把装饰图形伪装成可读波形；封面艺术可以抽象，但不能表达不存在的数据。

### 3D

- 使用 poster 作为列表表达，并明确 3D 类型；真正 GLB 仍由详情/3D 工作台处理。

## 文件夹与侧栏问题

Owner 明确认为“已有全局左侧导航，再把目录树放左边”可能不美观。

当前工作假设是：不要增加第二个永久左栏。Codex 曾提出“中央内容 + 可折叠右侧 `文件夹 / 详情` 上下文 Dock + 顶部范围选择器 + 多选移动 overlay”，owner 同意先做原型，但尚未确认最终视觉。

Claude 可以：

- 在不增加永久双左栏的前提下独立设计更好的结构；或
- 如果要挑战右侧 Dock，必须明确说明如何同时解决大量嵌套目录、拖放整理、详情查看、1280px 空间和移动端问题。

## 必须覆盖的状态

### `/assets`

- 默认有内容、某文件夹空、搜索无结果。
- 首次加载、筛选切换、分页加载、请求失败与重试。
- 新生成资源回流提示，不打断当前浏览位置。
- 单文件上传、多文件队列、部分失败、逐项重试、成功插入。
- 普通浏览、单项详情、选择模式、批量动作 pending、危险确认。
- 文件夹搜索、排序、新建、重命名、拖入资产。
- 桌面、约 1280px、375px；键盘焦点和 overlay 关闭后 focus return。

### picker

- 单选、多选、达到 `maxSelection`、`mediaType` 锁。
- 最近素材、搜索结果、文件夹结果、空结果。
- 内联上传、上传后自动选中、上传失败恢复。
- 桌面 Dialog、移动 Drawer、关闭后焦点返回原任务。

## 视觉质量要求

- 作品是第一视觉层，应用 chrome 退后。
- 不做通用 SaaS/dashboard：避免多层卡片、每个筛选都套 pill/边框、平均用力的工具条。
- 不使用紫色 AI 渐变、玻璃拟态、装饰性发光或与任务无关的动效。
- 可以为 Assets 域建立独立视觉性格，但不能改全局应用侧栏皮肤。
- 使用现有项目字体和图标体系；新增用户可见文案需 en/ja/zh。
- 状态不能只靠颜色表达；桌面点击目标至少 32/36px，触屏至少 44px；支持 reduced motion。
- 动效只服务 Dock 连续性、选择反馈、资源回流和上传状态。

## 禁改范围

- 不修改生成、provider、credit、auth 或公共 Gallery 语义。
- 不接管画布并行任务。
- 设计阶段不改 `src/**`，不写 page 规范，不宣称实现授权。
- 不运行现有存量缩略图 `--force` 回填；其 immutable key 会产生缓存风险。

3. Owner 选向后，制作一个 1440px 高保真关键切片，至少展示：默认浏览、目录/组织展开、资源详情。

6. 输出可核对的状态与响应式契约，不只提供一张静态美术图。
