## 1. 「丝滑」拆成可工程的维度

帖子核心：**跟手 + 惯性 + 物理衰减**，不是「多几个 fade」。

| 维度          | 用户感知             | 工程手段（2026 主流）                                         |
| ------------- | -------------------- | ------------------------------------------------------------- |
| **跟手**      | 拖/滚几乎零滞后      | 指针事件直连 `transform`；少在 scroll handler 里 setState     |
| **惯性**      | 松手后继续滑、自然停 | 原生 overflow 惯性；或 Lenis 类 smooth-scroll（慎用在精密台） |
| **弹簧/缓动** | 到位不硬切           | CSS `cubic-bezier` / Motion spring；统一 duration 档          |
| **布局连续**  | 展开不「跳」         | `layout` 动画 / FLIP；共享布局 id                             |
| **合成层**    | 60fps                | 只动 `transform`/`opacity`；避免 layout thrash                |
| **克制**      | 久用不累             | 主路径短；装饰少；`prefers-reduced-motion`                    |

业界补充（2025–26）：

- **CSS Scroll-Driven Animations**：滚动驱动尽量上 compositor，少 JS scroll listener。
- **Lenis 等 smooth scroll**：营销站「黄油滚」常见；**仪表盘/创作台**要警惕抢原生滚动与 a11y。
- **Motion（framer-motion）**：SaaS/React 状态驱动 UI 的默认选择。
- **GSAP**：时间线、ScrollTrigger、跨元素编舞更强；营销与复杂 timeline 更合适。

评论共识（同帖线程）：动画很好，但**长时间高频操作**时过度动效会伤效率 → 创作台必须「丝滑但精确」。

## 2. 如何把 PixelVault 做成丝滑（分层）

### 2.1 浏览面（Gallery / 素材网格 / 卡库列表 / 营销）

- 列表：**原生滚动 + 惯性**优先；超长列表虚拟化。
- 卡片 hover：transform 抬升，duration 用全局 token（见 references）。
- 可选：短区间 CSS scroll-driven reveal（非必须 Lenis）。

### 2.2 工作台（Studio / LoRA 装配 / 提示词 / 画布 chrome）

- 面板、Sheet、Popover：**布局过渡 + 焦点管理** > 花哨 timeline。
- 模型选择器 / 下拉：展开 150–250ms 统一 ease；内容区滚动跟手。
- 参数旋钮/滑条：**禁止**松手惯性改值；精确优先。

### 2.3 画布（React Flow）

- 视口 pan/zoom：交给引擎与浏览器；**不要**外包一层 GSAP 抢指针。
- 节点选中、工具条、助手 dock：Motion / CSS token。
- 边/状态：轻量 transition；生成中反馈清晰即可。

### 2.4 性能清单（丝滑的一半是性能）

- 大列表虚拟化；图片懒加载 / 尺寸约束。
- 避免在 `scroll`/`pointermove` 里整树 re-render。
- 动画属性限 transform/opacity。
- 开发者工具 Performance：目标交互路径 60fps。

## 3. GSAP 能否用在工程页（画布 / LoRA / 素材 / 提示词）？

### 3.1 本仓现行硬规则（2026-07-27）

| 区域                                                         | 库                                                            |
| ------------------------------------------------------------ | ------------------------------------------------------------- |
| **App 内部**（画布、Studio、LoRA、Assets、Prompts、ui 原语） | **仅** `motion` / `framer-motion`                             |
| **首页营销**                                                 | GSAP **允许**，且 **动态 import**、不进主 chunk（首页营销域） |

来源：`CLAUDE.md` 动画库分工。gsap-skills 的「默认推 GSAP」**不得**覆盖本规则。

### 3.2 调研结论：工程页 **不建议** 引入 GSAP

| 理由                   | 说明                                                                     |
| ---------------------- | ------------------------------------------------------------------------ |
| **问题类型不匹配**     | 工程页 90% 是状态驱动 UI（开关面板、选中、列表），Motion 更贴 React 模型 |
| **双运行时成本**       | GSAP + Motion 两套时间轴/清理/SSR 心智；包体与维护成本上升               |
| **画布冲突风险**       | React Flow 自管 transform；GSAP 直接 tween DOM 易与 React 抢源           |
| **ScrollTrigger 诱惑** | 素材/提示词若上全局 smooth scroll，易破坏虚拟列表与 a11y                 |
| **许可与技能噪音**     | 工程已指定 Motion；再开 GSAP 会诱导 agent 到处写 timeline                |

### 3.3 GSAP **适合**的场景（本仓已划定）

- 首页 pin / 分段叙事 / 长滚动 storytelling（已有 GSAP 落点）。
- 未来若有 **独立营销落地页**（非 `/studio/*`），可同样动态 import。

### 3.4 若未来要「工程页也用 GSAP」的红线（默认仍否）

仅当同时满足才复议：

1. 某条路径 **Motion 实测掉帧**，且 profile 证明是库瓶颈；
2. 需要 **多秒级多对象 timeline** 且与 React 状态弱耦合；
3. owner **书面改** CLAUDE/brand 分工；
4. **动态 import** + 域隔离，禁止进 `components/ui` 默认路径。

**2026-07-30 建议：不放开。** 画布 / LoRA / 素材 / 提示词继续 **Motion + CSS token**。

### 3.5 Motion vs GSAP 速查（对工程页）

|                               | Motion   | GSAP             |
| ----------------------------- | -------- | ---------------- |
| React 状态/variants           | 强       | 需 useGSAP 小心  |
| 手势 / layout                 | 强       | 弱/另接          |
| 复杂 timeline / ScrollTrigger | 弱       | 强               |
| 营销长滚                      | 可用     | 更强             |
| 本仓工程页                    | **默认** | **禁止（现行）** |
