## 1. 页面职责

`/assets` 是**统一私有资产中心**：所有已完成的生成结果与用户上传资源在此汇集，用户在这里**找、看、整理、复用**。

它首先要回答三个问题：

1. 我刚生成的那个东西在哪？
2. 这一堆东西怎么归到它该在的地方？
3. 我要的那张（那段）是不是这张，能不能马上拿去用？

**不负责**：生成执行（属各创作域）· 公开展示（属 Gallery）· credit · 生成中/失败任务的状态跟踪（仍由原创作域负责，Assets 只承接已完成产物）。

### 路由清单

| 路由                        | 作用                                                                                                                                                                                                                                             |
| --------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| `/assets`                   | 左边文件夹栏 + 全部素材大河                                                                                                                                                                                                                      |
| `/assets?projectId=<id>`    | 大河只剩这个夹（连子夹）；`projectId=none` = 未归档。首屏由服务端读参，切换走 `pushState` + `popstate`。旧的 `?view=folders`（文件夹总览页）已退役，打开落回大厅                                                                                 |
| `/assets?generationId=<id>` | 大厅上直接把这一张打开（桌面 / 平板是就地查看器，手机是全屏详情；列表上下文保留）                                                                                                                                                                |
| `/assets/<id>`              | **素材详情整页**：与抽屉共用 `AssetDetailContent`，只换外壳。服务端按 owner 校验，非本人/未登录一律 `notFound()`（不用 403，避免泄露 id 存在）；`generateMetadata` 给标题 + 封面且恒 `noindex, nofollow`。详情里的「复制链接」复制的就是这条 URL |

## 3. 桌面结构（1440 关键切片）

### 顶栏（单行，高约 56，吸顶长条）

`素材 + 总数` · 类型 · 状态 · 模型 · 时间 · 排序 · ——弹性—— · 上传（主按钮）· 选择 · 密度 S/M/L

- **Owner 2026-08-30 最终确认（第二轮 mock + 真机反馈）**：顶栏固定在素材滚动容器上方，滚动网格时不消失；桌面收为内容区 `11/12`、最大 `1536px` 的居中浮动工具条，约 56px 高、`rounded-2xl`、实色白底、细边框与轻投影，不再使用横贯内容区的全胶囊。后续真机反馈明确移除低价值的顶部搜索框，把五个分面筛选直接放进原搜索区域；框内按“标题 + 数量 + 分面筛选｜弹性留白｜上传主动作 + 选择次动作 + 密度分段”分组，上传是唯一大面积黑色控件。默认无筛选时保持 56px；条件生效后，可删除 chip 与“清除全部筛选”留在同一个吸顶框内并自然增加一行。首次进入以 320ms 轻微下落淡入，滚动吸顶后以 200ms 平滑增强边框/投影，密度选中块以 200ms 滑动；全部遵循 `prefers-reduced-motion`。移动端保持全宽、允许控件换行。

- 密度控制的是**目标行高**（见 §5），不再等价于固定列数 4/6/8。
- ⛔ **顶栏不再放搜索框或两组图标 segmented** —— 统一使用五个文字分面，见 §3.1。

### 3.1 分面筛选栏（取代原来的两组图标 segmented）

放在吸顶顶栏内、紧跟 `素材 + 总数`，占用原搜索框区域；「全部素材」段头只保留当前命中数量。五个**文字**下拉：`类型 · 状态 · 模型 · 时间 ｜ 排序`。

| 维度 | 选择方式    | 选项                           | 数据来源                                          |
| ---- | ----------- | ------------------------------ | ------------------------------------------------- |
| 类型 | 多选        | 图片 / 视频 / 音频 / 3D        | `outputType`                                      |
| 状态 | 多选        | 收藏 / 已发布 / 我上传的       | `isLiked` · `isPublic` · `provider='user-upload'` |
| 模型 | 多选 + 搜索 | 实测 **23 种**                 | `model`                                           |
| 时间 | 单选        | 今天 / 7 天 / 30 天 / 今年     | `createdAt`（引擎已有 `timeRange`）               |
| 排序 | 单选        | 最新 / 最早 / 最近更新的文件夹 | 已有                                              |

**⭐ 默认全部维度未选** = 全部素材、不限类型。**「不选」就是「全部」，不需要一个「全部」按钮**（owner 2026-08-11：初始状态应是全部素材，图片默认不点击）。

- 触发器回显当前值：未选显示维度名（`类型`），选 1 项显示该项名（`图片`），选多项显示 `类型 2`。
- **生效的筛选在顶栏内渲染成可删 chip 行**（仅在有筛选时出现）+ 末尾「清除全部筛选」。一眼看全当前口径，一键回到全部。
- 手机：分面在顶栏内另起一行并允许换行。**不另做一套移动 chips**（一个模型走到底）。

**为什么改**：① 图标组含义不明（地球=已发布？）；② 组内互斥导致无法「图片＋视频」同看；③ 低频搜索框长期占位，而**模型（23 种）和时间是这个库里更有区分度的两个轴**；④ 原「视图」组把状态（收藏/已发布）和来源（本地上传）混成一组，属分类错误。

## 5. 真实比例网格 · 算法契约

> owner 需求 3「当前尺寸限制死，无法展示真实尺寸与比例」的正式解法。实测比例谱 **0.56 → 2.77**（立绘竖条 → 三视图横带），`aspect-square + object-cover` 对这类内容是毁容级裁切。

1. **justified rows**：贪心装行，行内等高，按真实宽高比分配宽度，**整行铺满容器**。
2. **末行也铺满**；仅当铺满会使行高超过目标行高 **1.5 倍**时，才回落到目标行高（末行只剩一两张的情形）。
3. **超宽图与常规图同排**。⛔ 不给超宽图开「独占整行」的特例 —— 独占会在行右侧留下大片空白，而 justified 本身就已经保证不裁切。
4. `ar` 只做安全阀 clamp `[0.4, 3.2]`（防脏数据），真实数据全部原样参与排版。**无意裁切归零。**
5. 无宽高的存量记录（实测 135 条里有 14 条）按 1:1 兜底参与排行。
6. **密度 = 目标行高**，按断点各有一套刻度：

   | 断点          | S   | M（默认） | L   |
   | ------------- | --- | --------- | --- |
   | 桌面 ≥1280    | 150 | 196       | 260 |
   | 平板 768–1279 | 128 | 168       | 222 |
   | 手机 <768     | 92  | 124       | 168 |

7. 容器宽度取**容器自身 `clientWidth`**，不手算 padding；页面加 `scrollbar-gutter: stable`（滚动条出现会让容器缩水，导致已排好的行溢出）。
8. **验收判据是程序化量测**：`行宽 / 容器 clientWidth ≥ 99%` 且 `documentElement.scrollWidth ≤ clientWidth`。⛔ 不接受目测。

> **实现补注（切片 5 / 5b 落地时确定）**
>
> - **进度是真的**：`uploadImageFileAPI` 早就支持 `onProgress`（R2 直传走 XHR），队列直接用它的字节级进度，不是假动画。

### 7.2 「加入文件夹」面板（选择模式与详情共用，2026-09-28 取代「移动到文件夹」）

一张图可以同时在好几个夹里，所以这是「加入」不是「移动」。面板从键长出来（选择条上的「加入文件夹」、详情里的文件夹键）：

1. 头：「加入文件夹」+「已选 N 张」；搜索框（跨层级，子夹带父路径）。
2. 整棵树（两层，▸ 展开子夹；选中的图已经在某个子夹里时父夹自动展开），每行一个勾选框 + 小封面 + 名字 + 张数：**勾 = 选中的都在**，**半勾 = 只有几张在**。
3. 点一行就落库：不是全在 → 全放进去；全在 → 从这个夹拿出。⛔ 没有「确定」。
4. 图例一行说明勾 / 半勾与「点一下 = 全部放进去；再点 = 从这个夹拿出」。
5. 底部「新建文件夹并放进去」：就地打字，回车建在最外层并把选中的放进去。

**撤销契约**：关上面板时若有净变化，底部出一条（6 秒）：只放进一个夹「已放进「X」」、放进好几个「已放进 N 个文件夹」、只拿出一个「已从「X」拿出」、有放有拿「文件夹已更新」。撤销按**每个夹的净变化**往回写（这次新放进去的拿出来、这次拿出的放回去），⛔ 不动原来就在的那些。

### 7.3 上传点击后 —— 缺的是「网格里的占位瓦片」

**现状**：`prependGeneration` **只在上传成功后**调用 → 从点下「上传」到成功为止，网格**毫无反应**，用户只能在角落 toast 里找信号。

**改成乐观占位**：

1. 选中文件 → **网格最前面立即插入占位瓦片**（虚线框 + 文件名 + 进度环 + 百分比），同时右下角上传队列面板出现（§7 上传队列）。
2. 单张完成 → **占位瓦片原地换成真图，不跳位**。
3. 单张失败 → 占位瓦片变**错误瓦片**（红边 + 原因如「超过 15 MB 上限」+ 行内「重试 / 移除」），不静默消失。
4. 落夹目标 = **当前范围**（夹内页 = 该夹；顶部「上传到此夹」按钮同理），队列面板顶部显示目标且可改。
5. 若新资源**不属于当前视图**（例如当前在「收藏」）→ 不插网格，改由队列项给「完成 · 查看」跳过去。现有 `shouldKeepAssetAfterPatch` 已有这个判断，接上即可。
6. 占位瓦片按文件真实宽高比参与 justified 排版（本地 `Image` 可先读到尺寸）；读不到时按 4:5 兜底，拿到真图后重排该行。

## 8. picker（`AssetSelectorDialog`）关键切片

**任务型 shell，与 `/assets` 不同构**（owner 2026-08-09 确认）：共享数据、筛选、网格、选择、上传的行为/API/状态/可访问性，**不共享 shell 与信息架构**。

### 8.1 文件夹选择 —— 176px 可折叠导航栏（⚠ 这条是钟摆的第三个位置，别再荡回去）

**历史**：现状是 280px 竖树 → 被判「吃 40% 宽 = 缩小复刻整个素材页」→ 改成**横向 chips rail** → owner 2026-08-11 指出「文件夹多了这边就不好选择了」，正是原始需求 **F1「文件夹选择目前是横向的，很难选」**。⛔ **两端都试过了，都不对**：

| 形态            | 为什么不行                                                                         |
| --------------- | ---------------------------------------------------------------------------------- |
| 280px 竖树      | 吃掉 40% 对话框宽度，网格只剩三列，且把管理页的 CRUD 一起搬了进来                  |
| 横向 chips rail | 一行装不下 16+ 个夹，其余全塞进 `更多文件夹 ⌄`；**不支持嵌套**（子夹根本没有位置） |

**定案**：左侧 **176px 可折叠导航栏**（880 宽对话框里 = **20%**，非 40%）。与旧竖树的关键差别是**它只装导航，不装管理**——没有新建/重命名/删除、没有密度、没有批量动作。分四组：

1. **智能视图**：最近（默认）/ 全部素材 / 收藏 / 未分类（带计数）。
2. **最近用过**：3 个最近用过的文件夹 —— picker 的最高频路径，一击直达。
3. **全部文件夹**：完整树，`▸` 展开子夹，缩进表达层级，滚动容纳任意数量。
4. 栏顶**搜索文件夹**：跨层级扁平命中，子夹显示父路径（`爱弥丝 鸣潮/`）。夹数量增长时唯一 O(1) 的路径。

行为契约：

- 标题栏有**折叠开关**，收起后网格吃满整宽（记忆用户偏好）。
- `未分类` 只在智能视图出现一次，**不在「全部文件夹」里重复列**（它是系统集合不是用户夹）。
- 点 `▸` 只展开/收起，**不切换范围**；点行本体才切范围。
- 当前范围高亮 = 左侧 2px 黑条（与主页夹树同一语言）；同一个夹若同时出现在「最近用过」和树里，两处同时高亮。
- **<768 手机**：导航栏塌成工具行里的**范围触发器**（显示当前范围名）+ 全屏 sheet，**同一份数据换个壳**；选中即收起。
- 2026-09-28 起：夹的顺序与素材页左栏同一个手动顺序，张数口径同左栏（连子夹、同一张只算一次）；「未分类」改叫**未归档**。

### 8.2 其余结构

- 结构：标题 + 折叠开关 + **只读锁定徽标**（`🔒 仅图片`）+ 关闭 › [导航栏 | 搜索 + justified 小网格（行高桌面 132 / 移动 220）+ 底部条]。
- 顶部搜索只搜**素材内容**（提示词/模型）；**搜文件夹在导航栏自己的搜索框**里，两者不混。
- **首格是内联上传格**（虚线），上传完成即选中。
- **mediaType 锁 = 不渲染，不是灰掉**。锁 `image` 时视频/音频/3D **不进候选** —— 灰掉等于承诺「可选」，会误导。
- 三契约保持：
  - **单选**：点击瓦片 = 选中并立即关闭返回原任务；底部只有「取消」。
  - **多选**：瓦片 checkbox + 底部 `已选 N / 上限 M` + 「添加 N 张」；达到 `maxSelection` 时**拒绝新增并就地红字提示**「最多只能选 M 张，先取消一张再选」，不静默吞掉点击。
  - **mediaType 锁**：见上。

### 8.3 单选 / 多选的判据 —— 看**消费端是槽还是集合**，不是「要不要允许多选」

现状 19 个生产挂载点里**只有 2 个多选**（`LoraTrainingDialog` 训练集、`node/ReferenceLandingTabs` 参考图落地），其余 17 个单选。

**为什么必须保留两种**（⛔ 不要为了「统一」把所有入口改成多选）：

|            | 单选                                                                   | 多选                                                                             |
| ---------- | ---------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| 消费端语义 | **填一个槽**（替换）：`setHydratedGeneration(gen)`、音频封面、角色特写 | **往集合里加**（追加 + 有容量）：`addFromUrl` / `addReferenceFromAsset` / 训练集 |
| 回调       | `onSelect(gen)`                                                        | `onConfirmMany(gens[])` + `maxSelection`                                         |
| 完成动作   | 点一下就返回，**1 击**                                                 | 勾选若干 + 确认，**N+1 击**                                                      |

全改多选 = 17 个高频入口（选参考图是最常做的动作）从 1 击变 2 击，且单槽消费端会收到数组、每个调用点都得自己决定「取哪个算数」。**这是纯回退。**

⚠ **但判据现在用错了地方**：`ReferenceImageChip`（Studio 参考图）的消费端是 `imageUpload.addFromUrl` —— **追加**语义，且 `useImageUpload` 有 `maxImagesRef` 容量（模型声明，如 Kling v3 允许多张）。它是**集合**，却挂成单选 → **要放 4 张参考图得开 4 次弹窗**。`GenerateComposer`（`addReferenceFromAsset`）同型。

→ **施工判据**：逐个调用点问「这个消费端是**替换**还是**追加**」。追加的一律改多选，并把**剩余容量**传给 `maxSelection`（照抄 `LoraTrainingDialog` 的 `MAX_IMAGES - imageUrls.length` 写法）。

**实现补注（切片 6 / 6b / 6c 落地时确定）**

- picker 现在是**自己的组件** `AssetPickerBrowser`，`KreaAssetBrowser` 的 picker 模式（`onSelect` / `pickerMultiSelect` / `pickerMaxSelection` / `mediaType` 四个 prop + 横向 chips rail + 底部确认条）**整体退役，不留开关**。
- 对话框宽度从 `max-w-3xl`(768) 改到 `max-w-4xl`(896)：176px 导航栏在 768 上是 22.9%，超了「≤20%」这条验收判据；896 上是 **19.6%**，也正好回到设计假定的 880 量级。
- 「最近」这一档**没有单独实现**：智能视图里它与「全部素材」在 `sort=newest` 下是**同一条查询**，做两行等于摆一个假承诺。现为 全部 / 收藏 / 未分类 三档，「最近用过」那一组给的是**文件夹**（localStorage，契约本来就这么写）。
- picker 的 localStorage 偏好用**懒初始化**读，不走「先默认值再 effect 纠正」：它挂在 Radix portal 里、服务端从不渲染，因此没有 hydration mismatch，也就不必触发 `setState-in-effect`。
- picker 首帧读取按账号和筛选隔离的图片缓存，后台刷新当前第一页；图片请求使用 `includeTotal=0`，通过游标与 `hasMore` 翻页。分类计数在图片就绪后加载，文件夹及计数复用 30 秒缓存并合并在途请求，上传后强制刷新计数。分类统计由一次多维分组与一次收藏计数组成；类型总数不受所选类型影响，其余导航计数遵循类型筛选。
- **6c 复核结果**（判据 = 消费端替换还是追加）：改成多选的三个 —— `ReferenceImageChip`、`LoraReferenceImageCards`（都是 `imageUpload.addFromUrl` 追加 + `useImageUpload.maxImages` 容量，为此给 hook 补了可渲染的 `maxImages`）、`storyboard`（`[...prev, gen]` 追加、无上限）。保持单选的四个 —— `Studio3DWorkspace`（源图/已有 3D 都是填槽）、`AssetDetailSheet`（音频封面填槽）、`ReverseEngineerPanel`（反推一张；09-24 随拆分与反推删除）、`LoraTrainingDialog`（**本来就是多选**）。`AssistantReferencePicker` 的消费端全在 `node/**`，按 Non-goals 留给画布会话（6d）。

**⚠ 按域分工，17 个调用文件对半开**（本包只动非画布那 8 个）：

| 域                        | 文件                                                                                                                                                                                                  | 本包是否动手                                                                   |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------ |
| **非画布** 8 个           | `ReferenceImageChip`(⚠错挂) · `Studio3DWorkspace` · `LoraTrainingDialog` · `LoraReferenceImageCards` · `AssetDetailSheet` · `AssistantReferencePicker` · `ReverseEngineerPanel`（已删）· `storyboard` | ✅ 动                                                                          |
| **画布 `node/**`\*\* 8 个 | `GenerateComposer` · `VideoComposer` · `ReferenceLandingTabs` · `CanvasAppearancePanel` · `CanvasImageSelectionToolbar` · `CharacterDetailBody` · `ImageFamilyBody` · `VoiceDetailBody`               | ⛔ **只出清单与判据，交画布会话** —— 本包 Non-goals 明写「不接管画布并行任务」 |

**`VideoComposer` ✅ owner 2026-08-11 已拍板：改多选，但必须避免刷屏。** 它选中后走 `spawnReference(...)` —— **每选一张 = 画布上 spawn 一个新节点并连线**，所以「改多选」等于「一次生成 N 个节点」。⚠ **多选只在同一个添加位内成立**（一次选的 N 张共享同一个 `role`，跨 role 批量没有语义）。落位四约束 + 一条「N 个节点会精确重叠」的高置信预测与证伪法：交接 `assets-cf-session-handoff-2026-08-11.md` §六（已随任务包清理，git 历史可取）。**施工归画布会话，不在本包。**

**顺带的实现简化**：`AssetSelectorDialog` 现在按 `multiSelect` 渲染**两整棵 `<KreaAssetBrowser>`**（两套 props、两条路径）。应合成一次渲染 + 一个 `mode` prop —— 两种模式在界面上本就只差 checkbox 与底部条。

- 移动端走底部 drawer（`ResponsiveDialog` 现有行为），关闭后焦点回到触发器。
- ⛔ 不把完整素材页缩进弹窗（现状病根）：**picker 里不出现文件夹门牌墙、不出现密度控制、不出现批量管理动作**。导航栏是任务导航，不是管理面板。

## 10. 与其他业务域的差异来源

Assets **不能长得像** Canvas（深色工程台）或 LoRA（冷瓷灰白装配台）。但差异**不来自配色**——本页明确跟随全局 shadcn 中性皮。差异来自：

1. **内容即主色**：全页 chrome 中性，唯一有色的是作品本身。
2. **真实比例的 justified 节奏**：其他域都是规整卡片阵列，只有这里由内容比例决定版式。
3. **带小封面的文件夹栏**：每个夹一行、一张最近放进来的小封面，拖图上去就放进去。

三个标志性组件：**文件夹栏** · **justified 真实比例大河** · **上传队列面板**。

## 11. 不能破坏

双维组织（视图 × 文件夹）· 所有完成产物自动回流 · picker 三契约 · 密度偏好持久化（`pv:assets:density`）· 上传是资产入口而非生成 · 素材页不执行生成 · `generationId` deeplink · 触屏软键盘策略 · ResponsiveOverlay focus return。
