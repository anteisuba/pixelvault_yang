## 1. video-shotcraft 是什么（事实）

### 1.1 产品形态

| 维度           | 内容                                                                                                                                                                |
| -------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **定位**       | 给 **Claude Code / Codex 等 coding agent** 用的 **Skill**，不是面向终端创作者的 SaaS                                                                                |
| **成片技术**   | **[Remotion](https://www.remotion.dev/)**（React 写时间线 → 确定性渲染 mp4）                                                                                        |
| **画面来源**   | **真实产品页截图** + 2.5D 页面相机（PageCam）+ 手搓字卡/UI 动效；**不是** Seedance/Kling 生成视频                                                                   |
| **核心资产**   | ~104 张镜头配方卡 · ~161 动效样式/样片 Gallery · Ink Press 全片模板 · 149 SFX · 制作流水线文档                                                                      |
| **主客群片种** | Web/桌面 **产品宣传片 / 功能演示 / 发布视频**                                                                                                                       |
| **许可**       | 库本身 **Apache-2.0**；Remotion 另有 [商业许可](https://github.com/remotion-dev/remotion/blob/main/LICENSE.md)（个人/小团队与公司规则不同）；音频见库内 ATTRIBUTION |

### 1.2 仓库结构（可吸收 vs 不可直接嵌）

```text
video-shotcraft/
├── SKILL.md                 # Agent 入口与模式分流（模板 / 自主 / 共创）
├── references/
│   ├── pipeline.md          # 八阶段流水线（简报→styleframe→映射→分镜→采集→实现→声→检）
│   ├── shots/               # 配方卡（10 类：opening/camera/ui-entrance/…）
│   ├── sequences/           # 全片骨架
│   ├── aesthetic-rules.md   # 视觉 QA
│   ├── music-beat-sync.md   # 卡点
│   └── sound-design.md      # SFX 方法论
├── demos/                   # 每卡 Remotion TSX（缓动/时值真相）
├── gallery/                 # 静态样片站
├── template/                # 可渲染完整工程
└── assets/lib|scripts|audio # 组件、截图脚本、BGM/SFX
```

### 1.3 它的「助手」是谁

- **执行者** = 本机/CI 上的 **coding agent**（读 SKILL、写 Remotion、跑 `npx remotion still/render`）。
- **不是** 浏览器里的聊天 dock。
- 确认模型（共创）：廉价确认物前置（简报 → 方向 → 镜头映射 → 分镜放行 → 再实现）。

### 1.4 镜头卡价值形态（抽象）

每张卡大致提供（语义层，可移植）：

- **用途 / 能量 / 建议时长**
- **运动语法**（飞入、orbit、发牌、字标落地…）
- **参数表与已知坑**
- **demo 源码**（只对 Remotion 路径有执行价值）

Gallery 在线：https://vincentwei1021.github.io/video-shotcraft/

## 2. PixelVault 助手现状（对照事实）

### 2.1 助手在产品里的位置

| 面                      | 角色                                                                   |
| ----------------------- | ---------------------------------------------------------------------- |
| **画布助手 dock**       | 「剧本脑」：对话 →（目标）ScriptDoc → 投影节点 → 生成图/视频           |
| **Studio prompt 助手**  | 提示增强 / 装配，与画布分壳                                            |
| **成片主路径**          | 多模型 **生成式** 媒体：图 + Seedance Reference 等视频；角色卡身份编译 |
| **北极星（已有 plan）** | 一句话 + 素材 → 助手铺画布 → 出片（`canvas-assistant-pipeline`）       |

### 2.2 已知断层（与 shotcraft 无关但决定「合」的时机）

1. 助手写画布能力不完整（工具/审批链）
2. 读节点上下文曾残缺（名字/`@`）
3. **散文剧本 → ScriptDoc 结构化** 仍是主缺口
4. 批量队列/取消等执行层

→ **在管道未通前硬塞 Remotion，只会再开一条半残产品线。**

### 2.3 数据落点

- `ScriptDoc`：`roles` / `shots`（summary、camera、emotion、dialogue…）→ `projectScriptDocToGraph`
- 视频：节点 harvest → `image_urls` / `@ImageN` → Seedance 等
- **无 Remotion 依赖**；app 内动画栈是 `motion`/`framer-motion`（首页 GSAP 另域）

## 3. 本质差异（为什么不能「整库合并」）

| 维度             | video-shotcraft                   | PixelVault 画布助手                   |
| ---------------- | --------------------------------- | ------------------------------------- |
| **像素从哪来**   | 截图 + 代码动画（确定性）         | 生成模型（随机/参考约束）             |
| **「镜头」含义** | 动效配方 + Remotion 实现          | 叙事分镜 + 生成 prompt/参考           |
| **角色一致性**   | 页面/UI 为主，弱角色戏            | **CharacterCard / 多镜身份** 一等     |
| **执行环境**     | 本机 agent + Node + Chromium 渲染 | 浏览器 SaaS + API + Worker            |
| **时长形态**     | 常 30–40s 宣发片、帧级时间轴      | 多镜短 clip 拼接、模型时长 cap        |
| **声音**         | 钉帧 SFX + BGM 卡点               | TTS / 参考音频 / 模型原生声（另一套） |
| **用户**         | 开发者用 agent 出片               | 创作者在画布里排演生成                |
| **成功标准**     | 像素 QA、缓动命门、卡点 ≤3f       | 脸不漂、戏通、参考编译正确            |

**隐喻：**

- shotcraft = **「用代码搭的产品宣传片摄影棚」**
- PixelVault = **「多模型 AI 片场 + 身份卡 + 节点导演台」**

共享的是 **导演语言**（节奏、能量曲线、一镜一动效、呼吸位），不是 **摄影机机身**。

## 4. 合并可能性：三档方案

### 方案 A — 知识蒸馏进助手（**推荐默认**）

**合什么**

| 吸收                          | 做法                                                     | 不吸收                           |
| ----------------------------- | -------------------------------------------------------- | -------------------------------- |
| 八阶段流水线的 **产品化裁剪** | 助手 system / 路由：简报→风格→映射→分镜→（生成）→审      | Remotion 实现阶段整段            |
| 镜头卡 **frontmatter 语义**   | 内置「运动/机位词表」：能量、建议秒数、适用场景          | demo TSX、PageCam                |
| sequences 能量曲线            | ScriptDoc 生成时约束：开场低能→功能段→收尾高能；一镜一动 | 帧级 `beatF(n)` 除非做 BGM 高级  |
| aesthetic 可迁移条            | 「呼吸 hold」「禁装饰 glint 群发」→ 审片 checklist 文案  | remotion still 工作流            |
| Gallery 用法                  | 外链或镜像 **样片索引** 给用户「挑运动感觉」             | 把 161 mp4 全进 monorepo（体积） |

**落到本仓的接口（设计向）**

```text
用户：「帮我排一支 8 镜短片 / 产品介绍」
  → 助手（结构化）输出 ScriptDoc
       camera / summary 可引用 shotcraft 风格标签
       例：camera="orbit close-up, single hero arc, hold 1s on logo"
  → projectScriptDocToGraph
  → 生成仍走 Seedance/图模型（卡编译见角色卡调研 §10）
```

可选数据：

- `docs/` 或 `src/constants/` 下 **精简 shot lexicon**（20–40 条常用，不必 104 全搬）
- ScriptDocShot 可选字段：`motionRecipeId` / `energy`（中期）

**工作量级**：文档 + prompt/lexicon +（可选）字段 — **周级**，且不挡 P0 管道。  
**风险**：低。许可 Apache-2.0 可衍生；注明出处与 NOTICE 即可。

---

### 方案 B — 「产品宣传片」旁路模式（**有明确 B2B 宣发需求时**）

在助手里增加 **创作模式开关**，与叙事 AI 片场并列：

| 模式                      | 后端                                               | 用户得到               |
| ------------------------- | -------------------------------------------------- | ---------------------- |
| **AI 片场（默认）**       | ScriptDoc → 画布 → 生成模型                        | 角色戏、风格化、多模态 |
| **宣发·Remotion（旁路）** | 导出 brief + 镜头表 +（远期）触发 Remotion 工程/CI | 像素级 UI 产品片       |

实现阶梯：

1. **B0**：助手只输出 shotcraft 兼容的「设计 spec / 分镜 Markdown」+ 外链 Gallery 卡名 → 用户自己在 agent 里跑 skill（**零合并代码**）。
2. **B1**：服务端打包 `template` 替换清单（截图 URL、文案）下载 zip。
3. **B2**：CI/Worker 跑 Remotion render（**重**：Chromium、并发、Remotion 公司许可、成本）。

**何时才做 B2**：owner 明确要「站内一键渲宣传片」且接受 Remotion 许可与渲染成本。  
**否则停在 A 或 B0。**

---

### 方案 C — 全栈合并（**否决建议**）

把 demos/template/assets/lib 并进 Next 应用、助手直接写 Remotion 并渲染。

| 问题     | 说明                                                      |
| -------- | --------------------------------------------------------- |
| 双引擎   | 生成视频 + Remotion 时间线，产品叙事分裂                  |
| 栈冲突   | Remotion/Three 渲染与现有 Worker/fal 链路无关；运维面翻倍 |
| 用户错位 | 创作者要角色一致与生成，不是 dev server 截图表            |
| 机会成本 | 助手管道 P0–P2 未完，合并会拖死北极星                     |

## 10. Claude 联动全流程拆解（她怎么做到的）

> 回答：「和 Claude 联动产出剧本然后生成视频」的**真实机制**，以及 PixelVault 可抄的流程优化点。

### 10.1 她没有「API 打通 Claude 产品」

video-shotcraft **不是** Claude.ai 插件，也不是站内嵌 Claude。

| 层               | 实际是什么                                                                                                             |
| ---------------- | ---------------------------------------------------------------------------------------------------------------------- |
| **运行时**       | 用户本机 **Claude Code / Codex**（能读文件、写代码、跑终端）                                                           |
| **联动方式**     | 仓库当 **Skill**：`SKILL.md` 进 agent 上下文；agent **按文档阶段** 读 `references/*`、写 Remotion、执行 `npx remotion` |
| **「剧本」**     | 设计 spec + 分镜表（Markdown/表格），存在项目文件里，**不是** SaaS 的 ScriptDoc                                        |
| **「生成视频」** | **确定性渲染**（截图纹理 + TSX 动画 + SFX），**不是** 文生视频 API                                                     |

所以「和 Claude 联动」= **把制作方法写成 agent 可执行的说明书 + 配方库 + 可跑工程**，让 Claude **当制片+剪辑工程师**。

### 10.2 端到端流水线（共创模式，最完整）

```text
用户：装 skill / 丢 repo 链接 →「给我的产品做宣传片」
        │
        ▼
【入口】SKILL.md 模式分流
  · 模板 Ink Press / 自主自由创作 / 共同创作
  · 可选：Gallery 挑镜头卡名
        │
        ▼
┌─ 阶段 0  产品理解 ─────────────────────────────┐
│ 只读检查项目（路由/视觉 token/数据风险）          │
│ 产出：产品简报（Agent 先填推荐+依据，再问 1–3 问）│
└────────────────────────────────────────────────┘
        │ 用户确认
        ▼
┌─ 需求→执行决策表 ──────────────────────────────┐
│ 用途/受众/时长/音乐/合规 → 可追溯执行选择         │
└────────────────────────────────────────────────┘
        │
        ▼
┌─ 阶段 1  视觉方向 ─────────────────────────────┐
│ ≤3 个文字方向 →（可选）HTML styleframe 静帧      │
│ 锁定色板/字体/动效性格 tokens — 还不写视频代码     │
└────────────────────────────────────────────────┘
        │ 用户确认方向
        ▼
┌─ 阶段 2  功能→镜头映射 ────────────────────────┐
│ 功能清单 × shots/ 配方卡 frontmatter             │
│ 「用哪种运动语法讲这个功能」— 还不是完整分镜      │
└────────────────────────────────────────────────┘
        │ 用户确认映射
        ▼
┌─ 阶段 3  完整分镜 + 制作放行 ──────────────────┐
│ 顺序/时长/主动作/素材/字幕/SFX + 能量曲线        │
│ 放行后：不再重开业务题，只补实现细节               │
│ 产出物 = 稳定「设计 spec」（审查基准）             │
└────────────────────────────────────────────────┘
        │ ★ 剧本/分镜在这里锁死
        ▼
┌─ 阶段 4  最终素材采集 ─────────────────────────┐
│ 按分镜截全页 2x + 元素切片 + layout.json         │
│ （放行前不做全量采集，避免废片）                   │
└────────────────────────────────────────────────┘
        │
        ▼
┌─ 阶段 5  逐镜头实现（=「生成视频」）────────────┐
│ 每镜：library.json 校验卡名 → 读配方卡 → 读 demo  │
│ TSX → copy 组件 → 换产品截图/文案                 │
│ 每镜 remotion still 自检 → 改完整片 re-render     │
└────────────────────────────────────────────────┘
        │
        ▼
┌─ 阶段 6  声音 ─────────────────────────────────┐
│ 画面时间线锁定后才钉 SFX；BGM 卡点可选            │
└────────────────────────────────────────────────┘
        │
        ▼
┌─ 阶段 7  独立终检 ─────────────────────────────┐
│ 干净上下文 subagent 对照 aesthetic + 设计 spec   │
│ 终渲：带 BGM / 无 BGM 两版                        │
└────────────────────────────────────────────────┘
```

**自主模式**：0–3 不暂停，Agent 自己记判断连续干完。  
**模板模式**：跳过创作，按 Ink Press 换皮。

### 10.3 为什么这条链「像能成片」

| 设计点                     | 作用                                                     |
| -------------------------- | -------------------------------------------------------- |
| **廉价确认前置**           | 方向/分镜用表与静帧定，不在渲视频后才吵架                |
| **配方卡 + demo 源码**     | 语义卡 ≠ 实现；**demo 是参数真相**，禁止凭卡名瞎写       |
| **一镜一动 + 呼吸位**      | 降低同质化与节奏翻车                                     |
| **分镜放行后才全量采素材** | 控制返工半径                                             |
| **验收贯穿 + 独立审查**    | 制作者自检有确认偏差                                     |
| **Agent 有手**             | 能读写文件、跑命令 — 比「只会聊」的助手强在 **执行闭环** |

### 10.4 和 PixelVault 目标链路对照

```text
【shotcraft + Claude Code】
  聊/读项目 → 简报表 → 方向 → 映射 → 分镜(放行)
       → 截图素材 → Remotion 代码 → still/render → 声 → 检
       （全程 agent 有 shell + 文件系统）

【PixelVault 目标北极星】
  聊 → ScriptDoc → 投影画布节点 → 批量生成图/视频
       → 用户审 → Seedance 等汇点
       （浏览器 SaaS；执行靠 API + Worker）

【PixelVault 今日缺口（管道 plan）】
  聊 → 常停在 Markdown 散文
       ✗ 未稳定落入 ScriptDoc
       ✗ 助手不能可靠建节点/连线
       ✗ 自动链最后一环易断
  （内容质量可以；管子没接上）
```

## 11. 放到本项目：可优化的流程（按优先级）

> 原则：**抄她的「阶段门 + 结构化放行 + 廉价确认」**；**不抄 Remotion 当主成片机**。  
> 身份/生成仍走角色卡编译 + Seedance（见角色卡调研 §10）。

### 11.1 流程改造总图（建议）

```text
用户一句话 / 素材 / 卡
        │
        ▼
① 创作简报门（新，薄）     ← 学 shotcraft 阶段0：用途·时长·角色·调性
        │ 确认或「全权」
        ▼
② ScriptDoc 大纲门         ← 已有两阶段引擎；对话路径必须走 JSON
        │ 确认
        ▼
③ 分镜深稿门               ← camera/emotion/dialogue；注入运动词表(可选)
        │ ★ 制作放行 = ScriptDoc 锁定版本
        ▼
④ 投影画布                 ← projectScriptDocToGraph（补 shot/bg）
        │ 应用前询问（已有骨架）
        ▼
⑤ 定妆/参考齐套            ← 角色卡 ≥1 图；节点覆盖；可选锁定
        │
        ▼
⑥ 批量生成 + 审阅态        ← 学「每镜 still」→ 每节点 通过/重来
        │
        ▼
⑦ 视频汇点 Seedance        ← 编译卡/参考，不是塞剧本全文
        │
        ▼
⑧ 可选：成片检查清单       ← 学 aesthetic 可迁移条（一镜一信息等）
```

### 11.2 可直接学的流程优化（不引入 Remotion）

| #       | 学她什么                           | 本仓怎么落                                                                                      | 价值                          | 依赖               |
| ------- | ---------------------------------- | ----------------------------------------------------------------------------------------------- | ----------------------------- | ------------------ |
| **F1**  | **结构化输出，禁止散文当分镜真相** | 助手大纲/分镜路径 **强制** `ScriptDoc` JSON（`node-script-doc.service` 已有契约，对话路径接上） | 堵住断层③                     | P2                 |

| **F9**  | **设计 spec 作审查基准**           | 放行时的 ScriptDoc 快照 + 选用角色卡 id 列表，供「重生成对照」                                  | 可复现                        | 轻量               |
| **F10** | **独立终检思路（弱化）**           | 助手「成片检查」模式：只读对照 F9，不重写分镜                                                   | 后期                          | 非 P0              |

### 11.3 不要学的（会歪主线）

| 她的做法                | 为何不原样搬                                          |
| ----------------------- | ----------------------------------------------------- |
| 分镜后全量页面截图采集  | 你主路径是生成图/参考图，不是 dev server 截产品页     |
| 每镜 copy Remotion demo | 成片机不同                                            |
| 帧级 SFX 钉表           | 除非做时间线剪辑产品；Seedance 声另一路               |
| 自主模式一路不停确认    | SaaS 烧 credit，默认应 **共创门** 或明确「全权+预算」 |

### 11.4 与现有任务包的对齐

| 管道 plan         | 对应本节                         |
| ----------------- | -------------------------------- |
| P0 节点名 / `@`   | 助手「有眼」— 投影后才能闭环引用 |
| P1 写画布工具     | F6 — 对标 Claude「有手」         |
| P2 散文→ScriptDoc | F1/F4 — 对标分镜真相源           |
| P3 队列取消       | 批量生成可运营                   |
| 审阅态 / 批量审   | F7                               |

### 11.5 一句话产品契约（可写进 domain）

> 助手负责把对话收敛成 **可放行的 ScriptDoc**；画布负责 **投影与生成**；角色卡负责 **身份视觉**；视频模型只吃 **编译后的媒体+瘦 prompt**。  
> 任何一步若仍是「只有聊天记录、没有结构化真相」，都不得进入烧钱生成。

## 12. 产品意图升级：剧本节点 + 人工审核门（owner 2026-07-30）

> 本节是对 **§0–§11 知识蒸馏结论** 的**产品向延伸**，不是推翻「不整仓合并 Remotion」。  
> 目标：把 shotcraft / Runway Agent / LTX / 学术 STAGE 等的 **阶段门 + 审核**，落到 PixelVault 画布上的 **一等节点：剧本节点**。

### 12.1 用户意图收敛（原话 → 可设计需求）

| #   | 用户说法                                                   | 产品语义                                                                 |
| --- | ---------------------------------------------------------- | ------------------------------------------------------------------------ |
| 1   | 做「剧本」节点                                             | 画布上有一个 **Script / Episode 对象**，不是仅 dock 里的聊天气泡         |
| 2   | LLM 设计人物、服装、背景、镜头、音频，最终视频             | **多阶段制片管道**：身份 → 定妆/服化 → 场景 → 分镜静帧 → 音频 → 视频汇点 |
| 3   | 每次生成都要人工审核；要的就过，不要就打回改 prompt 重生成 | **Human-in-the-loop（HITL）** 为默认；过审资产才可下游消费               |
| 4   | 助手生成剧本节点到画布                                     | 助手 **有手**：投影/创建 Script 节点 + 子图骨架                          |
| 5   | 根据上传的图/视频拆解分析，再生成新图/视频                 | **分析入口**（参考拆解）+ **生成出口** 双轨；分析也要可审                |
| 6   | 执行用 AI，改成什么样由用户定；也可纯手动                  | **双轨操控**：Agent 提议 / 用户改提示词或手动画节点；同一真相源          |

**一句话：**

> **剧本节点 = 结构化制片合同（ScriptDoc + 审核状态）在画布上的壳；**  
> **LLM = 提议与执行的手；用户 = 每一镜/每一张身份的最终导演。**

### 12.2 业界对照（2026 联网快扫）

> 用途：找 **交互契约与管线形状**，不抄对方成片引擎。链接随产品改版可能变，以官方页为准。

#### 12.2.1 Runway Agent（最接近「助手 + 审 + 多镜」）

来源：[Creating with Runway Agent](https://help.runwayml.com/hc/en-us/articles/51601639579667-Creating-with-Runway-Agent)（help 文，抓取日约 2026-07）。

| 能力                     | 做法                                                      | 对本仓的启示                                                   |
| ------------------------ | --------------------------------------------------------- | -------------------------------------------------------------- |
| **计划 → 生成**          | Agent 先计划，再选模型生成图/视频/声/乐/旁白              | 不要「聊完直接烧 12 路」；先结构化计划                         |
| **生成前审批开关**       | **Ask before generating media** vs Automatically generate | **默认 Ask** 对齐 owner「每次审核」；全权模式必须显式 + 预算感 |
| **计划可改**             | 用户先认可 outline 再 burn credit                         | = shotcraft 廉价确认 + 本仓 F5                                 |
| **多镜自动拼 Final Cut** | 多 clip 进时间线，可手动 trim/split                       | PV 已有视频汇点/装配方向；**先审单镜再拼** 更贴 owner          |
| **Generations 网格**     | 会话产物网格浏览                                          | = 管道 plan 已写的 **批量审阅视图**                            |
| **模型择优偏好**         | Speed / Cost / Quality                                    | 后期；本期先固定用户选的模型族                                 |

社区观察（二级来源，仅作旁证）：Agent 2.0 叙事里常见 **先认 storyboard 再生成、弱镜可 flag**——与「分镜放行」同构。

#### 12.2.2 LTX Studio Elements（最接近「身份跨镜绑定」）

来源：[LTX How to Storyboard](https://ltx.io/blog/how-to-storyboard) 等公开文。

| 能力                      | 做法                                  | 对本仓的启示                                                                                 |
| ------------------------- | ------------------------------------- | -------------------------------------------------------------------------------------------- |
| **Elements**              | 角色/道具/服装/场景标成可复用 Element | 对齐 **CharacterCard / 背景卡 / 图集**，不是再造一套「聊天里的角色」                         |
| **剧本名 → 同一 Element** | 第 1 场与第 7 场同名角色绑同一参考    | ScriptDoc `roleIds` + 节点 `scriptRef` 已有挂钩；**审核通过后的定妆图才应成为 Element 真源** |
| **分镜后可手改**          | 改角色、机位、风格再出片              | 双轨：LLM 提议 + 用户改节点                                                                  |

公开评测共性：storyboard 一致性「够 pitch」；成片角色仍要 **人工抽检**——支持 owner 的强制审核门，不要做成全自动黑箱。

#### 12.2.3 Kling Agent / 一键分镜（参考品，非合并对象）

公开 release 叙事：**一键 storyboard → 多角度 → 批量生成**。偏「快产」；**弱 HITL**。  
对 PV：**可学入口一键**，但默认节奏必须比 Kling 更「共创」，否则与「每步审核」冲突。

#### 12.2.4 学术 / 框架：STAGE 等（管线形状）

[STAGE: Storyboard-Anchored Generation](https://arxiv.org/abs/2512.12372)（CVPR 2026 线）公开流程抽象：

```text
Director Agent → 结构化分镜
    → 起止关键帧（STEP）
    → Refiner Agent 增强 prompt
    → 现成视频模型出多镜
```

**可抄：** Director / Refiner **分职**、关键帧锚定、多镜记忆包思路。  
**不抄：** 端到端替换 PV 的 Seedance/Kling 执行层；训练 STEP 不在本产品范围。

NVIDIA 等 **Video Storyboarding**（多镜特征共享）属模型侧一致性，产品侧仍应用 **参考图/卡编译**（本仓已有路径）。

#### 12.2.5 video-shotcraft（已评，重申与剧本节点关系）

| shotcraft            | 剧本节点产品                              |
| -------------------- | ----------------------------------------- |
| 共创模式阶段门       | **审核门状态机**（§13）                   |
| 设计 spec 作审查基准 | **锁定的 ScriptDoc 版本 + 已过审资产 id** |
| 每镜 still 自检      | **每节点 待审→通过/打回**                 |
| Remotion 实现        | **不进主路径**（仍 §4 方案 C 否）         |

#### 12.2.6 业界共性 → 本仓必须遵守的 5 条

1. **计划与生成分离**；默认生成前有人类闸。
2. **身份是跨镜一等公民**（Element/Card），不是每镜重写外貌。
3. **分镜/关键帧比成片便宜**，先锁再烧视频 credit。
4. **网格审阅** 是多节点产品的必需品，不是锦上添花。
5. **Agent 提议 ≠ 结果保证**；产品文案与 UX 必须承认迭代环。

## 13. 本仓怎么设计：剧本节点（Script Node）草案

> **非实现授权。** 与 `canvas-assistant-pipeline`、现有 `ScriptDoc`、节点族能力设计对齐；冲突时以已拍板管道 plan 为准，本节只补「剧本壳 + 审核门」形状。

### 13.1 概念分层（避免「剧本」一词三义）

| 层            | 是什么                         | 今天落点                         | 剧本节点后                             |
| ------------- | ------------------------------ | -------------------------------- | -------------------------------------- |
| **L0 对话**   | 助手聊                         | dock 消息                        | 仍存在；**不能**当分镜真相             |
| **L1 合同**   | 结构化剧本                     | `ScriptDoc`（`roles`/`shots`/…） | **真相源**；版本化                     |
| **L2 壳**     | 画布上的「这一集/这条片」      | **缺一等节点**                   | **`script` 剧本节点**（本节）          |
| **L3 执行图** | 角色/背景/镜头静帧/声/视频节点 | 已有节点族 + 投影                | 由 L1 投影/增量更新；**审核态**挂在 L3 |
| **L4 成片**   | 多镜拼接/导出                  | 视频汇点 / assembly 方向         | 仅消费 **已过审** 视频节点             |

**原则：** 剧本节点 **不代替** 角色卡、不代替视频卡；它是 **目录 + 状态机 + 放行开关**，子资产仍是画布上的独立节点（可审、可手改、可重生成）。

### 13.2 用户故事（端到端）

```text
A. 从零
   用户对助手：「做一个 6 镜雨夜追逐短片」
   → 助手产出/更新 ScriptDoc（L1）
   → 画布出现【剧本节点】（L2）+ 投影骨架角色/场景/镜头位（L3，未生成）
   → 用户在剧本节点或网格里逐步「放行生成」
   → 每张图/每段视频：待审 → 通过 | 打回（改 prompt / 换参考）→ 再生成
   → 全镜过审后：视频汇点可拼 / 导出

B. 从素材
   用户上传参考图/视频 → 挂到剧本节点「参考匣」或分析任务
   → LLM 拆解：人物候选、服装、场景、节奏/镜头建议（分析稿，待审）
   → 用户勾选采纳 → 写入 ScriptDoc + 生成身份卡/节点
   → 同 A 的生成与审核环

C. 纯手动
   用户不经过助手：自己建角色/镜头/视频
   → 可选「收编进剧本节点」绑定 scriptRef
   → 同一审核态与下游规则
```

### 13.3 剧本节点在画布上长什么样（信息架构）

**卡面（建议）**

| 区域   | 内容                                                                        |
| ------ | --------------------------------------------------------------------------- |
| 标题   | 片名 / ScriptDoc.title                                                      |
| 进度条 | 阶段：简报 · 大纲 · 分镜锁 · 定妆 · 分镜静帧 · 音频 · 视频 · 成片           |
| 计数   | 角色 n · 镜 m · 已过审 / 待审 / 失败                                        |
| 参考匣 | 用户上传的图/视频缩略（分析源）                                             |
| 主 CTA | 当前阶段主动作唯一：`推进计划` / `放行本批生成` / `打开审阅网格` / `拼成片` |
| 次要   | 打开 ScriptDoc 表 · 解锁分镜 · 全权模式（危险）                             |

**展开 / 详情**

- ScriptDoc 表视图（角色行、镜号、camera、dialogue）—— **廉价确认物**
- 与画布节点的链接列表（点击定位）
- 审核日志（谁过审、打回原因、prompt 版本）

**不做什么**

- 不在剧本卡内嵌完整视频时间线编辑器（成片编辑可另表面）
- 不把 12 路生成进度全塞进一张卡（用审阅网格 + 节点盖章）

### 13.4 与现有类型/投影的关系

| 已有                            | 剧本节点如何用                                               |
| ------------------------------- | ------------------------------------------------------------ |
| `ScriptDoc` / `ScriptDocSchema` | L1 唯一合同；剧本节点 `data.scriptDocId` 或内嵌快照 + 版本号 |
| `scriptRef` on nodes            | L3 节点挂回 L1/L2；重投影更新而非复制                        |
| `projectScriptDocToGraph`       | 从 L1 生成/更新 L3；**补 shot + background**（管道 P2 连带） |
| 角色卡 / Identity               | 定妆过审后的图 → 身份真源（对齐 LTX Element）                |
| 助手「应用前询问」              | 扩展为：**计划应用** + **批量生成放行** 两级门               |
| 节点盖章四态                    | **+ 待审（awaiting_review）**（管道 plan §2.2 已点名）       |

### 13.5 阶段管道（推荐默认，可折叠）

对齐 shotcraft 共创 + Runway Ask + 本仓 F 系列，裁成 **可计费友好** 的 8 门：

```text
G0  意图/简报        用途·时长·调性·素材范围          [确认]
G1  大纲 ScriptDoc    roles 粗 + shots 摘要            [确认]
G2  分镜深稿          camera/emotion/dialogue/服装提示  [★ 制作放行 = 锁版本]
G3  身份定妆          角色/服装参考图生成              [每资产审核]
G4  场景/道具         背景图等                         [每资产审核]
G5  分镜静帧          shot 关键帧（可选但强烈建议）    [每资产审核]
G6  音频              TTS/参考声/BGM 草稿               [每资产审核]
G7  视频 clip         Seedance/Kling… 吃已过审参考     [每镜审核]
G8  汇点/成片         仅已过审 clip                     [终检可选]
```

**规则：**

- **G2 前** 默认不批量烧图视频（廉价确认）。
- **G3–G7** 默认 **单资产或小批** 放行；「全权连跑」需二次确认 + 预估 credit。
- **打回** 只重开 **该资产及其直接下游**（例如定妆打回 → 依赖该脸的未过审视频作废或标脏），不默认撕掉整份 ScriptDoc。
- **解锁 G2** 才允许改 logline/镜数结构（学 shotcraft「放行后不重开业务题」）。

### 13.6 审核状态机（节点级）

```text
                    ┌──────────────┐
                    │  draft       │  仅有 prompt/槽，未请求生成
                    └──────┬───────┘
                           │ 用户或助手「放行生成」
                           ▼
                    ┌──────────────┐
                    │  generating  │
                    └──────┬───────┘
                           │
              ┌────────────┼────────────┐
              ▼            ▼            ▼
         completed     failed      cancelled
              │
              ▼
        ┌─────────────┐
        │ awaiting_   │  ★ 新增默认态（自动铺出后）
        │ review      │
        └──────┬──────┘
               │
       ┌───────┴────────┐
       ▼                ▼
  approved          rejected
  （可被下游      （回 draft/generating
   harvest）        用户改 prompt/参考）
```

**下游消费规则（硬）：**

- 视频 harvest **默认只吃** `approved` 的身份图/静帧/声。
- `awaiting_review` / `rejected` **不得静默进** `image_urls`（可提示「未过审参考已排除」）。
- 手动强制「用未过审」= 显式危险操作（可选后期）。

**打回载荷（建议字段）：**

- `rejectReason`（可选短文本）
- `promptPatch` 用户编辑后的下一版 prompt
- `reviewer`（user）· `reviewedAt`
- 保留上一版媒体 URL 作对比（不立刻删 R2）

### 13.7 执行权：谁提议、谁拍板、谁动手

| 动作            | LLM/助手                       | 用户                               |
| --------------- | ------------------------------ | ---------------------------------- |
| 写/改 ScriptDoc | 提议 + 结构化写入（经审批）    | 表内手改、解锁后改结构             |
| 建节点/连线     | 工具调用（P1）经「应用前询问」 | 完全可手动画布                     |
| 写生成 prompt   | 从 ScriptDoc + 卡编译生成建议  | **可整段覆盖**；打回后以用户版为准 |
| 点生成          | 仅在「已放行」队列执行         | 主 CTA / 网格批量过审生成          |
| 过审/打回       | **不得**自批自过（防确认偏差） | **唯一人**（未来团队再谈角色）     |
| 上传分析        | 出「拆解草案」                 | 勾选采纳哪些角色/镜头              |

**产品契约（可进 domain）：**

> AI 可以建议一切、执行一切已放行的生成；  
> **「这是否算数」只由用户的审核动作决定。**

### 13.8 上传图/视频：拆解分析轨

```text
上传 → 分析任务（多模态 LLM；视频理解优先已有 Gemini 视频能力路径）
     → 分析稿（非 ScriptDoc）：
          · 出场人物候选 + 外貌/服装描述
          · 场景/时间/天气
          · 镜头切分建议 / 节奏
          · 可用作参考的关键帧时间戳（若视频）
     → 用户勾选
     → 写入 ScriptDoc + 创建/更新节点 + 参考图挂载
     → 进入 G3+ 生成与审核（新生成 ≠ 原片搬运，除非用户要「重绘同构图」）
```

**边界：**

- 分析稿 **也要确认门**（廉价），避免「拆错人设却连烧 20 张」。
- 版权/肖像：产品层提示用户对上传素材有权使用（法务文案另案）。
- 与「永久归档」：过审生成物进 Gallery/Assets；草稿可 TTL 策略另定。

### 13.9 助手如何「生成一个剧本节点」

依赖管道 plan 的 **P1 写画布 + P2 ScriptDoc**，建议工具粒度：

| 工具（概念名）                 | 作用                                                           |
| ------------------------------ | -------------------------------------------------------------- |
| `upsert_script_doc`            | 写 L1                                                          |
| `ensure_script_node`           | 画布上创建/更新 L2 壳，绑 project                              |
| `project_script`               | 调投影：角色/背景/shot 位                                      |
| `propose_generation_batch`     | 列本批将烧的节点 + 模型 + 估 credit —— **停等用户**            |
| `enqueue_approved_generations` | 仅 `approved_to_run` 队列                                      |
| `set_review_state`             | **禁止**助手把节点标为 approved；最多标 generating/failed 辅助 |

「应用前询问」UI 应对 **propose\_\*** 类工具展示：计划 diff + 费用感。

## 14. 方案对比与拍板框（剧本节点专题）

### 14.1 三种产品形态

| 方案                             | 形态                     | 优点                            | 缺点                              | 建议     |
| -------------------------------- | ------------------------ | ------------------------------- | --------------------------------- | -------- |
| **S0 仅 dock**                   | 剧本只在助手里           | 开发量小                        | 无画布锚点、难审、难进度          | 过渡期   |
| **S1 剧本节点 + 子节点**（推荐） | L2 壳 + L3 执行图 + HITL | 对齐画布心智、可手动可 AI、可审 | 要补投影/审核态/网格              | **默认** |
| **S2 超级剧本卡内嵌一切**        | 单卡吞掉所有生成         | 表面简单                        | 违背「节点=对象」、难连接、难双轨 | 否       |

### 14.2 审核粒度

| 粒度               | 说明            | 建议                   |
| ------------------ | --------------- | ---------------------- | ------------------------ |
| 仅整集过审         | 一次点通过全片  | 太粗，废 credit        |
| **每生成资产过审** | 每张图/每段视频 | **默认**（owner 原意） |
| 仅视频过审         | 图自动过        | 角色漂了难追           | 可选「信任定妆」高级设置 |

### 14.3 待 owner 拍板

| #   | 问题                                | 建议默认                             |
| --- | ----------------------------------- | ------------------------------------ |
| 1   | 剧本节点是否一等节点族（新 type）？ | **是（S1）**                         |
| 2   | 默认 Ask before generate？          | **是**                               |
| 3   | 定妆未过审能否进视频？              | **否**                               |
| 4   | 助手可否自动标 approved？           | **否**                               |
| 5   | G5 分镜静帧是否强制？               | **默认开，可项目关**（省 credit）    |
| 6   | 上传分析是否一期？                  | **二期**；一期先 ScriptDoc+审核+网格 |
| 7   | 与 shotcraft Remotion？             | **仍不进主路径**（A 知识蒸馏）       |

### 14.4 成功判据（调研层，供日后 task 引用）

1. 用户能从助手或手动得到 **画布上的剧本节点**，并看到阶段与待审计数。
2. 任一生成物默认 **待审**；未过审不进入视频 harvest。
3. 打回后用户能改 prompt/参考并只重跑该支。
4. 全流程可不靠助手完成（双轨）。
5. 不引入 Remotion 亦可闭环出多镜 AI 视频。
