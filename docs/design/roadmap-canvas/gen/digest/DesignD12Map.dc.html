D12 · 助手：做出用户想要的结果
1目标
「想要的结果」指什么
已定说一次、改一两次就拿到想要的图 / 视频；用户不用背提示词技巧
已定LLM 只负责理解与配参数，出图永远是图片 / 视频模型
建议只看两个数：同一目标生成了几次（返工轮数）· 用户说「不是这样」几次（纠正次数）；先记进每轮结账，不做看板
2一条链
听懂 → 看懂 → 选对 → 生成 → 你判断 → 按你说的改
听懂
已落系统提示要求跨轮维护「这件事的简报」：要改什么 · 必须保留 · 参考分工 · 未决事项 —— 只在提示词里，没有存下来
建议简报结构化进每轮结账（目标 · 必须保留 · 可以改 · 参考分工 · 未决），下一轮注入；你纠正一句就改这份简报，不再每轮从零理解
已定简报不单独显示；你的纠正改动了它时，回复里说一句（例「记下了：保留构图」）
看懂
已落图片 / 视频直接喂多模态模型（56b）；视频取关键帧 + 字幕
建议关键判断先说一句：画风 · 媒介（2D / 3D / 写实）· 角色是谁 —— 说错了你一句话就能改，「3D 说成 2D」这类错不会悄悄进提示词
选对
已落模型规则表 model-strengths：71 个模型逐条写法 · 负面提示档位 · 方言
已定NAI：拦中文整句与夸张权重，未核实的角色先查 Danbooru
建议加一张可维护的「选型知识」表（常量）：例 出角色图 → NAI V5 Full（Curated 不认识新角色）；助手换了你没点名的型号时，回复里说一句理由
生成
已定生成键做成开关：开 = 配好就按 · 关 = 你按；默认关，开关放在确认卡的生成键旁
已落钱闸：服务端没有任何工具能建 generation；助手只出确认卡，由客户端按下 —— 开关开也只是客户端替你按
你来判断
已定出图后不自检，由你指出问题
按你说的改
建议只改你指出的那部分；其余参数与参考原样保留（写进简报的「必须保留」）
已落每轮一行「本轮记录 · N 项」，可展开、可撤销
3什么时候问 · 什么时候做
已定意图清楚、没有冲突 → 直接配；免费可撤销的自动落（字段闪一次 + 一行回执）
已定真冲突才问：两个要求互斥 · 参考与文字矛盾 · 缺关键信息且猜错代价大；反问框一次一题，回答只授权当前这一问
已定建议写在回复里，不变成问题，也不变成必选
已定技术故障（参考不可读）重试一次后如实说，不装成需求冲突
建议步数用完不静默：最后一步必须说「做到哪 · 还剩什么 · 你说哪句我就接着做」（工作台一轮 8 步，画布 16 步）
已定花钱的那一步：开关关（默认）→ 配好停在确认卡；开 → 确认卡自动按下，仍留在时间线上可见
