# 画布 · 生成提示词框（施工基准）

> **画布级共享组件**，不属于任何单一节点族。owner 2026-07-27 确认关键切片。
> 数值唯一来源：[`canvas-skin-spec-2026-07-26.md`](../../plans/canvas-skin-spec-2026-07-26.md)。本文不新造色值。
> 相关：[图片卡](canvas-image-card.md) · [声音卡](canvas-voice-card.md)

## 0 · 它是什么

选中一张卡后，**挂在卡下方**的浮层：**参考图槽 + 指令文本 + 参数条**。用户打一句话、按发送，生成一个新资产。

与卡**上方**近场工具条的分工：

|      | 上方工具条                             | 下方生成提示词框    |
| ---- | -------------------------------------- | ------------------- |
| 性质 | 点了就执行的**预设能力**（编辑/超分…） | **自由指令**        |
| 输入 | 无（或固定参数）                       | 一句话 + 可选参考图 |

## 1 · 位置

**贴宿主卡下方**，左对齐卡左缘。

⚠ **修订规格 §8**：原文写「浮层 composer 贴节点**右侧**、顶对齐」，**改为贴下方**。理由：入边从左进、**右侧是下游的地盘**，贴右侧会盖住「这张图喂给谁」。§8 自身的纪律「永远不盖住它自己的入边与上游卡」延伸下来就该包含下游。

**浮层配方**（§8 浮层 composer 一栏）：`#FFFFFF` · 圆角 **`12px`** · 边 `1px rgba(0,0,0,0.08)` · 投影 `0 4px 12px rgba(0,0,0,0.04), 0 8px 24px rgba(0,0,0,0.06)` · padding `16px` · 组间 `20px`。

## 2 · 出现时机

- **选中单张卡 → 出现**
- **多选 → 不出现**（一次只能对一个对象说话）
- **新建节点 → 自动出现并聚焦输入框**（起手势）
- 从画布空白处唤起（无宿主卡）→ 出现，且此时才需要选模式（见 §3）

## 3 · 模式由上下文推出，**不给下拉** ✅ 已拍板

参考站的五个模式到本项目只剩两个，且能由宿主节点族推出：

| 参考站模式 | 本项目                                       |
| ---------- | -------------------------------------------- |
| 视频生成   | ❌ 走组装台（「组装台 = 唯一下单」条款保持） |
| Agent 模式 | ❌ 右侧已有助手 dock，两个入口会打架         |
| 文本生成   | ❌ 六族里没有文本节点，产出无处可落          |
| 图片生成   | ✅ 挂在图片卡下                              |
| 音频生成   | ✅ 挂在声音卡下                              |

**规则**：挂在某族卡下 → 锁定该族的生成，**不显示模式控件**；只有从画布空白处唤起（无宿主）才出现「图片 / 音频」二选一。

收益不只是省一个控件 —— **无效组合从根上不存在**（不可能在图片卡下选中音频生成）。这是「模式决定槽轨、模型决定参数」的延伸。

## 4 · 两种宿主，语义不同

| 宿主       | 本质   | placeholder                 | 参考图槽                                                     |
| ---------- | ------ | --------------------------- | ------------------------------------------------------------ |
| **空卡**   | 文生图 | 「描述你想生成的画面…」     | 空槽 = `+ 参考图` / 从素材库选                               |
| **有图卡** | 图生图 | 「说说想把这张图改成什么…」 | **第一格钉宿主图缩略，不可删，角标「正在改」**；其后才是空槽 |

⚠ 参考站两种都用「描述你想生成的画面…」—— 在有图的卡下面这句是错的：用户不是在描述要生成什么，是在描述要**改**什么。

⚠ 宿主缩略钉在槽首解决两件：卡滚出视口也不丢参照 · 后加的图语义清楚（是**额外**参考，不是要改的对象）。

**素材库入口**：与 `+ 参考图` 并列，复用既有 `AssetSelector`。

## 5 · 参数条（按模式重组，不是固定几个下拉）

| 模式         | 参数条                                                                                        |
| ------------ | --------------------------------------------------------------------------------------------- |
| **图片生成** | ▤ 用模板 ∨ · 模型 ∨ · 比例+清晰度 ∨ · 张数 ∨ · 发送（见 §5.5）                                |
| 音频生成     | ⬜ 等声音卡那一轮定（已知参数是 `AUDIO_KIND`（SPEECH/SFX/MUSIC）与音色，**不是比例/清晰度**） |

- 控件高 **`24px`**（§6 紧凑档；三档梯子 24/28/32 见 §1 的 2026-08-10 修订），底 `--canvas-fill-control rgba(0,0,0,0.04)`
- **发送键**：圆形 **`32px`**（旧 36），`--canvas-action #0A0A0A` 墨底白箭头（§0.6）
- ⛔ **`⚡` 消耗占位已删除**（owner 2026-07-27 真机后判定：「这个没用可以删掉」）。原方案是「留空但占位（虚线框 + `—`）」，实际效果是一个永远显示 `—` 的虚线框 —— 纯噪音，且它占的位置未必就是将来真实消耗该待的地方。

  **等真接 credit 时再加回来**，那时它有真实数字。⚠ 届时必须与三级审批门第二道（批量总消耗）**共用同一个计算**，不做两套。

### 比例 + 清晰度 —— 直接复用既有实现

规格 §3.3 原文：「图形在上（按真实比例画的小矩形，非文字 pill）、文字在下；选中态是**填充块**不是描边。**现状代码已做对（`VideoComposer` 画幅可视化选择块），保留**。」

参考站的 popover 与之一字不差。**不重做**。

⚠ **原文写的「比例十档」是错的（2026-07-27 实读更正）**：那是**参考站**的档位，不是本项目的。代码里 `STUDIO_IMAGE_ASPECT_RATIOS` 与 `VIDEO_ASPECT_RATIOS` **都只有 5 档**（1:1 / 16:9 / 9:16 / 4:3 / 3:4）。

**以代码为准，用现有的 5 档**，不要为这个组件发明一套全站独有的十档 —— 那会让画布的比例选择与 studio 各页不一致，而「同一个概念在不同页给不同选项」是比"档位少"严重得多的问题。要加档是**全站一起加**的另一件事。

清晰度三档（1K / 2K / 4K）沿用现状。

## 5.5 · 从提示词模板取用 ✅ owner 2026-07-27 拍板（新增功能）

> owner：「可以再加一个新功能就是从这个项目的提示词模板直接使用提示词。不过这个点击后的 UI 需要设计。风格我想保持画布这边一致。」

### 域定义

> **模板是提示词的「起点」，不是配方还原。** 它只回答一件事：这段话从哪儿开始写。

### 入口位置 —— **底部参数条**，与模型/比例/张数同一行 ✅ owner 2026-07-27 拍板

`▤ 用模板` 放在底部那一行，和其它控件并列。

> ⚠ **推翻我的原方案**。我原本主张放在 prompt 区，理由是「它作用于文本，不是参数」。owner 定为底部一行。

**owner 这个放法有个更站得住的分组原则**：底部那一行本来就是**「点开都是选择器」**的地方（模型 ∨ / 比例 ∨ / 张数 ∨），用模板同样是「点开一个选择器」；而 prompt 区保持**纯文本输入**，不掺任何控件。

**按交互类型归组，比按语义归组更站得住** —— 用户扫这一行时形成的预期是「这里的每个东西点下去都会弹一个选择面板」，把模板放进去正好符合；放在 prompt 区反而是那片纯文本区里唯一一个可点控件，是个例外。

### 形态 —— 浮层，封面优先

浮层（非模态，同「比例」弹层那一档 —— 挑模板不该离开画布）。约 `430 × 380`，配方沿用 §1 的浮层材质。

| 部件   | 说明                                                                             |
| ------ | -------------------------------------------------------------------------------- |
| 搜索   | 搜名字 / 正文 / 标签                                                             |
| 轻筛选 | `最近用` / `全部` / `用得最多`（对应 `lastUsedAt` / `usageCount`，库里已有字段） |
| 网格   | **封面图当主**（`Recipe.coverImageUrl`），标题 + `用过 N 次` 在下                |
| 正文   | **退到 hover** 才浮现在封面上                                                    |
| 无封面 | 字形兜底，同 `/prompts` 现有卡的 fallback，不另造                                |

**为什么封面当主**：挑提示词时人认的是「长什么样」，不是读文字。`/prompts` 页现有的卡已经是这个形态，**复用它，不新造一套**。

### 预筛：按输出类型与宿主同族

挂在图片卡下 → 只列 `outputType = IMAGE` 的模板。同 §3「无效组合从根上不存在」那条纪律。

### ⛔ 只取提示词文本 ✅ owner 拍板

`Recipe` 在库里绑着 `modelId` / `params` / `referenceAssets` / `negativePrompt`。**这些一概不取，也不提示。**

owner 明确选了「只取文字，其余不提」而非「一并套用」或「给一条可点的追加提示」。

**代价要说清**：**「一键还原同款配方」这件事在画布上不存在**。想连模型和参数一起还原，去 `/prompts`。这是有意的取舍 —— composer 是**画布上的快速起手**，不是配方管理器；把配方还原塞进来会让这个小浮层承担两种不同的任务。

⚠ 将来若要加回「一并套用」，**别做成静默替换用户已选的模型** —— 那是最容易出事的一种「贴心」。

### 插入语义：替换 + 一次撤销 ✅ owner 拍板

输入框已有内容时**直接替换**（模板是起点不是补丁），插入后短暂显示一个 `撤销`，误操作拿得回来。

**不做每次弹窗问「替换还是追加」** —— 这是高频操作，加一道确认很磨人。

### 零重造

数据与卡形态全部复用 `/prompts` 现有的（`PromptTemplateList` 的卡、`Recipe` 查询链路）。**不新建 API，不新造卡。**

## 6 · 扩大 = **打开该节点的详情页**，不是 composer 自己的模态 ✅ owner 2026-07-27 更正

> owner 原话：「不是删除。是和 composer 那边有冲突了。**点击扩大后应该是这个页面**。但是目前这个页面已经过时了需要重新设计。」

⛔ **本节原先写的「扩大 = composer 自建一个 modal（含提示词历史 chip 行）」作废。**

**正确关系**：composer 是**收拢态**，节点详情页是**它的展开态**。点 `⤢` 就是打开这个宿主节点的详情页。

## 7 · 结果落点 ✅ 已拍板

**新建节点 + 自动连线（原卡 → 新卡），新卡落原卡右侧。不覆盖。**

三条理由：合「成分永不消失」条款 · 来源关系正是连线三维度编码要展示的东西 · 「改之前 vs 改之后」是最常见需求，覆盖就没得比。不想要的删掉比恢复被覆盖的容易。

**一条对称的例外**：**空卡**下的框生成时，结果**直接填进这张空卡本身**，不新建。空卡是「为此而建的容器」，有图卡是「已存在的成分」。

**生成完成后**：新卡自动选中（`--canvas-accent` 2px 环），框跟着挂到新卡下面 —— 可以立刻接着改下一版。这条链路是本组件最值钱的地方：迭代成本降到「打一句话按回车」。

### ⚠ 2026-07-28 owner 真机实测暴露的四条（全部已定修法）

owner 用 `×4` 实发一次，结果：**只出 2 张**、**提示词与参考图被清空**、控制台刷屏 `Couldn't create edge for target handle id: "null"`。

#### ① 张数必须**串行排队**，不能并发

`MAX_ACTIVE_JOBS_PER_USER: 2`（`constants/config.ts:571`）是**平台硬限**。现实现把 `batchCount` 展开成 N 个并发 `/api/studio/generate`，`×4` 于是成 2 废 2（后两个 `ACTIVE_GENERATION_LIMIT_EXCEEDED` 429）。

**也没有「一次请求出 N 张」这条路** —— 生成入参里没有张数字段。

**修法：串行**。前一个落地再发下一个。⚠ 别改成「一次发 2 个」去顶满限额 —— 用户在别处（studio / 其它节点）的生成同样占这 2 个名额，顶满等于把别处挤死。

#### ② 发送后**不清空草稿** —— 现实现与规格相反

现实现是「乐观重置」：草稿在知道成功与否之前就清了，失败时用户的提示词和参考图一起没。

但本节写的是「**可以立刻接着改下一版**」—— 那正要求**保留**提示词与参考图槽，改一个词再发。清空把这个组件最值钱的循环打断了。

**修法：发送后保留全部草稿**（提示词 + 已加的参考图）。宿主切到新卡后，钉在槽首的宿主缩略图**跟着换成新卡的图**（你现在是在改这一版），其余槽保持。

#### ③ 失败要**说出来**

现在 429 是静默的，用户只看到「少了两张」，不知道为什么。失败必须给出原因（复用 `canvas-image-card.md` §3 的失败态：**具体原因 + 重试**）。

#### ④ 生成中的卡**要露端口**，并需要「生成中」态

⚠ **这是 §3「空态不露端口」的边界没想清楚**（那条是我写的）。原文理由是「空卡还没有内容，露出端口等于承诺一件做不到的事」——**但正在生成的卡是有东西要来的**，不该继承空态的规则。

后果：结果卡在生成窗口内没有端口 → React Flow 报错刷屏、**边在生成期间不可见**（等图落地卡有了端口，边会自己接上，所以不是功能坏掉，是过程中的噪音与关系断档）。

**修法**：`空` 与 `生成中` 分开 —— **只有真正的空态不露端口**，生成中/失败/就绪都露。

⚠ 另外 `canvas-image-card.md` §3 的五态里**根本没有「生成中」**（那里的「上传中」是上传，不是生成），所以结果卡现在显示成 `□ 空 / 拖入即可上传`。**需要补第六态**，两文一起改。

⚠ **2026-07-28 落地时真机复测又暴露一层：本节原文「等图落地卡有了端口，边会自己接上」不成立。** `showSourceHandle`/`showTargetHandle` 只是把 `<Handle>` 元素加进/移出 DOM——React Flow 自己的 store 不会因为 DOM 多了两个 handle 就自动重新 measure 它们的位置去接边（同 `use-update-node-internals-on-init.ts` 记录的那个 React Flow 底层问题：`handleBounds` 不随 DOM 变化自动刷新，只是那个 hook 只管首次挂载那一刻，管不到"节点已挂载、生命周期中途端口数量动态变化"这种场景）。真机验证：不加显式通知时，边数据在 store 里确实存在（`onConnect` 正确执行了），但 `.react-flow__edges` 里只有空 `<defs>`，控制台也不报错——不是过程噪音，是边真的连不上，直到用户手动碰一下节点触发 React Flow 自己的重新 measure。**补法**：`ImageSourceStarter` 里 `isEmpty`（决定端口显隐的同一个布尔）变化时，调用 `@xyflow/react` 的 `useUpdateNodeInternals()` 显式通知一次——这是官方文档给「运行时增删 handle」场景指定的机制。真机复测：端口从 0→2 后边立即渲染（DOM `g.react-flow__edge` 从 0 变 1，与 store 里的 edge id 对上）。
