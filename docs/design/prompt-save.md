# 保存提示词设计

施工单 `d-prompt-save`（设计，已定）→ `p-prompt-save-impl`（实现，待做）→ `p-gallery-recipe`。2026-10-21 出稿；原稿 https://claude.ai/artifact/7NzJhCcGHjX6kWGCDKekeW （云端，已停更，以本文为准）。

## 已定（10-21 owner）

- 每张作品出图时由服务端记下完整配方：**数据库加一列**。
- **只留一颗「复刻」**：把整套配方连同种子装回对应的台，不自动出图；想变化就在台里改种子或参数。原稿里的「引用」并进这一颗。

## 结论

「能不能复刻」不该取决于当时有没有点保存。每张作品在出图那一刻由服务端记下完整配方，各处的「保存」只是给这份配方起个名字、放进模板库。任何一张旧图都能原样复刻，全站一套保存逻辑。

## 现状（10-21）

| 保存入口                    | 存下什么                       | 问题                                  |
| --------------------------- | ------------------------------ | ------------------------------------- |
| 各台模板面板「存下当前」    | 这一台此刻的提示词、模型、参数 | 存的是「现在」，不是「那张图」        |
| LoRA 结果图「存成模板」     | 挂载、底模、参数、提示词       | 整套只在浏览器内存里，刷新就没了      |
| 素材页 / 查看器「存为模板」 | 从作品记录反推                 | LoRA 只剩链接和权重，底模和触发词没了 |
| 提示词页「新建」            | 手写                           | 正常                                  |

底层：作品 `snapshot` 和模板 `params` 都是无类型 JSON；LoRA 模板有 `loraSetup` 与旧 `advancedParams.loras` 两种形状。

> 10-28 起 LoRA 台已能存「提示词 + 挂的 LoRA」模板（`p-library-assistant-link`），实现时先看那段代码，别做第二套。

## 方案

1. **一份有类型的「生成配方」**（Zod，全站一份形状，按台四种）：
   - 图片：提示词 · 负面 · 模型 · 参数 · 参考图 · 种子
   - 标签 / NAI：整体标签 · UC · 各角色（标签、位置、互动、台词）· 画面文字 · 画风串 · 采样器 / 步数 / CFG · 模型 · 种子
   - LoRA：底模 · 挂载列表（名字 · 链接 · 权重 · 触发词 · 来源 Civitai / HF 的 ID）· Runner 参数 · 提示词 · 负面 · 种子
   - 视频：提示词 · 引用文件 · 模型 · 视频参数
2. **出图时服务端写进作品**（新列）。旧作品尽力从旧快照补，补不全就在界面写「配方不完整：缺底模」，不静默缺。配方列既存 LoRA 的 id 也存快照（LoRA 删了作品仍说得清当时用了什么）。
3. **一颗保存键，各处同一个组件**：各台结果图、素材查看器、画廊查看器（别人公开的作品 = 做同款，只存公开部分）、画布节点。三个状态：存 → 已存（去看看）→ 同一份配方不重复存。所有入口调同一个接口「从这张作品存配方」。模板面板「存下当前」保留，用来存还没出图的草稿。
4. **提示词页详情补齐三块**（套用库骨架，不单写一套）：配方（按类型显示全部字段，缺的写明缺）· 出过的作品（每张都能「复刻这张」）· 保存信息（存自哪台、来自哪张作品、第几版、日期、用过几次）。

## 分步

1. 定配方 schema，出图时服务端写进作品（加一列）。
2. 统一保存接口与保存键，先替换 LoRA 和素材查看器两处。
3. 「复刻」接到四个台。
4. 提示词页详情补齐。
5. 画廊做同款（`p-gallery-recipe`）、画布、助手改读同一份配方。

## 连带

- 「我最近用的」排序（见 [libraries.md](libraries.md)）同样依赖这一列。
