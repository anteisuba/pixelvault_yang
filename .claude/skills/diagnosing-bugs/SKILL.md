# 复杂故障诊断

用于根因不明、间歇性故障或性能回退。范围、授权与验证遵循 `docs/WORKFLOW.md`；按需要读取相关实现与域契约。

先从错误、日志、调用链和现有测试确定用户的确切症状。代码阅读与构建复现可以交替进行；已有明确证据时不必走固定阶段或枚举假设。

选择能区分原因的反馈方式：现有测试、请求回放、浏览器操作、隔离 harness 或性能测量。优先覆盖实际失败链路，不能仅以“未抛错”代替症状验证。缩小复现到足以区分原因即可，不要求每个输入都不可再删。

间歇性故障记录触发条件、样本量与失败率，按证据决定是否增加采样或控制时序，不固定运行次数或要求达到某个失败率。压力和重放只在授权环境内执行，避免重复扣费或生产写入。

复现受环境限制时，继续分析已有代码、日志和契约，明确区分假设与已证实原因。只请求缺少的访问或原始证据；没有复现不等于不能调查，也不能据此宣称修复已验证。

对仍有歧义的原因提出可证伪预测，使用能区分它们的定向观测；性能问题比较同等条件下的基线。临时日志加可检索标记，只记录必要信息，完成后清理。

在实际触发故障的边界增加有价值的回归保护，确认其能捕获原问题，再验证修复。若没有合适的自动测试边界，记录验证缺口，使用现有可行证据，不为此自动扩大架构重构范围。需人工触发且脚本确有帮助时，可用 [交互复现模板](scripts/hitl-loop.template.sh)。

完成授权的修复、受影响验证与临时探针清理后报告根因、行为变化和未验证项。若回归测试已覆盖原始复现，无新变化或疑点时不重复跑同一检查；相关架构建议作为有证据的后续项，不强制启动另一流程。
