## 〇 · 本轮不重开的（规格 §12.1 已拍板，参考图逐条印证）

- 族图标 + 名字在**卡外上方**，改名原地编辑
- 卡内 `padding: 0`，卡即媒体
- 唯一主动作在媒体窗内**居中浮层**，仅 hover / 选中出现，不常驻（参考站的「替换」即此形态）
- 状态浮标在媒体窗内左上角，形 + 词双编码
- 端口在卡左右缘垂直居中
- 近场工具条在**卡外上方**，玻璃胶囊
- 主动作一律**墨色实底** `#0A0A0A`

## 一 · 卡宽 ✅ 已拍板（owner 2026-07-27）

**随媒体真实比例，限 `min 180px` / `max 480px`。先不做拖拽把手。**

⚠ **规格 §6 的 `--canvas-card-w: 250px` 是错的，须改**。它取样了参考站某一张卡当成固定值；参考图里同屏三张图片卡明显不等宽（目测 ~200 / ~445 / ~200）。固定宽会把 9:16 竖图压成邮票、把宽幅拉成细条，与「卡即媒体」的前提冲突。

改成 `--canvas-card-w-min: 180px` / `--canvas-card-w-max: 480px`。

## 二 · 上传：并入节点 ✅ 已拍板（owner 2026-07-27）

**「上传」不再是独立入口。** 与卡匣降级同一条纪律：一个对象只有一个产生它的地方。

- 添加节点菜单里**删掉「上传」**，只留「添加图片节点」
- 建出来的空卡**本身就是 dropzone**，点击开文件选择器
- **拖文件到画布空白处** = 直接建节点并就地上传，不经过菜单
- 拖文件到**已有空卡** = 填进那张卡

⚠ 这条修订结构条款，需同步回 `canvas-visual-redesign-2026-07-25.md` §7.1。

### 四态

| 态         | 卡内                                                                                                                                                                           | 状态浮标             | 主动作                   |
| ---------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ | -------------------- | ------------------------ |
| **空**     | dropzone：中心 `--canvas-ink-muted` 图片图标 + 一行「拖入或点击上传」。⚠ 卡边用 `--canvas-stroke-focus` 档，不用 `.08` —— 规格 §3.1 例外条：既无图标也无文字的纯色块必须用强边 | `□ 空`               | 整张卡即主动作           |
| **上传中** | 半透明白 + 一道扫光 · 中心「上传中 N%」+ `×`                                                                                                                                   | `↻ 上传中`           | `×` 取消                 |
| **失败**   | 保留框，中心换失败原因 + 「重试」                                                                                                                                              | `▲ 失败`             | 重试                     |
| **就绪**   | 图铺满，`padding: 0`                                                                                                                                                           | 不显示（有图即就绪） | hover 出「替换」居中浮层 |

⚠ **上传中必须显示真实百分比**。规格 §5 写的「生成中 `↻`（无百分比）」是给**生成**用的（生成拿不到进度），上传有进度，不要一刀切。

## 三 · 点卡扩大 = 模态 ✅ 已拍板（owner 2026-07-27）

**走模态，但暗底被否 —— 全部值从 v0.2 已有配方推出，不新造。**

| 部件               | 值                                                                                       | 出处                      |
| ------------------ | ---------------------------------------------------------------------------------------- | ------------------------- |
| 遮罩               | `rgba(255,255,255,0.72)` + `blur(20px)`                                                  | §8 玻璃族同材质，不是黑纱 |
| 模态面             | `#FFFFFF` · 圆角 `16px` · 边 `1px rgba(0,0,0,0.08)` · 投影 `0 4px 20px rgba(0,0,0,0.10)` | §8 左侧合体面板同配方     |
| 图的衬垫           | `--canvas-bg #F1F1F1` + `1px rgba(0,0,0,0.08)`                                           | §0.5-④ 分层靠极小明度差   |
| 左右分栏           | `1px rgba(0,0,0,0.08)` 竖分隔，**不做二次投影**                                          | §8                        |
| 主动作「下载图片」 | `--canvas-action #0A0A0A` 墨底白字                                                       | §0.6                      |

**设计要点**：参考站用深灰底是为了让图跳出来。浅色系里的等效做法不是加暗，是**把图放进比模态面略深一档的凹槽**（`#F1F1F1` 衬垫 vs `#FFFFFF` 面）——「嵌在浅井里」而非「站在暗舞台上」。

细节两条：

- 纯白 / 浅色图在衬垫上边界会糊 → 由 `.08` 发丝边交代（与节点卡同一条，§11-①）
- 透明 PNG 的棋盘格**只用 `#FFFFFF` / `#F1F1F1` 两色**，不引入第三个灰

**右侧信息栏比参考站多一件**：这张图**是谁生成的 / 来自哪个节点**。参考站那栏是「无生成信息」的空壳，我们有完整生成元数据，是白送的差异。

### 立成通则

> **改参数的详情 → 原地长大**（必须一直看见入边）
> **看内容的详情 → 走模态**（要大、要压掉画布干扰、入边此刻不重要）

这解释了为什么组装台 detail 档原地长大而图片卡走模态，两者不矛盾。

## 四 · 「编辑」与「生成提示词框」是两件事 ✅ 结构已定（owner 2026-07-27）

owner 拍板的分档：

| 档               | 位置                               | 内容                                                                         | 现状                                                                        |
| ---------------- | ---------------------------------- | ---------------------------------------------------------------------------- | --------------------------------------------------------------------------- |
| **能力**         | 卡**上方**近场工具条的「编辑」按钮 | 消除 / 扩图 / 重绘 / 超分 —— 点开是全屏编辑器（左竖工具轨 + 底部 取消/确认） | 仓里已有 `CanvasImageEditWorkspace.tsx`（816 行），**不重写，只换 v0.2 皮** |
| **生成提示词框** | 卡**下方**浮层                     | 参考图槽 + 指令文本 + 参数条（模式/模型/比例·清晰度/张数/消耗/发送）         | **全新，项目里没有**                                                        |

⚠ **「生成提示词框」是画布级共享组件，不属于图片卡。** owner 明确要求「设计成共同的组件」，且模式下拉里有 `Agent模式 / 图片生成 / 视频生成 / 音频生成 / 文本生成` 五档 —— 一个组件按模式换产出。这正是已确认结论「**模式决定槽轨，模型决定参数**」的落地形态。

**因此本轮（图片卡）不含它**，它单开一轮。见 [`canvas-generate-composer-design-2026-07-27.md`](canvas-generate-composer-design-2026-07-27.md)（待建）。

### 已确认的要求（记给下一轮）

- 位置：**图片下方**（⚠ 与规格 §8「贴节点右侧、顶对齐」冲突，须改 —— 右侧是下游的地盘）
- 能放图片（参考图槽）
- 尺寸选择（比例 + 清晰度两段）
- 一次出多张图
- 模型选择器
- 模式切换
- **扩大后是 modal**，遮罩是**浅色模糊**（参考图 4 实证），与图片详情模态共用同一套遮罩配方（§三）
- ⚠ **本项目特有**：还要一个**从素材库选择图片**的入口（owner 追加）

### 模式下拉**不放「视频生成」** ✅ 已拍板（owner 2026-07-27）

**视频一律走组装台**，「组装台 = 唯一下单」那条结构条款保持不变。

理由：视频模型有**三种接口形态**（多参考聚合 `image_urls≤9 + video_urls≤3 + audio_urls≤3`、跨模态总闸 ≤12 / 单张首帧 / Gemini Omni Flash 的内容数组且**无时长参数**）。一个通用框装不下三种形态，硬装就会出现「界面上有时长滑杆、引擎压根不吃」这类谎。

模式下拉实际保留：`Agent 模式 / 图片生成 / 音频生成 / 文本生成`。

## 五 · 编辑器（能力档）✅ 分期已定（owner 2026-07-27）

**外壳**照参考图 1：全屏 · 顶部标题 + 重置 + 关闭 · **左竖工具轨** · 底部缩放 + 快捷键提示 + `取消` / `确认`（墨底）。

**左轨内容分两期：**

### P1 · 先装我们已有的 AI 能力

消除 / 扩图 / 重绘 / 超分 —— 即 `CanvasImageEditWorkspace.tsx`（816 行）现有的那组。**不重写逻辑，把它重新排进这个外壳并换 v0.2 皮。**

### P2 · 区域标注 + 指令（owner 原话：「对图片某个部分标注，然后说想改什么地方」）

⚠ **这明确不是参考站那种自由画笔。** owner 要的是：**框选一块区域 → 对这块说想改成什么**。产出是**结构化指令**（区域 + 文字），不是烧进像素的红箭头。

这与 [[project-image-edit-extensions-ideation]] 记的设想完全一致：「框选区域 + 挂注释（DevTools 检查器式，非手绘箭头）；编号框上图 + 指令列表进 prompt / 区域→mask 双路」。**那份设想直接复用，不重新设计。**

形态要点（待 P2 单独出切片）：

- 框选后区域上落一枚**编号角标**（①②③），右侧同步出现一条「①：\_\_」的指令行
- 多个区域 = 多条指令，成为一份**指令列表**
- 提交时两条路：指令列表拼进 prompt（通用模型）· 区域转 mask（支持局部重绘的模型）
- 纯几何变换（裁剪 / 缩放 / 翻转）**不进这里**，做成近场工具条的一次性动作

owner 2026-07-27 给的方向：**「上面是编辑，下面是生成提示词框」**。

初步理解：编辑区在上（选区 / 标注），指令输入在下，改完在同一面板内发起生成 —— 即标注的产出不是烧进像素的批注，而是**喂进下方 prompt 的结构化指令**（「指哪儿」+「说什么」）。若属实，与 [[project-image-edit-extensions-ideation]] 的「编号框 + 指令列表」是同一条路。

⚠ **必须先厘清的既有事实**：仓里已有 `CanvasImageEditWorkspace.tsx`（816 行），它是 **AI 能力面板**（消除 / 扩图 / 重绘 / 超分 / 抠图，走 `canvas-image-edit-capabilities`），**不是**标注器。参考图 6/7 的「编辑图片」是手动标注与变换（裁剪/涂鸦/文字/箭头/框圈/翻转），两者目的不同：

|                   | 产出                | 调模型           |
| ----------------- | ------------------- | ---------------- |
| 已有 AI 能力面板  | 新像素              | ✅               |
| 参考站标注编辑器  | 烧进图里的批注      | ❌               |
| 「编号框 + 指令」 | 结构化指令 → prompt | ✅（下一次生成） |

**等参考图到位再定。** 裁剪 / 翻转这类纯几何变换建议不进任何编辑器，做成近场工具条的一次性动作。

## 五 · 横切项（不在本轮，单独立片）

**动效补齐**：owner 观察到「不少按钮缺少过渡动画」。规格 §9 已定三档时长（`150 / 250 / 420ms`）与两条曲线，但那是给新写的东西用的，现有元件大多没接。做法应是**审计式**——把画布域内所有可点元件列表，对照 §9 一次扫完，而不是边设计边零散补。
