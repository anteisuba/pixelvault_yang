> 状态：**调研结论，非实现授权**。对照业界实践与 PixelVault 现状，给出可落地原则与改造优先级。

> 相关：`docs/checklists/ui.md` P0 响应式项、`src/hooks/use-mobile.ts`、`src/app/globals.css` / `canvas.css` / `home-v4.css`。

## 0. 一句话

| 问题               | 结论                                                                                                                                                                                       |
| ------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 优秀响应式是什么？ | **不是把桌面缩小**，而是按 **视口宽度 + 指针类型 + 可用高度 + 键盘/安全区** 重排信息优先级与交互形态。                                                                                     |
| 本项目弱在哪？     | 断点语义偏「二值化」（&lt;1024 = mobile）、工作台/画布/LoRA 多为 **桌面优先再补丁**；容器查询与内容驱动断点用得少；部分页仍靠缩放/隐藏而非重设计。                                         |
| 怎么变好？         | 建立 **布局模式表**（phone / tablet / desktop / wide）+ **域级策略**（营销流式 vs 工作台简化 vs 画布只读/限编）+ **流体字号/间距** + **container queries** + 强制 375/768/1024/1440 验收。 |

## 1. 业界：优秀响应式的核心原则

### 1.1 正确目标

| 差的做法                     | 好的做法                                        |
| ---------------------------- | ----------------------------------------------- |
| 只改 `width: 100%`、缩小字号 | 改 **信息架构**：什么一等、什么进抽屉、什么删除 |
| 仅用一个 `isMobile` 布尔     | 多轴：宽度、高度、指针、方向、键盘              |
| 断点堆魔法数字               | **语义断点**与组件 **容器断点** 分层            |
| 桌面画完再「适配手机」       | 关键任务先定 **最小可用布局**，再增强           |
| 所有工具一屏塞满             | **主任务优先**；次要 chrome 折叠/路由化         |

### 1.2 设计系统层（推荐默认）

1. **Mobile-first CSS**  
   基础样式 = 窄屏可用；`md:` / `lg:` 只加能力，不推翻主路径。

2. **流体优于跳变（在合理范围内）**
   - 字号：`clamp(min, preferred, max)`（如标题 `clamp(1.25rem, 2vw + 1rem, 2rem)`）
   - 间距：用 token 阶梯（4/8/12/16/24…），大屏用更大 step，而不是随机 `p-3 md:p-8`
   - 栅格：`minmax(0, 1fr)`、`min-width: 0` 防 flex/grid 溢出

3. **Viewport 单位用现代的**
   - 高度：`100svh` / `100dvh`（避开旧 `100vh` 移动浏览器地址栏坑）
   - 本项目已有 `svh`、`--keyboard-inset`，应 **统一** 而不是混用

4. **Container Queries（2025–26 标配）**
   - **视口断点** → 壳层（侧栏、TabBar、整页分栏）
   - **容器断点** → 卡片内部、composer、列表项（嵌在侧栏/抽屉里时宽度 ≠ 视口）
   - Tailwind 4 / 原生 `@container` 适合 Studio 嵌套面板

5. **Pointer / hover 能力**
   - `@media (pointer: coarse)` → 更大命中区（项目清单：fine 32/36、coarse **44**）
   - `@media (hover: hover)` → 才依赖 hover 露出主操作；触屏要常驻或长按/菜单

6. **安全区与键盘**
   - `env(safe-area-inset-*)`
   - 软键盘：`visualViewport` / 已有 `KeyboardInsetBridge` + `data-keyboard-open`
   - 底栏：`keyboard-hidden-while-open` 模式要 **全站一致**

7. **内容驱动，不是设备点名**  
   避免「iPhone 专用 class」；用 **布局能力**（能否并排 60/40、能否钉住侧栏）描述断点。

### 1.3 产品型 App 的三种响应式策略

| 策略              | 适用                  | 做法                                                                                         |
| ----------------- | --------------------- | -------------------------------------------------------------------------------------------- |
| **A. 流式重排**   | 营销首页、图库、资料  | 单列→多列；导航压缩；媒体优先                                                                |
| **B. 工作台降级** | Studio、LoRA Generate | 桌面：分栏；平板：主列+抽屉；手机：**一屏一任务**（输入 / 结果 / 设置分页或 bottom sheet）   |
| **C. 画布专用**   | Node canvas           | 小屏默认 **浏览/点选**；重编辑进全屏 sheet；避免「缩小的无限画布当主创作面」除非明确产品承诺 |

优秀产品（Figma/Linear/Notion 等）在小屏 **减少模式**，而不是 1:1 复制桌面密度。

### 1.4 验收标准（业界可测）

- **375 / 390 / 768 / 1024 / 1280 / 1440** 主路径可完成（不仅首页）
- 横竖屏切换无致命裁切
- 无横向滚动（除有意横向轨）
- 触屏主按钮 ≥ 44px；焦点可见
- 软键盘打开后 CTA/输入仍可达
- CJK 长文案不撑破 chip/导航
- `prefers-reduced-motion`
- 视觉回归：desktop + mobile 分套（项目已有 playwright mobile）

## 2. PixelVault 现状（代码事实）

### 2.1 已有基础（优点）

| 点                 | 位置/行为                                                             |
| ------------------ | --------------------------------------------------------------------- |
| 全局 **1024 二断** | `MOBILE_BREAKPOINT = 1024`（`use-mobile.ts`）= 侧栏/TabBar/`lg:` 同界 |
| 键盘 inset         | `globals.css` + KeyboardInsetBridge；dock 随键盘上移                  |
| safe-area          | TabBar、部分 fixed 底栏                                               |
| `100svh`           | 首页域、部分 studio 高度                                              |
| Responsive 浮层    | `responsive-dialog` / `responsive-popover` / drawer                   |
| Checklist          | ui.md：375 主路径、触屏、ResponsiveOverlay                            |
| 画布               | `canvas.css` 有 `max-width: 767px`、lg 浮动卡等局部规则               |
| LoRA Generate 文档 | 曾写「按工作区宽度切 60/40，非裸 md」——**方向对，落地需统一**         |

### 2.2 主要问题（与「优秀」的差距）

| 问题                   | 表现                                                                                |
| ---------------------- | ----------------------------------------------------------------------------------- |
| **断点过粗**           | 几乎只有 &lt;1024 vs ≥1024；768–1023 平板常被当「手机 chrome + 半桌面内容」，最易丑 |
| **桌面优先债务**       | Studio / 画布 / LoRA 复杂台面先为宽屏设计，手机靠隐藏与缩放                         |
| **JS 与 CSS 双源**     | `useIsMobile()` 与 Tailwind `lg:` 需人工同步；易漂移                                |
| **缺容器查询**         | 侧栏内卡片、composer 仍按视口写断点 → 嵌套宽度错误                                  |
| **信息优先级未产品化** | 窄屏仍试图暴露桌面同级控件（多面板、装配+助手+结果）                                |
| **域策略不一**         | 首页/图库/Studio/画布各自为政，无统一「布局模式」文档                               |
| **测试偏冒烟**         | mobile spec 有，但难覆盖「每域主任务在 375 可完成」                                 |

### 2.3 分域现状简表

| 域                  | 现状倾向                   | 优秀目标                          |
| ------------------- | -------------------------- | --------------------------------- |
| 营销首页            | 流式较好（svh、单列）      | 继续；字号/间距流体化             |
| Gallery / Assets    | 栅格缩放常见               | 列数容器查询；筛选进 sheet        |
| Studio 图/视频/音频 | dock + 多面板，窄屏挤      | 输入/结果 **二态或三 Tab**        |
| LoRA Generate       | 桌面 60/40；移动未完全确认 | 单列：装配→输入→结果；出图 sticky |
| 画布                | 小屏难编辑                 | 限编 + 详情全屏；加号/生成保留    |

## 3. 优秀响应式：可执行框架（建议本项目采用）

### 3.1 布局模式（比设备名好）

| 模式            | 大致宽度  | 壳层                 | 内容策略                            |
| --------------- | --------- | -------------------- | ----------------------------------- |
| **compact**     | &lt;768   | TabBar + 顶栏精简    | 单列；一屏主任务；次要进 sheet      |
| **cozy**        | 768–1023  | 可保留窄 rail 或抽屉 | 单主列 + 可选右侧抽屉；禁止三栏硬塞 |
| **comfortable** | 1024–1439 | 侧栏 + 主工作区      | 双栏允许（如 60/40）                |
| **wide**        | ≥1440     | 同上 + 更宽内容 max  | 限制行长；侧栏可双开                |

实现：CSS 变量 `--layout-mode` 或仅用对齐的 Tailwind 断点；**JS 需要时读同一 token**。

### 3.2 三层断点职责

```text
1) Viewport（壳）     → 侧栏 / TabBar / 整页分栏
2) Container（部件） → 卡片网格列数、composer 内控件换行
3) Input modality    → coarse 命中区、hover 策略
```

### 3.3 工作台模板（Studio / LoRA）

**Desktop (comfortable+)**

```text
[ chrome ]
[ 输入区  ~60%  |  结果/监视  ~40% ]
```

**Tablet (cozy)**

```text
[ chrome ]
[ 主列 100%：默认输入；结果用底部 sheet / 分段切换 ]
```

**Phone (compact)**

```text
[ 顶：模式/模型精简 ]
[ 中：当前步（输入 | 结果 | 参数 三选一）]
[ 底：主 CTA 固定，避开键盘与 TabBar ]
```

### 3.4 画布模板

| 模式         | 允许                                                               |
| ------------ | ------------------------------------------------------------------ |
| compact      | 平移缩放、选节点、打开详情 sheet、生成；**不**追求完整多检视器并排 |
| cozy         | 左列表或底 dock 二选一                                             |
| comfortable+ | 现有多面板                                                         |

### 3.5 组件级清单（每个可复用组件）

- [ ] `min-width: 0` / 文本 truncate 或 wrap 策略
- [ ] 触屏命中 ≥44px（或例外有文档）
- [ ] 不依赖 hover 才能完成主任务
- [ ] 在 **窄容器**（非仅窄视口）下可测
- [ ] fixed 元素考虑 safe-area + keyboard-inset
- [ ] 图片/视频 `max-w-full`、固定比例位防 CLS

## 4. 技术选型（与本栈契合）

| 手段                    | 建议                                                                    |
| ----------------------- | ----------------------------------------------------------------------- |
| Tailwind 4              | 继续；扩展 `@theme` 语义断点名，少 arbitrary                            |
| `clamp` + spacing scale | 标题/section 间距优先流体                                               |
| `@container`            | 新卡片网格、studio-shared 面板优先                                      |
| `useIsMobile`           | 逐步改为 `useLayoutMode()` 返回 compact/cozy/… 或仅 CSS                 |
| 测试                    | 扩展 mobile 用例：**Studio 生成主路径、LoRA 出图、画布打开节点** 在 375 |
| 设计交付                | 改版关键切片 **至少桌面 + 375** 两态（ui-page 已要求，执行要硬）        |

## 5. 改造优先级（调研建议，非排期）

| 优先级 | 项                                                         | 理由            |
| ------ | ---------------------------------------------------------- | --------------- |
| **P0** | 书面冻结 **布局模式表** + 与 `lg`/1024 对齐说明            | 止住各自为政    |
| **P0** | Studio / LoRA **compact 主路径**：输入↔结果切换 + 固定出图 | 用户体感最大    |
| **P1** | 画布 compact 限编策略产品确认                              | 避免假适配      |
| **P1** | 共享组件上 container query（卡片、composer）               | 修嵌套宽度 bug  |
| **P1** | 平板 cozy 专项（768–1023）                                 | 现在最尴尬区间  |
| **P2** | `useLayoutMode` 收敛 JS 断点                               | 工程卫生        |
| **P2** | 流体字号进 domain/page token                               | 营销+工作台标题 |

## 6. 反模式（本项目应避免）

1. 用 `scale(0.8)` 塞桌面布局进手机
2. 只藏侧栏、主区控件密度不变
3. 断点写成 640/768/1024/1280 混用且无文档
4. 手机端依赖 hover 才出现「生成/保存」
5. 画布小屏承诺与桌面完全相同的生产力
6. 为响应式复制一整份组件树（维护灾难）— 用 **同一组件 + 布局 variant**
