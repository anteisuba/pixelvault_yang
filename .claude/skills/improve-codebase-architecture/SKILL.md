# 架构审计与优化

先按用户请求区分只审计、设计讨论和已授权重构。通用授权、文档与验证范围见 `docs/WORKFLOW.md`。

1. 读取目标域文档、调用链与测试，寻找具体理解成本、重复协调、职责耦合和难以覆盖的失败路径。必要时参考 `codebase-design`，不强制改写领域术语。
2. 对每个有证据的问题给出文件位置、影响、最简单可行改变和验证方式。没有真实收益时不要仅为“加深模块”改架构。
3. 少量问题直接报告；复杂结构比较可参考 [HTML-REPORT.md](HTML-REPORT.md)，把临时可视化放系统临时目录。报告载体不成为固定前置步骤。
4. 只审计则交付发现；已授权重构则实现最小端到端切片，更新所有调用方并验证。只有需要用户决定的业务边界才停下来讨论，不强制转入 grilling。
5. 稳定决策写到现有 `docs/references/` 所属文档，不新建 CONTEXT/ADR。子代理按当前会话授权与能力使用，不要求特定工具或固定数量。
