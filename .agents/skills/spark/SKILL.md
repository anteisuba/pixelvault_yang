# 想法探索与规格收口

用于用户要求头脑风暴、需求探索或设计规格；不自动拦截已有明确目标的修复、配置修改或已批准实现。

- 先读相关代码和域文档，从已有上下文回答目标、用户、约束和成功标准。只询问会改变方案的缺口，每次聚焦一个需要取舍的决策。
- 有实质权衡时比较可行方向并给出推荐；UI 改版依 `docs/scenes/ui-page.md` 保留三个结构方向与关键切片确认。
- 设计覆盖必要的模块边界、数据流、失败路径与验证；不为简单任务强制逐节审批或创建固定数量的任务。
- 用户只要求探索时交付方案与未决项；用户同时授权实现且所需决策已明确时，继续实施。技能本身不构成额外停止条件。
- 已确认的稳定结论更新到现有 `docs/references/` 对应文档，未决方案留在对话；不自动提交。
- 可视化只在有助于比较或理解时使用。确实需要浏览器原型时再读 [visual-companion.md](visual-companion.md)，选择当前环境可用载体。
