§0

先说三条：台账记的六项里，有三项定性是错的

六路读码 + 三条对抗性复核，加上我自己在真浏览器里的实测。下面每条都带证据位置 —— 因为这三条如果照原样修，会修出问题来。

台账原话判定实际是什么
#2 假进度条 推翻 那条是不定式扫光：38% 宽的固定色块在 1.2s 内从 translateX(-100%) 跑到 260%， 不携带也不接收任何百分比，没有 aria-valuenow。 canvas.css:220-222 的注释自己写明「A real percentage needs backend progress events; this neutral sweep at least shows work-in-progress」—— 这是诚实降级，恰恰是遵守而不是违反 ImageCardMediaState.tsx:107 那条「禁止假造」。 画布里唯一带百分比的是上传，走 XHR 真实字节数，还有回归测试锁着。
#16 选中环与失败边打架 推翻 两者落在正交属性上，层叠里不可能互相覆盖 —— canvas.css:730 选中态是 box-shadow: 0 0 0 2px， canvas.css:733 失败态是 border-color。 NodeShell.tsx:426 的注释是决定性反证：「原来的 ring + border 组合去掉，避免和 canvas-card 的 box-shadow 打架」—— 打架是过去时，已经修过了。
A7 八态共用一张灰白牌，实拍只认得出 idle 推翻推理 「只认得出 idle」不是糊在一起的残留，是设计意图：NodeStatusBadge.tsx:22 idle → return null（素卡 = idle）。
实拍里看不到别的态，真实原因是这枚章在五族卡上被显式关掉了 —— hideStatusBadge 出现在 IdentityCollectorCard / ImageSourceStarter / SeedanceNode / VoiceNode，加上 NodeMediaPreview 的 hideStatusBadge={isImageKind}。 今天它只活在 video/audio/text 三种 kind 与详情面板上。
这三条都不是「台账写错了」这么简单 —— 它们是同一类错误：把「看不出来」直接归因成 「做得不好」，而没查为什么看不出来。真正的病因在下一节，比记的那版更糟。

§3

提案：按「现在有多需要你的注意」排强度

现有 token 内重排，一个新色不造。判据只有一条 —— 这个状态出现时， 用户需不需要为它停下来。

idle不盖章
最常见的态。素卡本身就是「还没开始」
done改成不盖章
卡上有成品图，那就是完成信号。再盖一枚是说两遍
ready最轻一档
「可以按了」。信息量低，不该和失败一样重
running唯一带动的
正在发生 → 靠动效说，不靠加重颜色
failed唯一该喊的
要人处理。全画布唯一的红
ready ≡ done 这个 bug 其实提示了答案。两枚章长得一样却没人抱怨过，说明其中一枚本来就是多余的 —— 而多余的是 done：完成的证据是卡上那张图，不是章。这样 ready 也就自然成了最轻一档， 不用再跟 done 抢辨识度。

§4

还有一件事：这枚章根本不在卡上

它是 position:absolute; bottom:100%，画在卡外、压在画布底上， 却继承了 .node-card-paper 那套按纸背 #ebe5d8 算过的墨色。 今天实际底是 #F1F1F1 画布（卡背也早被刷成纯白）。这就是 stale/disabled 只有 3.44 的根因 —— canvas.css:529 给 --canvas-ink-subtle 的注释原话就是「只在卡背上用，别放画布底」，而它恰恰放在了画布底上。

NodeShell.tsx:482 的注释写着「把它挪进媒体窗左上角浮标是 S4 的事」—— S4 只挪了图片族，video/audio/text 还留在卡外。所以这里不是新方案，是把做了一半的迁移做完： 章进卡内，底色就成了已知的白卡，纸背算出来的那套墨色也就重新成立了。

§5

要你拍板的四件

① done 还盖不盖章？ 我建议 不盖 —— 卡上有图就是完成的证据，再盖一枚是同一件事说两遍， 而且正是它逼着 ready 也得同色。若你要留，那就得给 ready 另找一档，代价是多一个编码位。
② ready 该由章说，还是由生成钮说？ ready 的意思是「模型和提示词都齐了，能按了」。这件事生成钮的可用/禁用态已经在说。 我建议 章保留但压到最轻（灰、无点、无动），不建议直接删 —— 详情面板那条链路上没有生成钮。
③ 三个永不发生的态（queued / stale / disabled）怎么处置？ 我建议 枚举留着、编码不设专属档，走一条有注释的中性兜底。 ⚠ 枚举值不能删 —— 老项目 JSON 里可能存着，删了 Zod 解析会整份失败 （NODE_TYPE_IDS 那次教训同理）。若你认为它们是「计划要接」而不是废弃，告诉我，我按八档画。
④ 章进卡内（把 S4 做完）现在做还是单列？ 它是 3.44 那条不达标的根因，但改的是**位置**不是颜色，动的面比批 3 其余项都大。 我建议 这一批一起做 —— 不然颜色怎么调都是在错的底色上调。
