| 「**图片在下层**」拖过面板时看不见自己在拖什么 | 节点住在 `.react-flow__viewport` 里，那个元素带 `transform` = **独立层叠上下文**，里面的 z-index 翻不出去；而左栏在它外面（L4）。所以**给节点提 z-index 是没用的** —— 只能走 z 阶梯早就预留的 **L8「拖拽 ghost」**：portal 一个跟手的缩略图到 body（实测 z=80 命中测试里在最顶）。⚠ 替身必须 `pointer-events:none`，否则它自己会挡住落点命中                                                                                          |
| 「**图片和线分离**」松手后卡在图在这、线在那   | 我复用了吞噬那条的 `playNodeBounceBack`：卡片元素带 `fill:forwards` 的 transform 飞回起点，而 RF 的 wrapper（handle 与边的锚点）留在落点，**位置提交写在动画的 `finally` 里**。这一路只要有一次重渲把被动画的元素换掉，`finished` 就再也不 settle → transform 永久留着、位置永不提交。改成**同步提交**：没有中间态。丢掉的只是 300ms 滑行，而它服务的是「拖到另一张卡上」那个场景 —— 这里落点根本不在画布上，本来也没有「从哪滑回来」 |

⭐ 教训是同一个形状的第 N 次：**复用一段代码时，要连它的前提一起搬**。`playNodeBounceBack` 的前提是「落点在画布上、期间没有会重渲的写操作」，这两条在 8-b 都不成立。

**⚠ 第三条（owner 同批实拍）：「音频还不能放上去」——已补。** 落点是**两种**不是一种：

| 拖什么                                  | 落到卡上 = 什么                       | 为什么不是同一件事                                                                                                                                                        |
| --------------------------------------- | ------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **图**（散图 / 特写 / 任意 image 节点） | 追加进卡的 `referenceAssets` 图集     | 卡的图集是**这张卡长什么样**的证据，多张并存                                                                                                                              |
| **音色**（voice 节点）                  | **连一条「音色 → 卡」的边**，不写图集 | 收割侧本来就这么读的：`harvestUpstreamAudioBindings` 的 Pass 1 走**两跳**（音色 → 角色卡 → 视频），它认的是边不是图集。写进图集等于凭空发明第二套绑定，收割一个字都读不到 |

⛔ 所以这里**没有新造闸**：音色分支直接调 `connectReferenceNode`，合法性 / 重复 / 容量三道闸与 `@` 菜单、「从画布选择」**共用同一处**。头注也写了这一点，免得日后有人在这儿补一份。
⭐ 顺带一条判据：`canConnectNodeTypes` 那张停用的准入矩阵里，「character 接受 voice」被明写成 **音色 audio-binding hop** —— 放开准入让这条边**能画**，但它的语义一直在，不是这次现编的。
⚠ 没封面的音色替身画的是**一块中性面**不是破图框（`previewUrl` 允许缺席）—— 音色本来就不一定有脸。

⚠ **手势本身自动化验不了**：`left_click_drag` 会变成框选文字，手写 `PointerEvent` 序列也驱动不了 React Flow 的 d3-drag。**tsc / eslint / 全量 vitest 全绿只证明代码自洽，不证明画面** —— 这正是本轮反复栽的那个形状，所以这条明确标着**待 owner 亲手试**。要试的四件：拖一张散图到卡上会不会高亮 · 松手后图集会不会多一条 · 本体会不会弹回原位 · **拖一个音色到角色卡上，卡角的 ♪ 会不会亮**（音色走的是边，证据在 ♪ 不在图集）。

- ✅ **`CANVAS_INGEST_DRAG_GESTURE_ENABLED = false` 已查清（2026-08-10）**：三个猜测（bug / 体验 / 没做完）**都不是**。代码头注原话是 "The retired canvas-ingest gesture remains in this file until its wider cleanup task removes the related helpers" —— 它是**被 owner 退役的「吞噬」手势**（2026-07-26 拍板，见 `project-canvas-redesign`），留在文件里只是等清理。
  ⭐ **所以 8-b 不能指望打开它**，而且方向本来就不同：那个 flag 管的是「画布节点拖到**画布节点**上」，8-b 要的是「画布节点拖到**面板里的卡**」—— 跨画布/面板的另一条 DnD 通路，不是同一件事。8-b 要自己搭。

**✅ 8-d 入卡的线作废（owner 2026-08-10 拍板，8-b 落地后当场追加）**

owner 原话：「之前不是通过连线吗，现在有了这个功能后，连线这个可以作废了。**但是卡片 → 视频这个应该保留**。」

⚠ **我第一轮把方向读反了**（以为要停的是「卡 → 视频」那条出边），已收回。停的是**入边**：`* → 卡` 不画 + 卡的**入端口撤掉**。理由与两类入边的证据落点全在契约 [`canvas-identity-card.md` §3](../references/pages/canvas-identity-card.md) 的新增段，这里不复述。

**⬜ 8 的真前置：卡片到底搬不搬家（部分已解）**

⚠ **这张两读法表已被两次拍板切开**，别再照原样读：卡**不搬家**（2026-08-10）· 入卡的线**不画**（同日，8-d）。也就是说落地的是 A 与 B 的一个**交叉点** —— 卡还住画布，但它那一侧的线按 A 的呈现级做法停了，而「所有素材边都不画」（B 的本体）**仍未动**。

B 方向的原始设计里，这一条是**成套**的：卡片 = 纯收集器 → **住进左侧 rail** → 素材→节点**不画线**（只有制片轨画线）→ 拖卡到腰带 = 再喂一镜。报告的「剧本走法」也是这么写的：「左 rail 新建角色卡 → …… 腰带卡入 @小满卡」。

**但阶段 1–6 只实现了腰带那一半。** 今天真机上：卡片仍是画布节点（`image` + `role=character`）· 素材→节点的边**照画**（本轮数边全程都在数它们）。也就是说「腰带当家」落了，「卡搬家 + 素材无线」没落。

这决定了 rail 下段是两个完全不同的东西：

| 读法           | rail 下段是什么                                                                            | 工作量                                                                                                                                                    |
| -------------- | ------------------------------------------------------------------------------------------ | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **A 卡真搬家** | 卡的**家**：画布上不再渲染卡、素材边不画（报告明写「数据层仍建边，呈现级改动，收割零改」） | 渲染层 + 交互层大改：卡从 React Flow 撤出、边按语义分两类只画一类、反查（「这张图被谁用了」）必须同批做成一等公民 —— 报告自己把它列为该方向的**第一风险** |
| **B 卡不搬家** | 卡的**快捷入口**：rail 下段是一份镜像列表 + 拖拽手势，画布照旧                             | 一个面板段 + 一条 DnD 通路                                                                                                                                |

⚠ **不许猜。** 两者差一个数量级，且 A 会连带改「素材→节点画不画线」这条**全域视觉语法**。

**8-a 落地记（三条判断，规格里读不出来）**

1. **两条落点各归各的，不能共用 `land()`。** 那条路对主路是 `spawnReference` —— 会**再建一个散图节点**。可那张图已经在画布上了，复制一份出来正是阶段 3「只剩一套机制」要消灭的东西。所以：主路 → `connectReferenceNode`（连边，与 `@` 菜单同一个动作、同一道容量闸）；收集器卡 → 写 `referenceAssets`。
2. **卡那条不发明新契约** —— `NODE_STUDIO_REFERENCE_SOURCE_IDS.canvas` 早就在，且它的注释已经写死口径：`sourceId` 存**源节点 id**（「id within the source's own namespace」）。**拆出**（`extractReference`）正是靠 `source==='canvas' && sourceId` 判断源节点还在不在、要不要重新物化。顺着它写，拆出零改动就正确。为此把 `ResolvedReferenceMedia.generationId` 改名成 `sourceId`（一个字段按 source 解释，而不是两个字段抢一个槽）。
3. ⚠ **候选必须先按媒体种类挡一道再取 url。** `getNodePrimaryMediaUrl` 读的是 `imageUrl ?? mediaUrl` —— 一个出过片的视频节点返回的是 **mp4 地址**。真机第一版实拍到网格里有一张裂图（那个 `videoReference` 节点），点下去会把视频 URL 塞进「参考**图**」集。判据用 `NODE_MEDIA_KIND_BY_NODE_TYPE` 而不是「url 后缀像不像图片」—— 后者是猜，前者是契约。

**⚠ 为什么新加了 `listCanvasImageSources` 而不是复用 `listConnectableReferences`**：两个问题不一样。那个问「谁能**连**进来」（按 `evaluateCastIngest` 判，含没有图的音色/文本，且会过滤已连的）；这个问「画布上有哪些**图**可以拿」（判据只有「它有没有主图」）。收集器卡要的是一张 URL 不是一条边，硬拿前者当后者用，卡里会列出一堆点了没反应的音色和文本节点。
