### 阶段 1 · 腰带核心（本轮最重的一块）

**做什么**

- `ReferenceManagerPanel` + 详情面板「已引用/已连接」架 + 「管理素材」按钮 **三合一**为一个具名槽架组件。
- **三级折叠**：静息摘要 → 分类 → 缩略图。规则=**折缩略图，不折账**（任一级都读得到「有多少、满没满」）。
- **两档密度 = 同一个件的两个默认折叠深度**（紧凑档默认折起 / 完整档默认展开），**不是两套渲染**。
- 正文回纯文本，`@` 只落槽不留字；发送时走既有 legend 注入。

**⚠ 两条硬纪律（本轮踩过，写死）**

1. **分类区必须从能力契约派生**，不许在组件里手写。原型逐格手写导致**四处漏视频区**（含详情面板档，正好戳穿「两档同一份名单」的论点）。事实源 = `node-video-send-slots`。
2. **容量检查必须收进「落槽」那一个函数**，不许每个入口各写一遍。原型给 `@` 加了新入口就漏一道闸——9/9 被塞成 10/9、总额 13/12。

**验收**：紧凑档与完整档的计数**框出来是同一个数** · 满载 12 装得下且拒绝说对是哪条限制（分项满说分项、分项没满但总额尽说总额）· 三级折叠任一级都能读到账。

### 阶段 4 · 文本

四件套：①独立「文本」入口 + 可变分类（四字段降为「分镜」模板）②**卡即编辑器**（卡面直接改、编辑即保存）③下游可见化 ④composer 文本模式当 LLM。

- **文本落点 = 正文引用胶囊，不进腰带**。判据是**物种**：图/音/视频是二进制素材只能当槽；文本与提示词同质。
- ⭐ **位置即拼接顺序** —— 今天 `mergePromptWithUpstreamText` 的先后写死在代码里，胶囊解决它。
- 胶囊三动作：跳源 / **展开为文字**（脱钩）/ 移除。
- **`@` 全局**：所有输入框（视频/图片/音频 composer、详情面板 prompt、**助手会话** —— `94c86e9c` 自陈还没接）。菜单 = 搜索 + **已引用置顶** + 素材引用按模态分组。落法按物种；**已引用的再 @ 一次 = 定位高亮，不重复添加**（否则发两遍）。
- **文本节点里的 `@` = 给 LLM 的多模态输入**（看图/看视频写字）。能力矩阵**已建成**：`ASSISTANT_MEDIA_CAPABILITIES` —— **只有 Gemini 能吃视频**，OpenAI 仅图，DeepSeek/Anthropic 纯文本；`AssistantMediaReference.source` 已含 `'canvas'`，**是复用不是新链路**。
  ⚠ 文本节点引用上限 **8**（`ASSISTANT_MEDIA_LIMITS.maxReferences`）≠ 视频的 12，**别复用 `node-video-send-slots`**。
  ⚠ 视频 50MB 上限要在 UI 说出来。
- **新能力（不是修 bug）**：图片生成今天**不读**上游文本（显式视频门），文本槽要出现在图片节点上，就得给图片收割加读文本。**只在这一阶段做，别提前当缺陷修。**

## 三、横切纪律（每阶段都适用）

1. **契约派生，不手写**：分类区、容量、参数档位一律从能力契约取。本轮两次翻车都是这个形状。
2. **闸设在一处**：多入口的东西，检查收进它们共同经过的那个函数。
3. **不许静默**：拒绝要说对是哪条限制；发不出去的素材要标出来；失败给原因。
4. **素材是用户的劳动**：切模式、切模型都**不销毁**素材，只标「不会发送/读不了」。
5. **形态即说明**：不可用就不渲染或置灰+原因，别写解释文案。
6. **行号会漂移**：所有引用按符号名 grep，别照行号跳。
7. **闸门三样**：全量 tsc + 全量 vitest **+ eslint**（前两样绿仍会被 pre-commit 的 eslint 拦）。
8. **dev server 是 owner 开的（3000）**：不 kill、不另起、不并行 build。
