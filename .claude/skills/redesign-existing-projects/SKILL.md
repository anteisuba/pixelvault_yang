# 现有页面改版

先读当前页面职责与实际行为，把观察到的问题和用户目标分开。改版需遵循 `docs/scenes/ui-page.md` 的方向与关键切片确认；明确的局部修复直接处理。

审计信息层级、内容密度、主要操作、可发现性、错误恢复、键盘路径和移动端布局。只提出能说明用户收益的改变，保留页面负责的能力与真实数据。

候选方向应在结构上不同；不强制背景图片、卡片、渐变、固定字体或动效。既有外观是证据，确认后的 page 文档才是实施依据。

按确认方向修改现有模块，避免为外观任务改路由或后端契约。复用现有依赖、组件行为与 token 分层；按相关 UI checklist 验证实际交互、三语和移动端。
