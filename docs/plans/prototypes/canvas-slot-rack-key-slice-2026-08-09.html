owner 四问的答复

① 腰带能不能做成折叠？

已改三级：静息摘要 → 分类 → 缩略图。折叠的边界是「折缩略图、不折账」——任何一级都能读到有多少、满没满。两档密度因此简化为「同一个件的两个默认折叠深度」，不再是两套渲染。

② 文本槽点击后要不要把内容加进输入框？

默认不复制出来的字会和源节点脱钩，同一段话就有了两本账——正是这轮要消灭的东西。而且文本今天已经会在发送时自动拼进最终提示词（owner 上一轮截图里「查看发送内容」开头那段就是它），再复制一份进输入框会发两遍。

给了一步显式的「取用为文字」——单向、且取用即转：内容变成你可编辑的普通文字，槽位同时消失，从此与源节点无关。所以任何时刻都只有一本账：要么它是槽（自动拼），要么它是你的字（你自己管），不会两者同时。

③ 底部加提示词模板

已加放在参数条最左，与模型/参数并列（那一行本来就是「点开都是选择器」的地方）。规格沿用 2026-07-27 已拍板的：只取提示词文本，模型与参数不动；替换 + 一次撤销；封面优先的浮层。

零重造：画布图片 composer 已经有这个件（GenerateComposerTemplatePicker），studio 侧是 PromptTemplatePicker。视频线缺的只是把同一个件挂上来并把预筛改成视频类。

④ 全能参考能不能也设关键帧？

今天不能，而且不是 UI 的选择这是 provider 契约：火山三种场景互斥，首尾帧只在关键帧端点成立，参考端点走的是多模态那一档。代码两处把这条钉死了——video-model-send-plan.ts 里 supportsFirstLast = !referenceMode && …（参考模式下 keyframeSlots 直接给 1），node-video-keyframe-plan.ts 里非「关键帧档且双槽」原样返回、不谈首尾。

所以全能参考里那些图都是同权参考（@图N 位置 token），没有「第一帧/最后一帧」的角色。若在 UI 上画出首尾帧，就是伪装一个未接通的能力——发出去仍然只是普通参考图，用户会以为控制住了片头片尾。

本稿的处理：切到全能参考时，原来戴帽子的两张帽子掉下来、变成图4/图5（状态 1 里就是这样），差别一眼看得见，不用文案解释。设计不阻塞未来——具名槽的语法已经在这个件里了，哪天 provider 开了（注释提到 BytePlus 同源、能力表也有首尾帧），把契约打开具名槽自己就长出来，不用重画。

⚠ 顺带一条已核实的同类缺陷：minimax 声明支持关键帧但实际只发 first_frame，用户填的尾帧会被静默丢掉——正是这一轮在治的那类。
