03 助手设计：先弄清目标，再执行
已确认的原则：遇到真正冲突就停下来问用户，确定意图后继续；用户没考虑到的事项可以建议，但建议不能自行变成必选要求。
• 维护目标、必须保留项、允许改变项、参考分工与未决事项；接受用户纠正，避免每轮从零开始。
• 首次参考冲突暂停相关写入并提问；回答只授权当前问题及对应参考图。后续出现新冲突仍需停下来，不把一次确认当永久通行证。
• 参考图不可读最多进行一次有界重试；技术故障不能伪装成需求冲突，也不要求用户重新描述全部意图。
• 批量编辑／自动续跑共享修改摘要，保存已完成操作并刷新画布快照，减少重复创建和记录覆盖。
• 修复模型候选校验上限与重复候选导致的多节点配置失败；模型解析、工具结果和结束步骤同步完善。
• 请求校验错误贯通日志编号与开发环境详情，便于定位真实失败环节。
• 仍须区分：配置已保存、素材处理中、待生成、生成完成、成图已验证。写好提示词不等于输出完全还原。

05 图片引用：画布名＋缩略图＋准确传图
用户决定：所有画面名称以画布节点名称为准，用户看得到缩略图，后端发送的也必须是那张图。
• 附件条、@ 候选与引用块、用户／助手正文、本轮记录统一显示画布名与缩略图。
• 选择绑定稳定图片标识，而非附件列表序号。附件换序不换图；原图被移除或不可用时阻止发送。
• 历史 reference image N 按原消息的图片 URL 解析，不能拿今天的第 N 张替代。重名歧义不猜图。
• “生成图3”优先作为完整节点名称解析，不解释成第 3 个附件。
• 助手视觉请求发送实际图片和名称映射；生成请求按实际输入顺序附名称对照表，过滤空图／不可用图并同步去重，图片与名称保持一致；不改写用户保存的原始提示词。
• GPT-6 Luna 真实核验“生成图3”的黑色背景、遮嘴动作、服装以及到精修节点的连线通过。本轮未为此再做付费图片生成，不能据此承诺成图一致性。

06 即梦与 LibTV 调研结论
两边均以同一组机器人冲突图和用户提供的时夜.jpeg 做过登录后多轮测试：分析 → 反问 → 批量布置 → 纠正 → 节点配置核对。
• 即梦：多图冲突首轮未识别，明确指出后才给选项；未指定服装时直接建了三套方案。后来复用指定节点，参考、提示词、比例、画风与布局可以在节点里核验。用户允许后完成一次真实换装生成，页面回执 8 积分；成图出现后助手仍思考，未完成承诺的逐项自检。显示余额不能代表最终账单。
• LibTV：首轮多图冲突、服装未定时能显示问题块等待回答；但后续“比例不变＋腿长翻倍”冲突中擅自选了腿翻倍并修改节点。纠正后恢复旧节点，未重复创建。部分新增配饰建议仍被写入提示词。
• LibTV 显示余额 197，当前 Lib Image 节点显示 15 积分／张；人工模型菜单未找到明确 GPT 名称，未认定品牌别名就是 GPT，也未换别的模型代为生成。
采纳：直接可回答的问题块、参考图可见绑定、可复用节点、简短回执；规避：默认替用户选冲突、未经验证承诺“100%还原”、建议混入必选要求、生成后不收尾。以上是样本观察，不是竞品全场景能力结论。
