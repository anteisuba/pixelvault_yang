## 0.1 · 第一版复盘（2026-07-26，实看设计稿）

设计稿：Claude Design 项目 `2b10381c` 文件 `视频组装台.dc.html`（9 格状态 + 1 张上下文图）。

**做对的（信息设计，是资产，下一轮必须保留）**：三个上限在界面上真数得出来（图 6/9 · 音 1/3 · 视 0/3 · 0.0s/15.0s）· 满载 9/9 第 10 张被拒并标「不会发送」+ 给出「替换掉某一格 / 断开这条边」两条出路 · 模型不支持音频时槽位斜线降级 + 「为什么失效」+ 回退路径 · 生成中明写「不确定态（无百分比）· 无法预估剩余时间」· 每态唯一主动作（补素材 / 取消生成 / 重试 / 加入成片）· 失败带 `request id` 且注明「成分仍在画布上 · 未改动」· 上下文图给了左竖 rail + 班底架 + 常显连线（图=实线蓝 / 音=虚线青 / 视=紫虚线圈）+ 右助手 dock。

> **推翻项因此收窄为**：下面第 2 条（凭空造能力的五个模式 tab，仍必须删）、第 3 条（只剩浅色）、第 4 条（响应式与键盘未交代）。第 1 条作废。
> 唯一附带修正：2a 的极细边（≈0.92 对比）在可操作元件上不达 3:1，需加深 —— 这条稿子自己也提过。

**歪掉的（外壳语言，是负债，下一轮必须推翻）**：

1. **抄了参考截图的整套元件语法** —— 稿子自述「按「想要状态」截图重铺」，并逐条列了从截图拿的东西：浅底点阵、卡外标题、白卡+极细边+柔和投影、左右边缘常显 handle、卡上「替换」浮起钮、composer 作为节点右侧独立浮层（pill 标签页 → 槽格行 → 提示词 → 底部参数条 + 圆形发送）、⚡积分紧贴发送键。
2. **搬进了别家的功能分类学** —— composer 顶部出现「文生视频 / 图生视频 / 首尾帧 / 全能参考 / 视频编辑」五个模式 tab。**我们的对象模型里没有这五种模式**：这个节点本身就是"参考档装配"，也没有"视频编辑"。这已经不是像不像的问题，是**凭空造能力**（违反检测器第 5 项）。
3. **只剩浅色一版** —— 深色 1a 被删，违反 brief「浅色与深色两版都成立」。
4. 响应式（平板 / 375px）与键盘/焦点未见交代。

**根因不在模型，在喂法**：第一版（深色 1a）本来是它自己按功能推的方向；owner 后续让它"按截图重做"，截图就从「气质参考」升格成「布局模板」。§2 的黑名单只挡住了第一轮的附件，没挡住后续对话里的口头升格。

**新增一条硬纪律**：任何一轮只要说了"按截图/照这个"，就等于把截图升格为规范 —— 想引用截图只能说「我要这种**密度**」「我要这种**近场操作节奏**」，并且必须同时说「**元件语法与分类学不要照搬**」。

## 1 · 第一轮粘贴用 prompt（自包含，直接复制进 Claude Design 新项目）

> 说明：这段刻意**不提我们现在长什么样**，只讲功能、对象、真实上限、任务、状态、结构契约。它自包含 —— Claude Design 读不到我们的仓库。

```text
你在为一个 AI 创作工作台里的「画布（导演台）」设计一个关键组件。请只按功能设计，不要参考任何现有产品的外观，也不要问我现在长什么样——现状不是答案。

【产品语境】
这是一个个人 AI 创作工作台。画布是「长视频导演台」：在一张自由无限画布上把「剧本 → 分镜 → 逐镜生成 → 拼接成片」编排出来。它面向的是「第二次以上」的创作——同一个角色要跨多个镜头长得一样、声音一样，最后拼成一条完整的片子。轻量的单次生成有另一个页面负责，这里不做。

【本轮唯一任务】
设计「视频组装台」这一个组件（画布上的一张大卡）。它是画布上唯一真正「下单」的对象：把一组素材汇进来 + 写一条提示词 → 生成一段视频。
它必须让人一眼看清四件事：这次生成会送出去什么、还差什么、上限还剩多少、下一步点哪。

【它装什么（真实的 provider 合同，不能改也不能美化）】
一次生成 = 1 条提示词 + 三个数组：
- 参考图 image_urls：最多 9 张。超出的条目必须诚实标出「不会发送」，不能静默丢掉。
- 参考音频 audio_urls：最多 3 条，而且只有「reference 档」的模型支持；换到不支持的模型，音频槽必须诚实失效并说明原因，不能留一个假槽位。
- 参考视频 video_urls：最多 3 段，且合计时长 ≤ 15 秒。
参数：时长 4–15 秒；分辨率 480p / 720p / 1080p（fast 档没有 1080p）；画幅 16:9 / 9:16 / 1:1 / 4:3 / 3:4。
提示词里用 @名字 引用具体素材（例：@林皎），这些 @ 引用和上面的槽位是一一对应的关系，设计要让这个对应看得见。

【素材从哪来（画布上的关系）】
画布上有别的对象通过**常显连线**喂进这张卡：
- 角色卡 / 场景卡：一个「身份」= 名字 + 一组出场图（主图恒第一）+ 绑定的一条参考音频。同一张角色卡会被多个镜头引用。
- 静帧图：中间产物，先出静帧再喂视频。
- 参考视频段。
连线是一等公民、默认常显、按类型区分。**绝对不要设计成「素材被吃掉后消失」**——成分永远留在画布上，卡里只显示它的凭证。

【必须用这份真实内容，不许用 Lorem 或 "Character A"】
项目《霜降的信》，6 镜，风格「冷调胶片，手持轻微晃动」。
班底：角色「林皎」（出场组 3 张：旧邮局门口中景 / 侧脸特写 / 全身雨衣；音色：林皎 · 参考音频 8s）；角色「老周」（出场组 1 张：柜台后半身；音色：老周）；场景「旧邮局 · 黄昏」（1 张）。
要画的是镜 3：林皎把信推过柜台，老周迟疑地没有立刻接。
成分 = 林皎 3 张 + 老周 1 张 + 场景 1 张 + 镜3静帧 1 张 = 6/9 图；音色林皎 = 1/3 音；参考视频 0/3。
提示词原文：@林皎 把信推过柜台，@老周 迟疑地停在半空没有立刻接。参考 @旧邮局 · 黄昏 的光线，手持轻微晃动，冷调胶片。
参数：12 秒 · 720p · 16:9 · 模型 Seedance 2.0 Reference。

【必须交付的状态（缺一格算没做完）】
1. 紧凑态：这张卡摊在画布上、没被展开时长什么样。
2. 展开态：需要写提示词/调参数/看结果时的完整形态，并说明它怎么处理遮挡（原地长大 / 侧开 / 半屏）。
3. 缺素材：只有提示词、没有任何上游成分——「还差什么」要读得出来。
4. 满载：9/9 图，第 10 张被拒绝，上限与拒绝理由怎么表达。
5. 模型不支持音频：音频槽失效 + 原因可读。
6. 生成中：进度只能是不确定态（后端没有真实百分比事件）——不许画百分比数字或确定进度条。
7. 失败：错误可读 + 可重试。
8. 已出片：结果视频在卡上 + 一个「加入成片」的入口（成片序列本身在另一个视图里，不要在这张卡里做时间线）。

【结构契约（已拍板，不许改）】
- 主场是自由无限画布（可平移缩放框选），这张卡是画布上的对象，不是一个页面表单。
- 三条槽轨（图 ≤9 / 音 ≤3 / 视 ≤3）+ 提示词面 + 结果监视，是这张卡的骨架。
- 关系靠常显连线读，槽轨只表达「这次装了什么」，不取代连线。
- 每个对象上最多一个主动作，按状态改写（缺素材→补素材 / 齐了→生成 / 出片了→加入成片）。不要并列五个按钮。
- 状态不能只靠颜色表达。正常文本对比度 ≥4.5:1，UI 边界 ≥3:1。要同时给出浅色与深色两版都成立的方案（深浅哪个当默认由你论证，我们不预设）。
- 键盘可达、焦点可见；尊重 prefers-reduced-motion。

【明确禁区】
- 不要用材质隐喻当设计出发点（"制片桌""胶片工作台"这类叙事我们试过两轮，都失败）。
- 不要装饰性纹理、霓虹发光、渐变堆叠、玻璃拟物当主视觉手段。
- 不要发明产品能力：没有成品配乐/音效轨、没有自动分镜、没有"AI 建议"面板、没有真实百分比进度、没有审核评分。
- 不要把助手、图片编辑、资源管理塞进这张卡——它们各有自己的位置。
- 不要输出整页施工稿：本轮只要这一个组件 + 一张「它能落进画布骨架」的上下文示意。

【交付格式】
先用 3–5 句话说明你的空间与层级判断（为什么槽轨这样排、提示词与槽轨的关系、展开怎么不挡住画布），再出图。每一张图标明它是哪一格状态。最后逐条自查并回答：上面 8 格状态是否都出了？三个上限数字（9 / 3 / 3 段 15 秒）是否都在界面上真实可见？有没有画任何我禁掉的东西？
```

## 2 · 喂什么 / 绝不喂什么

**喂**：上面这段 prompt · 简报 [`canvas-redesign-cd-brief-2026-07-25.md`](canvas-redesign-cd-brief-2026-07-25.md) 的 §事实与状态矩阵 / §已确认结构契约 / §审美方法与禁区 / §本轮真实内容 · owner 另发的"想要状态"截图（**到了再喂，且只说"我要的是这种交互气质/信息密度"，不说"照这个做"**）。

**绝不喂（第一轮全部拉黑）**：

- ❌ `/studio/node` 的任何截图、录屏、web capture —— owner 定调"按功能设计"，这是第一号污染源。
- ❌ `src/app/canvas.css`、`node-canvas.md`、`canvas-workbench.md` 的造型段（暖炭/纸卡/石绿、冷石墨/钨丝琥珀）。
- ❌ 简报里「组装台今天已有的零件」那一节 —— 那是**实现期约束**（Sonnet 用来复用行为），不是设计输入。它会让 Claude Design 围着现有组件形状画。
- ❌ **已同步的 56 组件设计库**（`.design-sync/`，见 memory `project-design-sync-claude-design`）—— 它带着当前皮肤，一复用就把旧皮端回来。**本轮开一个独立项目，不要在那个项目里做，也不要引用它的组件。**
- ❌ 其它域的皮肤（LoRA 冷瓷灰白、首页白厅画廊）—— 域视觉身份彼此独立。
- ⚠ 设计系统只准提取**脊柱层**（间距/字号尺度/状态语义/对比度纪律），不提取任何域皮肤。

## 3 · 每轮怎么说话（防漂移话术）

| 场景             | 该说                                                                   | 不该说                               |
| ---------------- | ---------------------------------------------------------------------- | ------------------------------------ |
| 反馈不满意       | 「第 4 格（满载 9/9）没有表达出被拒绝的那张图，请只改这一格」          | 「感觉不太对，再来一版」「做漂亮点」 |
| 结构被改了       | 「你把槽轨合并了，违反结构契约第 2 条：三条槽轨是骨架。请恢复」        | 「我更喜欢原来那版」                 |
| 想收窄           | 「本轮只改提示词区与槽轨的对应表达，其它区域保持不动」                 | 「整体再优化一下」                   |
| 它想扩张         | 「不要加这个能力，它不存在。请删掉并说明剩下的状态怎么覆盖」           | 沉默（默认接受 = 假能力进设计）      |
| 每轮结尾固定追问 | 「这一版满足结构契约哪几条？违反了哪几条？8 格状态现在覆盖到第几格？」 | ——                                   |

**一轮只改一件事。** 每轮结束把结论追加到简报的《Owner 反馈记录》表（一次一行）。
